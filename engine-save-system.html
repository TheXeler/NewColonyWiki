存档系统状态

本页按 Engine/Save/SaveSystem.cpp 的当前实现整理，用来判断哪些状态会被保存、哪些只是占位或仍需补齐。

入口和文件布局

控制台命令 save [name]、load [name] 和 save_list 通过 Engine::save_world、Engine::load_world 调用 SaveSystem。保存槽 ID 只能包含字母、数字、下划线和短横线。窗口关闭或退出游戏时，如果世界仍处于活动状态，引擎会先暂停模拟、取消未开始的后台 chunk 工作，并同步保存当前槽后再释放资源。

文件当前内容加载行为
manifest.jsonengine_version、slot_id、world_name、world_seed、tick、mod_list_checksum、last_written。必须存在；版本不等于当前 0.1.0 时拒绝加载。
world.jsonworld_seed、tick、terrain_sea_level、WorldMap 配置和 tile 列表、天气状态。恢复世界 seed、tick、世界地图配置、海平面和天气。
entities.json实体 ID 和一组标准 ECS 组件。清空 ECS World 后按原 ID 重建实体和组件。
regions/*.ncr按 32×32 chunk region 写出已加载 chunk。文件头包含 magic/version、region 坐标、header size、1024 项 chunk offset/size/flags table 和 v2 block id 字典；chunk payload 保存 sub-chunk uniform/palette/dense BlockState{id,data} 表示和独立 lights overlay。payload 使用内置 RLE 压缩，压缩后不变小时自动保留未压缩数据。读档会读取 region 文件并恢复成 ChunkSnapshot；运行时 chunk streaming 会按目标 chunk 坐标定向打开对应 r.x.z.ncr，优先从当前 slot 的 region payload 加载 snapshot，缺失时才重新生成地形。targeted streaming 会缓存 region header/table，并按 offset 只读取目标 chunk payload。v2 region 会通过保存的 block id 字典把已知字符串 id 重新映射到当前 MOD registry hash，缺失 block 保留原 numeric fallback。far chunk unload 会复制 terrain/light-dirty snapshot 后排入后台 region 写回任务，再卸载运行时 chunk。
mods.json已加载 MOD 的 id、name、version、side。用于 MOD 差异诊断；不会自动下载、启用或重排 MOD。
factions.jsonNPC 阵营实例和阵营对关系。恢复实例、关系值、倾向和 last_changed_tick。
jobs.jsonWorkPool 活跃 job 和 next_id。清空当前 WorkPool 后恢复活跃工作。
focuses.json焦点触发状态、活跃焦点和 next_instance_id。恢复已触发状态和仍在显示的焦点。

会保存的实体组件

entities.json 当前覆盖以下标准组件。保存时尽量同时写字符串 ID 和哈希，加载时优先用字符串 ID 重新从当前注册表计算哈希。

  • 基础空间与生命：Position、Speed、Rotation、Scale、Health、Name。
  • 殖民者与 AI：Needs、Mood、ColonistTag、AIState、Profession、Civilization、WorkerPriorityConfig、NavAgent。
  • 物品与交互：HeldItem、Equipment、BlockInteractor、Stats。
  • 实体原型和表现：PrototypeRef、EntityVisual、EntityAnimation、HeadVisual、InterestPoint。

MOD 校验

存档会保存当前 MOD 列表校验码。读档时如果当前校验码不同，加载不会立即失败；系统会输出 missing、added、active 差异并继续尝试加载。

当前限制

限制影响
engine_version 必须匹配版本不匹配时直接拒绝加载。
region streaming writeback 仍需完善regions/*.ncr 已使用 offset table、sub-chunk representation、RLE payload compression 和 v2 block id dictionary；读档后的 chunk streaming 会定向读取当前 slot 的 region payload，并缓存 region header/table 来避免重复解析。far chunk unload 会把已标记修改的 terrain 或 light overlay chunk 复制为 snapshot 并异步写回 region，切换存档根目录、清理 pending work 和 shutdown 时会等待未完成写回；当前仍缺少更完整的数据迁移策略，例如已删除/重命名 block 的替换规则。
建筑和区域实例未单独序列化BuildingSystem、ZoneSystem 的运行时实例不在当前存档文件中恢复。
Lua 数据组件不保存engine.data 是运行时 Lua 状态，不进入存档，也不参与网络复制。
MOD 自定义组件没有扩展点只有 C++ 已列出的标准组件会被 SaveSystem 显式保存。
MOD 差异只诊断不修复缺失 MOD、版本差异和新增 MOD 只会记录差异，仍需要用户或启动流程处理。
当前存档会保存实体、世界配置、天气、阵营、工作、焦点状态和已加载 chunk 的 region 数据；运行时 far chunk unload 已有异步 dirty region writeback，targeted region streaming 已缓存 header/table，纯 light overlay 变化也会触发 region 写回，新 region 文件会保存 block id dictionary 并在加载时按当前 MOD registry remap。建筑、区域、MOD 自定义运行时状态和更完整的数据迁移规则还需要补齐。
