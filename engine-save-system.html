存档系统状态

本页按 Engine/Save/SaveSystem.cpp 的当前实现整理，用来判断哪些状态会被保存、哪些只是占位或仍需补齐。

入口和文件布局

控制台命令 save [name]、load [name] 和 save_list 通过 Engine::save_world、Engine::load_world 调用 SaveSystem。保存槽 ID 只能包含字母、数字、下划线和短横线。

文件当前内容加载行为
manifest.jsonengine_version、slot_id、world_name、world_seed、tick、mod_list_checksum、last_written。必须存在；版本不等于当前 0.1.0 时拒绝加载。
world.jsonworld_seed、tick、terrain_sea_level、WorldMap 配置和 tile 列表、天气状态。恢复世界 seed、tick、世界地图配置、海平面和天气。
entities.json实体 ID 和一组标准 ECS 组件。清空 ECS World 后按原 ID 重建实体和组件。
chunks.json当前写出 chunk_overrides: []。只校验 engine_version；尚未恢复方块改动。
mods.json已加载 MOD 的 id、name、version、side。用于 MOD 差异诊断；不会自动下载、启用或重排 MOD。
factions.jsonNPC 阵营实例和阵营对关系。恢复实例、关系值、倾向和 last_changed_tick。
jobs.jsonWorkPool 活跃 job 和 next_id。清空当前 WorkPool 后恢复活跃工作。
focuses.json焦点触发状态、活跃焦点和 next_instance_id。恢复已触发状态和仍在显示的焦点。

会保存的实体组件

entities.json 当前覆盖以下标准组件。保存时尽量同时写字符串 ID 和哈希，加载时优先用字符串 ID 重新从当前注册表计算哈希。

  • 基础空间与生命：Position、Velocity、Rotation、Scale、Health、Name。
  • 殖民者与 AI：Needs、Mood、ColonistTag、AIState、Profession、Civilization、WorkerPriorityConfig、NavAgent。
  • 物品与交互：HeldItem、Equipment、BlockInteractor、Stats。
  • 实体原型和表现：PrototypeRef、EntityVisual、EntityAnimation、HeadVisual、InterestPoint。

MOD 校验

存档会保存当前 MOD 列表校验码。读档时如果当前校验码不同，加载不会立即失败；系统会输出 missing、added、active 差异并继续尝试加载。这个行为适合开发期诊断，但还不是完整的发布级依赖解析或迁移策略。

当前限制

限制影响
没有跨版本迁移层engine_version 必须完全匹配；旧存档不能自动迁移。
方块改动未恢复chunks.json 是占位结构，挖掘、建造、方块数据等世界差异读档后依赖 seed 重新生成。
建筑和区域实例未单独序列化BuildingSystem、ZoneSystem 的运行时实例不在当前存档文件中恢复。
Lua 数据组件不保存engine.data 是运行时 Lua 状态，不进入存档，也不参与网络复制。
MOD 自定义组件没有扩展点只有 C++ 已列出的标准组件会被 SaveSystem 显式保存。
MOD 差异只诊断不修复缺失 MOD、版本差异和新增 MOD 只会记录差异，仍需要用户或启动流程处理。
当前存档适合开发期保存实体、世界配置、天气、阵营、工作和焦点状态；还不能作为发布级长期存档兼容承诺。涉及世界方块改动、建筑、区域或 MOD 自定义运行时状态的功能，在依赖存档前需要补齐序列化和迁移策略。
