存档系统状态

构建模块：存档工作目录的发布与恢复、region 文件读写和 region header 缓存位于 engine/saveio.dll；世界状态捕获、序列化、恢复和网络状态文档由 engine/save.dll 的 SaveSystem 提供。它通过 SaveHost 借用宿主服务；SaveSystemHost.cpp 留在 engine.dll，提供六个 Engine 入口适配，世界发布与所有者屏障继续由 Engine 控制。2026-10-11 模块链接、完整项目续编和依赖暂存通过，未运行游戏或测试。边界与验证记录见 docs/engine-runtime-final-split.md。

经验接口支持负整数增量：扣除后最低为 0，不降低已有等级；正增量封顶 INT32_MAX。计算全程使用 i32，在运算前判断边界，INT32_MIN 扣除也不会发生取反溢出。工作奖励和升级阈值配置仍要求正整数，测试源码未执行。

经验值、奖励和升级阈值使用 i32 整数。累加前检查上限，超出时取 INT32_MAX，再按整数阈值升级；不使用 i64 或浮点累加。存档、网络、经济日志和 UI 同步使用整数经验，配置拒绝小数、负数和越界值。职业历史无法写入时，当前职业保持原样。测试源码尚未执行。

结算后清理工人关联同时检查工作 UUID：若回调重建工作池并复用了原数字编号，外层不会清掉不同 UUID 的新工作。两种 AI 入口的同编号复用测试源码已补，尚未执行。

拆除回调为工人分派其他工作后，外层结算保留新的 AI 关联与方块兴趣点；忙碌工人缓存按回调后的 AI 状态更新，不强制改为空闲。两种 AI 入口均有重分派测试源码，尚未运行。

AI 原生结算使用工作副本，拆除回调返回后重新按编号和 UUID 检查活动工作，避免工作池扩容导致悬空指针；回调已经取消或替换的工作不再由外层完成或取消。相关回调变更测试源码尚未运行，这不撤销回调已经发生的世界效果。

建筑删除回调使用定义和实例副本，同一 UUID 的递归删除被拒绝，回调后按原 UUID 重新查找再移除，避免回调扩容建筑数组或替换回调导致引用失效。异常释放删除保护，但不撤销回调已发生的世界副作用。拆除掉落与方块修改的整体事务仍未完成，测试源码未执行。

原生工作结算返回 Applied、Deferred 或 Rejected。缺少狩猎目标 Health、缺少方块交互器或建筑拆除拒绝时，两个 AI 入口走工作取消、不授予成功经验、不发布完成通知。进度到 1 后保留活动记录直到完成或取消提交。Deferred 仍需后续方块处理或 Lua 结算，因此不代表效果已提交；完整事务尚未完成，测试源码未执行。

工作坐标转为方块整数坐标时，先检查 floor 后的值是否有限且处于 i32 范围内；错误坐标在写入 BlockInteractor 或兴趣点之前抛错，避免有限大浮点数转换越界。负数仍按 floor 取整，相关边界测试源码尚未执行。

AI 的 Task 执行入口在 complete_task 成功后清除当前 Task、忙碌状态及兴趣点；完成后使用提前保存的标签，不再读取已移除的任务指针。推进已将任务标为失效，世界效果和经验仍发生在通知提交之前，因此此顺序修复不等于完整完成事务或可安全自动重试。

工作推进拒绝负数、NaN 和无穷时间步，异常输入不改写进度。有限输入的进度计算先使用 double，再限制到完成值后写回 float，避免除法溢出污染工作状态。相关测试源码未执行。

直接派工与目标替换共用有限坐标、有限非负时长、目标类型/动作/载荷类型枚举检查。直接派工保留零时长支持，目标替换和批量派工要求正时长。非法输入在分配身份或取消旧工作前拒绝；测试源码未执行。

目标工作替换在取消旧工作前检查编号耗尽、编号冲突、时长和有限坐标；已知无法派工时直接拒绝并保留旧工作。内存分配或其他后续失败的整体回滚仍待完成，测试源码未执行。

替换同一目标的工作共用 cancel_task 的资源释放检查：旧预约无法释放时保留该工作并停止新增替代工作，不提前发布取消通知。旧工作取消成功后的新建失败仍不具备整体回滚；测试源码未执行。

单项中断和解除工人工作先检查预约能否释放，失败时保留该工作分配、进度、预约及通知队列。中断工人全部普通工作先准备整批通知，再以一次 release_many 发布相关预约释放；拒绝释放时所有相关工作的分配与进度保持原状，成功后才发布中断通知。Battle Task 由战斗停止或失能清理路径管理；征召交接另将旧个人 Move 的取消与经营任务中断纳入同一预约发布。测试源码尚未运行。

工作完成先复制并入队通知，再移除工作和身份索引；末尾记录通过不抛异常的移动填补空位。通知分配失败不会提前失效工作。已有索引/重复完成测试源码，分配失败注入和运行验证尚未执行。

网络状态接收器使用本包复制后的实体候选世界解析工作 UUID 和同步装备缓存，不能读取旧活动实体世界。SaveSystem 成功后更新该候选，NetworkSystem 在会话发布门内最终交换实体世界；拒绝包不发布候选修改。此路径已补源码测试，尚未运行；实体增量不带状态文档时的关联清理仍待核对。

Lua 的 remove_pending_candidate 在删除待入籍候选实体前也执行工作引用清理；清理抛错时不会继续销毁实体。袭击超时撤退通过显式传入的工作池执行同样清理，再销毁成员；网络实体替换仍需独立处理。相关测试源码未执行。

实体移除前为已入队的激活、完成、取消、中断通知及本次新取消通知捕获 worker/target UUID；多个实体依次移除时保留之前捕获的身份。Engine 每次排出通知队列前也为整批捕获实体身份，防止前一个监听器删除实体影响后续通知；捕获异常时保留队列供重试。快照字段不写入活动工作或存档。建筑身份和其他关联仍需独立核对，测试源码未执行。

居民和普通实体死亡时，在销毁实体前清理工作引用：取消该实体负责或作为目标的工作；仅因该实体临时跳过的工作则清除跳过者和期限，继续保留。居民死亡监听器返回后再清理一次，覆盖回调新建的关联。其他实体移除入口仍需核对，不能把这一清理视为全局销毁钩子；相关测试源码未执行。

工作记录的实体引用使用 designated_worker_uuid、assigned_worker_uuid、claimed_worker_uuid、skipped_worker_uuid 和 target_entity_uuid。空字符串表示无引用；非空值必须是已存在实体的 UUID。磁盘读取按待加载实体身份映射解析，网络读取按候选世界解析，全部成功后才发布工作。写入时非零运行时句柄没有合法 UUID 会使快照生成失败。库存内容没有独立数字或 UUID 身份；预约句柄仍为数字，任务引用遵循当前 TaskId 契约。上述路径尚未在本轮编译或执行验收。

入口和文件布局

2026-09-28：任务集合使用 tasks.json 的 tasks 数组，网络世界状态文档 ID 为 tasks。当前格式不读取旧文件或字段，不提供迁移和别名。任务身份为 TaskId UUID。行为树 ID 和节点字段已移除；本轮未编译或运行测试。

实体的 AIState 保存 lod_level、busy、current_task_uuid 与 current_plan_step。恢复时核对当前任务存在且分配给该实体；任务池中每个已分配任务也必须与实体状态对应。网络实体快照同步执行步骤。本次源码变更尚未编译或运行测试。

控制台命令 save [name]、load [name] 和 save_list 通过 Engine::save_world、Engine::load_world 调用 SaveSystem。保存槽 ID 只能包含字母、数字、下划线和短横线。RmlUI 的读档按钮会先显示世界加载遮罩，再执行同步存档恢复；只有逻辑服务器、存档状态、MOD 世界回调、初始殖民地、相机可见区块、实体渲染快照和 RmlUI 世界数据全部就绪后，ui_phase 才会切换到 playing。加载中途失败会丢弃半初始化世界并关闭其会话，不会把它保存为正常存档。直接调用 Engine::load_world 的控制台/程序接口仍保持同步语义。窗口关闭或退出游戏时，如果世界仍处于活动状态，引擎会先暂停模拟、取消未开始的后台 chunk 工作，并同步保存当前槽后再释放资源。

自动保存

自动保存的节奏按游戏内时间计算，由玩家在设置的 Game 页选择：关闭、每 12 小时、每 1 天、每 3 天、每 7 天、每 15 天。界面上是大类选项，内部用索引 0-5 表示（关闭=0、12 小时=1、1 天=2、3 天=3、7 天=4、15 天=5），持久化在 settings.json 的 auto_save_index 字段，默认每 1 天。

引擎侧由 AutoSaveFrequency 与 auto_save_interval_ticks() 定义（Engine/Scripting/ScriptEngine.hpp）；判定方式是“世界时钟跨过间隔的整数倍”（ScriptEngine::update_timers），因此 12 小时这种跨半天的间隔与 1/3/7/15 天共用同一套逻辑，不再依赖原先每天固定 tick 的单点检查。

触发时写入的存档槽固定为 auto（显示名 AutoSave，根目录为存档根），接线在 Engine.cpp 的 set_auto_save_callback。Engine::init 会用设置值调用 set_auto_save_frequency，设置页改动时立即生效。Lua 侧可用 engine.settings.set_auto_save("never"|"12h"|"1d"|"3d"|"7d"|"15d") 与 engine.settings.get_auto_save() 读写同一设置。

会保存的实体组件

entities.json 当前覆盖以下标准组件。保存时尽量同时写字符串 ID 和哈希，加载时优先用字符串 ID 重新从当前注册表计算哈希。

  • 基础空间、视野与生命：Position、Speed、VisionRange、Rotation、Scale、Health、Name。VisionRange 保存非负基础半径；Health 必须保存有效的 base_max 基础容量；缺失或无效时拒绝加载，不从已修正的 max 推导基础值。基础容量为零也是有效值。
  • 保存 Speed 和 Rotation 时，通过统一属性接口读取 ECS 基础值；持续修正后的速度和朝向由修正来源重新解析。Name 也通过统一接口读取 ECS 字符串。保存 Health 时，current 和 max 从统一属性接口取得当前解析值，base_max 通过同一接口读取独立基础容量。解析失败或结果超出 Health 整数范围时拒绝捕获，不保存旧投影值。
  • 实体基础属性 Map 不得包含 position.x、current_hp 等 ECS 权威字段的同名键；保存捕获和读档都会拒绝这类冲突。
  • 殖民者与 AI：Needs、Mood、ColonistCondition、Attributes、AttributeModifierGroups、ColonistBackground、ColonistTag、AIState、Job、Civilization、WorkPriorityConfig、NavAgent。基础属性按完整路径保存在 Map 中；每个实体的修正组保存来源、组 ID 和修正项，读档时先完整校验，再恢复到运行时。带 ColonistTag 的实体必须保存包含 colonist.* 的属性 Map，缺失时拒绝保存或读档。读档还校验导航路径数量、当前位置和路径点数组长度，拒绝越过 NavAgent 容量的记录。
  • 实体能力属性统一保存在 Attributes Map；空 Map 的组件存在性也随存档保留。运行时新增属性的来源另存在 AttributeSources。保存与加载都拒绝指向不存在属性键或空来源的记录；加载还拒绝重复来源键。旧实体 Attachments 存档组件会被拒绝。物品内容中的附件仍随其 ItemStack 保存。
  • 物品与交互：BlockInteractor、Inventory、GroundItemPile 与 Equipment 随实体保存；实体背包同时保存基础槽数和实际内容，读档校验物理槽数与已恢复修正后的 inventory_slots 一致。owner_items.json 的实体背包行也记录基础槽数，并与实体记录核对；客户端恢复带服务器解析缓存的实体时，也拒绝物理槽数与同步解析值不一致的背包。方块容器和仓储策略写入同一文件。装备组件保存完整 ItemStack，地面堆使用实体 UUID；普通库存内容没有独立实例身份。
  • 实体原型、属性和表现：PrototypeRef、Attributes（生成时展开后的属性 Map）、EntityVisual、EntityAnimation、HeadVisual、InterestPoint。原始 capability JSON 不再随实体保存。

MOD 校验

存档会保存当前 MOD 列表校验码，校验码只覆盖已加载内容（启用并通过加载的 Mod）。读档时如果当前校验码不同，加载不会立即失败；系统会按同一口径输出 missing（存档时需要、现在未安装）、disabled（仍安装但已禁用）、added（现在多出来的内容）和 active 差异，并继续尝试加载。旧存档的 mods.json 没有 enabled 字段，这些条目按“参与过世界内容”处理，因此卸载 Mod 仍会被报为 missing。

当前限制

限制影响
engine_version 必须匹配版本不匹配时直接拒绝加载。
region streaming writeback 仍需完善regions/*.ncr 当前格式使用 offset table、有符号垂直 sub-chunk representation、RLE payload compression 和 block id dictionary，并拒绝旧固定高度格式；读档后的 chunk streaming 会定向读取当前 slot 的 region payload，并缓存 region header/table 来避免重复解析。far chunk unload 会把已标记修改的 terrain 或 light overlay chunk 复制为 snapshot 并异步写回 region，切换存档根目录、清理 pending work 和 shutdown 时会等待未完成写回。
区域实例序列化ZoneSystem 实例以 zones_schema_version 和 zones 写入 world.json，保存类型、形状、范围/体素、目标、过滤器和设置；加载世界和 Server 状态时按稳定实例 ID 恢复，未知 schema 版本会拒绝。
