资源 IO 与 UTF-8 路径

引擎运行时资源、MOD 数据、配置、存档和日志路径统一按 UTF-8 处理。Windows 上不要直接把 UTF-8 字符串交给 fopen、std::ifstream、std::ofstream 或第三方库的 char 路径 API。

统一入口是 Engine/Core/IO/FileIO.hpp。读取文本/二进制文件使用 nc::io::read_file、read_binary_file；写出使用 write_text_file、write_binary_file。需要 simdjson DOM 时使用 Engine/Core/IO/JsonIO.hpp 的 nc::io::load_dom，不要调用 parser.load(path)。

覆盖范围

  • JSON 数据和配置：MOD 清单、数据注册、控制台配置、本地化、设置和存档 JSON 都先通过 FileIO 读入内存，再解析。
  • 图片、shader、模型和脚本：stb_image、SPIR-V、Lua 脚本和 glTF 主文件改为内存加载；glTF 的外部文件读取通过 tinygltf filesystem callbacks 接到 FileIO。
  • glTF 路径转换使用 C++20 的 std::u8string 构造 std::filesystem::path，替代已弃用的 u8path()。模型主路径、外部纹理和 buffer URI 解码后的路径继续按 UTF-8 解释，与 GB2312 控制台代码页相互独立。
  • Shader 预处理的 #include 路径同样通过 std::u8string 构造文件系统路径；依赖时间检查和递归扫描保留 UTF-8 文件名语义。
  • 音频：Windows 上 miniaudio 使用 ma_sound_init_from_file_w；其他平台继续使用原生 char 路径。
  • RmlUI：运行时注册自定义 Rml::FileInterface，RML、RCSS 和字体文件都通过 UTF-8 安全路径打开。
  • 日志和随机访问文件：日志使用 FileIO 打开底层文件句柄；需要 seek/read 的区域文件先安全读入内存再解析。

开发约束

  • 新增资源加载点时，优先使用库的 memory API；如果库只有路径 API，Windows 上必须走宽字符 API 或接入该库的 filesystem callback。
  • 从 std::filesystem::directory_iterator 得到的 path 应直接传给 nc::io 的 std::filesystem::path 重载，不要先转成 path.string() 再打开。
  • EnginePaths 返回 UTF-8 字符串。传给 std::filesystem 的 exists、create_directories、remove、directory_iterator 等操作之前，必须先用 nc::io::path_from_utf8 转成原生路径；直接传入窄字符串（包括隐式转换）会在 Windows 上按 ANSI 代码页解码，创建乱码目录或访问错误位置。

中文安装目录下的配置

用户配置位于可执行文件旁的 config/。例如从 output/新殖民地/NewColony.exe 启动时，应读写 output/新殖民地/config/。设置文件的父目录创建与写入共用原生路径；Mod 配置、已保存服务器列表，以及 script-state/server.json、script-state/client.json 的读写入口均显式转换 UTF-8 路径。无效设置文件的删除也使用同一转换规则。

旧配置迁移时，先关闭游戏并备份原目录，再将需要的配置移到当前安装目录的 config/。

中文安装目录下的启动资源

若中文路径下无法发现 MOD 或加载启动资源，可在日志中核对实际访问的目录。引擎从安装路径解析资源，使用以下接口进行 UTF-8 与原生路径转换。

用途统一接口
UTF-8 字符串转原生路径nc::io::path_from_utf8
原生路径转 UTF-8 字符串nc::io::path_to_utf8
使用 / 分隔符的资源键、脚本快照键和 RmlUI 路径nc::io::path_to_generic_utf8
环境变量中的工具路径nc::io::path_from_environment，Windows 读取 UTF-16 值
文件读写、JSON 读取和 Windows 宽字符 API 参数继续使用 FileIO、JsonIO 和 nc::io::utf8_to_wide

不要在业务模块调用 path.string()、path.generic_string() 或复制 UTF-8/UTF-16 转换函数。已经是原生 path 的值继续直接传递；可执行文件定位等 Windows API 返回的宽字符路径可以直接构造原生 path。本轮执行了经授权的源码路径扫描与调用点检查，未执行编译、测试、导出或游戏启动验证。现有输出目录中的二进制文件需手动重新构建并导出后才能验证修复。

启动器 Main.cpp 与 EnginePaths.cpp 使用 GetModuleFileNameW 取得原生 UTF-16 路径，直接构造 path 不经过 ANSI 解码。启动器继续用宽字符 DLL API；EnginePaths 在需要字符串时通过 nc::io::path_to_utf8 输出 UTF-8。两处均在可执行文件路径缓冲区不足时扩容重试，避免固定 MAX_PATH 截断；这不代表所有 Windows 长路径限制均已解除。

C++20 路径弃用检查

bash/Build.bat 在 CMake 配置和编译前先运行 checker/start.py。入口按文件名顺序自动发现 checker/check_*.py 并传入 --fix；任一检查器失败或仍有需人工处理的问题，构建立即停止。新增规则按同一命名及退出码约定放入 checker 目录即可接入。可单独运行 python checker/start.py --check 只检查，不修改源码、不启动构建。Windows 构建入口需要 Python 3.10+，依次尝试 python 和 py -3。

从仓库根目录运行 python checker/check_cpp20_u8path.py，可检查 Engine 和 Tests 中已弃用的 std::filesystem::u8path 及命名空间别名调用；可追加文件或目录来限制范围。默认只报告，--fix 对 UTF-8 字符串字面量和同一范围的 begin/end 迭代器调用执行 C++20 路径转换，保留 UTF-8、BOM 和原有换行。变量类型、跨文件别名及复杂表达式无法确认时只报告人工处理，不直接改成窄字符串 path 构造，也不屏蔽警告。自动批量修改前后创建本地 Git 检查点，并保留原文件的 .u8path.bak；Git 或检查点失败则停止。生成目录和第三方代码不在默认扫描范围内。用法与边界见 checker/README.md；检查结果不代表已编译或执行测试，工具自身不运行构建和测试命令。

文件替换

io::write_binary_file_atomic(path, data, size) 将内容写入同目录临时文件，写入完成后替换目标。失败时保留原目标，父目录由调用方创建。
