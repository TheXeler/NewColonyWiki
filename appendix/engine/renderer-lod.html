Terrain LOD rendering

Stable loading focus

Chunk loading, simulation tiers, render residency, unload hysteresis, and LOD distance use the orbit camera's target as their common center. Rotating the view, changing pitch, or zooming changes the eye position without moving this center. The mouse wheel changes orbit distance within the camera's configured limits and keeps the target fixed; keyboard movement and explicit target changes move the loading area. Frustum culling still uses the actual view and projection matrices to decide which resident meshes to draw.

Network player loading ranges, city-loading barriers, initial world-loading progress, and chunk/navmesh debug overlays use the same target-centered coordinates. Each player sends the target chunk as the center of their existing PlayerLoadingRange packet; the packet format and network version are unchanged.

Heightfield sampling

Far terrain uses a stitched heightfield rather than replacing each horizontal sample with a full cube. Each sample chooses the median solid surface height and the most frequent surface block, which prevents isolated decorations from changing the material of an entire coarse cell.

Sampling rules and stitching

Non-occluding models, transparent decorations, and plant blocks are excluded from the solid heightfield. Fluid surfaces are sampled independently and written to the transparent mesh. Adjacent cells emit vertical faces only from the higher surface down to the lower surface. Chunk edges sample the neighboring chunk's actual solid and fluid surface heights and stitch to those heights; fixed-depth skirts are not generated. Bottom faces are not generated.

LOD step and refinement

The requested LOD step still increases linearly between the full-detail load radius and the render radius, but terrain sampling is capped at four blocks. Thus the farthest 16 by 16 chunk retains at least a 4 by 4 surface grid instead of collapsing to one height and material. Approaching a chunk rebuilds it with progressively finer samples until the ordinary voxel mesh is restored.

Coordinates, culling and bounds

Planet display copies follow the same translation-only coordinate semantics as simulation wrapping; rendering does not independently mirror local vertices. Incremental mesh replacement refreshes the GPU culling height bounds instead of retaining bounds from the previous LOD mesh. Vulkan frustum extraction uses its zero-to-one near clipping plane, and CPU and GPU AABB intersection tests include the same conservative seam tolerance.

Transparent surface order

Depth-tested world highlights and outlines now join the terrain/item transparency order instead of drawing as a final overlay. Each highlight triangle and line segment uses its center depth in camera space; pipeline and vertex/index bindings change with each source while adjacent compatible ranges remain batched. Opaque terrain and entities occlude them through the scene depth buffer; foreground transparent blocks blend over feedback behind them. Persistent zone outlines and volume-selection outlines use this path. Intentionally depth-independent debug lines remain in the final overlay. Both the single-pass and SSAO transparent-color paths use the same ordering. Center sorting remains approximate for long lines, large faces, and intersecting transparent geometry. This change has not undergone static validation, compilation, tests or a game smoke run.

Before the first visible terrain meshes arrive, an absent terrain aggregate with an empty draw list is a valid empty frame. It emits no terrain transparent commands and does not report a sorting failure. A missing aggregate with visible terrain, or a failed indirect buffer allocation or mapping, remains a rendering error.

Leaves, water, blended block model layers, and distant fluid surfaces use alpha blending with depth testing enabled and depth writes disabled. Transparent faces are sorted together from far to near by their center depth in camera space, including faces in the same sub-chunk and across display copies. Sorting is refreshed when the view or mesh data changes; camera movement does not rebuild or upload the resident vertex/index aggregate. Both the single-pass and SSAO rendering paths consume the same sorted indirect commands. The SSAO path accumulates these faces and transparent item meshes in a separate color layer, depth-tested against opaque geometry. The final composite applies SSAO to the opaque background before blending the transparent layer, so background occlusion does not stain foreground transparent surfaces. This change has not undergone static validation, compilation, tests or a game smoke run.

Each sorted face command retains its source chunk metadata index. GPU frustum culling changes only its instance count and preserves the blending order. Transparent visibility counters still count chunk meshes, rather than individual faces. Indirect draws are split at the device's draw-count limit; devices without multi-draw support submit commands individually in the same order. Center-depth sorting does not split intersecting polygons and cannot resolve every cyclic overlap; those cases would require polygon splitting or an order-independent transparency technique.

Mesh replacement

Transitions from a coarse chunk mesh to full-detail sub-chunk meshes always rebuild the complete resident sub-chunk set, ignoring any stale partial-dirty subset accumulated while the coarse mesh was active. Partial results prepared before a newer coarse mesh are discarded and rescheduled as complete rebuilds. The finished set is then published as one atomic renderer replacement, so the old LOD remains visible until every replacement mesh is ready. LOD surfaces consume the representative model face's UV range, UV rotation, tint index, directional-shading flag, and light emission. This applies uniformly to every registered block rather than special-casing terrain materials.
