Lua 事件系统

Lua 可以监听引擎/CoreMod 事件，也可以在 MOD 之间发布自定义 Lua 事件。

事件回调在 Lua 主线程执行。回调使用 protected call 隔离：某个回调报错会写入日志，但不会阻止同一事件的其他回调继续执行。

监听事件

local handler_id = engine.events.subscribe("core:stockpile_changed", 10, function(evt)
  if evt.current.item_id == "core:wood" then
    engine.log.info("wood delta=" .. tostring(evt.current.delta))
  end
end, false) -- 第二个参数是优先级，越大越早执行；默认是 0

-- 在 MOD 卸载或不再需要时取消
engine.events.unsubscribe(handler_id)

subscribe(event_id, priority, fn, world_bound) 的回调收到事件上下文：type、initial、current、cancel() 与 is_cancelled()，payload 字段在 current 里。事件 ID 必须在 data/events 中声明，未声明的事件注册会直接报 Unknown listener event。相同 priority 的回调保持注册顺序。

按来源和前缀监听

当前 Lua 事件 API 不提供来源参数或前缀订阅：engine.events 只有 subscribe、unsubscribe 和 emit，事件 ID 必须写完整并已在 data/events 中声明。需要在一组事件上复用逻辑时，分别订阅每个事件 ID。

发布自定义事件

-- mod_a
engine.events.emit("copper_age:ore_found", {
  x = 12, y = 48, z = -3,
  block_id = "copper_age:copper_ore"
})

-- mod_b
engine.events.subscribe("copper_age:ore_found", 0, function(evt)
  engine.log.info(string.format("ore at %d,%d,%d", evt.current.x, evt.current.y, evt.current.z))
end, false)

emit(event_id, payload) 先按 data/events 的字段 schema 校验 payload，再在当前 Lua runtime 内分发，不会自动进入 C++ 事件总线、网络同步或存档。未声明的事件和非 table payload 会被拒绝，schema 未列出的字段不会出现在 current 中。引擎权威的任务生命周期事件不允许由 Lua 发布。

清理订阅

-- 删除本 MOD 注册的指定订阅
local removed = engine.events.unsubscribe(handler_id)

unsubscribe(id) 只删除本 MOD 自己的订阅；公开 API 没有按事件名批量清除其他 MOD 订阅的入口。

引擎脚本环境（ScriptEngine）还会发出 block:interacted、raid:started/raid:wave/raid:ended 和 day_changed/season_changed/year_changed；它们没有在 data/events 中声明，MOD 监听器无法订阅。需要这些状态时请使用 core:tick 负载、engine.time 或 engine.raids.active() 查询。

完整签名可在 Lua API 速查 的“事件”分组查看。内置事件的 payload 以当前引擎和 CoreMod 实现为准，MOD 不应假定未列出的字段长期稳定。

与 tick 事件的选择

对“某件事发生后才需要运行”的逻辑使用事件；只有需要按固定模拟 tick 轮询的逻辑才使用 core:tick 事件或 engine.timers。事件回调中避免修改正在遍历的同一业务集合，复杂操作可记录状态后交给下一 tick 处理。
