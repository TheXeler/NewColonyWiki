引擎光照

体素光照由区块数据、光源 registry 和 GPU/CPU 光照路径共同维护。

运行时规则

  • 天空光和方块光使用 0 到 15 的 4 位光照等级。
  • 透明和半透明方块可以透光；不透明方块会阻挡光照。
  • 网格生成会在目标区块周围计算或读取一个临时的 3x3 区块光照网格，因此边界面会采样新生成的邻近光照。
  • LightSystem::compute_all_overlay_with_accessor 使用调用方输出 buffer，并复用 thread-local BFS 队列，避免 dirty mesh rebuild 时重复分配大块临时内存。
  • 区块网格化会采样可见面前方可透光单元格的光照值，并将其乘以逐顶点环境光遮蔽。
  • 影响发光或透光性的变更，会将受影响区块标记为需要重建。

方块光源

  • 方块 JSON 的 emission 字段定义 block light 强度，合法范围为 0 到 15。
  • 所有 emission > 0 的方块都会注册为光源，不限于火把。
  • GpuLightRegistry 在 chunk load/unload 和 block change 时维护全局光源表。
  • 新增光源会 seed GPU BFS frontier，mode 4 在 3x3 chunk volume 内传播 block light，并写入 ChunkDataStore 的 light overlay。
  • 删除光源会按移除光源等级清理受影响范围，再用重叠区域内仍存在的光源重新 BFS，以避免旧光残留并减少不必要的 block light 写回。
  • 同一 tick 内的同位置 pending add/remove 会做保守合并：同强度替换会取消暗化，add 后 remove 会取消新增，同位置重复 add 会保留最后一次。
  • chunk unload 只从 registry 和 LightSSBO 中移除该 chunk 的光源，并清理相关 pending 队列；它不会触发暗化 BFS。下一次 tick 只上传 light table，日志会出现 table_only=1。

LightBlock 调试日志

  • [LightBlock] tick 是每次 registry flush 的汇总日志，默认 DEBUG 等级。
  • upload 和 light_upload_bytes 表示 LightSSBO 全量上传成本；如果该项高，下一步应做增量上传或 sparse slot。
  • clear 表示删除光源时 CPU 清理受影响 block light 的耗时。
  • build 表示构建 3x3 GPU BFS volume 的耗时。
  • bfs 表示 mode 4 BFS dispatch 加同步等待的耗时；如果该项高，下一步应做异步 compute / 下帧 readback。
  • apply 表示把 GPU 输出写回 ChunkDataStore overlay 的耗时。
  • frontier、final_frontier、capacity、overflow 和 max_observed_frontier 用于判断 BFS frontier 是否被截断。
  • changed_chunks 表示本次 block light 写回导致的 mesh dirty fanout；后续 mesh rebuild 会通过 [Chunks] dirty dispatch 和 [Chunks] dirty upload 记录。
  • 存档会把动态光照保存为 chunk-level lights 数组，block payload 只保存 [id,data] state。

Dirty Mesh 调度

  • block light 写回后只把实际变化过的 chunk 放入 dirty 集合。
  • dispatch_dirty_chunk_rebuilds 会限制每帧提交的 dirty mesh rebuild 数量；积压较高时会小幅提高提交上限。
  • [Chunks] dirty dispatch 记录 dirty backlog、提交数、因预算或 inflight 重排的数量。
  • [Chunks] dirty upload 记录异步 dirty mesh 完成后的主线程上传数量、重排数量和预算耗时。

天空光

  • 天空光仍使用列扫描初始化和传播路径。
  • 天空光的隐式光源是天空柱，不使用 block light 的光源列表优化。

当前限制

  • ChunkDataStore::set_block_light() 当前写入 per-column light overlay，不再修改 sub-chunk 内的 BlockState voxel storage，因此 GPU block light 更新不会打散 uniform/palette sub-chunk。
  • Block 本体只保留 id/data 状态；LightData 不再是 block 字段。
  • ChunkDataStore::ChunkSnapshot 的 uniform、palette 和 dense payload 使用 BlockState{id,data}；region 存档 payload 也只写 state payload，动态光照保留在独立 lights overlay。
  • GPU pack 路径现在显式接收 BlockState 和 LightData。mesh 构建对已加载 chunk 和临时 dense chunk 都通过 light accessor 采样 overlay；旧的 dense Block.light 写回和读取兼容路径已删除。
  • 跨 chunk mesh 边界光照通过显式 neighbor_light(wx,y,wz) accessor 读取已加载 neighbor snapshot 的 light overlay；生成但未加载的临时 neighbor 没有 overlay 时返回空光照。
