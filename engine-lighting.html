引擎光照

体素光照以 CPU 为权威：区块数据持有光照 overlay，GpuLightRegistry 在模拟线程上做稀疏传播。

运行时规则

  • 天空光和方块光使用 0 到 15 的 4 位光照等级，并在顶点中分开传递；方块光不受昼夜变化影响。
  • 透明和半透明方块可以透光；不透明方块会阻挡光照。
  • 网格生成会保留 ChunkDataStore 中权威的跨区块 block light，并从相邻已加载列注入边界天空光；边界面会直接采样邻区光照。
  • LightSystem::compute_all_overlay_with_accessor 使用调用方输出 buffer，并复用 thread-local BFS 队列，避免 dirty mesh rebuild 时重复分配大块临时内存。
  • 区块网格化会分别采样可见面前方可透光单元格的天空光与方块光；不同光照组合的面不会被贪心网格合并。直接看见天空的表面不应用由一格高度差邻块造成的环境光遮蔽。
  • 光照传播只读取方块的透光结果并传递 0 到 15 的等级，不触发方块更新、随机刻或其他游戏逻辑。区块内分布由独立的列扫描和六邻接队列计算，跨区块只读取相邻边界。
  • 影响发光或透光性的变更，会将受影响区块标记为需要重建。

方块光源

  • 方块 JSON 的 emission 字段定义 block light 强度，合法范围为 0 到 15。
  • 所有 emission > 0 的方块都会注册为光源，不限于火把。
  • GpuLightRegistry 在 chunk load/unload 和 block change 时维护已加载列的光源登记。
  • 方块光传播是模拟线程上的 CPU 稀疏 BFS，结果写入 ChunkDataStore 的 light overlay。这是权威状态：它会被存档、被玩法（VisibilitySystem）读取，也会被 CPU 网格构建烘进顶点，因此不依赖 Vulkan，也没有 GPU 端权威副本。
  • 删除光源会按移除光源等级清理受影响范围，再用重叠区域内仍存在的光源重新 BFS，以避免旧光残留并减少不必要的 block light 写回。
  • 同一 tick 内的同位置 pending add/remove 会做保守合并：同强度替换会取消暗化，add 后 remove 会取消新增，同位置重复 add 会保留最后一次。
  • invalidation 是局部的：CHUNK_SIZE（16）大于 MAX_LIGHT（15），光照最多传播 14 格，因此不可能穿过一个完整区块列。卸载区块只为该列自身的光源排队清除；加载区块只重新播种它 3x3 邻域内的光源。两者都不再触发全世界重建。

LightBlock 调试日志

  • [LightBlock] cpu propagation 是每次 registry flush 的汇总日志，默认 DEBUG 等级。
  • adds / removes 是本 tick 消费的 pending 变更数，queued 是本次入队的 frontier 条目数，remaining 是仍未排空的 frontier。
  • remaining 非零（并附加 budget_hit=1）表示本次撞到每 tick 体素预算，剩余部分由后续 tick 继续；Engine 每 tick 传入 LIGHT_VOXEL_BUDGET_PER_TICK。预算同时覆盖删除清除与 BFS 排空：删除批次会快照到独立容器，并按 y 层逐层切分，因此一次批量删除（例如卸载一个含多个光源的区块）不会独占一个 tick。批量化只改变到达不动点的时机，不改变结果：传播是单调 max 泛洪，收敛后的取值一致。
  • changed_chunks 表示本次 block light 写回导致的 mesh dirty fanout；后续 mesh rebuild 会通过 [Chunks] dirty dispatch 和 [Chunks] dirty upload 记录。
  • 存档会把动态光照保存为 chunk-level lights 数组，block payload 只保存 [id,data] state。

Dirty Mesh 调度

  • block light 写回后只把实际变化过的 chunk 放入 dirty 集合。
  • dispatch_dirty_chunk_rebuilds 会限制每帧提交的 dirty mesh rebuild 数量；积压较高时会小幅提高提交上限。
  • [Chunks] dirty dispatch 记录 dirty backlog、提交数、因预算或 inflight 重排的数量。
  • [Chunks] dirty upload 记录异步 dirty mesh 完成后的主线程上传数量、重排数量和预算耗时。

天空光

  • 天空光使用列扫描初始化和六邻接传播。正上方无遮挡的可透光体素是直接天空源；离开直接天空列后，每传播一格等级减 1，降到 0 停止。
  • 自然光源在 05:00 到 08:00 从 6 均匀增加到 15，在 08:00 到 16:00 保持 15，在 16:00 到 19:00 从 15 均匀降低到 6，其余时间保持 6。网格保存的是以 15 为基准的天空可达等级；着色器根据当前自然光强扣除源强差值，因此夜晚离源三格为 3，而不是对白天亮度做比例缩放。
  • 昼夜变化只更新全局着色参数，不遍历体素或重建所有区块。放置、移除阻光方块，改变透光属性或加载区块时，才重新计算受影响区域的传播拓扑。
  • 顶点分别携带原始天空光等级、原始方块光等级和表面明暗。着色器先根据时间换算天空光，再合并方块光并应用面朝向和环境光遮蔽，避免表面明暗被误当成传播距离。
  • 天空光的隐式光源是天空柱，不使用 block light 的光源列表优化。

当前限制

  • ChunkDataStore::set_block_light() 当前写入 per-column light overlay，不再修改 sub-chunk 内的 BlockState voxel storage，因此 block light 写回不会打散 uniform/palette sub-chunk。
  • Block 本体只保留 id/data 状态；LightData 不再是 block 字段。
  • ChunkDataStore::ChunkSnapshot 的 uniform、palette 和 dense payload 使用 BlockState{id,data}；region 存档 payload 也只写 state payload，动态光照保留在独立 lights overlay。
  • GPU pack 路径现在显式接收 BlockState 和 LightData。mesh 构建对已加载 chunk 和临时 dense chunk 都通过 light accessor 采样 overlay；旧的 dense Block.light 写回和读取兼容路径已删除。
  • 跨 chunk mesh 边界光照通过显式 neighbor_light(wx,y,wz) accessor 读取已加载 neighbor snapshot 的 block-light overlay，并根据邻区列遮挡补充直接天空光。
