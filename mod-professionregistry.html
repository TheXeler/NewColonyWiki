职业注册

职业定义放在 Data/professions/ 下，引擎加载时自动扫描。职业决定了殖民者可以解锁哪些配方，以及需要什么工具块才能从事该职业。

JSON 格式

{
  "id": "core:blacksmith",
  "name": "Blacksmith",
  "max_level": 5,
  "required_block": { "id": "core:anvil_item", "count": 1 },
  "prerequisites": [],
  "unlocks_recipes": [
    { "id": "core:smelt_iron", "level": 1 },
    { "id": "core:craft_iron_pickaxe", "level": 2 }
  ]
}

字段说明

字段类型必填说明
idstring是唯一标识，格式 <mod_id>:<name>。允许字符：小写字母、数字、下划线、短横线、冒号。
namestring是职业显示名称。
max_levelint是最大等级，决定配方解锁的等级上限。
required_blockobject是从事该职业所需的工具方块。id 指向已注册的方块 ID，count 为所需数量。
prerequisitesstring[]否前置职业 ID 列表。例如铁匠可能需要先成为工人。空数组表示无条件可转职。
unlocks_recipesobject[]否该职业解锁的配方列表。每个条目包含 id（配方 ID）和 level（解锁所需等级）。
职业系统通过 required_block 控制门槛——殖民者背包中必须持有指定数量和类型的物品才能转职。配方按 level 阶梯解锁，等级提升后可获得更高级的制造能力。

ID 规则

  • 职业 ID 只能包含小写字母 a-z、数字 0-9、下划线 _、短横线 -、冒号 :。
  • 推荐格式 <mod_id>:<name>，例如 copper_age:coppersmith。
  • 如果省略冒号前缀，引擎自动补全为 <当前mod_id>:<名称>。

文件放置规则

  • 放在 Data/professions/ 下，支持任意深度的子目录。
  • 文件名随意，引擎只关心 JSON 内的 id 字段。
  • 每个 JSON 文件定义一个职业。

前置职业示例

如果铁匠要求先成为工人，可以这样写：

{
  "id": "core:blacksmith",
  "prerequisites": ["core:worker"],
  ...
}

引擎按拓扑顺序校验前置链，发现循环依赖或缺失前置时会报错。

验证命令

在控制台（按 ~）中确认职业注册成功：

mods                                  —— 确认 MOD 已加载
list_data professions                  —— 列出所有已注册职业
data core:blacksmith                   —— 查看单个职业的完整 JSON
