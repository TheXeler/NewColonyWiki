MOD 是怎样加载的

一个 MOD 就是一套数据文件加一个必须存在的 Lua 入口脚本。游戏先找到 MOD、排序、注册数据，最后跑脚本。搞清楚这个过程，后面加物品、写配方、写 Lua 才知道每样东西在哪个阶段生效。

一个 MOD 至少需要什么

游戏在 MOD 目录下找 mod.json。找到了就读取这个文件、检查依赖、排好加载顺序，然后递归扫描 data/ 下所有受支持的类型目录。入口脚本默认指向 scripts/bootstrap.lua，也可以在 mod.json 的 entry 字段改成别的存在路径。

mod.json 里最常见的字段还有 side、dependencies、load_after、load_before、conflicts、settings 和 ui。其中 dependencies 条目使用 name、minVer、maxVer；脚本沙箱不提供通用文件系统 IO 权限字段。

下面是一个典型 MOD 的目录结构。游戏会检查 data/ 下是否存在这些类型子目录，存在就走进去递归扫描 JSON 文件。

mods/my_mod/
  mod.json
  scripts/
    bootstrap.lua
  data/
    blocks/
    tags/
    entities/
    recipes/
    jobs/
    civilizations/
    focuses/
    factions/
    faction_spawn_rules/
    name_pools/
    diplomacy_proposals/
    features/
    crops/
    buildings/
    terrain/
    biomes/
    combat/
    audio/

加载流程

游戏启动时按下面六个阶段加载 MOD：

  1. 发现 MOD。引擎扫描传入的根目录；根目录自身有 mod.json 时会作为 MOD 读取，也会扫描其直接子目录。读出来之后，检查 id 是否重复、JSON 格式是否合法。
  2. 解析加载顺序。引擎按照 dependencies、load_after、load_before 三个字段计算最终顺序。dependencies 条目支持 name、minVer、maxVer；load_before: ["*"] 会尝试让该 MOD 排在其他 MOD 前面。循环依赖会直接报错。
  3. 应用玩家配置。读取运行目录 config/<mod_id>.json，把类型匹配的设置覆盖到清单默认值；enabled 决定非 core MOD 是否参与后续加载。
  4. 注册数据。引擎递归扫描受支持目录，把每条 JSON 记录放进数据注册表。注意，这时 Lua 脚本还没执行——数据在脚本执行前就已经可用了。
  5. 校验引用。配方里的输入输出、职业要求、文明开局物品、方块掉落、群系/地形方块、建筑材料等引用 ID 会被检查是否存在。出错的非 core MOD 会被禁用，依赖它的 MOD 也会被跳过。
  6. 执行入口脚本。所有数据注册完毕并通过交叉引用校验后，引擎按加载顺序执行每个已启用 MOD 的入口脚本。脚本返回一个表，引擎会读取 on_load、on_world_init、on_tick、on_shutdown 这些函数。

什么时候写 JSON，什么时候写 Lua

能用 JSON 写的东西，都放在 data/ 下。当前自动注册基础内容、经营规则、生态、动态天气、视野和难度等多类数据；professions 是 jobs 的迁移别名。Lua 只用来补充 JSON 做不到的事情。

不要在 Lua 里重新发明配方系统。新配方放在 data/recipes 下。也不要在 on_tick 里每帧扫描所有实体——用事件订阅和定时器代替轮询。

数据 ID 命名习惯

公共数据的 ID 通常写成 <mod_id>:<name> 格式，例如 copper_age:copper_ingot。这样做的好处是：其他 MOD 引用时一眼能看出数据来源，也不会和 core 或者其他 MOD 撞名；在同一个 MOD 内省略前缀时，加载器会自动补成当前 mod_id:。

核心数据 vs MOD 数据

CoreMod/data/ 下的 JSON 是核心数据的标准格式。MOD 数据也使用相同的格式，区别只在于 id 的前缀。CoreMod 内容通常使用 core:；同一个 MOD 内可以省略前缀，加载器会自动补成当前 mod_id:。跨 MOD 引用时必须写完整的 mod_id:name。

如果你在 MOD 里加载其他 Lua 文件，请使用 require。引擎会预编译当前 MOD 的 scripts/ 和生成 Lua 目录，并注册到可 require 的模块表；沙箱不开放 dofile、loadfile 或任意 package.path 文件搜索。
当前入口脚本文件必须存在，默认是 scripts/bootstrap.lua，也可以在 mod.json 的 entry 字段改成别的现有路径。纯 JSON 内容包同样需要一个入口文件，最简单的做法是让它 return {}。
