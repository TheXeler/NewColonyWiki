地形生成流程

这篇文章是引擎层面的地形生成流程参考。MOD 作者通常只需要关心 群系注册 与 地物注册；如果你想知道群系和地物是「在什么时候被使用」、或者想调试地形异常，请阅读本文。文中所述的内部结构（C++ 类名、阶段顺序）不是 API 兼容承诺，仅用于辅助理解。

本文记录 2026-06-14 修复后的实现。修复重点是消除气候采样的重复计算瓶颈；功能行为（地形外观、群系选择规则）没有变化。

总体架构

地形生成分为两层：

  1. 行星级世界地图（Engine/WorldMap/）：在世界创建时一次性生成一张六边形网格地图，为每格打上 海拔 / 温度 / 湿度 / 是否水域 / 群系 ID 标签。这是「宏观气候场」。
  2. Chunk 体素生成（Engine/Voxel/TerrainGenerator + Engine/ChunkManager）：玩家走到哪里，就为对应的 16×16×256 chunk 实时生成方块。生成时从世界地图采样气候，再叠加生物群系的局部噪声。

第一层:世界地图

输入

  • world_seed（u64 世界种子）
  • WorldMapConfig：planet_radius（六边形格半径，默认 48）、water_coverage（目标水域占比，默认 0.58）、solar_distance（恒星距离，影响温度）

步骤

  1. 铺六边形网格：在 q,r,s 立方坐标系上铺出半径 planet_radius 的六边形盘。每个 tile 的索引数量约 1 + 3R(R+1)，R=48 时约 7 千个 tile。盘子在 hex-pixel 空间呈 2:1 比例（宽 2R、高 R），匹配等距矩形投影的拟真地球展开图；r 方向的 hex-pixel 间距是 q 方向的一半。
  2. 计算海拔：用三组独立 Perlin 噪声叠加（broad / detail / ridge），公式：elevation = clamp01(0.50 + broad*0.34 + detail*0.12 + ridge*0.20)。
  3. 计算温度：基于恒星距离（越近越热）和纬度（两极更冷），并叠加海拔降温：temperature = clamp01(0.22 + solar_heat*0.72 - |latitude|*0.68 - elevation*0.16)。
  4. 计算湿度：Perlin 噪声主导，叠加雨影（高海拔背风面干旱）和极地干旱。
  5. 确定海平面：把所有 tile 的海拔排序，取 water_coverage 分位数作为 sea_level。这样无论地形分布如何，水域占比都精确匹配设定。
  6. 水域判定：elevation ≤ sea_level 即为水域 tile。
  7. 群系分类：调用 select_biome_for_climate，对每个 tile 根据（温度，湿度，海拔）匹配群系，写入 biome_id。后续 chunk 生成时直接读取这个预计算结果。

第二层:Chunk 体素生成

当玩家进入某个 chunk 的视距时，ChunkManager 异步生成该 chunk。完整流程如下：

阶段 0:气候采样（chunk 级宏观 + block 级扰动）

气候采样分两层，共同构成 multi-noise 气候空间的物理基础：

  • chunk 级宏观骨架（WorldMap::sample_climate_for_chunk）：
    • 把 chunk 坐标 (cx, cz) 归一化到有限星球（normalize_planet_chunk，处理经度回绕和极地折返）
    • 对所有世界地图 tile 做反距离加权平均：weight = 1 / (dist_sq + 0.015)
    • 输出当前 chunk 的 temperature / moisture / elevation / water / biome_id
  • block 级扰动（WorldMap::sample_climate_for_block）：在 chunk 级 climate 上叠加两个独立的中频 Perlin 扰动场（温度、湿度）。扰动周期约 48 块边长，幅度约 0.14。这让气候在 chunk 内连续漂移，是后续 per-column 群系选择能够"在同一 chunk 内出现多种群系"的来源。海拔不做 block 级扰动，避免海岸线逐块抖动。
性能优化（2026-06-14 修复）：气候采样结果是 chunk 局部常量，但旧实现对每列方块都会重新采样，造成每个 chunk 调用 sample_climate_for_chunk 上千次、每次遍历约 7 千个 tile。修复后 ChunkManager::cached_climate_for_chunk 用 thread_local 缓存每个 worker 线程最近一次采样的 chunk，使后续相同 chunk 的查询从 O(tiles) 降到 O(1)。
block 级扰动设计：sample_climate_for_block 不重复 IDW，而是复用 chunk 缓存的宏观气候，仅在末尾追加两次 Perlin 查询。per-column 调用的开销近似为两次 Perlin 噪声查询，不会随世界地图 tile 数量增长。

阶段 1:地形配置（terrain_config_for_chunk）

根据气候生成 TerrainConfig：

  • 从 data/terrain/default.json 读取 base_block / water_block / riverbed_block
  • 把 temperature / moisture 注入 cfg，供装饰阶段使用
  • 根据 elevation - sea_level 调整 base_height：海床降低、陆地抬升，钳制到 [36, WORLD_HEIGHT - 48]
  • 水域或近岸降低 amplitude（让海岸线更平缓）
  • river.water_level = sea_level - 2

阶段 2:群系选择（multi-noise 气候空间）

群系选择遵循 Minecraft 1.18+ 的 multi-noise 模型：群系不是 chunk 大小的离散格子，而是从连续气候场里"涌现"出来的连续区域——相邻 column 气候相同则群系必然相同，气候跨越群系 climate range 边界处就是天然的过渡带。

两个查询入口：

  • chunk 主导群系（select_biome_for_chunk）：返回单一群系，用于高度图、装饰、UI/minimap 等需要 chunk 级一致性的场合。优先用世界地图 tile 的 biome_id，找不到时走 select_biome_for_climate，仍失败回退到 select_biome。
  • per-column 群系（column_biome_lookup → sample_climate_for_block → select_biome_for_climate）：每个 column 独立采样气候，独立选择群系。同一 chunk 内不同 column 可落到不同群系，这是"颜料晕染"过渡的来源。

select_biome_for_climate 核心算法是纯气候距离最近邻：在 (温度, 湿度, 海拔) 三维空间里找最近的群系 climate range。完全落在某群系 range 内 → distance = 0；否则按"超出 range 边界的距离平方和"比较。同距离时取注册顺序最早的（确定性 tie-break）。不再有 hash 加权随机——这是相邻 column 不会因随机噪声被分到不同群系的关键，也是消除"草原/深海交错"问题的核心改动。

阶段 3:地形 pipeline（generate_terrain_for_chunk）

主体由 TerrainGenerator::generate_chunk 完成，但 ChunkManager 在外层加了一层「海岸线平滑」逻辑：

  1. 双线性高度混合：先用 generate_biome_height_map（SIMD 4 路 fbm 噪声）计算生物群系局部高度图，再用 base_height_at 把 cfg.base_height 替换为世界地图的双线性插值高度。这样相邻 chunk 之间的高低差异是平滑的，而不是突变。
    multi-noise per-column 高度（Phase 4）：高度图计算分三步。
    1. 先用 chunk 主导群系跑一次 generate_biome_height_map 拿到 chunk 级 fbm 高度骨架。
    2. 对每列查 per-column 群系，按群系的 height.amplitude_scale（噪声幅度倍率）和 height.offset（最终抬升）重新计算 surface_y。这样山地气候 column 在草原 chunk 内也能真的高起来，而不是被压平到草原高度。
    3. 3×3 box-blur 平滑。没有这一步的话，相邻 column 之间会因 amplitude_scale 或 offset 突变出现单格高的台阶。
    MOD 不写 height 块时默认 offset=0, amplitude_scale=1.0，保持旧的 chunk-dominant-only 行为。
    性能优化（2026-06-14 修复）：base_height_at 对每列方块都要求 4 个角 chunk 的基础高度。旧实现每个角 chunk 都重新采样气候，相当于 1 个 chunk 生成触发 256 × 4 = 1024 次气候采样。修复后 terrain_base_height_for_block 用 thread_local 的 4 角 cache，第一次调用预计算 4 个角的高度，后续 255 次调用只做纯插值，气候采样次数从 ~1024 降到 4。
  2. 海岸带处理：对每列判定距 chunk 边的距离。
    • 内部区（距边 ≥ 4 块）：按生物群系规则钳制高度（水域钳到 max_water_surface_y，陆地钳到 sea_level）
    • 边缘带（距边 < 4 块）：不钳制，让自然插值高度决定海陆，避免邻接 chunk 在边缘出现悬崖
  3. 方块填充（per-column 群系）：高度图仍是 chunk 级（用 chunk 主导群系算，避免相邻 chunk 边界出现悬崖），但 surface / subsurface 方块和 subsurface_depth 按 per-column 群系决定。例如草原 chunk 中某个 column 落到了沙漠气候，那一列的表层就是沙子而不是草；紧邻 column 若仍属于草原气候则仍是草。这是 multi-noise 在视觉上最显著的一步——chunk 内可以同时呈现多种群系的表层材质，过渡处呈现"颜料晕染"而不是硬切换。装饰阶段（树木、灌木、河流、洞穴）仍按 chunk 主导群系工作，per-column 装饰是后续可选增强。
  4. 地下矿石（generate_underground → place_ores）：用 m_cave_noise 的 3D Perlin 在指定 y 区间内把 replace_block 替换为矿石方块。矿石定义在 data/ores/。

阶段 4:大型特性（generate_large_features_and_decorations）

在已经填好基础方块的 chunk 上叠加四类特性，顺序敏感：

  1. 山脉抬升（raise_mountains，仅陆地群系）：用 m_noise 的 2D Perlin，noise > threshold 时按 (noise - threshold) / (1 - threshold) 抬升地表，并叠加 shore_fade 让海岸附近不抬升。
  2. 洞穴挖掘（carve_caves，biome.has_caves 时）：以 chunk 网格为锚点（每个 anchor 4×4 半径），用确定性哈希决定是否生成洞穴系统。生成时挖出椭球隧道，并向外延伸分支隧道。锚点机制保证相邻 chunk 挖出的洞穴能无缝衔接。
  3. 河流刻蚀（carve_rivers，biome.has_rivers 时）：用 m_river_noise 的 2D Perlin，在 |noise| < threshold 的窄带内挖出河道，并填充 water 到 water_level。河床底部铺 riverbed_block。
  4. 地表装饰（decorate_chunk）：遍历已注册的 TerrainFeature，按群系白名单过滤。对每列计算植被概率场：
    • 树木类：综合 vegetation.density、噪声权重、湿度权重、温度适宜度（基于 temperature_optimum 和 temperature_range）和坐标随机权重，决定是否放置树。放置时按 trunk_block + leaves_block 或单体 block 绘制。
    • 单方块特性（石堆、灌木、遗迹碎片等）：按 density * 6 次随机尝试放置。

噪声分层

TerrainGenerator 持有三组独立 Perlin 噪声（不同种子偏移），保证用途互不干扰：

成员种子偏移用途
m_noise无（直接用 world_seed）地表高度图、山脉抬升、装饰概率场
m_cave_noise0xA5A5... 异或矿石分布
m_river_noise0x5A5A... 异或河流路径

已知的未来改进

  • 极地折返处双线性高度异常：base_height_at 用四个角 chunk 的气候做双线性插值，在极地折返附近可能产生高度异常。考虑改用球面插值或对极地区域使用最近邻。该项影响面小（极地仅占星球一小部分），优先级低。
  • per-column 装饰：当前 decorate_chunk（树木、灌木、河流、洞穴）仍按 chunk 主导群系工作。如果要让 chunk 边界处的装饰也按 column 群系分布（比如草原 chunk 内的小片沙漠不长树），需要把装饰阶段改成 per-column 群系评估。改动面较大，留作可选增强。
multi-noise / 气候空间迁移
  • 群系选择从 hash 加权随机改为纯气候距离最近邻，相同气候必然映射到相同群系，相邻 column 不会因随机噪声被分到不同群系。
  • 气候采样新增 block 级扰动（sample_climate_for_block），让气候在 chunk 内连续漂移，是 chunk 内多群系的物理基础。
  • generate_terrain_for_chunk 新增 column_biome_at 参数，surface / subsurface 方块按 per-column 群系决定，同一 chunk 内可呈现多种群系表层。
  • per-column 高度（Phase 4）：群系可选 height 块声明 offset 和 amplitude_scale，让山地气候 column 在草原 chunk 内也能真的高起来；3×3 box-blur 平滑过渡，MOD 不写 height 块则保持旧行为。
  • 消除了"草原/深海交错"问题：相邻 chunk 同气候 → 同群系；chunk 内气候漂移 → 颜料晕染式过渡。
历史改进（2026-06-14 已完成）
  • 气候采样 thread_local 缓存：单 chunk 生成气候采样次数从 ~1024 降到 4。
  • terrain_base_height_for_block 4-corner thread_local cache：插值查询从 O(tiles) 降到 O(1)。
  • carve_caves 入口高度加入 biome 钳制，与 generate_biome_height_map 对齐。
  • place_tree_feature 按 leaves_radius 限制 trunk 位置，避免树冠跨 chunk 截断。
  • BiomeDescriptor 移除 6 个 tree_* 死字段，相关 JSON/Lua 解析同步清理。
  • 删除死代码 WorldMap::find_nearest_tile_for_chunk。

调试技巧

  • 控制台输入 engine.terrain.list_biomes() 列出所有已注册群系
  • 日志中若出现 [Worldgen] no biome match for chunk=...，说明气候采样返回 valid=false（通常是世界地图尚未生成或归一化失败），select_biome_for_chunk 走到了 select_biome 兜底分支。检查世界地图是否已通过 WorldMapGenerator::generate 正常生成。注意：multi-noise 改造后 select_biome_for_climate 是纯最近邻，总会返回候选，不会再因"climate range 缺口"打印该 warning。
  • 调试 column 级群系分布：用 engine.terrain.select_biome 在 Lua 控制台查询某个 chunk 的主导群系，或在生成器中临时调高 sample_climate_for_block 的扰动幅度（PERTURB_AMP）观察 chunk 内多群系变化是否如预期。
  • 启动加 --DEBUG 参数可看到 [WorldMap] 和 [Chunks] 日志，了解世界地图大小和 chunk 生成状况。
