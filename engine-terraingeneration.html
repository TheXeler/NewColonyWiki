地形生成流程

这篇文章是引擎层面的地形生成流程参考。MOD 作者通常只需要关心 群系注册 与 地物注册；如果你想知道群系和地物是「在什么时候被使用」、或者想调试地形异常，请阅读本文。文中所述的内部结构（C++ 类名、阶段顺序）不是 API 兼容承诺，仅用于辅助理解。

本文记录 2026-06-14 修复后的实现。修复重点是消除气候采样的重复计算瓶颈；功能行为（地形外观、群系选择规则）没有变化。

总体架构

地形生成分为两层：

  1. 行星级世界地图（Engine/WorldMap/）：在世界创建时一次性生成一张六边形网格地图，为每格打上 海拔 / 温度 / 湿度 / 是否水域 / 群系 ID 标签。这是「宏观气候场」。
  2. Chunk 体素生成（Engine/Voxel/TerrainGenerator + Engine/ChunkManager）：玩家走到哪里，就为对应的 16×16×256 chunk 实时生成方块。生成时从世界地图采样气候，再叠加群系的局部噪声。

第一层:世界地图

输入

  • world_seed（u64 世界种子）
  • WorldMapConfig：planet_radius（六边形格半径，默认 48）、water_coverage（目标水域占比，默认 0.58）、solar_distance（恒星距离，影响温度）

步骤

  1. 铺六边形网格：在 q,r,s 立方坐标系上铺出半径 planet_radius 的六边形盘。每个 tile 的索引数量约 1 + 3R(R+1)，R=48 时约 7 千个 tile。盘子在 hex-pixel 空间呈 2:1 比例（宽 2R、高 R），匹配等距矩形投影的拟真地球展开图；r 方向的 hex-pixel 间距是 q 方向的一半。
  2. 计算海拔：用三组独立 Perlin 噪声叠加（broad / detail / ridge），公式：elevation = clamp01(0.50 + broad*0.34 + detail*0.12 + ridge*0.20)。
  3. 计算温度：基于恒星距离（越近越热）和纬度（两极更冷），并叠加海拔降温：temperature = clamp01(0.22 + solar_heat*0.72 - |latitude|*0.68 - elevation*0.16)。
  4. 计算湿度：Perlin 噪声主导，叠加雨影（高海拔背风面干旱）和极地干旱。
  5. 确定海平面：把所有 tile 的海拔排序，取 water_coverage 分位数作为 sea_level。这样无论地形分布如何，水域占比都精确匹配设定。
  6. 水域判定：elevation ≤ sea_level 即为水域 tile。
  7. minimap 群系分类：调用 select_biome_for_climate，对每个 world-map tile 根据（温度，湿度，海拔）匹配主导群系，写入 biome_id 和 map_color。这只用于 minimap/地图显示，不参与 chunk 体素生成。

第二层:Chunk 体素生成

当玩家进入某个 chunk 的视距时，ChunkManager 异步生成该 chunk。完整流程如下：

阶段 0:气候采样（chunk 级宏观 + block 级扰动）

气候采样分两层，共同构成 multi-noise 气候空间的物理基础：

  • chunk 级宏观骨架（WorldMap::sample_climate_for_chunk）：
    • 把 chunk 坐标 (cx, cz) 归一化到有限星球（normalize_planet_chunk，处理经度回绕和极地折返）
    • 对所有世界地图 tile 做反距离加权平均：weight = 1 / (dist_sq + 0.015)
    • 输出当前 chunk 的 temperature / moisture / elevation / water / biome_id
  • block 级扰动（WorldMap::sample_climate_for_block）：在 chunk 级 climate 上叠加三个独立的中频 Perlin 扰动场（温度、湿度、海拔）。温度/湿度扰动周期约 48 块边长，幅度约 0.14；海拔扰动周期约 128 块（更慢，避免海岸线逐块抖动），幅度 0.05。这让气候在 chunk 内连续漂移，包括海拔——是后续 per-column 群系选择能够在 chunk 内出现 beach/shallow/deep 渐变的来源。扰动后水域判定（elevation ≤ sea_level）也随之更新。
性能优化（2026-06-14 修复）：气候采样结果是 chunk 局部常量，但旧实现对每列方块都会重新采样，造成每个 chunk 调用 sample_climate_for_chunk 上千次、每次遍历约 7 千个 tile。修复后 ChunkManager::cached_climate_for_chunk 用 thread_local 缓存每个 worker 线程最近一次采样的 chunk，使后续相同 chunk 的查询从 O(tiles) 降到 O(1)。
block 级扰动设计：sample_climate_for_block 不重复 IDW，而是复用 chunk 缓存的宏观气候，仅在末尾追加三次 Perlin 查询（温度、湿度、海拔）。per-column 调用的开销近似为三次 Perlin 噪声查询，不会随世界地图 tile 数量增长。

阶段 1:地形配置（terrain_config_for_chunk）

根据气候生成 TerrainConfig：

  • 从 data/terrain/default.json 读取 base_block / water_block
  • 把 temperature / moisture 注入 cfg，供装饰阶段使用
  • 根据 elevation - sea_level 调整 base_height：海床降低、陆地抬升，钳制到 [36, WORLD_HEIGHT - 48]
  • 水域降低 amplitude（避免海床大幅起伏）。近岸 chunk 不再单独压平。

阶段 2:群系选择（multi-noise 气候空间）

群系选择遵循 Minecraft 1.18+ 的 multi-noise 模型：群系不是 chunk 大小的离散格子，而是从连续气候场里"涌现"出来的连续区域——相邻 column 气候相同则群系必然相同，气候跨越群系 climate range 边界处就是天然的过渡带。

两个相关数据入口：

  • minimap 主导群系（WorldMapTile::biome_id）：世界地图 tile 的显示颜色来源。它表示该 tile 主要是什么群系，不再作为 chunk 生成输入。
  • per-column 群系（column_biome_lookup → sample_climate_for_block → select_biome_for_climate）：每个 column 独立采样气候，独立选择群系。实际地表/次地表方块、水域列判定和高度 profile 都使用这个结果。同一 chunk 内不同 column 可落到不同群系，这是"颜料晕染"过渡的来源。

select_biome_for_climate 核心算法是纯气候距离最近邻：在 (温度, 湿度, 海拔) 三维空间里找最近的群系 climate range。完全落在某群系 range 内 → distance = 0；否则按"超出 range 边界的距离平方和"比较。同距离时优先选 climate range 更窄 的群系（窄 range 表示该群系更"专一"，应该优先于宽 range 的"通吃型"群系，例如热带中湿度气候应归 jungle 而不是 desert）。不再有 hash 加权随机——这是相邻 column 不会因随机噪声被分到不同群系的关键，也是消除"草原/深海交错"问题的核心改动。

阶段 3:地形 pipeline（generate_terrain_for_chunk）

所有 surface 高度计算都基于世界坐标：fbm 噪声、气候采样、双线性宏观骨架都是纯函数 of (wx, wz)。因此相邻 chunk 在共享边界 column 上的高度一致（仅整数取整可能差 1），无需任何 chunk-local 高度图后处理。完整流程：

  1. Per-column surface_y 计算（TerrainGenerator::surface_y_for_column_climate）：
    1. 查 per-column 群系（column_biome_at → sample_climate_for_block → select_biome_for_climate）——用于方块 ID 选择（surface/subsurface block 不能混合）。
    2. 取宏观骨架高度 base_height_at(wx, wz)（terrain_base_height_for_block，4 角 chunk 气候的双线性插值）。
    3. 取 per-column 气候（column_climate_at → sample_climate_for_block）——用于高度 profile 混合。
    4. 混合 (offset, amplitude_scale) profile：用 IDW（反距离加权）混合所有 biome 的 height profile。距离 = 气候 (T, M, E) 到 biome climate range 的平方距离。气候落在某 biome range 内时（距离=0），用该 biome 的 profile（tie-break 选 range 最窄的）；否则按 1 / (distance + epsilon) 加权平均。这让 beach (+7) 到 ocean (-8) 的过渡是连续渐变，而不是 chunk 边界突变。
    5. 叠加居中 fbm 偏移：fbm * (amplitude / 2) * blended_amp_scale。fbm 输出范围 [-1, 1]，所以这一项是双向的 [-amp/2, +amp/2]——这是"chunk 中心不再系统性偏高"的关键。
    6. 加 blended 高度偏移：blended_offset。
    7. 叠加 ridge 山脉抬升：若 m_ridge_noise 在阈值之上，按 (noise - threshold) / (1 - threshold) * mountain.amplitude 加上抬升量。海洋 column 不再做 shore_fade 或海平面钳制，海床可自由起伏到海平面之上形成浅滩、孤岛。
    MOD 不写 height 块时默认 offset=0, amplitude_scale=1.0。
  2. 方块填充（per-column 群系）：surface / subsurface 方块和 subsurface_depth 按 per-column 群系（最近邻 biome）决定。如果 surface_y 低于 sea_level 或者 biome 是水域群系，column 标记为 underwater，水面填到 sea_level。陆地的 surface 高于 sea_level 时按实际高度填充，不再强制压平。
  3. 地下矿石（generate_underground → place_ores）：用 m_cave_noise 的 3D Perlin 在指定 y 区间内把 replace_block 替换为矿石方块。矿石定义在 data/ores/。
已废弃的 chunk-local 路径：早期实现用 generate_biome_height_map（SIMD 4 路 fbm）算 chunk 内部高度图，再用 3×3 box-blur 平滑 biome 边界、最外 4 圈 column 用 base_height_at 锚定 chunk 边缘。这套机制已被世界坐标 fbm 取代——所有 chunk-local 后处理都因为 fbm 本身就是世界坐标连续函数而变成多余的补丁。相应地 generate_base / generate_chunk / raise_mountains 等老入口已删除。
性能（2026-06-14 修复）：base_height_at 对每列方块都要求 4 个角 chunk 的基础高度。旧实现每个角 chunk 都重新采样气候，相当于 1 个 chunk 生成触发 256 × 4 = 1024 次气候采样。修复后 terrain_base_height_for_block 用 thread_local 的 4 角 cache，第一次调用预计算 4 个角的高度，后续 255 次调用只做纯插值，气候采样次数从 ~1024 降到 4。

阶段 4:大型地物（generate_large_features_and_decorations）

在已经填好基础方块的 chunk 上叠加地物，顺序敏感：

  1. 洞穴挖掘（carve_caves，biome.has_caves 时）：以 chunk 网格为锚点（每个 anchor 4×4 半径），用确定性哈希决定是否生成洞穴系统。生成时挖出椭球隧道，并向外延伸分支隧道。锚点机制保证相邻 chunk 挖出的洞穴能无缝衔接。洞穴入口高度直接用 height_at 的输出，后者已经包含 ridge 山脉抬升，所以入口与最终地表对齐。
  2. 地表装饰（decorate_chunk）：遍历已注册的 TerrainFeature，按群系白名单过滤。对每列计算植被概率场：
    • 树木类：综合 vegetation.density、噪声权重、湿度权重、温度适宜度（基于 temperature_optimum 和 temperature_range）和坐标随机权重，决定是否放置树。放置时使用单体 block 地物方块。树木可以放在 chunk 边缘 column。
    • 单方块地物（石堆、灌木、遗迹碎片等）：按 density * 6 次随机尝试放置。
山脉抬升已合并到 fbm 阶段（surface_y_for_column 末尾的 ridge noise 分支）。早期独立的 raise_mountains 后处理阶段已删除——它需要先扫描已生成的 chunk 数据找当前 surface_y 再叠加 uplift，而 ridge noise 作为 surface 公式的一部分可以直接在世界坐标上采样，跨 chunk 天然连续，不会出现"山脉从 chunk 边界突然隆起"的伪影。

噪声分层

TerrainGenerator 持有三组独立 Perlin 噪声（不同种子偏移），保证用途互不干扰：

成员种子偏移用途
m_noise无（直接用 world_seed）地表高度图 fbm、装饰概率场
m_cave_noise0xA5A5... 异或矿石分布
m_ridge_noise0xD1B5... 异或ridge 山脉抬升，叠加到 surface_y_for_column

已知的未来改进

  • 极地折返处双线性高度异常：base_height_at 用四个角 chunk 的气候做双线性插值，在极地折返附近可能产生高度异常。考虑改用球面插值或对极地区域使用最近邻。该项影响面小（极地仅占星球一小部分），优先级低。
  • per-column 装饰：当前 decorate_chunk（树木、灌木、洞穴）仍按 chunk 中心 column 的群系工作。如果要让 chunk 边界处的装饰也按 column 群系分布（比如草原区域内的小片沙漠不长树），需要把装饰阶段改成 per-column 群系评估。改动面较大，留作可选增强。
海洋深度与海岸过渡（2026-06-20 下午）
  • terrain_config_for_chunk 和 sample_chunk_base_height_value 移除 water chunk 的两个钳制：cfg.base_height ≤ sea_level - 4 和 cfg.amplitude ≤ 6。macro 完全按 elevation 平滑变化，海床 fbm 起伏跟陆地一样（amp=15），不再是平的"海底地板"。
  • sample_climate_for_block 新增第三个 Perlin 扰动场——海拔。周期 128 块（比温度/湿度的 48 块慢），幅度 0.05，让 chunk 内 elevation 也能连续漂移。这样 beach/ocean_shallow/ocean 群系选择在 chunk 内是渐变而不是按 chunk 中心离散判定，海岸过渡带自然变宽。扰动后 water 标志按新 elevation 重新判定。
  • CoreMod 重新设计海洋群系对：ocean（深海）offset -15、amp_scale 0.4、elevation 0.0-0.40；ocean_shallow（浅海）offset -3、amp_scale 1.2、elevation 0.40-0.50。浅海 fbm 起伏明显（±9 块），偶尔露出海面形成浅滩/孤岛；深海是相对平坦的深海平原，fbm 起伏只有 ±3 块。
  • river 群系 offset 改为 -3、amp_scale 0.4，避免新管线下河床偶尔高出 sea_level 形成"干河"。
边界连续性补丁（2026-06-20）
  • 新增 TerrainGenerator::surface_y_for_column_climate：把 biome 的 (offset, amplitude_scale) 按气候距离 IDW 混合，而不是离散选用最近 biome。这让 land biome (+7) 和 ocean biome (-8) 之间的 surface_y 是连续渐变，消除 chunk 边界悬崖。方块 ID 选择（surface_block 等）仍按最近 biome，因为方块类型不能混合。
  • ChunkManager 新增 column_climate_lookup() 回调，给 generate_terrain_for_chunk 传 column_climate_at 参数。所有内部调用点已更新。
  • CoreMod 的 beach 群系 climate range 收紧到 elevation 0.48-0.52（紧贴 sea_level），避免在内陆中等海拔地区误判为 beach。
  • decorate_chunk 允许树木放在 chunk 边缘 column。
世界级 fbm 重构（2026-06-19）
  • height_at 不再把 fbm 重映射到 [0, 1]——直接用居中输出 [-1, 1]，所以高度增量是双向的 [-amp/2, +amp/2]。这消除了"chunk 内部系统性高于边缘"的偏置。
  • 删除 Phase 1c 的 3×3 box-blur 和 4 圈 border zone 锚定——fbm 本身就是世界坐标连续函数，所有 chunk-local 后处理都成了多余补丁。
  • 删除水域 column 在 inner zone 钳到 max_water_surface_y 的逻辑——海床按 fbm 自由起伏，可在海平面之上形成浅滩/孤岛。
  • 删除 raise_mountains 后处理阶段。山脉抬升合并到 surface_y_for_column 的 ridge 分支，跨 chunk 天然连续。
  • 删除老入口 generate_biome_height_map / generate_base_from_height_map / generate_base / generate_chunk / raise_mountains，及 ChunkHeightMap typedef。
  • 新增 TerrainGenerator::surface_y_for_column：chunk 生成阶段每列调一次，组合宏观骨架 + 居中 fbm + ridge 抬升，应用 biome amplitude_scale 和 offset。
  • 新增 m_ridge_noise 成员（独立种子偏移）作为山脉抬升的来源。
  • carve_caves 入口高度直接取 height_at（已经包含 ridge），不再做水域钳制。
multi-noise / 气候空间迁移
  • 群系选择从 hash 加权随机改为纯气候距离最近邻，相同气候必然映射到相同群系，相邻 column 不会因随机噪声被分到不同群系。
  • 气候采样新增 block 级扰动（sample_climate_for_block），让气候在 chunk 内连续漂移，是 chunk 内多群系的物理基础。

  • per-column 高度（Phase 4）：群系可选 height 块声明 offset 和 amplitude_scale，让山地气候 column 在草原 chunk 内也能真的高起来；3×3 box-blur 平滑过渡，MOD 不写 height 块则保持旧行为。

性能改进（2026-06-18）
  • ChunkDataStore 内部改为 16 高度 sub-chunk 存储。全空气或全同类方块的 sub-chunk 只保存一个 uniform BlockState；多状态 sub-chunk 会优先保存 state palette + u8/u16 indices，palette key 只看 id/data，写入 id/data 时保守展开为 dense；GPU block light 写入独立 light overlay，不再修改 voxel state。
  • 主要读路径已切到 sub-chunk API：高度缓存通过 accessor 扫描 uniform/palette/dense 数据；NavMesh backprop 对已加载 chunk 可通过 accessor 从 ChunkDataStore 直接构建；GPU light registry 也通过 accessor 扫描发光方块和构建 BFS light volume。GPU probe / GPU fluid candidate 输入通过 copy_chunk_packed() 以 BlockState + LightData 打包；网络 chunk delta 使用 ChunkSnapshot 对比原始地形，snapshot 保留独立 lights 数组。
  • 存档写出的 block payload 只保存 [id,data] state，光照进入 chunk-level lights 数组。
  • ChunkMesher 新增 accessor 入口。LOD-only mesh refresh 不再重建 NavMesh，且只快照 BlockId 数组，不复制完整 Block，并会跳过已知全空气 sub-chunk 的 LOD 扫描。
  • chunk mesh 的 3×3 邻居缓存统一使用 MeshNeighborChunk：已加载 chunk 通过 ChunkDataStore::ChunkSnapshot 保留 sub-chunk/uniform 结构，未加载邻居才临时生成 dense terrain。dirty rebuild、async chunk build、初始核心 chunk 和同步 build_chunk_at 都不再为了读取已加载邻居而展开完整 dense Block 副本。LightSystem::compute_all_overlay_with_accessor 负责生成独立 light overlay，再通过 mesher light accessor 采样光照。
  • 渲染 chunk mesh 的 BlockVertex 从 40B 压缩到 32B：位置仍为 float3，UV 使用 half-float，atlas origin/size、light 和 surface grid coord 使用 16-bit normalized attribute。chunk CPU mesh 和 aggregate index buffer 改为 16-bit index，实体 mesh 仍保留 32-bit index。
  • chunk aggregate 增加 CPU cache 和 slice table：可见 chunk 集合不变时，三帧 in-flight 复用同一份拼接结果；同尺寸 chunk mesh 更新会覆盖所有 display copy 对应的 CPU slice，并只向 GPU copy 该 slice 的 vertex/index range。wrap seam 下同一 storage mesh 的 display offset 会在 partial update 时重新应用；尺寸变化但可见集合不变时会重排 aggregate CPU cache 并全量上传 GPU，避免重跑 frustum/sort/draw-list。aggregate GPU buffer 按增长 capacity 分配，减少 streaming 或 render distance 波动时的小幅扩容重建。

调试技巧

  • 控制台输入 engine.terrain.list_biomes() 列出所有已注册群系
  • 调试 column 级群系分布：移动鼠标查看 debug 面板中的 Biome，它显示的是当前 block column 的实际群系；也可以在生成器中临时调高 sample_climate_for_block 的扰动幅度（PERTURB_AMP）观察 chunk 内多群系变化是否如预期。
  • 启动加 --DEBUG 参数可看到 [WorldMap] 和 [Chunks] 日志，了解世界地图大小和 chunk 生成状况。
