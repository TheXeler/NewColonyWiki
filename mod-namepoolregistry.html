名称池注册

名称池（Name Pool）定义在 data/name_pools/ 下，以 JSON 描述。名称池提供随机命名素材，NPC 阵营在实例化时从中抽取词语生成随机名称。

JSON 格式

{
    "id": "my_mod:viking",
    "words": [
        "Ragnar", "Bjorn", "Erik", "Sigurd", "Harald",
        "Longship", "Shield", "Axe", "Fjord", "Saga"
    ]
}

字段说明

字段类型必填说明
idstring是唯一标识，格式 <mod_id>:<name>。
wordsstring[]是词汇列表。阵营从列表中随机抽取一个或多个词拼接为名称。
词汇数量没有上限，但建议保持 20~100 个以保证命名多样性。词汇越少，生成名称的重复率越高。

与阵营的关系

名称池被 NPC 阵营（data/factions/）引用。阵营定义中的 name_template 字段使用 ${random_name} 占位符，name_pools 字段指定引用哪些名称池：

{
    "id": "my_mod:viking_clan",
    "name_template": "${random_name} Clan",
    "initial_relation": 0,
    "max_relation": 50,
    "min_relation": -80,
    "inclination": "warlike",
    "name_pools": ["my_mod:viking"]
}

引擎在实例化阵营时，从 name_pools 指定的池中收集所有词汇，随机选取一个替换每个 ${random_name}，生成如"Ironhide Clan"这样的名称。

使用案例

案例 1：单池单占位符

最基础的用法：一个阵营引用一个名称池，模板中有一个 ${random_name}。

名称池 data/name_pools/viking.json：

{
    "id": "my_mod:viking",
    "words": ["Ragnar", "Bjorn", "Erik", "Sigurd", "Fjord", "Shield", "Axe"]
}

阵营 data/factions/viking_clan.json：

{
    "id": "my_mod:viking_clan",
    "name_template": "${random_name}部落",
    "initial_relation": -10,
    "max_relation": 30,
    "min_relation": -100,
    "inclination": "warlike",
    "name_pools": ["my_mod:viking"]
}

生成结果："Ragnar部落"、"Shield部落"、"Fjord部落"……每次实例化随机选一个词。

案例 2：多池合并

一个阵营可以引用多个名称池，引擎会将所有池的词汇合并后再随机选取。

名称池 A data/name_pools/colors.json：

{
    "id": "my_mod:colors",
    "words": ["Crimson", "Azure", "Golden", "Silver", "Obsidian"]
}

名称池 B data/name_pools/animals.json：

{
    "id": "my_mod:animals",
    "words": ["Wolf", "Eagle", "Dragon", "Serpent", "Phoenix"]
}

阵营 data/factions/beast_clan.json：

{
    "id": "my_mod:beast_clan",
    "name_template": "${random_name}氏族",
    "initial_relation": 0,
    "max_relation": 60,
    "min_relation": -60,
    "inclination": "neutral",
    "name_pools": ["my_mod:colors", "my_mod:animals"]
}

生成结果：从 colors + animals 共 10 个词中随机选，可能是 "Crimson氏族"、"Dragon氏族"、"Golden氏族"等。

案例 3：多重占位符

模板中可以使用多个 ${random_name}，每次独立抽取（允许重复）。

{
    "id": "my_mod:ancient_order",
    "name_template": "The ${random_name} ${random_name}",
    "initial_relation": 20,
    "max_relation": 100,
    "min_relation": -30,
    "inclination": "commercial",
    "name_pools": ["core:generic"]
}

生成结果："The Iron Wolf"、"The Storm Eagle"、"The Silver Silver"（可能重复）等。使用大池（如 core:generic 约 400 词）可以显著降低重复率。

案例 4：使用 CoreMod 通用池

不想创建自定义名称池时，可以直接引用内置的 core:generic。CoreMod 的所有阵营都这样做：

{
    "id": "core:merchant_guild",
    "name_template": "${random_name}商会",
    "initial_relation": 20,
    "max_relation": 100,
    "min_relation": -50,
    "inclination": "commercial",
    "name_pools": ["core:generic"]
}

生成结果："Ironhide商会"、"Stormcaller商会"等。

名称生成规则

  • ${random_name} 是唯一的占位符，大小写敏感。
  • 每个 ${random_name} 独立从合并后的词汇池中随机抽取，多次出现可能抽到同一个词。
  • 如果 name_pools 中引用的池 ID 不存在，该池被跳过；如果所有池都不存在，引擎回退使用全部已注册名称池。
  • 如果模板中没有 ${random_name}，名称就是模板原文（静态名称）。
  • 每个阵营实例的名称不同——同一个阵营定义被多次实例化时，每次独立生成。

内置名称池

CoreMod 注册了 1 个通用名称池：

通用 core:generic

包含约 400 个词汇，涵盖自然、金属、颜色、动物、地形、职业等类别。所有未指定专用名称池的阵营默认使用此名称池。

词汇分类示例：

类别示例词汇
金属/材质Iron, Copper, Bronze, Steel, Obsidian, Onyx
颜色Crimson, Azure, Violet, Amber, Scarlet, Cobalt
动物Wolf, Eagle, Raven, Dragon, Phoenix, Serpent
地形Ridge, Hollow, Vale, Glen, Summit, Canyon
建筑Fortress, Citadel, Tower, Bastion, Spire
职业Smith, Weaver, Mason, Brewer, Fletcher, Cooper
复合词Ironhide, Stormcaller, Moonshadow, Firebrand

文件放置规则

  • 放在 data/name_pools/ 下，支持子目录。
  • 文件名随意，引擎只关心 JSON 内的 id 字段。

验证命令

在控制台（按 ~）中确认名称池注册：

list_data name_pools              -- 列出所有已注册的名称池
data core:generic                -- 查看名称池的完整 JSON
