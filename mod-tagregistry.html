Wiki/Tag 注册

标签数据

标签让配方引用一组可以互相替代的稳定物品 ID，适用于任意木头、木板、食材等材料组。配方成员包括独立 items 和具有物品身份的 blocks；世界方块标签保留独立查询。标签是数据分组，不产生物品、配方或掉落内容。

格式

{
  "tag": "example:materials",
  "values": ["example:item_a", "example:item_b"],
  "replace": false
}

文件放在 data/tags/，以 tag 为登记键，不需要 id。values 可以混合引用 items 和 blocks 中的 ID，引用不存在的数据会拒绝加载。没有物品身份的方块（has_item_block: false 且没有同 ID 的独立物品）只加入世界方块标签，不会成为配方材料候选。

先收集内联标签，再处理独立标签文件。replace: false 合并成员并去重；replace: true 先清除同名标签的物品、方块成员及反向索引，再写入文件成员。不同定义的加载及覆盖仍遵循 Mod 数据注册顺序。

内联标签

items 和 blocks 都可以通过 tags 数组声明配方分组；已有 usage_tags 也加入配方成员索引。两种字段都必须是非空字符串组成的数组，缺省或空数组均可。相同成员不会重复计数。标签名按原字符串精确匹配，例如 grain 与 c:grain 是不同的组。

{ "id": "example:oak_log", "tags": ["c:logs"] }
{ "id": "example:birch_log", "tags": ["c:logs"] }
{ "id": "example:rice", "usage_tags": ["crop", "grain"] }

上述片段展示标签字段，其他物品或方块必填字段仍需填写。方块的 tags 同时加入世界方块索引；独立物品的标签和 usage_tags 不会让世界方块查询匹配到不存在的体素。独立标签文件中明确列出的方块仍可供世界查询使用。

配方用法

首批料理使用 core:raw_cooking_grains（小麦、玉米、高粱、燕麦、水稻）和 core:raw_cooking_tubers（马铃薯、芋头、山药、木薯粉）。这是投入资格组；grain 等展示用途标签还可能包含面包，不能用作禁止熟食再加工的边界。Tag决定可替换材料，实际成品营养及寿命由本次消耗原料的烹饪组件决定。

"inputs": [
  { "tag": "c:logs", "count": 4 },
  { "id": "example:binding", "count": 1 }
]

count 是该材料组的总消耗量，允许多种成员混合满足，例如橡木 2 份加白桦木 2 份。多个 Tag 或指定物品需求重叠时，联合分配材料，防止同一份库存被重复使用，也避免宽泛组提前占用指定物品所需的唯一材料。实际预留失败仍会释放已经取得的材料预留。开始加工后保存已选中的具体材料，完成时按这份记录结算。

CoreMod 的 data/tags/logs.json 定义 c:logs，目前成员为 core:wood；木板配方使用该组。扩展木材种类时，在新木材的 tags 中加入 c:logs，即可成为候选，不需要为每种木头复制配方。

Lua 查询

  • engine.tags.items(tag)：返回配方物品候选数组，每项包含 id、hash，按数值 hash 排序。
  • engine.tags.has_item(item_id_or_hash, tag)：查询物品是否属于该配方材料组。
  • engine.tags.of_item(item_id_or_hash)：返回物品所属的标签名，按字符串排序。
  • engine.tags.has、blocks、of_block、nearest_loaded_block 和 loaded_blocks 保持世界方块查询语义；list() 列出两类索引的标签名。

边界

  • 标签不能替代所有者库存内容、预约或产出表。
  • 方块采集结果只能来自 output_table，不能由标签推导。
  • 空标签内容不会生成默认成员。
  • 空候选组不能发布制作工作，不会变成匹配任意物品的通配需求。
  • 物品类别、营养、烹饪资格、品质及产出仍由各自定义决定，不会从 Tag 推导；食用方案和仓储策略已有的 usage_tags 规则不因独立标签文件而重写。
  • 标签索引与配方一起准备和提交；解析失败保留上一份已发布索引，成功重载会移除旧成员。
