Tag 注册（矿物词典）

Tag 是 Forge OreDictionary / Minecraft 1.13+ tag 的等价物。一个 tag 是若干方块的"别名"（如 c:ingots = 所有金属锭），配方输入可以用 tag 替代具体方块 ID，让不同 MOD 的同类方块互相等价。

命名约定

Tag 字符串是任意非空字符串，引擎不强制规则。社区约定：

  • c: 前缀：跨 MOD 通用 tag，如 c:ingots/iron、c:ores/copper、c:planks。
  • 带斜杠的层级路径：父 tag（c:ingots）和子 tag（c:ingots/iron）是独立 tag，互不自动包含；如果想继承需要在两边都声明。
  • MOD 私有 tag 使用 my_mod: 前缀避免冲突。

Tag 字符串内部按 FNV-1a 哈希索引，与方块 ID 共用同一套哈希。两个完全相同的 tag 字符串被视作同一个 tag。

声明方式

有两条路径，结果会合并到同一个 tag 字典。

方式一：就地声明（推荐用于小批量）

在 block JSON 顶层加 tags 字段：

{
  "id": "core:iron_ingot",
  "name": "Iron Ingot",
  "stack_size": 64,
  "tags": ["c:ingots/iron", "c:ingots", "c:metals"]
}

方式二：独立 tag 文件（推荐用于集中扩展）

在 data/tags/*.json 下声明。Schema：

{
  "tag": "c:ingots",
  "values": [
    "core:iron_ingot",
    "core:copper_ingot",
    "core:gold_ingot",
    "core:silver_ingot"
  ],
  "replace": false
}
字段类型必填说明
tagstring是声明的 tag 字符串。非空。
valuesarray是方块 ID 数组。每个 ID 必须指向已注册的方块，加载时会交叉校验。
replacebool否默认 false，追加到现有 tag。设为 true 时先清空该 tag 的所有声明再重新填充——用于让某个 MOD 完全覆盖其他 MOD 对该 tag 的定义。

使用 tag 的配方输入

配方 inputs[] 元素的 id 字段可以替换为 tag 字段（两者互斥，必须二选一）：

{
  "id": "core:compress_ingot",
  "inputs": [
    { "tag": "c:ingots", "count": 2 }
  ],
  "output": { "id": "core:iron_ingot", "count": 1 }
}

运行时匹配规则：手持的 HeldItem.item_id 只要出现在 c:ingots tag 的方块集合中即视为匹配。手持 2×铁锭 / 2×铜锭 / 2×金银锭（甚至 1×铁 + 1×铜）都能触发该配方。

配方输出（output）目前不支持 tag——产出必须是具体方块 ID。设计上"生产出来的东西"必须是确定的。
RecipeSystem 的 HeldItem 槽当前是单物品多次消耗模型（详见 配方注册 的注意事项）。多输入配方只在所有输入都匹配同一种手持方块时才能成功。Tag 输入也遵循这条规则：必须手持 N 个都属于该 tag 的同一种方块。

查询 API（Lua）

引擎在 engine.tags 命名空间下暴露只读查询函数：

engine.tags.has(block, tag)         -- bool；block 可传 hash 或 string id
engine.tags.blocks(tag)            -- 返回 { {hash=..., id=...}, ... }
engine.tags.list()                 -- 返回所有已声明 tag 的字符串数组
engine.tags.of_block(block)        -- 返回该 block 拥有的 tag 字符串数组

Tag 字典不暴露注册接口——注册只走 JSON 数据。Lua 只能查询。

内置 tag 示例

CoreMod 内置示例（见 CoreMod/data/blocks/ 与 CoreMod/data/tags/）：

Tag包含的方块
c:ingotscore:iron_ingot / core:copper_ingot / core:gold_ingot / core:silver_ingot（独立 tag 文件 data/tags/ingots.json + block JSON 内联声明，两种路径协同）

c:ores / c:ores/<metal>各类矿石

c:planks / c:woodencore:wood_plank

加载顺序

blocks 在 RecipeSystem 初始化前全部注册到 ModRegistry（Engine.cpp 中 load_all() → recipe_system.init_from_registry()）。RecipeSystem 初始化时：

  1. 清空 tag 字典。
  2. 扫描所有 type=="blocks" 条目的 tags 字段，逐项注册。
  3. 扫描所有 type=="tags" 条目，按 replace 决定追加/覆盖。
  4. 再开始解析 recipes，让 recipe input 中的 tag 能查到。

RecipeSystem 不被序列化，tag 字典随 RecipeSystem 重建——存档兼容零风险。
