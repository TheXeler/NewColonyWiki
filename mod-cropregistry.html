作物数据

完整最终设计及首批22种作物数值见源码文档 NCDOCS/种植系统设计.md，药材资格与四性见 NCDOCS/药材内容表.md。面向新建世界，不迁移旧农业记录。本页的开发进度不代表运行验收通过。

当前状态

CoreMod 按当前素材需求加入 core:wheat 作物定义，位于 data/crops/wheat.json。提供 core:wheat 收获物、core:farmland 耕地，以及 core:wheat_stage0 至 core:wheat_stage7 八个作物阶段。

小麦使用 Minecraft 四张双面竖片的作物模型，八张阶段贴图由已有工作区素材导入。作物方块为 transparent，角色可以穿过，不遮挡相邻面；它们没有物品方块形态，也不进入放置菜单。小麦的图标、掉落物使用独立的 item/generated 模型。耕地显示高度为 15/16 格；碰撞与射线选中仍采用引擎现有整格规则。

旧小麦八阶段内容及Lua农业、城邦存档／结算仍待迁移到最终五阶段规则。最终进入第五阶段即成熟；前四阶段各100成长值，基础速度为400除以正常生长日数再除以28,800。温度按正常、缓长、停长优先级判断，全部未命中立即枯萎。阶段达到上限时新阶段进度归零，超额不带入；末阶段不再处理成长环境。

新配置接口（已加入，运行态迁移中）

data/crops/*.json 新格式包含 id、可选 tilled_block（首次翻地目标，默认 core:farmland）、withered_block（默认 core:withered_crop）、defaults 与非空 growth_stages。阶段必须引用独立 block，其方块定义负责名称、文本、材质、模型和贴图。阶段 growth_limit 默认100，outdoor_required 默认true。sow_ticks、harvest_ticks 各默认60 Tick；可选正数 storage_lifetime_days 表示仓储寿命，省略或null表示不腐坏。yam_harvest_loss 仅山药启用。

{
  "id": "example:crop",
  "defaults": {
    "growth_limit": 100,
    "ground_rates": {"core:farmland": 0.001736111111111111},
    "temperature": {"normal": [5,32], "slow": [0,36], "stopped": [-15,40]},
    "outdoor_required": true,
    "drops": []
  },
  "growth_stages": [
    {"block": "example:stage0"},
    {"block": "example:stage1", "drops": "example:harvest"}
  ]
}

ground_rates 为任意下方方块ID到每Tick成长变化量的对象，允许正、零、负数。未写字段继承默认值；显式地块表与掉落表整表替换，空表不恢复默认。drops 可引用独立产出表，或内嵌固定产出数组 [{"id":"example:item","count":4}]，空数组表示无产物。温度三档为含端点的两个有限数值，空数组跳过该档；温度对象内未写的档位逐项继承。区间不要求嵌套，也不修正范围。slow将正成长减半，stopped和室内要求只停止正成长，负成长继续扣减并在进度归零时枯萎。不得在新格式中再写独立阶段 ticks。

未显式写 auto_harvest 时只有末阶段默认开启；阶段和作物默认均可显式覆盖。已加入共用 Simulation/CropRules.hpp，供新格式解析、成长规则及山药公式使用，新格式也接入Mod配置和交叉引用校验。engine.modding.get_crop_info(id) 对新格式返回 schema=2 与已展开默认值的阶段。engine.modding.evaluate_crop_stage(id,stage,progress,ticks,ground_id,temperature,outdoor) 返回progress、advance、withered、reason、can_sow；编号从1开始，仅计算当前阶段，跨阶段长区间必须按边界分段。测试源码已补，未编译、未执行。

最终运行规则（尚待完整接入）

新格式的原生／Lua路径已加入独立植株成长、成熟时点与留田腐坏、换种／休耕／枯萎清理派工，以及按工作UUID持有的单格编辑锁。农业开工监听器保存阶段、进度、执行者精度和已经解析的产出；Mining完成路径读取该快照，避免完成时重抽山药损失或重跑产出钩子。中断解锁并保留剩余成熟寿命；锁恢复同时核对原生有效工作或保留的生命周期通知。这些源码尚未运行验收，城邦原生档案及预测仍有旧格式假设，22种内置数据尚未切换。详细待办及检查证据见 NCDOCS/种植系统落实进度.md。

自动与手动收获、割除、枯萎拔除在工人抵达开工时锁定植株及执行者快照；中断解锁，不补算锁定时间；存读档不重复结算或重抽山药损失。换种收成熟、清幼苗后补种；休耕同样清理但不补种；删区只取消派工，植株独立继续生命周期。未加载区块暂停原生成长期，成熟腐坏按游戏时间继续。地面及成熟留田寿命为仓储一半，正常收获刷新产物寿命。

水塔占地1×1、高3格，覆盖同层9×9；木板16、石料8，工作台30秒合成，搬运抵达即时放置。水塔主动通过事件维护水田，耕地不查询邻塔。多塔不叠加，最后来源失效宽限300 Tick，恢复供水取消失水；拆塔后延迟处理独立存续。水塔、22种内置数据、独立植株、工作锁和玩家界面仍在开发中。

棉花、亚麻不入药，其余20种原植物可入药；木薯粉不能入药也不能直接吃，原木薯仅经1比1制粉进入烹饪。谷薯不供日常选食，蔬菜可直接吃。普通药草用于医疗包，四种特化药材不能替代它；药草与特化药材均不作日常食物。棉麻、四种特化药材及医疗包不腐坏。

接口边界

2026-10-12 城邦交接源码：农田 plots 新增 colony_uuid，待办行继续保存区域与任务归属；旧农田行省略归属时可从既有区域恢复。city_business 按归属停放、合并阶段、有效累计时间和待办身份，各候选用实际恢复解码器预检。已管理抽象城邦的区域不设置默认作物、不读取／修改农田地形、不推进生长或重下实体任务，即使区块仍加载；城邦原生任务使用所属城邦阵营。农业记录的停放已接入联合事务，抽象温度／增长／收获及地形校正仍需经营适配器，不能仅修改档案时点后恢复。本轮未编译、运行测试或启动游戏。

systems.farming 为 core:growing 默认设置 crop=core:wheat。泥土或草地下方对应的空区域格先派翻地工作，耕地空格派播种工作；两者使用 Build 工作与种植权限。播种与补种完全不消耗物品：不设置材料要求、不预约也不扣除背包和仓储物品，因此 CoreMod 不定义种子物品，作物 schema 也没有 seed_item 字段（引擎侧的格式校验、引用交叉校验和 get_crop_info 投影都已随种子物品一并移除）。原生完成结算仍校验任务、区域、作物、耕地、空位和碰撞，校验通过才放置幼苗，失败保留空格。

成熟后派 Cut 收获工作，沿已有方块/产出事务生成可回收地面小麦。作物收获保留种植区格子，后续无需任何材料自动补种。农夫职业允许种植与割除工作。每个目标只登记一个农业待办，并避开同格手动 Build/Cut 指令；一次扫描最多新派 16 个工作。

世界状态保存逐格作物阶段、有效累计时间，以及待办工作 UUID 和区域来源。农业待办行只保存 task_uuid、zone_id、crop_id、phase、坐标、归属和可选 plot_uuid；因为播种不持有任何物品预约，这里既不保存也不校验预约编号。加载及 Mod 上下文恢复只读校验坐标、阶段和任务身份，不重复播种。删除区域会取消其来源工作并停止该区域作物管理；已存在植株保留在世界中，可对成熟植株手动割除。原生 Server 接口 world.settle_farming(task_uuid,zone_id,crop_id,phase) 只接受对应 Build 完成上下文；world.advance_crop(zone_id,crop_id,x,y,z,stage) 校验区域、耕地与预期阶段后写入下一阶段。
