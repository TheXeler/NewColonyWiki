当前状态

本轮先完成22种作物展示，再按用户要求补齐实体水塔的制作、搬运放置、拆除及供水宽限。更广的城邦农业整合仍单独记录。展示入口、全部稳定ID、环境和占位素材限制见 NCDOCS/首批22种作物展示说明.md，水塔操作与验证边界见 NCDOCS/水塔实施说明.md。

CoreMod 的 22 种作物各注册一个方块。体素保存基础方块 ID 和 stage，方块的模型列表按阶段值选择外观，材质、碰撞与可切割性共用基础方块的定义。内置作物的状态 0 到 4 是五个生长阶段，状态 5 是枯萎形态。前四阶段为空产出，进入第五阶段即成熟。农务记录管理权威阶段、进度和植株身份。变更适用于新建世界。

小麦使用 Minecraft 四张双面竖片的作物模型，八张阶段贴图由已有工作区素材导入。作物方块为 transparent，角色可以穿过，不遮挡相邻面；它们没有物品方块形态，也不进入放置菜单。小麦的图标、掉落物使用独立的 item/generated 模型。耕地显示高度为 15/16 格；碰撞与射线选中仍采用引擎现有整格规则。

前四阶段各100成长值，基础速度为400除以正常生长日数再除以28,800。温度按正常、缓长、停长优先级判断，全部未命中立即枯萎。阶段达到上限时新阶段进度归零，超额不带入；末阶段不再处理成长环境。原生、Lua及城邦派工／档案已接入共用配置，城邦完整生命周期交接仍在逐项核对，不能将静态检查视为运行验收。

新配置接口（已加入，运行态迁移中）

调试控制台指令 crop_growth 在所有作物64倍正向成长与正常速度之间切换，每次回显开关状态及倍率。crop_growth 1 显式关闭，crop_growth 64 显式开启，crop_growth query 只查询。倍率同时用于实际成长与剩余时间预测，温度、露天、地块限制继续生效；负向成长、种收工时及成熟腐坏不加速。仅本次服务端进程有效，不写入配置或存档，重启恢复1倍。用法见控制台命令。

data/crops/*.json 的 block 引用基础方块，defaults 和非空 growth_stages 定义成长与产出。tilled_block 为首次翻地目标，默认 core:farmland。基础方块声明 block_state.property = "stage"、关联作物 crop 和有序 models。模型列表前几项逐一对应生长阶段，最后一项对应枯萎。模型路径相对于该 Mod 的 assets/models/，省略 .json，多个阶段可重复引用同一个模型。首个体素状态为 0，农务编号从 1 开始。阶段 growth_limit 默认100，outdoor_required 默认true。sow_ticks、harvest_ticks 各默认60 Tick，可选正数 storage_lifetime_days 表示仓储寿命，省略或null表示不腐坏。yam_harvest_loss 仅山药启用。

状态显示名使用形如 example:plant[stage=1] 的 blocks 本地化键。这个地址由引擎从基础 ID 和状态值计算，供任务精确核对当前形态。engine.world.get_block 同时提供 base_id、state_property 和 state_value。使用独立形态方块的 Mod 定义仍可逐阶段声明 block，并通过 withered_block 配置枯萎方块。

ground_rates 为任意下方方块ID到每Tick成长变化量的对象，允许正、零、负数。未写字段继承默认值；显式地块表与掉落表整表替换，空表不恢复默认。drops 可引用独立产出表，或内嵌固定产出数组 [{"id":"example:item","count":4}]，空数组表示无产物。温度三档为含端点的两个有限数值，空数组跳过该档；温度对象内未写的档位逐项继承。区间不要求嵌套，也不修正范围。slow将正成长减半，stopped和室内要求只停止正成长，负成长继续扣减并在进度归零时枯萎。不得在新格式中再写独立阶段 ticks。

未显式写 auto_harvest 时只有末阶段默认开启；阶段和作物默认均可显式覆盖。已加入共用 Simulation/CropRules.hpp，供新格式解析、成长规则及山药公式使用，新格式也接入Mod配置和交叉引用校验。engine.modding.get_crop_info(id) 对新格式返回 schema=2 与已展开默认值的阶段。engine.modding.evaluate_crop_stage(id,stage,progress,ticks,ground_id,temperature,outdoor) 返回progress、advance、withered、reason、can_sow；编号从1开始，仅计算当前阶段，跨阶段长区间必须按边界分段。

最终运行规则（尚待完整接入）

新格式的原生／Lua路径已加入独立植株成长、成熟时点与留田腐坏、换种／休耕／枯萎清理派工，以及按工作UUID持有的单格编辑锁。农业开工监听器保存阶段、进度、执行者精度和已经解析的产出；Mining完成路径读取该快照，避免完成时重抽山药损失或重跑产出钩子。中断解锁并保留剩余成熟寿命；锁恢复同时核对原生有效工作或保留的生命周期通知。22种内置内容已切换为五阶段新配置；城邦原生档案及预测已接入共用规则，但换种、清理、独立植株归档及跨模式恢复仍未全部闭合。详细待办及检查证据见 NCDOCS/种植系统落实进度.md。

自动与手动收获、割除、枯萎拔除在工人抵达开工时锁定植株及执行者快照；中断解锁，不补算锁定时间；存读档不重复结算或重抽山药损失。换种收成熟、清幼苗后补种；休耕同样清理但不补种；删区只取消派工，植株独立继续生命周期。未加载区块暂停原生成长期，成熟腐坏按游戏时间继续。地面及成熟留田寿命为仓储一半，正常收获刷新产物寿命。

水塔占地1×1、高3格，覆盖同层9×9；木板16、石料8，工作台30秒合成，搬运抵达即时放置。水塔主动通过事件维护水田，耕地不查询邻塔。多塔不叠加，最后来源失效宽限300 Tick，恢复供水取消失水；拆塔后延迟处理独立存续。上述内容、原生灌溉、工作锁及玩家界面已有源码；抽象安装、灌溉历史地形与覆盖边界仍需完成。

实体水塔领取成品时联合提交实际背包预约、零工时送达任务及安装状态；只在抵达开工时进入放置，放置受阻保留可回收成品供重试。未放置蓝图取消不发拆除产物，已建水塔拆除返还1份并保留归属。停用或移除来源即使发生在未加载区块，也从当前Tick开始独立宽限；启用后需加载确认塔身，确认有效时取消失水。面板新增安装阶段与失水地块倒计时。NPC待安装时保留实体模拟，抽象安装和跨边界合成仍后置，不将它们计为已完成。

城邦接管与恢复的核心状态白名单共用同一清单，含灌溉状态，写入数量从清单推导。新格式收获契约读取阶段有效掉落，支持引用、内嵌数组及空表；stage、drops 和 output_definition 记录对应配置，内嵌空表为 []。预测寻找当前起下一个允许自动收获的阶段；无后续可收阶段则返回不可用。抽象翻地结算会通知灌溉更新新耕地，不由耕地扫描邻塔。

模式交接使原生任务暂停并清除工人分配，农业目的状态通过 prepare_city_handover 按工作中断解锁：保留成长进度和平移后的剩余成熟寿命，不补算锁定期间；拒绝提交则原始状态与产出快照不变。普通存读档继续保留有效开工快照。成熟留田腐坏截止点会截断抽象时间段；空产出的正常收获仍使用作物收获工时，提前割除及枯萎拔除为20 Tick。

初始抽象城市已有水塔时，模板 native_initial.terrain 必须提供同层9×9范围除中心外80格地面的真实地形，包括区域外土地；缺失以 city_initial_irrigation_terrain_required 拒绝初始化，不从活区块或默认土壤补造。初始业务保存水塔来源，首个抽象时间段或即时实体化对账初始化供水。覆盖跨城邦边界的来源合成仍在开发中。

原生归档任务恢复按实际作物定义推导播种／收获工时，翻地保持40 Tick，不再固定种收为1秒。移除接口 prepare_crop_harvests 的收据支持 phase=harvest|clear|uproot，默认harvest；当前记录的 harvest_phase 与跨补种历史的 phase 保留操作类型。clear要求活的非末阶段，uproot要求枯萎植株。既有清理派工的交接使用20 Tick、空产出快照及同类收据；抽象模式主动创建清理工作、占用地块换种和休耕管理仍待补齐。

棉花、亚麻不入药，其余20种原植物可入药；木薯粉不能入药也不能直接吃，原木薯仅经1比1制粉进入烹饪。谷薯不供日常选食，蔬菜可直接吃。普通药草用于医疗包，四种特化药材不能替代它；药草与特化药材均不作日常食物。棉麻、四种特化药材及医疗包不腐坏。

接口边界

农务产出能力按职业继承规则适用于全部作物正常收获。开工时触发双倍产出的概率为 MIN(10 + (工作精度 - 1.0) * 10, 70)%，最低按0%处理；精度1、2、3分别为10%、20%、30%，最高70%。山药先扣挖坏损失，再对剩余收成判定职业加成。实际产物保存在开工快照，完成、存读档不重新抽取。抽象城邦收获使用相同解析入口与快照。

新增建筑字段 placement_item 表示搬运成品后即时放置：必须与唯一一份材料一致，construction_ticks 必须为0。systems.installation 先派搬运工作到实际物品来源，领入工人背包后派零时长放置工作，到场使用携带预约和建筑体素联合结算。普通建筑继续要求正建造工时。水塔使用此流程；工作台合成仍需木板16、石料8和30秒。

指令菜单已移除“种植与灌溉”入口，作物图鉴视图及其切换按钮也已删除；种植与灌溉模拟逻辑保留。种植区管理继续提供换种、休耕及自动拔除开关，列表显示从有效阶段配置推导的正常生长日数、对应地块和当前种植，设置失败显示重试提示。水稻显示水田10日，芋头默认显示普通耕地12.5日。保留的田间状态面板在末阶段不再显示0／100进度，负速度地块以 ground_negative 显示持续损失状态，归零仍以 negative_growth 表示枯萎。玩家界面沿用现有RmlUi窗口；本次仅静态检查。

systems.farming 为 core:growing 默认设置 crop=core:wheat。泥土或草地下方对应的空区域格先派翻地工作，耕地空格派播种工作；两者使用 Build 工作与种植权限。2026-10-17 起同一区域内仍有空格待翻地（含已派工但尚未结算的翻地）时，本次扫描只派翻地工作，等整块地全部翻完才开始派播种工作。播种与补种完全不消耗物品：不设置材料要求、不预约也不扣除背包和仓储物品，因此 CoreMod 不定义种子物品，作物 schema 也没有 seed_item 字段（引擎侧的格式校验、引用交叉校验和 get_crop_info 投影都已随种子物品一并移除）。原生完成结算仍校验任务、区域、作物、耕地、空位和碰撞，校验通过才放置幼苗，失败保留空格。

到达允许自动收获的阶段后派 Cut 工作，按开工时的有效阶段产出结算对应原料或纤维。作物收获保留种植区格子，后续无需材料补种。农夫职业允许种植与割除工作；旧职业文字中的种子解锁说法已修订。每个目标只登记一个农业待办，并避开同格手动 Build/Cut 指令；一次扫描最多新派16个工作。这些农业工作按任务重量5派发（个人队列总容量20），因此殖民者一次可领取最多4项相邻同类工作后依次执行，不再每格都重新回调度器领取；未声明重量的工作默认重量20，一次只持有一项。
