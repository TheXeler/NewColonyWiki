当前能力状态

帮助 MOD 作者判断哪些能力可以稳定依赖，哪些还处在接入、实验或未完成阶段。列表基于当前代码库的实际加载路径、系统初始化和 CoreMod 数据目录核对。

可稳定依赖

以下能力已经接入主流程，MOD 可以按公开文档使用。

能力状态说明
MOD 发现与加载可用mod.json、依赖与加载顺序（dependencies/load_after/load_before，支持 load_before: ["*"]）、side、conflicts、settings、用户设置覆盖和 MOD 翻译合并均已接入。脚本沙箱不提供通用文件系统 IO 权限。
数据注册可用ModLoader::load_mod_data 稳定加载基础内容、经营规则、生态、动态天气、视野和难度等多类 JSON；职业定义只从 jobs 读取，没有旧目录别名。
数据诊断可用重复 MOD ID、重复数据 ID、无效字段、配方/职业/文明/作物/方块引用错误会报告明确来源。
Lua 生命周期可用scripts/listeners/ 下的监听器以 @Event、@Priority 和执行端注释声明，返回回调函数后自动注册；其他模块按需 require。
Lua 事件与定时器可用engine.events 支持订阅、发布和取消订阅；engine.timers 支持持久任务 create、临时回调 temporary，以及 cancel、freeze、resume、status、query 和 current_tick。
Lua 随机数 API可用engine.random.seed/float/int/bool 使用 Xoshiro256** 确定性 RNG。
职业与配方可用职业 1-5 级、装备实例许可、前置职业、配方输入、职业要求、文明配方限制和解锁均已从注册表初始化。公开直通制作已禁用，CoreMod 制作统一走带资源预留的生产订单；固定制作结果由产出表决定。
文明接口文明注册、运行态和存档接口保留；NCDOCS 没有文明专项内容，CoreMod 当前定义为空，不生成初始方块、职业或配方修正。
要闻系统接口要闻 schema、运行态和存档接口保留；CoreMod 内容为空，不生成未在 NCDOCS 定义的随机事件、选项或效果。
派系、城邦与外交本体源码外交本体支持 Lua 注册开战／议和／贸易许可、不可移除的基础诉求、反议、双方状态与条约、存档同步和界面；战争与贸易可共存。城邦 AI 留空，新增源码未编译或运行。
战斗接口职业战斗属性、伤病/倒地/死亡和小队身份/成员状态摘要保留；专项文档未建立前不推进小队移动、接敌、命中、伤害、冷却、压制、阵型或区域法力，所有战斗命令无副作用拒绝，HUD 只显示接口未定。
本地化可用本体语言文件、CoreMod/MOD 翻译合并、UI 文本查询、Lua locale API 和运行时热重载已接入。详见本地化与翻译。
ECS 基础可用Archetype 存储、组件查询、实体 ID 代际和标准组件集可用；组件集合会随殖民者生存、选择和渲染状态继续演进，不以旧固定数量作为兼容承诺。
网络同步部分TCP Server/Client、Server 权威 UiCommand、命令结果、重连恢复、增量快照和 MOD 数据交换已实现；活体网络往返仍待显式验证。
控制台调试可用当前注册 75 个命令（另有 6 个内置别名），覆盖 MOD、数据、配方、实体、背包、阵营、网络、Lua 热重载、配置诊断和归档对比。

部分可用

这些系统已有核心代码或运行入口，但不应被 MOD 当作完全稳定承诺。

能力状态已实现未完成或风险
AI 行为 部分 TaskPool、TaskRegistry、A*、NavMesh/NavAgent、个人队列和来源结算接口。导航推进层只向实体下发局部 MovementTarget；实体运动层生成 MovementIntent 并据局部目标更新 Rotation；物理层消费意图后使用 PhysicsCollider 独立处理速度、体素/实体碰撞和权威位置。 搬运、施工、生产、饮食和治疗已接入事务闭环；未有专项规则的农业、巡逻、社交和战斗行为不生成默认玩法。
作物与农业 部分 data/crops schema 与加载接口已接入，CoreMod 提供 22 条作物定义；systems.farming 执行整地、播种、按地块速度与三档温度推进生长阶段，并结算成熟收获。 种植专项规则文档仍不完整；成长参数只来自作物记录本身的阶段上限、地块速度表和温度区间，引擎不生成额外默认值。
区域系统 部分 ZoneSystem、Lua engine.zone、矩形/3D 区域创建、查询、删除和版本化存档已存在；CoreMod 只注册露天仓储区和种植区。 露天仓储区已接入统一物品系统，种植区由 systems.farming 推进；旧居住、收获和采掘持续区域不存在。
建筑系统 部分 data/buildings schema、BuildingSystem、施工事务、工作点、存储点、治疗点、耐久、维修和版本化实例存档已接入。 NCDOCS 未给出其余建筑的具体形状、材料或工期；CoreMod 当前只有 core:workbench、core:crafting_spot、core:smoker 和 core:irrigation_tower 四条定义。
音频 部分 miniaudio 后端、SoundBank、data/audio 注册表接入、Lua engine.audio 播放/停止/音量 API 已存在。 CoreMod 仅含占位音效条目，实际音频资源尚未附带；3D 空间化和分组混音仍属实验层。
UI 系统 部分 玩家可见 UI 统一走游戏内 RmlUI：主菜单、HUD、暂停/设置、开发者控制台、小地图和全局提示由静态 RML/RCSS 文档驱动；经营类游戏内菜单通过 Lua 在 core:mod_ready 注册到底栏/窗口兼容层。旧即时模式/Lua 可见渲染层已移除。 Lua UI 兼容 API 已接入 RmlUI-backed 可见层，可显示底栏扩展、窗口/table/tabs_table、动态 RML 面板和浮动提示；MainMenuState 仍承载设置、暂停和世界创建状态。旧 CSS 主题后端不再应用样式，主题扫描只为旧配置兼容保留。
存档 部分 保存/加载框架、存档列表、原子写入、世界配置、天气、实体、文明研究、殖民者纪念记录、阵营、Job、工作资源预留、要闻状态和 MOD 差异诊断。详见存档系统现状。 存档依赖引擎版本和可解析的内容引用。自定义玩法数据可使用受管状态，格式与别名规则见 状态自动演进。
渲染与方块模型 实验 Vulkan 管线、Chunk 网格、纹理图集、BlockTextureRegistry 和多元素方块模型解析已实现。 渲染后端和复杂模型兼容性仍属于实验层，不作为 MOD API 稳定承诺。
体素地形与群系 部分 data/biomes 和 data/terrain 作为标准 mod_data 加载、校验并注册到 TerrainGenerator；支持权重、地表/次地表方块、地图颜色和默认地形方块。旧 data/ores 已移除，矿物由矿井规则提供。 世界生成整体仍属实验层，复杂装饰和脚本扩展契约还在收敛。

给 MOD 作者的建议

当前最适合开发内容型 MOD：方块、实体原型、配方、职业、文明、要闻、NPC 阵营、名称池、动作、地物、作物、建筑、群系、音频、本地化和少量 Lua 辅助逻辑。AI 高级行为和复杂 UI 扩展仍不建议作为强依赖；MOD 打包发布已有 Windows 流程。
