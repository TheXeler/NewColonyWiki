游戏内 RmlUI

游戏内 UI 的目标主路线是 RmlUI（HTML/CSS 风格、进程内渲染、合成进 Vulkan 画面）。本页记录它的依赖状态、资源入口、stub/真 backend 边界，以及把真 RmlUI 库接入构建的步骤。宿主层（RmlUiHost / RmlUiRuntime / RmlUiBridge）的接口与数据通道契约见 UI 框架 · 游戏内 RmlUI 宿主层。

引擎不再启动本地 HTTP server，不再以外部浏览器作为 UI 验收路径（ExternalBrowser / WebServer 已删除）。旧即时模式 UI 依赖也已从代码、构建和 vcpkg 依赖中移除。

当前状态（一句话）

玩家构建固定使用真实 RmlUI backend，构建系统无条件链接 RmlUi::RmlUi，在游戏窗口内绘制 main.rml 与副文档，并通过 RmlUiBridge 暴露通用数据模型与命令事件入口。NullRmlUiRuntime 只保留为显式诊断/失败回退路径；启用时会记录错误级日志且不渲染任何文档。

三层结构

组件文件职责
RmlUiHostEngine/UI/RmlUiHost.{hpp,cpp}引擎唯一集成点；持有后端与桥，暴露生命周期、输入、数据推送与命令消费。

RealRmlUiRuntimeEngine/UI/RmlUiRealRuntime.{hpp,cpp}真 RmlUI backend，玩家构建必编译；负责生命周期、主文档加载、输入、原始通道绑定、命令事件与最小 Vulkan RenderInterface。
RmlUiPanelRegistryEngine/UI/RmlUiPanelRegistry.{hpp,cpp}真 backend 的副文档注册表；集中声明并尽力加载 debug_input.rml、hud.rml、pause_menu.rml、global_toast.rml、dev_console.rml，以及仅 --DEBUG 可加载的 ui_lab.rml。旧的 minimap_zone.rml 不再加载，由战略世界地图悬浮窗替代。
RmlUiDataViewsEngine/UI/RmlUiDataViews.hpp + RmlUiDataBindings.cpp + RmlUi*DataViews.cpp面板 typed/derived view 边界；公开 API 仍由 RmlUiDataViews 提供，内部按领域拆到 HUD/Battle、Build/Research/Crafting、Colonists、Main Menu/Settings/Content Browser/Mod Manager、Minimap、DevConsole/Global Toast 和通用刷新胶水等实现文件。它集中注册与刷新 HUD 的 hud_* 字段、旧静态经营面板的派生数据、Minimap 的 minimap_status / minimap_tiles_rml，DevConsole 的 console_visible / console_history / console_input_rml / console_cursor_visible，全局命令反馈的 global_toast_visible / global_toast_rml，以及 UI phase 派生的 main_menu_visible / playing_visible / pause_visible / pause_menu_visible / settings_visible 与 settings_rows。
RmlUiBridgeEngine/UI/RmlUiBridge.{hpp,cpp}C++ ↔ 文档层双向数据/事件通道（快照 + 命令队列），与具体 backend 无关。

面板 runtime 边界

新增 RML 面板时，资源注册和 typed view 不再直接堆进 RmlUiRealRuntime.cpp。副加载文档（入口 main.rml 之外的面板/验证页）统一登记在 RmlUiPanelRegistry.cpp 的注册表中，保持“缺失不致命、主文档照常渲染”的加载语义。面板需要的结构化 DataModel 字段统一挂在 RmlUiDataViews.hpp 的同一个类上：RmlUiDataBindings.cpp 只保留 register_bindings() 的顺序调度，具体 struct/array/bind 注册、渲染、解析和刷新逻辑按领域拆到 RmlUiHudDataViews.cpp、RmlUiBuildCraftDataViews.cpp、RmlUiColonistDataViews.cpp、RmlUiMenuSettingsDataViews.cpp、RmlUiMinimapZoneDataViews.cpp、RmlUiConsoleToastDataViews.cpp、RmlUiLuaFragmentsDataViews.cpp、RmlUiTextDataViews.cpp 和 RmlUiCommonDataViews.cpp 等文件。refresh() 从原始 JSON 通道派生 typed view，并只 dirty 变更字段。

注册顺序契约：RmlUI 按类型名查表解析成员，因此 struct 成员若引用容器类型（如 ColonistEquipmentSlotView::bonuses 为 std::vector<ColonistBonusView>），对应的 RegisterArray<std::vector<T>>() 必须先于引用它的 RegisterMember() 调用；同理，作为成员或数组元素的 struct 类型必须先 RegisterStruct<T>()。任何一处顺序颠倒都会让 RegisterMember 静默返回 false，register_bindings() 随之失败，nc DataModel 创建不出来，真 backend 退回 null stub，主菜单与全部 RML 文档都不渲染。

RmlUiRealRuntime.cpp 仍保留稳定底座：创建 nc DataModel、绑定十二个原始 JSON 通道、缓存引擎推送的 UI 控制变量、处理通用 data-command / data-action click 事件、驱动 RmlUI 生命周期与 Vulkan 渲染。主菜单已迁到 RML 的完整页面 shell（Create World、Load Game、Multiplayer、Settings、Mod Manager、Content Browser、Wiki、Credits、Exit）；游戏内 HUD 底栏挂载 Lua on_load 注册的放置、伐木、采掘、区域、指令、制造、仓储、科技、招募、策略、日志和工作池槽位，并在实现阶段暂时增加人员列表。独立的“放置”入口先选择 placeable 方块，再复用通用 selection 划区、选择优先级/执行者并下达逐格 Build 工作；建筑设计不属于该入口，指令菜单也不再包含放置或建筑设计。人员详情使用角色菜单、个人信息、装备、转职和工作计划五个原生兼容层 Tab，各页操作只显示在对应 Tab 内；外层“返回人员列表”按钮通过兼容层按钮的 align="right" 元数据放在内容右下角，页签内按钮仍维持各自布局。通用药剂冷却槽的容量、占用、预留、逐槽剩余时间和容量来源显示在个人信息页，不归入治疗专属导航。运行中不显示难度入口。后续面板不得替换原始通道名契约；typed view 只能作为面板专用的附加绑定。

main.rml 是当前 RmlUI 主菜单入口文档，包含侧边导航、Create World、Load Game、Multiplayer、Settings、Mod Manager、Content Browser、Wiki、Credits 和 Exit 等页面/入口，不是浏览器网页布局。它还包含创建/读取世界共用的 world-loading 全屏遮罩，使用原生 <progress> 和 world_loading_state 快照复用启动进度条的视觉。快照按启动逻辑服务器、准备/恢复世界、初始化 MOD、建立初始殖民地、加载可见区块、生成食物/动物/世界资源、准备实体和初始化世界 UI 显示阶段提示；区块阶段额外显示 ready/total，实体阶段显示实体数。新世界的初始生态生成发生在可见区块就绪之后，并等待资源点导致的区块网格重建完成；读档不重复执行该阶段。加载期间 ui_phase 固定为 loading，HUD、世界输入和模拟推进保持门禁；只有服务器会话、初始殖民地、初始世界内容、相机可见半径内全部区块、实体渲染资源和 RmlUiHost::on_world_init() 后的数据刷新全部就绪，才切换到 playing。真 backend 由 RealRmlUiRuntime::load_document("main.rml") 加载；Null stub 下 load_document 返回 false（预期行为），但会记录请求的文档名与资源根用于诊断。

共享样式与 UI Lab

CoreMod/assets/ui/rml/shared/ 是独立 RML 文档的共享设计基础：base.rcss 提供 window/panel、section title、empty state 和 scrollable content；components.rcss 提供 title bar、按钮变体、tabs、list/table row、detail panel、meter 和 dialog overlay；layout.rcss 提供保守的行、堆叠和双栏布局。共享文件只使用项目现有 RmlUI 已验证的 RCSS 特性，不使用 CSS 自定义属性或 var()。页面通过多个 <link type="text/rcss" href="shared/..." /> 引入，再链接页面专用 RCSS；页面专用规则只处理页面几何和确有必要的差异。

ui_lab.rml 是真实 RmlUI backend 中的稳定设计预览，不读取世界、存档或 Lua 业务状态。它默认隐藏，普通运行不会加载；仅以 --DEBUG 启动时由 RmlUiPanelRegistry 加载。开发控制台使用 ui_lab、ui_lab show、ui_lab hide、ui_lab toggle 切换，也可用 ui_lab components 或 ui_lab tech_tree 直接打开指定场景。顶部场景可选择 Components 或 Tech Tree；Tech Tree fixture 覆盖完成、研究中、可研究、前置锁定、空列表和未选择详情，并且只通过 ui_lab_* typed binding 暴露给 DEBUG 文档。UI Lab 显示时不改变 ui_phase，只在自身窗口范围捕获指针；关闭按钮发送 core:ui_lab.hide。reload rml 会和其它副文档一起重新读取 UI Lab 及全部共享 RCSS，并保留重载前的显隐请求。

策划与 AI 协作使用 docs/ui-design-brief-template.md 声明布局树、状态、数据字段和命令 payload。图片只作为视觉参考，RML/RCSS 与结构化需求单才是实现契约。复杂兼容窗口迁移边界与顺序见 docs/ui-window-migration-assessment.md。

主菜单文本。ui_text 快照由 make_ui_text_json() 从引擎级 assets/lang/*.json 的 core:rml.* 键生成；Content Browser 分类标签使用同一位置的 core:content_browser.*。CoreMod 注册的 blocks、recipes、jobs 等内容翻译仍由 CoreMod/lang/*.json 承担，并在 MOD 加载阶段 merge。翻译缺失或值为空时会显示翻译键本身，避免 RML 绑定得到空字符串导致菜单只剩按钮背景。
字体：RealRmlUiRuntime::init() 只加载操作系统字体，不读取 CoreMod 或根 assets/ 下的字体资源。系统缺少候选字体时不会阻止启动，但文字可能显示为缺字方框。
字体家族名和字体样式必须精确匹配。RML 样式表统一写成单一家族名 Unicode，不要添加 CSS 风格的 fallback 列表。当前只以正体注册系统字体；不要使用 font-style: italic，除非运行时也注册相应系统字形。
dev 构建自动 staging：可执行文件按自身所在目录解析 core mod（EnginePaths::defaults() 令 base_dir = executable_dir()，故 core 路径为 <build>/bin/mods/core）。构建通过 stage_core_mod 这个 ALL 自定义目标复制整个 CoreMod/；当前命令带 CLEAN_DESTINATION=ON，会先清理 staged core 再复制，避免源码中已删除的内容残留。运行时只从可执行文件旁的 mods/core 读取 CoreMod，不回退到源码工作目录。复制逻辑由顶层 CMake 在配置时生成 CopyDirectoryExcludingGit.cmake，wiki 与根级 assets/lang 也有各自 staging/install 路径。

backend 选择

make_rml_ui_runtime() 工厂按以下顺序选择 backend：

条件返回
NC_UI_BACKEND=nullNullRmlUiRuntime（即使真 backend 已编译也强制 stub，便于无头/自动化运行）。
未设置 / 空 / rmlRealRmlUiRuntime（backend_name()=="rml-real"，is_real_backend()==true）。
真实 backend 初始化失败NullRmlUiRuntime stub（失败回退；不渲染文档，日志明确报错）。

Fallback：真 backend 的 init() 失败时，RmlUiHost::init() 会 shutdown 它并用 make_null_rml_ui_runtime() 替换，宿主层照常运行，游戏绝不因缺依赖崩溃。

接入真 RmlUI backend

vcpkg.json 已包含 rmlui 端口依赖（v6.3，默认 feature freetype，CMake 目标 RmlUi::RmlUi）。普通玩家构建会编译 RmlUiRealRuntime.cpp 并使用真实 backend。诊断/自动化场景如需禁用可见 UI，可设置 NC_UI_BACKEND=null：

  1. 常规 configure：cmake --preset export-release。第一次配置会让 vcpkg 安装/复用 rmlui[core,freetype] 及其依赖。
  2. 构建：cmake --build --preset build-export-release。构建脚本会 find_package(RmlUi CONFIG REQUIRED)、把 UI/RmlUiRealRuntime.cpp 加入编译并链接 RmlUi::RmlUi。
# vcpkg.json 片段
{
  "dependencies": [
    ...
    { "name": "rmlui", "version>=": "6.3" }
  ]
}

RmlUI 不是可关闭的构建选项；null stub 只通过 NC_UI_BACKEND=null 或真实 backend 初始化失败进入。

接口状态：RealRmlUiRuntime.cpp 使用 RmlUi 6.3 的 RenderInterface 签名（CompiledGeometryHandle、Span、Rectanglei、GenerateTexture 返回 texture handle）。升级后的构建与运行时验证由开发者按需执行。

数据模型与命令事件

RealRmlUiRuntime 在 RmlUI context 上创建名为 nc 的 DataModel。当前通用层把稳定通道全部绑定为 JSON 字符串变量：world_info、resource_snapshot、colonist_list、event_list、tech_tree、view_modes、orders_kinds、build_defs、craft_recipes、combat_state、construction_active、command_result，以及旧 Lua UI 兼容层的 lua_ui_bottom_bar、lua_ui_windows、lua_ui_floating、lua_ui_rml_panels。每帧 update 前，runtime 从 RmlUiBridge::latest_snapshot(channel) 读取最新值；缺通道或空字符串会暴露为 null，不会让文档层崩溃。变量变化时调用 DataModelHandle::DirtyVariable(channel)，由 RmlUI 在后续 Context::Update() 中刷新绑定。

RML 文档使用 data-model="nc" 后可直接绑定这些变量，例如 {{world_info}} 或 {{resource_snapshot}}。通用层始终保留原始 JSON 字符串绑定；特定 RML 面板可以在 RmlUiDataViews 内叠加最小 typed/derived view，但不得替换十二个通道名契约。command_result 也是同一个数据模型变量，由 Engine::dispatch_rml_ui_command() 写入桥后进入文档层。

全局命令反馈：global_toast.rml 是非 menu 阶段加载的全局副文档，用 global_toast_visible 和 global_toast_rml 在顶部中央显示最近一次需要注意的业务命令结果。Error toast 使用深红背景和红色侧边强调，确保在游戏画面上清晰可见。RmlUiDataViews 观察 command_result，按 waiting / blocked / error 分类成 warning / error / info 样式；成功结果对普通命令静默，避免菜单和普通点击刷出无意义的成功提示；但保存（core:pause.save）与加载（core:menu.load_game）属于玩家必须确认的里程碑结果，其成功也会作为 success 样式 toast 显示，对应文案来自 SaveResult::message。toast TTL 由 RealRmlUiRuntime::update(dt) 驱动，普通结果约 2.8 秒，错误约 4.2 秒。C++ 在写入 command_result 前追加 sequence 字段，保持原返回字段不变，同时让连续两条同形结果也能被识别为新事件。

按钮按压反馈：CoreMod 的主菜单、HUD、经营窗口、暂停/设置、科技与战斗界面统一使用 RmlUI :active 状态降低按钮透明度；原有按下配色仍可叠加，松开后自动恢复。游戏内底栏的页面入口统一使用 toggle 状态，重复点击当前高亮入口会关闭对应页面。

划区模式名称：HUD 的通用选区模式提示保留原始 designate_type_id 用于逻辑判断，同时通过区域定义的 name_key 生成已本地化的 designate_type_name。区域实例创建时也保存当时语言下的显示名称，不把 ${zones.*} 模板或 core:* 内容 ID 暴露给玩家。

持续区域表现与点击：shape_mode="2d" 的持续区域按地表平面渲染，不画一格高的六面体；3D/vertical 区域仍显示体积边框。2D 区域的可见平面参与世界射线拾取，并按实际区域格集合复核命中，所以储物区和种植区可直接点击选中；区域平面比其下方地形更近时优先，真正位于平面前方的实体仍保持实体选择优先级。选中后 HUD 摘要与管理入口继续读取同一稳定区域实例。

旧 Lua UI 可见层：LuaUi 现在保存完整注册定义，并把底栏槽位、窗口/table/tabs_table 内容和浮动提示渲染为已转义 RML 片段。hud.rml 通过 lua_ui_bottom_bar_rml、lua_ui_windows_rml、lua_ui_floating_rml 挂载这些片段；点击兼容按钮会发送 lua_ui:<handle>:... 内部命令，由引擎回调原 Lua on_click(ctx) / on_close(ctx) / on_click(row) / on_click(button) 后刷新兼容通道。table row 与 button 的回调 target 保持稳定，优先使用声明的 id，否则使用遍历位置，避免 5 Hz 快照刷新无意义重建 RML 并打断 hover 状态。engine.ui.window.register 和 engine.ui.rml.register_panel 都支持 background_argb 和 draggable，默认采用小地图同款 0xe815191d 半透明背景；窗口拖拽缺省跟随 flags = { "movable" }。engine.ui.rml.register_panel 额外通过 lua_ui_rml_panels 推送已校验的 document 路径、背景色和拖拽开关，真实 runtime 在同一个 RmlUI context 内动态加载/显示/关闭这些 MOD 面板文档，并为动态文档挂接与入口文档相同的命令和拖拽事件监听器。所有二级页面的纵向滚动区统一使用 overflow-y: auto，只有内容实际超过容器高度时才出现滚动条。科技树通过兼容窗口嵌入文档 body，HUD 入口显式加载其专用 RCSS；科技分类使用等宽横向栏，主体采用约 38/62 的列表/详情双栏并分别滚动，底部当前研究状态保持独立对齐。

经营问题：底栏“经营问题”入口只显示当前持续问题，不再混入结算日志或提供问题等级 Tabs。问题按来源显示原因、位置、关联对象和解决入口；点击带位置的问题使用 engine.view.focus_world 定位，双击可调用已声明的解决入口。新增或关键状态发生变化的全局警报和普通警告会分别以 [EconomyProblems][global-alert] 与 [EconomyProblems][warning] 写入 DEBUG 控制台；带世界位置的持续问题仍通过 engine.view.project_world 驱动本地警告气泡，解除后气泡与全局警报自动消失并留下内部经营日志记录。

生产、治疗与招募操作面板：制造菜单只创建殖民地全局生产订单，不再直通制作。其生产管理入口显示订单来源/模式、目标与过滤、缺额、尾单、优先级、指定者、兼容点、材料和停工状态，并提供目标、维持库存、最低品质、暂停和取消操作；同一面板的工作点视图显示输入/输出暂存、当前工作与执行者、道路/内部路径、兼容配方、上次结果和定位。治疗/招募面板显示治疗点容量和状态、患者阶段、治疗模板按每种伤病/状态分别配置的食物/药品/医疗包条件、个人药品槽及科技来源，以及五级招募的具体付款选择、实际付款、退款预览、候选确认和待入场状态。科技界面同步显示付款来源、累计进度、参与者、工作点和单元状态；暂停提示已付款与进度永久保留，且不提供取消入口。

设计方案：生产入口的设计面板分别承载锻造和药剂。锻造页从已解锁物品基型选择基础属性与词条最终等级，持续显示容量、难度、材料、有效性和错误；载入旧方案后保存会产生新方案。药剂页选择等级、剂型和逐味药材，显示每味与累计四性、固定材料、预计效果和最终 CD；缺药材/性状内容、许可、科技或容量时显示原因并禁用保存。空内容表保持空，不生成演示默认条目。

人员策略与候选详情：工作计划和排班页支持模板创建、复制、重命名、六类开关、24 小时时段及共同分配。殖民者可覆盖单个工作开关或小时，再清除覆盖回到实时关联模板。人员详情中的属性摘要、工作来源、装备槽、职业等级、属性修正、排班状态和模板列均通过 CoreMod/lang/*.json 的 core:colonists.* 键本地化。招募候选选中后除列表摘要外，还显示完整经历、属性修正、倾向、当前状态、职业履历及招募等级来源。

确认与禁用：狩猎和建筑确认都提供特级/1-9级与当前合格指定者选择，指定者按职业、工作计划、排班和当前目标路径筛选。采集、采掘和区域拖拽松开只更新确认预览，不立即提交；采集/采掘确认把逐目标命令发给 Host，区域确认携带类型和边界由 Host 创建，随后工具保持激活。采掘指示只在采掘工具激活时绘制，按六向连通区域合并为整体外框并叠加淡黄色半透明表面，退出采掘模式后既不保留边框也会把被隐藏的目标体素按原样恢复渲染，采掘模式内的鼠标方块射线忽略已经由采掘覆盖隐藏的方块，并在相机位于实体层内时先穿出不可见的起始实体段再命中实际显示表面。配置无效或过滤目标不可达成的生产来源不能从双击或确认按钮下单；招募付款必须同时达到营养与金币要求。仓储 UI 只能修改既有策略的过滤、入库/取用优先级和保留状态，坐标、容量、冷藏由 Host 保留，也不提供绕过区域删除确认的直接策略删除。进食方案同时明示整库保留排除和营养溢出后比较实际路径的选择顺序。建筑和区域工具保持到右键或 Esc 退出；采集和采掘只以 Esc 退出，右键仍旋转镜头。

视觉反馈：全局命令提示按信息、成功、警告和错误使用独立的高对比背景色；游戏内底部菜单使用不透明度更高的蓝黑面板背景和底边层次，选中对象的问题提示也使用独立的暖色提示底。

仓储、策略与矿井操作面板：仓储入口显示仓储位置/容量、物品明细、预留、品质、腐坏、冷藏和待清运状态，可修改入库/取用优先级、整库保留及物品/分类/标签过滤；策略入口聚合进食方案、治疗模板、工作计划与排班，其中进食方案支持创建、复制、重命名、分配以及营养、品质、腐坏、风险和食物过滤。矿井面板从指令入口打开，会先显示当前选中或悬停区块天然可见的矿物与丰度，即使该区块尚未建矿；已有矿井另显示剩余量、道路、执行者、输出待清运和问题，并可启停与定位。规则或难度表为空时显示配置屏障。

世界创建难度：Create World 从唯一 difficulty_rules 记录动态显示数据定义的预设；展开自定义后分别选择资源丰度、矿井耗尽、环境状态、需求、袭击、死亡和恢复窗口档位。预设与选项名称在引擎生成界面快照时按 label_key 本地化。缺失、重复或无效难度表会显示配置屏障并阻止开档，不会采用代码默认难度；CoreMod 当前提供一组中性测试难度用于系统验证，不代表正式平衡方案。选择结果在世界初始化前写入运行时状态，随存档与 Host 运行时状态同步。

地面物品与区域管理：地面物品详情读取当前选中或悬停体素，显示实例名称、数量、归属、腐坏/消失计时、回收授权、问题、来源和关联日志数量。允许/禁止自动回收通过 Host 命令修改；禁止时立即取消该实例尚未提交的回收工作并释放其预留。区域管理面板在打开时绑定当时选中的区域实例，之后不再跟随选中或悬停变化，当前只显示一个带二次确认的“删除区域”按钮。确认命令仍在 Host 上重新核算影响，取消未提交工作和目标格预留、移除露天仓储策略后才删除区域，已结算结果不回滚；删除成功后该窗口立即自行关闭，不再回退到“选择或悬停一个区域”之类的空态占位，该占位文案已从语言文件中移除。区域实例因重叠划区被清空而消失时，窗口同样按 zone/management 数据变化事件关闭。

Lua 窗口文本输入：通用 table 行支持 kind = "input_text"、当前值和 on_change(value)。兼容层渲染真实 RmlUI input，change 事件把当前 UTF-8 值送回稳定 Lua action callback。进食方案重命名使用该路径，不再生成占位名称；蓝图等既有 input_text 行也复用同一契约。

列表绑定约定：当前 RML 静态文档不直接在循环体内写 data-for 别名字段（例如 {{def.id}}、data-attr-data-param-id="def.id"）。RmlUI 6.1 的当前 Windows/vcpkg runtime 在启动加载阶段会把这些循环体当作普通静态元素解析，导致别名变量解析诊断。列表仍由 RmlUiDataViews 的 typed views 维护；C++ 从 typed rows 生成已转义的 RML 片段，暴露为 *_rml 字符串（如 build_defs_rml、research_nodes_rml、console_history_rml），RML 文档用 data-rml="..." 挂载。空数组输出空字符串，仍由 *.size == 0 的静态空态控制；未知状态只作为普通文本写入；按钮行写最终 data-command 与 data-param-* 属性，继续走同一个 context 级命令监听器。

除十二个业务通道外，runtime 还缓存一组UI 控制变量（与业务通道分开维护，不参与和 ScriptEngine/Lua 的数据契约）。当前有 ui_phase（取值 "menu" / "playing" / "pause" / "settings"），由引擎每帧按世界、暂停菜单和设置 shell 状态推入桥；RmlUiDataViews 将它暴露为 typed binding，并派生 main_menu_visible、playing_visible、pause_visible（pause 或 settings 都为真，控制遮罩背景）、pause_menu_visible（仅 pause 为真，控制按钮列表本身）、settings_visible（仅 settings 为真）与 settings_rows。ui_font_size 同样由引擎从用户设置推入桥，真 backend 会把它夹在 12-20 px 并应用到主文档、副文档和动态 RML panel 的 #ui-root body 上；默认值为 15 px。RML 文档使用这些布尔派生变量做 data-if，避免依赖字符串表达式兼容性。

文档到引擎的通用命令入口是 context 级 click 监听。监听器从事件目标向父级查找 data-command 或 data-action，找到后向 RmlUiBridge::enqueue_command({target, payload}) 入队。payload 规则：若元素带 data-payload，其内容作为 JSON 字符串原样入队；否则把所有 data-param-* 属性打包成简单 JSON 对象，例如 data-param-id="x" 会产生 {"id":"x"}。onclick 属性也作为 target fallback 读取，便于迁移旧写法；推荐新 RML 使用 data-command。

通用浮动面板拖拽：真实 backend 在同一个 context 级鼠标监听器里支持声明式拖拽。可移动的绝对定位面板声明 data-drag-panel="panel-id" 和 data-draggable="true"，其标题栏或其它拖动手柄声明 data-drag-handle="panel-id"；设为 data-draggable="false" 可禁用。左键按住手柄时 runtime 会把面板转换为内联 left/top 定位并在鼠标移动时更新位置，同时清掉 right/bottom，位置会被限制在当前 RmlUI viewport 内。该机制只改变 RmlUI 元素样式，不经过 RmlUiBridge 命令队列，也不会持久化到用户设置；需要跨会话保存时再把最终位置提升为 Engine-owned UI control state。

Pause / Settings MVP

pause_menu.rml 是当前最小暂停与设置入口。真 backend 加载 main.rml 后由 RmlUiPanelRegistry 尽力副加载 pause_menu.rml；文件缺失或解析失败不影响主文档。Null stub 只在显式诊断/失败回退路径下存在，不加载文档。

引擎继续使用既有 MainMenuState::pause_visible 与 TickManager::set_paused()。游戏中按 Escape 会打开/关闭暂停菜单；暂停菜单可见时，普通游戏快捷键和相机更新不会继续处理。RmlUI 按钮使用引擎拥有命令：core:pause.resume 取消暂停并返回游戏，core:pause.save 打开保存栏位选择对话框（“保存为新存档”或从已有存档列表选一个覆盖，由 core:pause.save_confirm 携 slot/name 执行、core:pause.save_cancel 关闭），确认后用选定槽位发起后台保存；core:pause.load_game 弹出确认对话框（core:pause.load_confirm_ok / core:pause.load_confirm_cancel），确认后在无保存任务运行时卸载当前世界并打开主菜单 Load Game 页，core:pause.settings 保持暂停并切到设置 shell，core:pause.return_menu 清掉暂停状态并调用 return_to_main_menu()；该路径会先停止模拟线程并自动保存当前世界，再清理世界资源，避免卸载期间并发访问已销毁对象。core:pause.quit_game 调用 request_exit()。

Pause / Settings typed view 由 RmlUiDataViews 提供：ui_phase、pause_visible、pause_menu_visible 和 settings_rows。文档布局上 #pause-overlay（暗色遮罩）在 pause 和 settings 阶段都显示，body 与遮罩显式铺满 RmlUI 视口，当前可见面板用 left/top: 50% 和负 margin 做绝对居中；#pause-menu（Resume/Save Game/Load Game/Settings/Return to Main Menu/Quit Game 按钮列表）只在 pause_menu_visible 为真时进入布局，#settings-shell 只在 settings_visible 为真时进入布局，两者互斥，避免设置阶段按钮列表与设置 shell 同屏重叠。Interface 设置页包含语言、UI scale、Font Size、主题和基础显示开关；font_size 会保存到用户设置并通过 ui_font_size 控制 RML 默认字号。

互斥派生变量的由来。先前 #pause-menu 与 #settings-shell 都用 pause_visible / settings_visible 控制，而 pause_visible 在 settings 阶段也为真，结果两块同尺寸的绝对定位面板在设置阶段同屏重叠绘制。新增只在该相位为真的 pause_menu_visible，让按钮列表与设置 shell 互斥：#pause-menu 改用 data-if="pause_menu_visible"，遮罩继续用 pause_visible。这是 RML/typed-view 层的小修，不改动 Escape 路径或暂停状态机。

Minimap Panel

minimap_zone.rml 与 minimap_zone.rcss 作为旧资源保留，但不再由 RmlUiPanelRegistry 加载。ui.world_map 在 on_world_init 阶段自动注册不可关闭、可拖动和缩放的战略世界地图悬浮窗及城邦列表，不再向 HUD 底栏注册地图按钮。地图格发送 core:world_map.select_start_site；Client 经网络提交，Host 验证 q/r 确实存在于地图快照后持久化选址，不在 UI 层补写地点合法性、初始人数或物资规则。

HUD / Resource Bar MVP

hud.rml 是当前最小游戏内 HUD。真 backend 加载 main.rml 后由 RmlUiPanelRegistry 尽力副加载 hud.rml 到同一个 RmlUI context；文件缺失或解析失败不影响主文档。Null stub 只在显式诊断/失败回退路径下存在，不加载文档、不解析 HUD 数据。

HUD 右上角日期时间区消费 nc 数据模型中的派生字段：hud_day、hud_year、hud_season 与 hud_time。资源条继续消费 hud_resource_count、hud_resources 与用于挂载资源行的 hud_resources_rml；其中 hud_resources 是 { id, label, amount } 结构数组，当前最多展示前 16 行资源，hud_resource_count 仍保留原始资源总数。资源行可点击打开对应物品的仓储摘要，显示总量、可用量、预留量、来源和腐坏范围。右侧 economy_alerts 区直接显示现有全局持续问题的聚合计数，点击打开已按问题筛选的经营问题面板。左下角 selection_summary 面板从当前可见实体快照或所选体素读取名称、归属、状态和首要经营问题；多选显示数量、同类/异类及共同归属。选中工作点坐标时额外显示类型、道路、当前工作、执行者、输入暂存和输出待清空状态，并把管理按钮直接落到生产面板工作点页；殖民者、区域和地面物品仍分别进入各自完整面板。左上角资源条和右上角日期/倍速条使用与小地图一致的半透明深色面板背景。底部命令栏位于屏幕正下方，提供经营主入口和专项系统的状态跳转，详见下文 底部栏入口 小节。

制造窗口的配方选择使用两级下拉筛选：第一层按职业族 career_id 聚合，第二层选择该职业下的具体职阶，并继续以完整职业 ID 匹配配方要求。通用配方、锻造设计和药剂设计作为职业层的独立类别。Lua UI 下拉框显式设置 selectvalue、selectarrow、selectbox 和 option 的背景、边框、悬停及选中样式。

伐木和采掘是底栏独立入口，直接进入对应的一次性选择工具；区域入口打开持续区域二级菜单。指令入口承载建筑、狩猎、取消工具和其余专项状态跳转。运行中不显示难度入口，难度调整只发生在新建世界阶段。

HUD 字段来源通道转换规则
hud_day / hud_yearworld_info读取 JSON 中的 day、year 整数字段。
hud_seasonworld_info优先从 season_key（如 core:season.spring）取后缀并首字母大写；缺失时按 season 序号 fallback。
hud_timeworld_info读取 tick_of_day，按 DAY_TICKS_PER_DAY=86400 格式化为 24 小时 HH:MM。
hud_resourcesresource_snapshot读取数组项的 label（缺失则用 id）与 amount。

当前限制：通用业务通道仍以原始 JSON 字符串暴露；HUD 在 RmlUiDataViews 内对时间、资源、经营警报和选择摘要做最小 typed/derived 转换。解析是容错的：字段缺失或类型不匹配时保留默认值或已有值，避免 HUD 因单个字段异常消失。

主菜单（Main Menu MVP）

主菜单直接画在 main.rml 内（不开新文档、不依赖已移除的即时模式 UI 或浏览器）。面板包在 <div id="main-menu" data-if="main_menu_visible"> 里：引擎进入世界后 ui_phase 变为 "playing"，main_menu_visible 变为 false，面板自动从文档布局中移除；回到主菜单（世界卸载）后又自动出现，无需额外开关。当前主菜单是右侧栏导航 + 左侧页面内容结构，提供 Create World、Load Game、Multiplayer、Settings、Mod Manager、Content Browser、Wiki、Credits 和 Exit。非世界态的主菜单及其所有二级页面在主循环末尾固定按 60 FPS 限帧；世界内继续使用 Graphics 设置里的 Render FPS Limit。

可见性是 UI 行为，不是开始游戏的判定条件。世界是否在运行始终由 m_world_active 决定；ui_phase 只是把同一事实镜像给文档，让面板显隐。若点击 Start World 后世界生成出现的问题，属于既有世界生成流程，与 RmlUI 无关。
主菜单不可见的两个历史根因（已修复）。其一，RmlUI 的字体家族匹配要求 RCSS 名称与注册名称一致；当前所有文档统一使用 font-family: Unicode，真 backend 在 Windows 或 Linux 上加载可用的系统 Unicode 正体，并以 Unicode 家族名注册。其二，RmlUI 给出的顶点是左上原点的屏幕像素坐标，rmlui.vert 必须按 Vulkan 正高度视口直接映射纵向坐标；旧 OpenGL 式翻转会令整张 UI 上下颠倒。
Start World 真人端到端复验。ON 构建启动后主菜单可见、文字正向；点击「Start World」按钮会发送 core:menu.new_game，日志依次出现主菜单 New Game 请求、[World] start_new_world(...) 与 [World] World started，随后 ui_phase 由 menu 切到 playing、main_menu_visible 变为 0，主菜单按预期隐藏。本轮没有再出现 integer value will be misrepresented in lua，世界成功启动；Lua seed 修复点暂未触发新阻断，留待世界内进一步观察。
副面板空态字体约束（已修复）。建造/制造/研究/殖民者等副面板的空态占位文本曾使用 font-style: italic，但 runtime 当前只注册系统正体。空态文字已统一改回正体并用颜色区分层级，避免请求未注册的斜体字形。
可见性诊断。RealRmlUiRuntime 在每次文档加载后会输出一行 [RmlUi][vis]，报告 #main-menu 是否在布局中、它的偏移尺寸与按钮尺寸；RmlUiDataViews 在 ui_phase 每次变化时输出一行派生结果（main_menu_visible/playing/pause/settings）；render() 首帧会输出一行确认主文档可见与渲染尺寸。这些都是低噪声、只在加载或相位变化时各一行，便于以后主菜单再次回归时从 latest.log 直接定位是「面板没进布局」「没被绘制」还是「相位派生错」。

开发者控制台（DevConsole MVP）

开发者控制台的可见 UI 已迁移到 RmlUI：CoreMod/assets/ui/rml/dev_console.rml 与 dev_console.rcss 作为副文档由 RmlUiPanelRegistry 加载，文档本身常驻，显示条件由 typed view console_visible 控制。控制台只在以 --DEBUG 启动时启用；这不是 NEWCOLONY_DEBUG 编译宏门禁。打开入口只监听物理 grave/backtick 键（GLFW scancode 41，同时兼容运行时 glfwGetKeyScancode(GLFW_KEY_GRAVE_ACCENT) 与 GLFW_KEY_GRAVE_ACCENT），但当 RML 控件有键盘焦点且控制台尚未打开时不抢占文本输入。字符输入事件不再切换控制台，切换键产生的字符会被吞掉，避免反引号落入输入框或控制台命令行。再次按下同一物理键会关闭控制台，不提供标题、关闭按钮或运行按钮，也不把 ESC 作为控制台关闭键。

数据绑定由 RmlUiDataViews 提供：console_input / console_input_rml 显示当前伪输入文本，console_cursor_visible 驱动输入行末尾光标闪烁，console_history 暴露最近提交的命令文本与新增日志，console_history_rml 挂载历史行，console_last_result 暴露最近一次提交状态，console_visible 控制面板是否进入布局。控制台不使用 RmlUI 原生 <input> 或 form；RealRmlUiRuntime::handle_input() 在控制台可见时拦截 key/char 事件并写入 DevConsole。Enter 执行当前命令；Ctrl+Enter 或 Shift+Enter 在伪输入中插入换行。历史输入行只显示 > 提示符，输出和日志行不显示 OUTPUT 等文字前缀。历史回显会在控制台面板内自动换行，不再横向溢出。

开盖即输入：按物理 grave/backtick 键调用 DevConsole::open() 置可见后，键盘输入由引擎直接送入 DevConsole 的伪输入状态，不需要 RmlUI 焦点，也不会进入 RmlUI 原生表单控件路径。控制台伪输入使用已注册的系统 Unicode 字体显示 console_input_rml，并在底部输入条内用固定宽度布局和末尾光标避免文字顶出屏幕。RmlUiPanelRegistry::update_console_focus() 会在打开跃迁时重新 Show() 控制台文档，并输出 [RmlUi][console] pseudo input active on console open。

Escape 不再和控制台绑定：控制台可见时按 ESC 只走既有游戏输入路径，不会关闭控制台；反过来，控制台的开关只由物理 grave/backtick 键负责。控制台可见时 wants_mouse 返回 true，并且普通 action 查询会被屏蔽；RML 文档包含全屏拦截层，所以控制台打开后会覆盖并吸收 HUD 资源栏、时间栏等提示区域的点击。Null backend 或未以 --DEBUG 启动时，控制台不初始化，物理 grave/backtick 键不会改变控制台状态。

历史 Pause / Settings / DevConsole 验证记录。当时的调试构建确认 real backend、主文档、副文档与数据模型绑定能够初始化。当前字体加载方式是操作系统提供的 Unicode 字体，不打包项目字体。主字体以 Unicode 家族注册；中文候选字体保留各自的系统家族名并加入 fallback 链，避免 RmlUi 6.3 把相同字重的字体当作 Unicode 重复 face 而丢弃。
键盘 / 鼠标交互未自动化复验。该运行环境下向运行中的游戏窗口注入键盘 / 鼠标（SendKeys、keybd_event、PostMessage WM_KEYDOWN、SendInput）均未触发 Escape 暂停或 ~ 开盖的相位变化（与既有「RmlUI 合成点击无响应」记录一致，根因是后台启动窗口拿不到真实键盘焦点）。因此 Pause/Settings 按钮、Escape 开合、~ 开盖、DevConsole 输入与 history row 的端到端点击 / 按键回路本轮未取得自动化证据，留待干净桌面环境真人复验。本轮以代码审查 + 日志 + 双构建验证这三条可靠信号定位并修复了两个确定问题：DevConsole 开盖不自动聚焦输入框（m_focus_input_next_frame 在渲染迁移到 RmlUI 后变成死代码），以及 Pause 菜单与 Settings shell 在 settings 阶段同屏重叠。

渲染路径（RenderInterface）

RmlUI 通过 Rml::RenderInterface 把文档几何交给宿主渲染后端。真 backend 当前实现了最小 Vulkan path：RmlUI compiled geometry 上传到 host-visible VMA 顶点/索引缓冲，纹理通过 VulkanTexture 上传并绑定 descriptor，支持 scissor，RealRmlUiRuntime::render(VkCommandBuffer) 会在 renderer UI callback 中调用 context->Render() 并录制 draw call。RmlUI 释放 compiled geometry 或 generated texture 时，backend 不会立即销毁 Vulkan 资源，而是按帧延迟回收，避免页面切换、输入框聚焦和 caret/文本重排期间上一帧 command buffer 仍引用已释放的 buffer、image view 或 sampler。

接入点：

  • Renderer::add_ui_render_callback() 维护 UI draw 回调链；旧 debug/UI overlay 已禁用，RmlUI 是唯一目标 UI 渲染路径。
  • Engine.cpp 在 RmlUI host 初始化后追加 m_rml_ui_host.render(cmd)，不启动浏览器、不走 HTTP/WebServer。
  • CoreMod/assets/shaders/rmlui.vert / rmlui.frag 由现有 MOD shader 预处理生成 SPIR-V。RmlUi 6.3 提供的顶点颜色和生成纹理都是预乘 alpha，Vulkan 管线因此使用 ONE / ONE_MINUS_SRC_ALPHA 混合，不能再用 SRC_ALPHA 重复乘 alpha。

当前渲染路径支持 compiled geometry、生成纹理、通过 stb_image 加载文档图片、scissor 和按帧延迟回收 Vulkan 资源；主菜单、HUD 与业务副面板均走此路径。复杂 effect、clip mask 和 render-to-texture 仍不是稳定能力。文本依赖运行平台提供的系统 Unicode 字体；候选字体均不可用时会记录警告，文字可能显示为缺字方框。

顶点坐标约定：RmlUI 供应的顶点是屏幕像素坐标（原点在左上、纵向向下），rmlui.vert 用 push constant 里的视口尺寸把它映射到 Vulkan 裁剪空间。Vulkan 视口同样原点在左上、纵向向下且高度为正，因此纵向分量必须用直接映射（像素 / 视口 × 2 − 1）；若误用 OpenGL 的翻转写法，整张 UI 会上下颠倒——topbar 落到窗口底部、主菜单跑到下方、字形头朝下。

输入路由与焦点捕获

InputManager 是 GLFW 输入入口。初始化 RmlUI host 后，Engine 会把 RmlUiHost 指针交给 InputManager；每个 GLFW 回调先注入 RmlUI，再保留现有游戏输入状态，游戏侧随后通过 ui_wants_mouse() / ui_wants_keyboard() 决定是否处理相机、选择、建造和快捷键。

GLFW 事件RmlUI 调用说明
cursor positionContext::ProcessMouseMove(x, y, modifiers)窗口坐标直接传入 RmlUI context。
mouse buttonProcessMouseButtonDown/Up(button, modifiers)GLFW left/right/middle button index 与 RmlUI button index 对齐；按钮回调会即时读取 glfwGetCursorPos()，避免使用过期的 cached cursor position 点击到旧坐标。
scrollProcessMouseWheel(Vector2f(dx, -dy), modifiers)水平滚轮保留 GLFW delta；垂直滚轮取反，因为 GLFW 正值表示向上滚，而 RmlUI 正值表示内容向下滚动。
key press/release/repeatProcessKeyDown/Up(key_identifier, modifiers)按键通过 GLFW key 映射到 Rml::Input::KeyIdentifier。
charcore:text_input.text用于引擎伪输入；真 backend 不再调用 RmlUI 原生 ProcessTextInput()，控制台反引号打开逻辑会吞掉对应字符，避免误输入。

Key 映射覆盖字母、数字、F1-F24、Escape/Enter/Tab/Backspace/Space、方向键、Home/End/Page、Insert/Delete、锁定键、左右 Shift/Ctrl/Alt/Super、数字小键盘和常用 US 符号键。Modifier 由 GLFW mods 与当前按键状态合并，映射到 RmlUI 的 Ctrl/Shift/Alt/Meta/CapsLock/NumLock 位；窗口启用 GLFW_LOCK_KEY_MODS 以便 GLFW 在支持的平台上提供 CapsLock/NumLock 状态。

捕获规则：当鼠标按下起点位于实际 UI 交互区域，或光标 hover 在按钮、带 data-command/data-action/onclick 的元素、输入控件、或计算样式为 pointer-events:auto 的非 rml/body 区域内时，wants_mouse=true，游戏不处理鼠标点击、拖拽和滚轮驱动的选择/相机逻辑；只用于覆盖展示的 HUD 壳层应保持 pointer-events:none，不会阻挡右键相机拖拽。当 RmlUI 有焦点元素时，wants_keyboard=true，游戏不处理文本输入和冲突快捷键。按 Escape 时，如果 RmlUI 当前持有键盘焦点，Engine 优先调用 RmlUiHost::clear_focus()，不触发暂停菜单/取消建造等游戏动作。Null backend 下所有输入安全忽略，wants_mouse 和 wants_keyboard 始终为 false。

DEBUG HUD 诊断叠层（debug_input）

debug_input.rml 是 F3 DEBUG HUD 诊断叠层（样式见 debug_input.rcss）：位于左上角资源栏下方，半透明、只读（pointer-events:none），不是业务面板，不承载主界面/主菜单/Settings/Content Browser/底部 HUD 功能，也不阻挡相机与 HUD 输入。内容由 Engine 每帧采集，经 debug_snapshot 桥通道（engine-owned，独立于业务十二通道契约，不经 Lua/ScriptEngine）推送到 RmlUiDataViews 的 debug_hud_rml typed view，文档用 <div data-rml="debug_hud_rml"> 绑定渲染。采集分七块：性能、模拟、历法、天气、相机、世界、种子/星球参数。

RealRmlUiRuntime::load_document() 在加载主文档 main.rml 之后，会让 RmlUiPanelRegistry 尽力副加载 debug_input.rml 到同一个 context。RmlUI 天然支持单 context 多文档叠加；验证面板默认隐藏，单按 F3 与 debug HUD 一起请求切换，但实际文档只在非 menu 阶段显示。文件缺失或解析失败属于非致命错误：日志里会出现 [RmlUi] debug_input.rml not available at '...'，主文档照常渲染。Null stub 不触发可见文档路径。

F3 日志分两层：Engine 层记录请求，关键词是 [Engine] F3 toggle、debug_hud_visible、rml_debug_panel_requested_visible、phase；RmlUI 层记录实际文档 show/hide，关键词是 [RmlUi][debug] document show / document hide、requested_visible、actual_visible、phase。F3+N / F3+B / F3+G / F3+L / F3+E 属于组合调试快捷键，不触发普通 F3 面板切换；其中 F3+G 只显示镜头当前区块从地面到地形生成高度的四条垂直边角线，不再铺开多区块地面网格。DevConsole 输入框持有 RmlUI 键盘焦点时，F3 不进入普通调试 HUD/面板切换分支。

生命周期

  • init：RmlUiHost::init(doc_root, w, h) 创建 backend；真 backend 调 Rml::Initialise()、CreateContext("main", ...)，尝试加载字体。
  • load_document：入口文档 main.rml（相对 doc_root）；真 backend 解析为绝对路径后 context->LoadDocument() 并 Show()。
  • update / resize：每帧 context->Update()；窗口尺寸变化且 framebuffer 为非零尺寸时调用 context->SetDimensions()。窗口最小化或 Vulkan surface 暂时报告 0 extent 时，Renderer 暂停 swapchain recreate/acquire/present 并等待恢复，RmlUI 不接收 0×0 尺寸。
  • handle_input：鼠标移动、按钮、滚轮、键盘按下/释放和文本输入都经 RmlUiHost 转发到 backend；真 backend 按 RmlUI 6.3 API 调用 ProcessMouseMove、ProcessMouseButtonDown/Up、ProcessMouseWheel 和 ProcessKeyDown/Up。文本字符不再调用 RmlUI 原生 ProcessTextInput，而是投递到引擎伪输入命令。
  • shutdown：RemoveContext + Rml::Shutdown()。真 backend 的 Vulkan 资源（管线、描述符池、纹理，以及 Rml::Shutdown() 触发释放的编译几何顶点/索引缓冲与纹理）随 backend 一起在 RmlUiHost::shutdown() 内释放，时机早于 Renderer::shutdown() 销毁 device，因此 RmlUI 侧不存在 device 失效后释放的风险。
  • shutdown 的 GPU 排空约束：RmlUiHost::shutdown() 在 Engine::shutdown() 中位于 Renderer::shutdown() 之前调用，而 Renderer::shutdown() 才是引擎在退出阶段第一次排空 GPU 队列（vkDeviceWaitIdle）的地方。这意味着 RmlUI 释放资源时，最近一帧记录了 RmlUI 绘制的 command buffer 可能仍被 GPU 占用，其引用的顶点/索引缓冲、纹理 image view、sampler、管线会被 validation 层标记为"仍被 command buffer 使用"。运行中释放的 geometry 和 texture 进入按帧延迟回收队列；shutdown 时真 backend 在 RealRmlUiRuntime::shutdown() 入口、于 Rml::Shutdown() 之前调用 vkDeviceWaitIdle(renderer device)，并在 VulkanRmlRenderInterface::shutdown() 入口再排空一次（覆盖 backend 重建等独立析构路径），保证 GPU 不再持有 RmlUI 资源引用后才开始销毁。null stub 没有 Vulkan 资源，不受影响。

退出顺序约束（引擎级，非 RmlUI 自身）：历史上短启动退出末尾的 0xC0000005 曾被怀疑为 RmlUI shutdown，实际根因在 mod 生命周期回调：mod 的 on_world_init/on_tick/on_shutdown 回调捕获了指向 Lua 函数的引用，其析构会回访 Lua 状态。因此这些引用必须在脚本引擎关闭 Lua 状态之前释放。ModLoader::release_lua_references() 在 Engine::shutdown() 关闭脚本引擎之前清空回调向量，确保 ~ModLoader 析构时不再触达已关闭的 Lua 状态。RmlUI shutdown 本身顺序正确，无需为该崩溃调整。
