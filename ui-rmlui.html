游戏内 RmlUI

游戏内 UI 的目标主路线是 RmlUI（HTML/CSS 风格、进程内渲染、合成进 Vulkan 画面）。本页记录它的依赖状态、资源入口、stub/真 backend 边界，以及把真 RmlUI 库接入构建的步骤。宿主层（RmlUiServer / RmlUiRuntime / RmlUiBridge）的接口与数据通道契约见 UI 框架 · 游戏内 RmlUI 宿主层。

引擎不再启动本地 HTTP server，不再以外部浏览器作为 UI 验收路径（ExternalBrowser / WebServer 已删除）。旧即时模式 UI 依赖也已从代码、构建和 vcpkg 依赖中移除。

当前状态（一句话）

创建世界的种子输入

种子栏使用 RmlUI 原生 input type="text"，沿用现有位置与外观，空值通过本地化 placeholder 显示“自动生成”。光标移动、选择、退格、删除及复制粘贴由原生控件处理，系统剪贴板由 RmlUI SystemInterface 接到 GLFW；不再使用按钮和种子专用的字符编辑状态。

change 事件经 data-change-command="core:world_config.seed" 提交完整的 value 字符串，沿用 create_world_config 快照与 main_menu_seed_text 绑定。种子不经浮点数转换，接收端检查完整十进制文本及无符号 64 位范围；空值或 0 保持自动生成语义。输入栏最多容纳 31 个字符；非法文本或越界值显示本地化错误，禁用开始按钮，创建命令也独立拒绝该状态，直至输入被修正。无效草稿不会覆盖已接受的种子或写入设置。有效种子继续由现有 world_seed 设置与世界初始化路径保存和使用，未新增世界存档字段。

公共 payload_u32_value 同时接受 JSON 整数和十进制字符串，拒绝负数、小数、越界及不完整转换，修复数字字符与编辑按键被解析成 0 的问题。原生表单控件获得焦点时，编辑按键不再同时发送给旧菜单字符编辑逻辑。

创建世界的名称输入

世界名称栏也使用原生 input type="text"，保留原有布局与外观，支持光标定位、文本选择、退格/Delete 和系统复制粘贴。data-change-command="core:world_config.name" 提交完整的 value 字符串，经 create_world_config.world_name 与 main_menu_world_name 回显；原名称专用的 name_focus / name_done / name_text / name_key 命令、逐字编辑分支和编辑标志已移除。保存名称及其他旧菜单字段继续使用各自现有机制。

清空名称时保留空白草稿，以 New Colony 作为占位文字；不会在用户删除最后一个字符时强行填回默认值。创建世界时，空名称才解析为 New Colony。名称继续使用原有 64 字节缓冲区，最多保存 63 个 UTF-8 字节；输入栏的 63 字符上限不能代替接收端的字节容量检查。超长或包含控制字符的完整输入保留为可修改的 UI 草稿，名称栏下方显示本地化原因，开始按钮和创建命令都拒绝该无效状态。拒绝时不截断中文字符，不覆盖已接受名称，也不将无效草稿写入设置。

名称草稿仅属于当前菜单会话；重置世界配置时清除，成功发起创建时使用已接受名称并清除草稿。设置仍使用现有 world_name 字段，世界身份及存档格式不变。新增错误字段完成快照、typed DataView、绑定、脏通知和清理接线。

合成与生产独立窗口

制作完成诊断日志：使用 NewColony.exe --DEBUG 启动后，在本次运行的日志中搜索 [ProductionTrace]。已确认正常的配方加载、客户端提交/返回、命令接收/返回、调度读取配方、参考工作者和工作点候选详情诊断已移除。保留 order_created、dispatch 和 order_status，用请求 ID、订单 ID/UUID、配方 ID 和任务 UUID 关联收尾流程。既有的制作经济日志、[AI][work] settled、告警及错误日志继续保留。

completion_prepare 记录制作完成准备是否接受，以及原生接口给出的拒绝原因；completion_publish 记录联合提交是否接受。提交被拒绝时，原因含内部阶段、具体错误或校验拒绝标识，以及 @LuaBindingsTasks.cpp:行号。阶段覆盖原记录、保留计划、材料预约、任务契约、产物定义、材料来源、订单关联、产物创建、职业准备、完成回执、事件候选、业务候选和联合发布。异常保留原始 what()，不再全部退化为笼统的 publication pending；尚无专用错误名的校验用阶段及源码行定位。首个拒绝被保留，外层事务拒绝不会覆盖更内层的原因。日志只观察结果，不放宽校验、不改变重试或资产提交顺序。

completion_delivery_begin 表示原生完成队列开始交付该制作任务；completion_delivery 区分结果尚未发布与已接受，记录监听器失败标识及队列待处理数量；completion_acknowledgement 记录原生完成队列是否确认并移除该任务。manufacturing_notice_acknowledged 记录制造通知的种类、序号、失败监听器数量及通知回执已接受。AI 的 settled 日志不能单独证明产物、订单和通知均已完成。

Lua 等待日志按任务 UUID 和阶段去重，同一失败原因不逐 Tick 重复输出；完成队列等待观察存在原票据上，仅观察变化时记录。去重数据仅在 VM 或票据生命周期内，制作提交成功及世界重置时清理，不写入存档。日志沿用现有 Debug 级别，普通启动不输出；通过正式构建、导出更新运行包后生效。

列表与滚动条：配方与订单页共用左侧 .craft-list。合成窗口与法术编辑器使用 shared/components.rcss 中的 .ui-scrollbars 样式。纵向条宽 8px，横向条高 8px，滑块有悬停和按下颜色，箭头尺寸为零。合成窗口中的列表、右侧详情及材料选择都使用该样式。

制造入口改为 craft_menu.rml，通过 Lua RML panel 生命周期加载，craft_screen_state 经 typed DataView 绑定到 craft。窗口居中并用遮罩捕获世界输入，不修改暂停或速度；Escape 先关闭材料/取消确认，再关闭主窗口。配方与订单分两个页签，列表和详情分别滚动，底部操作保持可见。

独立 RML 文档通过 .ui-window-close 使用和 Lua 窗口相同的红底关闭按钮。转职之路通过右上角关闭，职业详情可以单独收起。事件概览、提醒和普通事件详情使用同样的按钮，重大事件仍通过选择或确认处理。

普通配方、锻造设计和药剂设计统一下单；设计编辑仍单独打开，关闭编辑器后返回。职业与配方分类 Tag 独立筛选；无有效分类归杂项。工作点管理页保留设施状态与定位，并增加打开对应兼容配方的合成入口，订单依然全局调度。

配方页默认显示已解锁科研的配方，材料不足、没有合格工作者或没有可用工作点不会把这些条目隐藏，配置异常的已解锁条目仍显示原因。原“仅看可生产”按钮改为“显示全部配方（含未解锁）”；开启后把科研未解锁配方纳入当前搜索、职业、分类和工作点筛选，未解锁项仍不可下单。开关在本次世界会话中保留，卸载世界后恢复默认关闭。生产共享快照补齐殖民地、来源标识、创建顺序、请求关联、取消状态、工作者、材料限制、在途任务和配置原因，避免合成界面的殖民地筛选误隐藏仍在等待的订单，并保留现有超时查询及详情展示。该快照仍从服务端现有订单生成，不新增订单账本或持久化格式。

定量数量表示批次；维持库存表示选中目标产物的件数，默认取一批产出量。随机结果展示范围，库存补足材料仅为快照估算。材料种类允许按输入项多选严格限制，预览用联合容量匹配，避免重复计算共享替代材料；零允许种类禁用下单，普通缺料允许创建等待订单。已有订单只读，唯一变更操作为确认取消；旧暂停、恢复、改目标 API 为其他调用方保留，但不再由新订单页提供。

合成库存预览补入露天仓储区及散放的地面物资，不再仅统计方块容器。地面物资沿用现有物资来源查询，数量扣除预约，界面继续按实际殖民地归属筛选；保留物资不计可用量，保留策略证据未知时显示未知。地面物资不要求仓库入口或设施启用证据，列入预览只是取料候选，不证明实际工作者可达；容器仍要求其入口、启用及保留策略证据，实际取料与提交继续由既有服务端规则校验。本次仅修正界面派生快照，未修改预约、搬运或制作执行规则。

客户端创建请求在窗口外跟踪。关闭后仍接收结果；超时或断线不能直接当作创建失败并重发，恢复连接后先按请求 UUID 查询服务器。下单成功留在配方页，重复确认过的请求返回已有订单。浏览与草稿只保留在本次世界会话。中英文标签位于 CoreMod 本地化中；RML/RCSS 只修改源码，运行仍读取可执行文件旁的 mods/core。

制作下单改用 engine.ui.command.create_request_id() 生成客户端请求 UUID，供 client_request_id 去重和状态查询；不再调用服务端专用的 engine.identity.create()。新接口仅供已发布客户端运行时调用，候选加载和服务端调用均拒绝；请求 UUID 不授予世界资产创建权限，订单 UUID 仍由服务端分配。补齐棉/亚麻旗帜、切石机和石砖配方，以及制作界面所查询的物品名称的中英文本地化。

制作界面的实现和验收清单见 docs/crafting-screen-implementation.md。

面板未显示排查：底栏选中只表示 Lua 面板句柄已注册，页面还需要有效业务快照才能显示。合成窗口若反复记录 production_options.lua: bad argument #3 to 'max' (number expected, got boolean)，说明旧库存预览把库存查询的数量与已知状态两个返回值一起传入了 math.max；源码已改为先用局部变量接收数量。法术编辑器的 spell_editor_state 还必须列入 RML_UI_SNAPSHOT_CHANNELS，以支持周期发布及命令后的即时刷新；源码已补齐此项。运行仍读取可执行文件旁的 mods/core，需经正式构建、导出更新运行包；不直接修改导出副本。

玩家构建固定使用真实 RmlUI backend，构建系统无条件链接 RmlUi::RmlUi，在游戏窗口内绘制 main.rml 与副文档，并通过 RmlUiBridge 暴露通用数据模型与命令事件入口。NullRmlUiRuntime 只保留为显式诊断/失败回退路径；启用时会记录错误级日志且不渲染任何文档。

三层结构

组件文件职责
RmlUiServerEngine/UI/RmlUiServer.{hpp,cpp}引擎唯一集成点；持有后端与桥，暴露生命周期、输入、数据推送与命令消费。
RmlUiRuntimeEngine/UI/RmlUiRuntime.{hpp,cpp}RmlUI backend 抽象接口 + NullRmlUiRuntime stub + make_rml_ui_runtime() 工厂。
RealRmlUiRuntimeEngine/UI/RmlUiRealRuntime.{hpp,cpp}玩家构建必编译；负责生命周期、主文档加载、输入、原始通道绑定和命令事件，通过 rmlbackend.dll 调用 Vulkan 绘制。
RmlUiRenderBackendEngine/UI/RmlUiBackend.{hpp,cpp}rmlbackend.dll 提供 Vulkan RenderInterface 与 system/file interfaces；工厂和自定义 deleter 在同一 DLL 分配及释放，宿主在 Rml::Shutdown() 后释放接口。
RmlUiPanelRegistryEngine/UI/RmlUiPanelRegistry.{hpp,cpp}真 backend 的文档注册表；集中加载 manage_hud.rml、battle_hud.rml、status_bar.rml、暂停与设置等文档，并负责经营和战斗模式互斥显示。仅 --DEBUG 加载 ui_lab.rml。
RmlUiDataViewsEngine/UI/RmlUiDataViews.hpp + RmlUiDataBindings.cpp + RmlUi*DataViews.cpp面板 typed/derived view 边界；公开 API 仍由 RmlUiDataViews 提供，内部按领域拆到 HUD/Battle、Build/Research/Crafting、Colonists、Main Menu/Settings/Content Browser/Mod Manager、Minimap、DevConsole/Global Toast 和通用刷新胶水等实现文件。它集中注册与刷新 HUD 的 hud_* 字段、旧静态经营面板的派生数据、Minimap 的 minimap_status / minimap_tiles_rml，DevConsole 的 console_visible / console_history / console_input_before_rml / console_input_after_rml / console_cursor_visible，全局命令反馈的 global_toast_visible / global_toast_rml，以及 UI phase 派生的 main_menu_visible / playing_visible / pause_visible / pause_menu_visible / settings_visible 与 settings_rows。
RmlUiBridgeEngine/UI/RmlUiBridge.{hpp,cpp}C++ ↔ 文档层双向数据/事件通道（快照 + 命令队列），与具体 backend 无关。

面板 runtime 边界

新增 RML 面板时，资源注册和 typed view 不再直接堆进 RmlUiRealRuntime.cpp。副加载文档（入口 main.rml 之外的面板/验证页）统一登记在 RmlUiPanelRegistry.cpp 的注册表中，保持“缺失不致命、主文档照常渲染”的加载语义。面板需要的结构化 DataModel 字段统一挂在 RmlUiDataViews.hpp 的同一个类上：RmlUiDataBindings.cpp 只保留 register_bindings() 的顺序调度，具体 struct/array/bind 注册、渲染、解析和刷新逻辑按领域拆到 RmlUiHudDataViews.cpp、RmlUiBuildCraftDataViews.cpp、RmlUiColonistDataViews.cpp、RmlUiMenuSettingsDataViews.cpp、RmlUiMinimapZoneDataViews.cpp、RmlUiConsoleToastDataViews.cpp、RmlUiLuaFragmentsDataViews.cpp、RmlUiTextDataViews.cpp 和 RmlUiCommonDataViews.cpp 等文件。refresh() 从原始 JSON 通道派生 typed view，并只 dirty 变更字段。

注册顺序契约：RmlUI 按类型名查表解析成员，因此 struct 成员若引用容器类型（如 ColonistEquipmentSlotView::bonuses 为 std::vector<ColonistBonusView>），对应的 RegisterArray<std::vector<T>>() 必须先于引用它的 RegisterMember() 调用；同理，作为成员或数组元素的 struct 类型必须先 RegisterStruct<T>()。任何一处顺序颠倒都会让 RegisterMember 静默返回 false，register_bindings() 随之失败，nc DataModel 创建不出来，真 backend 退回 null stub，主菜单与全部 RML 文档都不渲染。

RmlUiRealRuntime.cpp 创建 nc DataModel，绑定原始 JSON 通道，缓存引擎推送的 UI 控制变量，处理通用 data-command / data-action 点击事件，并驱动 RmlUI 生命周期与 Vulkan 渲染。主菜单使用 RML，游戏底栏挂载 Lua 在 core:mod_ready 注册的放置、伐木、采掘、区域、指令、制造、科技、招募、日志及人员入口。工作池窗口由 F3+T 切换。独立放置入口先选择 placeable 方块，再复用通用 selection 划区、选择优先级或执行者并下达逐格 Build 工作。难度设置位于新建世界阶段。结构化视图作为面板的附加绑定，保留原始通道名。

双击人员列表中的居民或对世界中的单个居民使用管理入口，可打开个人信息。人员详情使用独立的 colonist_details.rml，由 ui.colonist_details 注册。colonist_details_state 将选中居民投影到 colonist_details 结构化绑定。顶部固定显示身份与三项生命需求，内容区可以滚动。

个人信息包含基础信息、心情、特性、职业、物品栏、方案和工作计划。基础信息集中展示工作与战斗属性、当前任务、个人队列、编队及药剂冷却。职业页可打开已有转职树。人员转职树从储存区内的地面物品堆和方块库存列出可用装备。没有符合当前职业的装备时显示储存区提示。

DEBUG 日志浏览器与调试设置

用户确认深色背景已恢复，但此前普通块布局的消息列仍逐字换行。此次将表头和正文改为 RmlUI 原生 table，显式声明 table、table-column、table-row 和 table-cell，不依赖 HTML 默认样式。时间列、级别列采用紧凑固定列宽，内容列的 width: 100% 写在 column 上：按 RmlUI 的表格规则，它表示分配剩余宽度，而不是占用整张表后再 flex 收缩。单元格在列宽分配后才排版，消息保留 pre-wrap 和 break-word；不再使用绝对定位的时间/级别单元格或带大左内边距的日志行。

窗口仍按视口比例适配宽高，采用 RmlUI 支持的 vw/vh 直接建立尺寸来源，避免外层百分比包含块未解析时传下零宽。标题、筛选、表头和页脚保留原有上下布局，中间新增有明确宽度的相对定位容器，由 flex 仅分配剩余高度；滚动区以绝对定位的 width: 100%; height: 100% 取得最终内容区域，内部表格以 width: 100% 做普通表格排版，不作为 flex 内容参与预先测量。较窄视口同步缩小元数据列和间距。

窗口与级别按钮现为直角方框，右上角使用共享 ui-button ui-button-compact 矩形文字按钮；中文为“关闭”、英文为“Close”，沿用既有 core:log_browser.close 命令。日志筛选、分页、DEBUG 门禁和自动弹出逻辑均未改变。

日志窗口的 box-shadow 保持 none，保留用户已确认正常的深色不透明背景和边框。RmlUi 6.3 的阴影会把背景、边框一并转成离屏纹理；当前 Vulkan RmlUI 后端只有基础几何、纹理和 scissor 接口，尚未实现图层、滤镜与 SaveLayerAsTexture，零纹理回退白纹理会使这条路径不能可靠呈现原背景。日志页面继续避开该路径，没有扩展通用渲染后端；运行资源通过正常 staging/export 管线更新。

仅以 --DEBUG 启动时，原生面板注册表才加载 log_browser.rml。窗口标题为“日志浏览器”，不显示图标或启动参数装饰；窗口使用视口比例确定宽高，在较小窗口中保留标题、筛选和底部操作，仅中间日志区滚动。日志列为时间、级别和内容，长文本自动换行。它是独立、非模态浮窗，可以与主菜单、加载、游戏、暂停、设置及建筑设计界面共存，指针只在窗口内被捕获；关闭按钮和 Esc 关闭窗口，关闭日志不会同时返回设置或改变游戏暂停状态。开发者控制台打开时保留控制台的 Esc 优先级。

DEBUG、INFO、WARN、ERROR 四个级别默认全部不选；全部不选和全部选中均显示全部日志，选中部分级别时仅显示相应记录。筛选按钮显示当前缓存中各级别的条数，底部显示当前记录范围、筛选后的总数与缓存总数。日志按每页最多 32 条呈现，使用“上一页”“下一页”浏览；打开、切换筛选或点击“滚动到底部”时返回最新页。查看旧页时保留该次快照，避免新日志不断移动正在阅读的内容；回到最新页后恢复刷新。筛选只影响浏览，不改变文件日志阈值。

设置增加仅在 DEBUG 模式可见的“调试设置”分类，包含“出现 ERROR 时自动弹出日志浏览器”和手动打开入口。自动弹出默认开启，通过 settings.json 的布尔字段 debug_log_auto_popup 保存；旧设置文件缺少该字段时采用开启默认值。开关立即影响随后观察到的新 ERROR，确认设置才写盘，放弃更改恢复已保存值，恢复本页默认值重新开启。普通启动隐藏整个调试分类，并忽略自动弹出开关；普通启动仍按原有规则写日志文件。

日志缓存由 Core Logger 拥有，客户端在启动时根据 --DEBUG 显式启用；不把日志镜像到命令控制台，也不从远程服务端传送日志。缓存按接收顺序保留最近 2048 条 DEBUG/INFO/WARN/ERROR，超过容量时淘汰最早记录。Logger 单条 UI 缓存上限为 16384 字节，浏览器每条实际排版文本限于 2048 字节的完整 UTF-8 边界，超长记录附截断提示；文件日志继续使用完整消息。缓存属于进程诊断状态，不写入世界存档，也不重读旧日志文件。所有日志生产线程只写入受锁保护的缓存及错误修订号，RmlUI 帧线程负责显示；窗口隐藏时不复制记录，最新页至多每 0.1 秒刷新一次，筛选和打开操作可立即刷新。仅当前页进入 data-for；可见行内容不变时不标脏日志数组，避免新 DEBUG 日志反复重建与筛选无关的行。首次自动弹出也不再一次创建 2048 行。

自动弹出依据新 ERROR 的修订号，与当前级别筛选无关；同一条 ERROR 不重复弹窗。关闭自动弹出期间观察到的错误仍可手动查看，重新开启不会重放这些旧错误；后续新增 ERROR 可再次弹出。窗口跨 RML 文档重载保留本次运行的筛选和显隐请求，UI 关闭时清理绑定存储；日志线程不保留 RmlUI 元素、事件回调或 VM 引用。

RealRmlUiRuntime 在 RmlUI context 上创建名为 nc 的 DataModel。当前通用层把稳定通道全部绑定为 JSON 字符串变量：world_info、resource_snapshot、colonist_list、event_list、tech_tree、view_modes、orders_kinds、build_defs、craft_recipes、combat_state、construction_active、command_result，以及旧 Lua UI 兼容层的 lua_ui_bottom_bar、lua_ui_windows、lua_ui_floating、lua_ui_rml_panels。每帧 update 前，runtime 从 RmlUiBridge::latest_snapshot(channel) 读取最新值；缺通道或空字符串会暴露为 null，不会让文档层崩溃。变量变化时调用 DataModelHandle::DirtyVariable(channel)，由 RmlUI 在后续 Context::Update() 中刷新绑定。

RML 文档使用 data-model="nc" 后可直接绑定这些变量，例如 {{world_info}} 或 {{resource_snapshot}}。通用层始终保留原始 JSON 字符串绑定；特定 RML 面板可以在 RmlUiDataViews 内叠加最小 typed/derived view，但不得替换十二个通道名契约。command_result 也是同一个数据模型变量，由 Engine::dispatch_rml_ui_command() 写入桥后进入文档层。

全局命令反馈：global_toast.rml 是非 menu 阶段加载的全局副文档，用 global_toast_visible 和 global_toast_rml 在顶部中央显示最近一次需要注意的业务命令结果。Error toast 使用深红背景和红色侧边强调，确保在游戏画面上清晰可见。RmlUiDataViews 观察 command_result，按 waiting / blocked / error 分类成 warning / error / info 样式；成功结果对普通命令静默，避免菜单和普通点击刷出无意义的成功提示；但保存（core:pause.save）与加载（core:menu.load_game）属于玩家必须确认的里程碑结果，其成功也会作为 success 样式 toast 显示，对应文案来自 SaveResult::message。toast TTL 由 RealRmlUiRuntime::update(dt) 驱动，普通结果约 2.8 秒，错误约 4.2 秒。C++ 在写入 command_result 前追加 sequence 字段，保持原返回字段不变，同时让连续两条同形结果也能被识别为新事件。

按钮按压反馈：CoreMod 的主菜单、HUD、经营窗口、暂停/设置、科技与战斗界面统一使用 RmlUI :active 状态降低按钮透明度；原有按下配色仍可叠加，松开后自动恢复。游戏内底栏的页面入口统一使用 toggle 状态，重复点击当前高亮入口会关闭对应页面。

列表绑定约定：当前 RML 静态文档不直接在循环体内写 data-for 别名字段（例如 {{def.id}}、data-attr-data-param-id="def.id"）。RmlUI 6.1 的当前 Windows/vcpkg runtime 在启动加载阶段会把这些循环体当作普通静态元素解析，导致别名变量解析诊断。列表仍由 RmlUiDataViews 的 typed views 维护；C++ 从 typed rows 生成已转义的 RML 片段，暴露为 *_rml 字符串（如 build_defs_rml、research_nodes_rml、console_history_rml），RML 文档用 data-rml="..." 挂载。空数组输出空字符串，仍由 *.size == 0 的静态空态控制；未知状态只作为普通文本写入；按钮行写最终 data-command 与 data-param-* 属性，继续走同一个 context 级命令监听器。

除十二个业务通道外，runtime 还缓存一组UI 控制变量（与业务通道分开维护，不参与和 ScriptEngine/Lua 的数据契约）。当前有 ui_phase（取值 "menu" / "playing" / "pause" / "settings"），由引擎每帧按世界、暂停菜单和设置 shell 状态推入桥；RmlUiDataViews 将它暴露为 typed binding，并派生 main_menu_visible、playing_visible、pause_visible（pause 或 settings 都为真，控制遮罩背景）、pause_menu_visible（仅 pause 为真，控制按钮列表本身）、settings_visible（仅 settings 为真）与 settings_rows。ui_font_size 同样由引擎从用户设置推入桥，真 backend 会把它夹在 12-20 px 并应用到主文档、副文档和动态 RML panel 的 #ui-root body 上；默认值为 15 px。RML 文档使用这些布尔派生变量做 data-if，避免依赖字符串表达式兼容性。

文档到引擎的通用命令入口是 context 级 click 监听。监听器从事件目标向父级查找 data-command 或 data-action，找到后向 RmlUiBridge::enqueue_command({target, payload}) 入队。payload 规则：若元素带 data-payload，其内容作为 JSON 字符串原样入队；否则把所有 data-param-* 属性打包成简单 JSON 对象，例如 data-param-id="x" 会产生 {"id":"x"}。onclick 属性也作为 target fallback 读取，便于迁移旧写法；推荐新 RML 使用 data-command。

通用浮动面板拖拽：真实 backend 在同一个 context 级鼠标监听器里支持声明式拖拽。可移动的绝对定位面板声明 data-drag-panel="panel-id" 和 data-draggable="true"，其标题栏或其它拖动手柄声明 data-drag-handle="panel-id"；设为 data-draggable="false" 可禁用。左键按住手柄时 runtime 会把面板转换为内联 left/top 定位并在鼠标移动时更新位置，同时清掉 right/bottom，位置会被限制在当前 RmlUI viewport 内。该机制只改变 RmlUI 元素样式，不经过 RmlUiBridge 命令队列，也不会持久化到用户设置；需要跨会话保存时再把最终位置提升为 Engine-owned UI control state。

Pause / Settings MVP

pause_menu.rml 是当前最小暂停与设置入口。真 backend 加载 main.rml 后由 RmlUiPanelRegistry 尽力副加载 pause_menu.rml；文件缺失或解析失败不影响主文档。Null stub 只在显式诊断/失败回退路径下存在，不加载文档。

从主菜单或暂停菜单打开设置时，两个命令入口都调用引擎内的 open_settings 初始化设置状态，默认显示 Game（游戏）页；在设置窗口内切换分页仍由 core:settings.page 处理。

滑条外观：设置页使用深色凹槽、暗青绿色渐变填充和轨道内部的 28×16px 青灰色滑块。滑块中心通过 RmlUI 原生 repeating-linear-gradient decorator 绘制竖向握持条纹，顶部浅边与底部深边表现厚度；悬停提亮、按下时偏暖。settings-slider-travel 留出轨道内边距，滑块按数值比例做反向自身宽度平移，使最小值和最大值处均完整留在轨道内。新建世界页已移除四项星球参数滑条。原生显示效果待验收。

设置滑条：.settings-slider 是自绘控件，由 RmlBridgeCommandListener 处理左键按下、移动和松开。点击轨道或按住拖动会按最小值、最大值和步进计算数值，移出轨道仍继续调整并夹在有效范围内；松开左键结束拖动，右键不启动或结束该手势。生成的控件带稳定 ID、data-slider-command、data-slider-min/max/step 及命令参数，禁用项通过 data-slider-disabled 拒绝拖动。设置滑条发送 core:settings.set 的 key/value；已删除新建世界参数专用的比例命令和松开保存逻辑。拖动只在步进值变化时发送更新；快照重建控件后按文档来源地址在 context 的现存文档列表中重新定位，再按稳定 ID 查找控件，不跨事件保存元素或文档指针。文档重载入口清除拖动状态。设置修改仍遵循下述确认保存流程。待人工检查主菜单和游戏内设置的轨道点击、连续拖动、两端限值及步进按钮。

设置修改立即生效，只有确认才保存。设置窗口只保留右下角返回按钮；返回按钮、点击窗口外背景和 Escape 都经由 core:settings.back 处理。存在未确认改动时打开模态确认框，主菜单和游戏内暂停菜单共用此行为。“确认并返回”（core:settings.exit_confirm）统一保存各分页的用户设置、按键绑定和 Mod 配置，再返回原菜单；保存失败时保留提示并允许重试。“放弃修改并返回”（core:settings.exit_discard）回读保存的设置和按键文件，并恢复最后确认的 Mod 配置；首次运行尚无文件时使用进入设置时保留的基线。恢复同时应用窗口模式、分辨率、渲染选项、音量、语言、主题、相机距离和自动保存频率，不替换世界或菜单导航状态。恢复失败时保留窗口并显示错误。“继续编辑”（core:settings.exit_cancel）或在提示框打开时按 Escape 只关闭提示框。没有改动或已经确认时直接返回；游戏内返回设置的上一级仍保持暂停。按键重绑等待输入时，Escape 优先取消重绑。按键绑定和 Mod 设置的编辑也会标记未确认状态，切换分页不会清除它。分页内的保存操作也走统一确认路径；引擎关闭和其它自动保存入口不会将未确认的设置写入文件。

底部“默认值”（core:settings.defaults）先打开确认弹窗。core:settings.defaults_confirm 才恢复当前分页的默认值，并标记为未保存；core:settings.defaults_cancel 或 Escape 关闭弹窗，保持当前设置。Controls 页的单项默认按键和整页重置也先确认；单项提示明确说明会移除冲突绑定。恢复默认值后仍可确认保存，或在返回时放弃修改并恢复已保存设置。恢复默认与返回确认复用 settings_exit_confirmation_pending / settings_exit_confirmation_rml 的模态视图绑定，快照通过 defaults_confirmation_pending 区分文案和命令。

Pause / Settings typed view 由 RmlUiDataViews 提供：ui_phase、pause_visible、pause_menu_visible 和 settings_rows。文档布局上 #pause-overlay（暗色遮罩）在 pause 和 settings 阶段都显示，body 与遮罩显式铺满 RmlUI 视口，当前可见面板用 left/top: 50% 和负 margin 做绝对居中；#pause-menu（Resume/Save Game/Load Game/Settings/Return to Main Menu/Quit Game 按钮列表）只在 pause_menu_visible 为真时进入布局；设置窗口是独立文档 settings.rml，只在 settings_visible 为真时显示，因此设置阶段不会与按钮列表同屏重叠。Interface 设置页包含语言、UI scale、Font Size、主题和基础显示开关；font_size 会保存到用户设置并通过 ui_font_size 控制 RML 默认字号。

Graphics 设置页的 Display 区块提供分辨率与窗口模式（0=窗口化、1=无边框、2=全屏）。没有任何持久化窗口模式时，启动默认值由 ui::default_window_mode_index() 决定：普通启动为无边框，带 --DEBUG 启动为带边框窗口，方便开发时直接拖动或关闭窗口。settings.json 中的 window_mode_index 始终优先；该键只在玩家于设置页选过窗口模式时写回（MainMenuState::window_mode_user_set），因此普通运行的默认值不会被一次 --DEBUG 启动固化成持久选择，“恢复默认”也会清除该偏好。

互斥派生变量的由来。先前 #pause-menu 与 #settings-shell 都用 pause_visible / settings_visible 控制，而 pause_visible 在 settings 阶段也为真，结果两块同尺寸的绝对定位面板在设置阶段同屏重叠绘制。新增只在该相位为真的 pause_menu_visible，让按钮列表与设置 shell 互斥：#pause-menu 改用 data-if="pause_menu_visible"，遮罩继续用 pause_visible。这是 RML/typed-view 层的小修，不改动 Escape 路径或暂停状态机。

Minimap Panel

minimap_zone.rml 与 minimap_zone.rcss 作为旧资源保留，但不再由 RmlUiPanelRegistry 加载。ui.world_map 自动注册不可关闭、可拖动和缩放的战略世界地图悬浮窗及城邦列表，不再向 HUD 底栏注册地图按钮。地图格发送 core:world_map.select_start_site；Client 经网络提交，Server 验证 q/r 确实存在于地图快照后持久化选址，不在 UI 层补写地点合法性、初始人数或物资规则。

游戏 HUD

manage_hud.rml 与 battle_hud.rml 是同级模式 HUD，由 RmlUiPanelRegistry 在同一个 RmlUI context 中加载并互斥显示。战斗模式状态由 Lua 的 battle_hud 数据通道提供，Lua 不再将战斗 HUD 注册为动态面板。status_bar.rml 独立承载日期与倍速控件。Null stub 只在显式诊断/失败回退路径下存在，不加载文档、不解析 HUD 数据。

独立状态栏右上角的日期时间区消费 nc 数据模型中的派生字段：hud_day、hud_year、hud_season 与 hud_time。左上角资源库存提示栏及其专用 HUD 数据绑定已移除；resource_snapshot 仍供制造等其他界面使用。经营问题底栏按钮、问题列表窗口和右侧聚合警报栏已删除，economy_alerts 通道及其 HUD 绑定也已移除。左下角 selection_summary 从当前可见实体快照、所选体素或命中的物品堆读取名称、归属和状态；首要经营问题仅在 DEBUG 模式显示。选中工作点坐标时额外显示类型、道路、当前工作、执行者、输入暂存和输出待清空状态，并把管理按钮直接落到生产面板工作点页。命中物品堆时选择保存 pile_entity_uuid，物品详情与管理入口优先于同坐标的区域和工作点；点击射线会比较物品堆、实体、区域和地形距离。右上角日期/倍速条使用与小地图一致的半透明深色背景。底部菜单提供经营主入口，详见 底部栏入口。

制造窗口的配方选择使用两级下拉筛选：第一层按职业族 career_id 聚合，第二层选择该职业下的具体职阶，并继续以完整职业 ID 匹配配方要求。通用配方、锻造设计和药剂设计作为职业层的独立类别。Lua UI 下拉框显式设置 selectvalue、selectarrow、selectbox 和 option 的背景、边框、悬停及选中样式。

伐木和采掘是底栏独立入口，直接进入对应的一次性选择工具；区域入口打开持续区域二级菜单。指令入口承载建筑、狩猎、取消工具和其余专项状态跳转。运行中底栏不再提供难度按钮及其面板；难度调整只发生在新建世界阶段。

HUD 字段来源通道转换规则
hud_day / hud_yearworld_info读取 JSON 中的 day、year 整数字段。
hud_seasonworld_info优先从 season_key（如 core:season.spring）取后缀并首字母大写；缺失时按 season 序号 fallback。
hud_timeworld_info读取 tick_of_day，按 DAY_TICKS_PER_DAY=86400 格式化为 24 小时 HH:MM。

当前限制：通用业务通道仍以原始 JSON 字符串暴露；HUD 在 RmlUiDataViews 内对时间、经营警报和选择摘要做最小 typed/derived 转换。解析是容错的：字段缺失或类型不匹配时保留默认值或已有值，避免 HUD 因单个字段异常消失。

底部栏入口

公共容器与窗口对齐：hud-bottom-layout 从 HUD 左上角开始，显式设为 width: 100%、height: 100% 和 box-sizing: border-box，外框与游戏窗口的 UI 视口一致，随窗口尺寸变化。左右各 12px、底部 18px 内边距用于放置内容；纵向 flex 的 justify-content: flex-end 把详情和菜单一起放在底部。菜单框是宽度 100%、最大宽度 1680px 的居中 block；注入按钮的 lua-ui-bottom-bar 显式设为宽度 100% 的横向 flex，并启用 flex-wrap: wrap 和居中对齐。按钮使用 flex: none，外框宽 104px、高 36px，外边距为纵向 3px、横向 6px。不要恢复菜单框与按钮容器连续自动宽度的 inline-block 嵌套：内容定宽与外层 flex 的尺寸计算可能让菜单缩成单列竖条。详情仍是公共纵向容器的独立上方模块。按钮尺寸与激活态采用同一组带底栏 ID 的选择器，避免通用样式覆盖激活背景。

左下角详情的 selection_summary.capabilities 通过 hud_selection_capabilities 显示为独立的“特殊能力”栏。它读取方块注册表的 building_capabilities，并按 core:squad_assembly tag 识别小队集结与解散功能，不按旗帜方块 ID 写死；贸易点通过 core:trade_point 方块声明的 building_capabilities: ["trade_point"] 显示为特殊能力。实际工作点会补入 work_point 能力，在原有任务、执行者、道路和输入输出详情前显示可用、已占用、停用或不可用状态；仅声明能力但没有实际工作点时显示“尚未配置工作点”。能力名称使用 ui.core:block_capability.<能力 ID> 本地化键，未提供翻译时回退能力 ID；无能力或切换至实体选择时隐藏该栏。方块名称使用 blocks 分类本地化，工作点所属建筑使用其 name_key。

经营 HUD 的选择详情 selection-summary 与菜单 bottom-bar-slot 是 hud-bottom-layout 内两个独立模块，按纵向 flex 布局排列：详情在左侧、菜单在其下方居中。公共容器尺寸保持与窗口一致，菜单换行时底部内容组向上占用更多空间，详情不再依赖固定的底部偏移；模块间距为 10px。详情最大高度为视口高度的 32%，超出后纵向滚动。公共容器不接收鼠标，详情和菜单各自接收交互；指定工具激活时公共容器隐藏。

点击选中的实体方块在世界中显示金黄色外框，鼠标移开后保留，取消选择或该位置变为空气后停止绘制。外框使用独立的深度测试线段通道，因此前方地形和写入深度的模型会遮挡它；普通渲染、抗锯齿重建和 SSAO 几何路径均创建对应管线。采掘等工具标记仍使用原有可透视外框。选择高亮不依赖 DEBUG 开关；进入划区或建筑设计工具时暂停该外框，让工具预览优先显示。

DEBUG 经营问题提示：ui.economy_notice 只在运行参数包含 --DEBUG 时读取问题快照。新问题实例或同实例原因变化会排队弹出单条提示，包含问题、原因、来源、位置和建议；有坐标时提供定位按钮。持续重复报告同一问题不重复弹出，待显示问题已解决时跳过；关闭当前窗口后再显示下一条。卸载世界或关闭 MOD 时清理窗口和队列。正常运行不读取该提示快照、不创建提示，业务问题记录仍供工作系统使用。旧 economy_panel 模块、生命周期监听器、core:economy.alert 命令及其 before event 已删除。

底部栏游戏内菜单入口由 lua-ui-bottom-bar 插槽按 priority 注入，label/tooltip 走 lang/*.json 的 ui.core:* 键，支持中英切换。manage_hud.rml 不再保留 Build / Craft / Colonists / Research / Zones 静态按钮，也不再通过 core:panel.toggle 打开这些旧静态副文档。

主菜单（Main Menu MVP）

多人游戏主页面只保留用户名、服务器列表、状态提示及底部操作区，不显示“已保存服务器”标题或名称、地址和端口的常驻表单。底栏严格分成两行：第一行为“添加服务器、编辑、删除”，第二行为“加入服务器、直接连接、刷新、返回”。两行和上方列表宽度一致，行内按钮使用相同的 Flex 比例分配全部可用宽度，只在相邻按钮之间留百分比间距；页面和弹窗布局采用百分比、视口单位及 em，不使用固定像素尺寸。列表独占可用中间区域；页面外壳、内容容器、列表、滚动区域、条目和操作行都显式建立宽度约束，避免 RmlUI 对自动尺寸及后续拉伸的处理使百分比控件塌缩。殖民地选择继续由进入世界后的独立界面处理，不在主菜单中创建覆盖服务器列表的同位置面板。点击服务器后显示选中边框；未选中时“加入服务器”“编辑”“删除”禁用。页面不提供“断开连接”“启动服务器”或“开始世界”按钮。

“添加服务器”和“编辑”分别通过 core:multiplayer.add、core:multiplayer.edit 打开独立遮罩弹窗。新增使用新的草稿，编辑从所选记录回填名称、地址、端口；输入采用 data-value 双向绑定，普通网络状态刷新不会覆盖正在输入的草稿。弹窗确认回调将三个字段和弹窗代次一起提交到 core:multiplayer.dialog_submit；后端检查代次、非空地址及 1–65535 的整数端口，再写入配置目录中的 saved_servers.json。保存失败时保留弹窗并显示错误；成功时选中新建或修改的记录。“取消”和 Escape 通过 core:multiplayer.dialog_cancel 关闭弹窗并丢弃草稿，不改动保存记录或当前连接配置。弹窗打开期间，主页面操作和服务器选择禁用。

添加、编辑、直接连接弹窗在全屏遮罩中的独立 Flex 容器里水平、垂直居中。这里不使用 transform: translate(...)：当前 VulkanRmlRenderInterface 仅提交几何平移和视口参数，没有实现 RmlUi 的 SetTransform，变换会造成绘制位置和鼠标命中位置不一致。确认与取消均通过 data-event-click 回调提交命令；取消仍调用 core:multiplayer.dialog_cancel，Escape 使用同一取消处理。

“直接连接”通过 core:multiplayer.direct 打开地址、端口弹窗，确认后复用客户端配置命令；“加入服务器”使用当前所选记录。两者进入同一条远端客户端路径：客户端发送不带本地种子的 discovery Hello，等待服务端 Welcome、完整首快照及 save_state:world 文档，从服务端文档取得世界种子、地图参数、脚本世界 ID 和初始 Tick；随后只准备客户端世界、应用权威快照并创建 Client ModRuntime，不调用 core:menu.new_game、不创建本地 Server ModRuntime、不开本地单人存档。握手、首快照、MOD 数据或客户端初始化失败都会关闭网络、清空远端连接配置、销毁部分客户端世界，并把带原因的失败提示留在多人页面，因此失败后仍可直接创建单人世界。删除会更新 saved_servers.json，刷新会重新读取该文件。没有服务器记录时显示空状态，返回按钮只在底部操作区显示。

每条服务器记录右侧显示状态、Ping、探测丢包率、服务端游戏版本和统一 MOD MD5 后四位。进入列表时，后台最多并发查询四个地址；“刷新”重新读取列表并发起新一轮查询。每个服务器在独立 TCP 查询连接中发送四次 ServerStatusRequest（类型 14），等待匹配序号的 ServerStatusResponse（类型 15）；单次响应期限 750ms。Ping 是成功响应的平均往返时间，探测丢包率是已发送请求中超时/未收到响应的比例，不等同于底层 TCP/IP 丢包率。无法建立查询连接时，Ping 和丢包率保留未测量状态。版本和 MD5 来自该服务端响应，不以本机版本或 FNV registry hash 代替；旧服务端不支持查询时显示“无响应”。查询不认证为玩家、不进入世界、不改变当前连接；查询连接不计入已认证玩家数。

统一 MD5 以实际已加载的全部 MOD 为集合：按 MOD ID 排序，包含 ID、版本以及 MOD 根目录下按相对路径排序的所有文件路径和内容字节，包括 manifest、脚本、数据和资产；字段带长度分隔，路径统一为 UTF-8 正斜杠，不包含绝对安装目录，禁用且未加载的 MOD 不参与。引擎建立/刷新网络内容快照时重算完整 32 位十六进制 MD5，查询响应发送完整值，列表只显示最后四位。该短码是供玩家对照内容的标记，不替代完整握手内容检查。

Mod Manager 和 Content Browser 的标题、搜索区与三列内容按页面可用高度排列；分类和条目列表在各自列内滚动。Content Browser 的第一列标题是“类型”，分类与条目按钮填满所在列；类型列不生成滚动条，鼠标滚轮由 RmlUI 命令监听器直接滚动类型列表，条目列保留可见滚动条。条目名称优先使用当前语言中“内容类型 + 条目 ID”的翻译；缺少该翻译时使用数据声明的翻译键或名称，最后回退到 ID。详情保留 ID、类型、所属 Mod 与描述；不显示文件路径或原始 JSON。数据对象和列表按结构生成可折叠分组，实体的 capabilities 按组件逐项展开。“打开注册表说明(Wiki)”位于内容区下方、返回按钮左侧，并按当前类型打开说明页面。

主菜单直接画在 main.rml 内（不开新文档、不依赖已移除的即时模式 UI 或浏览器）。面板包在 <div id="main-menu" data-if="main_menu_visible"> 里：引擎进入世界后 ui_phase 变为 "playing"，main_menu_visible 变为 false，面板自动从文档布局中移除；回到主菜单（世界卸载）后又自动出现，无需额外开关。当前主菜单是右侧栏导航 + 左侧页面内容结构，提供 Create World、Load Game、Multiplayer、Settings、Mod Manager、Content Browser、Wiki、Credits 和 Exit。非世界态的主菜单及其所有二级页面在主循环末尾固定按 60 FPS 限帧；世界内继续使用 Graphics 设置里的 Render FPS Limit。

开发者控制台（DevConsole MVP）

开发者控制台的可见 UI 已迁移到 RmlUI：CoreMod/assets/ui/rml/dev_console.rml 与 dev_console.rcss 作为副文档由 RmlUiPanelRegistry 加载，文档本身常驻，显示条件由 typed view console_visible 控制。控制台只在以 --DEBUG 启动时启用；这不是 NEWCOLONY_DEBUG 编译宏门禁。打开入口只监听物理 grave/backtick 键（GLFW scancode 41，同时兼容运行时 glfwGetKeyScancode(GLFW_KEY_GRAVE_ACCENT) 与 GLFW_KEY_GRAVE_ACCENT），但当 RML 控件有键盘焦点且控制台尚未打开时不抢占文本输入。字符输入事件不再切换控制台，切换键产生的字符会被吞掉，避免反引号落入输入框或控制台命令行。再次按下同一物理键会关闭控制台，不提供标题、关闭按钮或运行按钮，也不把 ESC 作为控制台关闭键。

数据绑定由 RmlUiDataViews 提供：console_input_before_rml / console_input_after_rml 按光标位置把伪输入切成两段（光标停在哪，两段就在哪分开），console_cursor_visible 驱动夹在两段之间的光标闪烁，console_history 暴露最近提交的命令文本与命令自身的输出行（即 DevConsole::report / report_warning / report_error 写入的 Output/Warning/Error 行），console_history_rml 挂载历史行，console_last_result 暴露最近一次提交状态，console_visible 控制面板是否进入布局。控制台不使用 RmlUI 原生 <input> 或 form；RealRmlUiRuntime::handle_input() 在控制台可见时拦截 key/char 事件并写入 DevConsole。Enter 执行当前命令；Ctrl+Enter 或 Shift+Enter 在伪输入中插入换行。左右方向键按 UTF-8 码点移动光标，Ctrl+左右按词移动，Home/End 跳到行首行尾，Delete 删除光标后的字符，Ctrl+Backspace / Ctrl+Delete 按词删除；光标始终落在码点边界上，不会切开多字节字符。上下方向键先在渲染出来的行之间移动光标（列位置会被记住，越过短行后回到原列），到首行或末行后改为翻阅历史，Ctrl+上下始终翻阅历史。伪输入的行切分由 ConsoleInputLayout.hpp 的 console_input_layout() 计算：换行符断行、制表符占 4 列、达到 CONSOLE_WRAP_COLUMNS（96）列后强制断行；数据视图与光标移动共用这一份布局，所以渲染出来的行与上下键的落点不会不一致。历史输入行只显示 > 提示符，输出与警告/错误行不显示 OUTPUT 等文字前缀。历史回显会在控制台面板内自动换行，不再横向溢出。

日志与游戏内控制台严格分离。引擎日志只流向运行日志文件与 stdout，绝不进入游戏内控制台：Logger::write_record() 不再镜像到控制台，DevConsole::sync_debug_log_entries() 及其在 RmlUiConsoleToastDataViews.cpp 的逐帧调用已删除，debug::Console 类删除后 Console.hpp 只剩 LogLevel。反方向由 DevConsole::report() / report_warning() / report_error() 负责：写一行游戏内历史，同时写一条服务器 INFO/WARN/ERROR 日志。EngineConsoleCommands.cpp 的控制台输出全部走这三个入口，控制台命令回显与将来的聊天也走这条 INFO 双向通道。不要把日志流接回控制台，也不要恢复日志镜像。

开盖即输入：按物理 grave/backtick 键调用 DevConsole::open() 置可见后，键盘输入由引擎直接送入 DevConsole 的伪输入状态，不需要 RmlUI 焦点，也不会进入 RmlUI 原生表单控件路径。控制台伪输入使用已注册的系统 Unicode 字体显示光标前后的两段文本，输入条随内容长高（最小一行，最多 110px，超出后在条内滚动），历史面板用 flex 占据剩余空间，细条光标避免文字顶出屏幕。RmlUiPanelRegistry::update_console_focus() 会在打开跃迁时重新 Show() 控制台文档，并输出 [RmlUi][console] pseudo input active on console open。

Escape 不再和控制台绑定：控制台可见时按 ESC 只走既有游戏输入路径，不会关闭控制台；反过来，控制台的开关只由物理 grave/backtick 键负责。控制台可见时 wants_mouse 返回 true，并且普通 action 查询会被屏蔽；RML 文档包含全屏拦截层，所以控制台打开后会覆盖并吸收 HUD 时间栏等提示区域的点击。Null backend 或未以 --DEBUG 启动时，控制台不初始化，物理 grave/backtick 键不会改变控制台状态。

历史 Pause / Settings / DevConsole 验证记录。当时的调试构建确认 real backend、主文档、副文档与数据模型绑定能够初始化。当前字体加载方式是操作系统提供的 Unicode 字体，不打包项目字体。主字体以 Unicode 家族注册；中文候选字体保留各自的系统家族名并加入 fallback 链，避免 RmlUi 6.3 把相同字重的字体当作 Unicode 重复 face 而丢弃。
键盘 / 鼠标交互未自动化复验。该运行环境下向运行中的游戏窗口注入键盘 / 鼠标（SendKeys、keybd_event、PostMessage WM_KEYDOWN、SendInput）均未触发 Escape 暂停或 ~ 开盖的相位变化（与既有「RmlUI 合成点击无响应」记录一致，根因是后台启动窗口拿不到真实键盘焦点）。因此 Pause/Settings 按钮、Escape 开合、~ 开盖、DevConsole 输入与 history row 的端到端点击 / 按键回路本轮未取得自动化证据，留待干净桌面环境真人复验。本轮以代码审查 + 日志 + 双构建验证这三条可靠信号定位并修复了两个确定问题：DevConsole 开盖不自动聚焦输入框（m_focus_input_next_frame 在渲染迁移到 RmlUI 后变成死代码），以及 Pause 菜单与 Settings shell 在 settings 阶段同屏重叠。

渲染路径（RenderInterface）

RmlUI 通过 Rml::RenderInterface 把文档几何交给宿主渲染后端。真 backend 当前实现了最小 Vulkan path：RmlUI compiled geometry 上传到 CPU-visible VMA 顶点/索引缓冲，纹理通过 VulkanTexture 上传并绑定 descriptor，支持 scissor，RealRmlUiRuntime::render(VkCommandBuffer) 会在 renderer UI callback 中调用 context->Render() 并录制 draw call。RmlUI 释放 compiled geometry 或 generated texture 时，backend 不会立即销毁 Vulkan 资源，而是按帧延迟回收，避免页面切换、输入框聚焦和 caret/文本重排期间上一帧 command buffer 仍引用已释放的 buffer、image view 或 sampler。

接入点：

  • Renderer::add_ui_render_callback() 维护 UI draw 回调链；旧 debug/UI overlay 已禁用，RmlUI 是唯一目标 UI 渲染路径。
  • Engine.cpp 在 RmlUI server 初始化后追加 m_rml_ui_server.render(cmd)，不启动浏览器、不走 HTTP/WebServer。
  • CoreMod/assets/shaders/rmlui.vert / rmlui.frag 由现有 MOD shader 预处理生成 SPIR-V。RmlUi 6.3 提供的顶点颜色和生成纹理都是预乘 alpha，Vulkan 管线因此使用 ONE / ONE_MINUS_SRC_ALPHA 混合，不能再用 SRC_ALPHA 重复乘 alpha。

当前渲染路径支持 compiled geometry、生成纹理、通过 stb_image 加载文档图片、scissor 和按帧延迟回收 Vulkan 资源；主菜单、HUD 与业务副面板均走此路径。复杂 effect、clip mask 和 render-to-texture 仍不是稳定能力。文本依赖运行平台提供的系统 Unicode 字体；候选字体均不可用时会记录警告，文字可能显示为缺字方框。

字体图集与纹理绑定容量：RmlUI 把字形绘制到生成纹理中，每张字体图集和每张 UI 图片占一个 combined-image-sampler descriptor，容量不是字符数量。旧后端只有一个 64-set 池，删除纹理时未归还 descriptor，页面切换和建筑设计图标加载会累积耗尽名额；2026-10-12 运行日志在打开建筑设计后记录 failed to allocate texture descriptor。RmlUI 6.3 默认字体引擎在加入新字形后会重建对应字体句柄的共享图集并递增版本，已有文字检测到版本变化后也会换用新图集，因此分配失败可能连原本正常的文字一起影响，并非只影响新界面的文字。生成失败的回调纹理会缓存失败状态；渲染时其零句柄在当前后端回退白纹理，字形四边形显示成大小不一的白块。不同字体大小的图集独立更新，现有日志未记录逐个字体句柄，尚不能证明一次更新直接影响所有字号。修复后每张纹理记录所属池，在原有延迟销毁点调用 vkFreeDescriptorSets 并归还名额；所有已有池的空位优先复用，存活纹理超过容量时按 64 个名额增加新池。池地址在扩容时保持稳定，关闭时先排空 GPU、销毁纹理再销毁池。DEBUG 日志记录池数和容量，真实分配失败记录 VkResult。此修复未编译或运行游戏验证。

顶点坐标约定：RmlUI 供应的顶点是屏幕像素坐标（原点在左上、纵向向下），rmlui.vert 用 push constant 里的视口尺寸把它映射到 Vulkan 裁剪空间。Vulkan 视口同样原点在左上、纵向向下且高度为正，因此纵向分量必须用直接映射（像素 / 视口 × 2 − 1）；若误用 OpenGL 的翻转写法，整张 UI 会上下颠倒——topbar 落到窗口底部、主菜单跑到下方、字形头朝下。

输入路由与焦点捕获

全屏透明 HUD 的文档 body 与内部布局壳层都必须设置 pointer-events: none，实际面板再显式启用输入。RmlUi 默认会把被点击的文档提升到前面；只让内部 #hud 穿透、却保留透明 body 接收鼠标，会让普通 HUD 在建筑设计的世界放置点击后盖住设计按钮。引擎对文档壳层返回 wants_mouse=false 不能代替 RmlUi 自身的命中穿透规则。

InputManager 是 GLFW 输入入口。初始化 RmlUI server 后，Engine 会把 RmlUiServer 指针交给 InputManager；每个 GLFW 回调先注入 RmlUI，再保留现有游戏输入状态，游戏侧随后通过 ui_wants_mouse() / ui_wants_keyboard() 决定是否处理相机、选择、建造和快捷键。

快照发布策略（主线程 UI 数据路径）

桥通道不是每帧无条件重算的。Engine::run() 的每帧块按"谁在屏幕上"分组发布，因为真 backend 会逐通道比较 JSON、只在内容变化时 DirtyVariable，而生成 JSON 才是主线程的开销：content_browser_state 会重新解析所选注册表类型的每条数据，ui_text 有约 271 个本地化字段。

组通道发布条件
每帧（任意相位）ui_phase、main_menu_page、ui_text、ui_font_size、world_loading_state、minimap_snapshot、sim_speed无条件，均为廉价直出或缓存值。ui_phase 驱动副文档 Show/Hide 与所有派生可见布尔，绝不能按相位门控：世界离开 loading 的状态机在每帧块之后运行，因此 playing 只可能由这一处发布。
HUD 面selection_summary仅 playing / building_design（manage_hud.rml 是唯一消费者）。经营问题提示由 DEBUG 客户端 tick 独立驱动。
菜单面main_menu_background_rml、wiki_external_confirm_pending仅 menu 相位（两者都在 #main-menu 内）。main_menu_background_rml 是引擎缓存的背景滑片片段，只有每 30 秒换片的那一帧内容才变化，其余帧推送的是同一个字符串（背景图池见 UI 图片资源）。
按页面create_world_config / main_menu_network_state / load_game_saves / content_browser_state / mod_manager_state仅 menu 相位且当前页面对应（Create World / Multiplayer / Load Game / Content Browser / Mod Manager）。
设置settings_statesettings 相位，或 menu 相位下的 Settings 页。
暂停面save_dialog_pending / load_dialog_pending / save_name / save_collision仅 pause 相位（pause_menu.rml 承载存档/读档对话框）。

跳过的通道不会清空面板：真 backend 为每个已注册通道保留最后一次 JSON，门控每帧重新求值，因此页面或面板重新可见的那一帧就会重建其载荷。rml_ui_phase_key() 已把世界内暂停子页面折叠进 menu/settings，所以按相位判断与屏幕实际内容一致。事件驱动的 publish_rml_ui_snapshots(changed_channels)（命令回复后的即时刷新）不参与门控，只过滤 0.2s 周期全量刷新。

全量刷新按帧预算分片：publish_rml_ui_snapshots_staged() 每帧只在 RML_UI_PUBLISH_FRAME_BUDGET_MS 预算内推进 RML_UI_SNAPSHOT_CHANNELS 的下一片，从下一次刷新游标继续，因此主线程不会在一帧里构建完整个通道列表并长时间持有模拟锁。colonist_list 与 storage_state 没有独立的线程内构建路径，它们和其它通道一样在刷新时经 engine.ui.data.snapshot(channel) 调用 CoreMod 注册的 provider（residents_views.lua / storage_snapshot.lua）。进入世界的强制全量刷新仍由主线程一次构建全部通道（面板立刻有值），所以入世界时仍可能出现一次数十毫秒的持锁。

O(tiles) 采样陷阱：WorldMap::sample_climate_for_chunk() 会遍历世界上每一个 tile 做反距离加权，所以任何"每帧 × 每格/每列"调用它都是 O(帧数 × 格数 × tile 数)。区块构建路径已用 ChunkManager::terrain_base_height_for_block() 的每区块角点缓存消掉这条（原为每区块约 1024 次全图扫描）；minimap_snapshot 曾是最后一个每帧调用者（17×17=289 格），现按 (m_world_lifecycle.world_generation(), 相机所在区块) 记忆化。该键是精确的：tile 的 q/r/elevation/temperature/moisture/water 在 WorldMapGenerator::generate() 之后不再被写入（classify_world_map_biomes() 只写 biome_id 与 map_color，而 minimap 配色不读这两者），且 Engine::m_world_map 的每一次赋值都发生在 m_world_generation 自增之后。给每帧路径新增全图采样前，先确认这一条。

职业树按需构建，不随 colonist_list 载荷走。colonist_list 的行不再包含 class_tree：该载荷会被序列化成 JSON 交给 RML 桥，而职业树的逐职业 abilities/equipment_options 曾占据其大头（实测：整列都带树时 20.8ms，只给选中行带树 14.8ms）。人员面板 colonists_panel.build_classes() 改为调用 require("network.career_client").query(uuid)（与面板同处一个 Lua 状态，数据不过桥），只在真正显示该殖民者时构建一次；[RmlUi][colonists] career_detail 诊断行在该殖民者的树内容变化时报告拿到的职业选项数量。注意：Engine/UI/RmlUiDataViews* 里的 selected_colonist_view.class_tree typed view 仍会解析该字段，因此它现在恒为空；当前没有任何 .rml 绑定它（面板走 Lua 视图模型），需要时再决定是否删除这个 C++ 视图。
Lua 快照分发按通道注册提供器。engine.ui.data.register(channel, provider) 由 CoreMod/scripts/listeners/mod_ready/*.lua 在 mod_ready 阶段逐通道登记（例如 resources_snapshot.lua 注册 resource_snapshot 与 resources，residents_views.lua 注册 colonist_list 与 colonists），engine.ui.data.snapshot(name) 只调用该通道自己的 provider，未登记的名字直接返回 nil，不存在兜底批量构造。因此给 RML_UI_SNAPSHOT_CHANNELS 添加通道时，必须在某个 mod_ready 监听器里为同名通道注册 provider，否则该通道只会得到 null。
通道必须登记才会被 typed view 看到。RealRmlUiRuntime::refresh_snapshots() 只轮询 RML_UI_CHANNELS 与 RML_UI_CONTROL_VARS 两个列表，lookup() 对未登记的通道返回空指针。selection_summary 和 main_menu_network_state 已登记在控制变量列表；旧 economy_alerts 已随警报栏删除。新增 engine-owned 通道时必须同时加进该列表，否则数据永远到不了文档。

ui_text 缓存：Engine::ui_text_snapshot_json() 以 LocalizationManager::revision() 为键缓存该载荷。revision 在任何本地化变更（加载、合并 MOD 翻译、set_locale、热重载、clear）时自增，所以控制台 locale_set 与保持同一 locale id 的热重载都能正确失效。该通道被 manage_hud.rml、building_design.rml、tech_tree.rml、battle_hud.rml、dev_console.rml 与主菜单共同绑定，因此不能按相位门控，只能按内容失效。

主线程 UI 计量：帧剖面把 UI 路径拆成 UiSnapshots（每帧业务推送块）、UiPublish（0.2s 全量刷新，含入世界强制刷新）、UiCmds（命令取件）与 UiDispatch（逐命令 Lua 派发）；WorldLoad 覆盖世界加载状态机（区块就绪扫描与 world:generate_initial_content），世界创建阶段另有三层已有的 DEBUG 分解，排障时先读它们、不要重复插桩：[WorldStart] new_world ... steps=[Setup, WorldMap, LuaRandom, TickState, ModWorldInit, Factions, BuildChunks, Landing]，其中 BuildChunks 展开为 [WorldStart] build_initial_chunks ... steps=[TerrainCache, CoreChunks, OuterEnqueue, NavFloodFill]，CoreChunks 再展开为 [WorldStart] core_chunks detail nav=... lighting=... meshing=... upload=... store=... chunks=...（lighting/meshing 带 (sum) 标记：核心 3×3 的光照与网格化跑在模拟线程池上并行，两个数字是各任务耗时之和，可大于 CoreChunks 墙钟；nav/upload/store 仍是串行墙钟）。--DEBUG_OPT:UI_STATS[=interval]（需同时带 --DEBUG）按窗口打印 UI 各段的 hits/均值/峰值，以及逐通道快照成本前 10 名 —— 该表覆盖 0.2s 全量刷新中仍在主线程构建的通道与每帧块里 8 个较贵的载荷构造器（minimap_snapshot、selection_summary、content_browser_state、settings_state、mod_manager_state、create_world_config、load_game_saves、main_menu_network_state），以及只剩一次字符串比较的 main_menu_background_rml（引擎缓存的背景滑片片段），因此不需要先看总量、再插桩定位单个构造器。

性能回归门：bash\PerfGate.bat（实现见 bash/PerfGate.ps1）会在固定窗口内跑一遍游戏，从日志里提取 WorldStart/CoreChunks/tick 总量与 ModTick/UiChannels/UiPublish/UiSnapshots/colonist_list 以及锁等待、[ERROR]、关闭期 Vulkan 泄漏计数，与 bash/perf_baseline.json 对比：时间类指标用百分比容差（默认 30%）并带 0.5ms 绝对下限（避免 0.03→0.04ms 的抖动误判），计数类指标只要增加就判回归（对锁等待/错误/泄漏，基线为 0 时在 JSON 里取多次运行的最大值以保持稳定，因此“修好后重记基线”才有意义）。取数默认跑两轮（-Runs）并逐指标取最优（时间取最小、计数取最大），以抵抗共享机器的波动。

负载闸：被占用的机器（游戏、其他构建、杀软扫描）会把每个指标等比放大，看起来像全项回归——实测过一次 79–81% CPU 下所有指标翻倍而代码未变。因此门禁在运行前后用 Win32_PerfFormattedData_PerfOS_Processor 采样总 CPU 占用，超过 -MaxCpuPercent（默认 35%）就拒绝判定并打印原因，可用 -Force 强制比较。退出码：0 通过、1 回归、2 找不到可执行文件、3 机器繁忙或无日志。-Record 重记基线，-Seconds/-TolerancePercent/-FloorMs/-Runs/-Exe 可调；默认优先用 output\NewColony\NewColony.exe（请先跑 bash\DebugExport.bat 导出当前构建），因此它比较的是同一套二进制与场景下的相对变化。导出目录为 output/NewColony/，bash/DebugExport.bat 和 bash/DebugExport.sh 同时生成 output/NewColony-<mmdd>-<id>.zip。日期取打包时的本地月日，序号取 output/ 下当天同名 ZIP 的最大数字序号加一，从 01 开始，至少两位；例如已有 NewColony-1104-01.zip 和 NewColony-1104-03.zip，下一个为 NewColony-1104-04.zip。其他日期和旧的 NewColony.zip 不参与编号，已有 ZIP 保留，压缩包内包含顶层 NewColony/ 目录。

模拟 tick 计量：模拟线程对应的是 --DEBUG_OPT:TICK_STATS[=interval]（同样需要 --DEBUG）：每个窗口按段打印 tick 内各段的均值与峰值，并给出 tick 总量均值/峰值，用于区分“每 tick 都在花”与“周期性尖峰”两类成本。Network 段已拆出 NetSnapshot（网络快照捕获）。[Perf] Slow simulation tick ... sections=[...] 只覆盖超过阈值的那一帧，读它是尾部样本而不是均值。模拟段与主线程 UI 段互不重叠：UI 计量的时间花在持锁的 0.2s 全量刷新上，会以 [Perf] Simulation mutex held ... 的形式体现在模拟线程等待里。

倍速卡顿通道计量：[Perf][SpeedCommand] 标记 Lua 实际应用的倍率与模拟 tick。模拟线程可因 owner task 在预定 tick 时间之前醒来；每次更新只按上一次更新至今的真实耗时推进 TickManager，提前唤醒不再额外计入完整 tick 周期，且不会推迟原定唤醒。客户端一次通道派发超过 50ms 时，[Perf][ClientChannels] 记录整批消息数、已派发数、连接通知数、取队列耗时和总耗时；随后按耗时排序，以 [Perf][ClientChannel] 打印前 8 个通道及字段的消息数、字节数、解码耗时和接收回调耗时。按通道拆分的数值用于定位批量积压来源，和帧日志中的 SimLock2、UiSnapshots 及模拟锁等待对照阅读。其他 UI 与模拟细分日志已移除；常规窗口统计仍可使用 UI_STATS 和 TICK_STATS。

DEBUG HUD 诊断叠层（debug_input）

debug_input.rml 是 F3 DEBUG HUD 诊断叠层（样式见 debug_input.rcss）：位于左上角，半透明、只读（pointer-events:none），不是业务面板，不承载主界面/主菜单/Settings/Content Browser/底部 HUD 功能，也不阻挡相机与 HUD 输入。内容由 Engine 每帧采集，经 debug_snapshot 桥通道（engine-owned，独立于业务十二通道契约，不经 Lua/ScriptEngine）推送到 RmlUiDataViews 的 debug_hud_rml typed view，文档用 <div data-rml="debug_hud_rml"> 绑定渲染。采集分七块：性能、模拟、历法、天气、相机、世界、种子/星球参数。

RealRmlUiRuntime::load_document() 在加载主文档 main.rml 之后，会让 RmlUiPanelRegistry 尽力副加载 debug_input.rml 到同一个 context。RmlUI 天然支持单 context 多文档叠加；验证面板默认隐藏，单按 F3 与 debug HUD 一起请求切换，但实际文档只在非 menu 阶段显示。文件缺失或解析失败属于非致命错误：日志里会出现 [RmlUi] debug_input.rml not available at '...'，主文档照常渲染。Null stub 不触发可见文档路径。

生命周期

  • init：RmlUiServer::init(doc_root, w, h) 创建 backend；真 backend 调 Rml::Initialise()、CreateContext("main", ...)，尝试加载字体。
  • load_document：入口文档 main.rml（相对 doc_root）；真 backend 解析为绝对路径后 context->LoadDocument() 并 Show()。
  • update / resize：每帧 context->Update()；窗口尺寸变化且 framebuffer 为非零尺寸时调用 context->SetDimensions()。窗口最小化或 Vulkan surface 暂时报告 0 extent 时，Renderer 暂停 swapchain recreate/acquire/present 并等待恢复，RmlUI 不接收 0×0 尺寸。
  • handle_input：鼠标移动、按钮、滚轮、键盘按下/释放和文本输入都经 RmlUiServer 转发到 backend；真 backend 按 RmlUI 6.3 API 调用 ProcessMouseMove、ProcessMouseButtonDown/Up、ProcessMouseWheel 和 ProcessKeyDown/Up。文本字符不再调用 RmlUI 原生 ProcessTextInput，而是投递到引擎伪输入命令。
  • shutdown：RemoveContext + Rml::Shutdown()。真 backend 的 Vulkan 资源（管线、描述符池、纹理，以及 Rml::Shutdown() 触发释放的编译几何顶点/索引缓冲与纹理）随 backend 一起在 RmlUiServer::shutdown() 内释放，时机早于 Renderer::shutdown() 销毁 device，因此 RmlUI 侧不存在 device 失效后释放的风险。
  • shutdown 的 GPU 排空约束：RmlUiServer::shutdown() 在 Engine::shutdown() 中位于 Renderer::shutdown() 之前调用，而 Renderer::shutdown() 才是引擎在退出阶段第一次排空 GPU 队列（vkDeviceWaitIdle）的地方。这意味着 RmlUI 释放资源时，最近一帧记录了 RmlUI 绘制的 command buffer 可能仍被 GPU 占用，其引用的顶点/索引缓冲、纹理 image view、sampler、管线会被 validation 层标记为"仍被 command buffer 使用"。运行中释放的 geometry 和 texture 进入按帧延迟回收队列；shutdown 时真 backend 在 RealRmlUiRuntime::shutdown() 入口、于 Rml::Shutdown() 之前调用 vkDeviceWaitIdle(renderer device)，并在 VulkanRmlRenderInterface::shutdown() 入口再排空一次（覆盖 backend 重建等独立析构路径），保证 GPU 不再持有 RmlUI 资源引用后才开始销毁。null stub 没有 Vulkan 资源，不受影响。

个人信息与职业树

个人信息页的“字段 / 值 / 详情”表头下方使用 3px 灰蓝色分割线，与数据内容分开。兼容层表格支持可选的 header_class 字符串，将额外 RCSS 类名附加到表头行；未提供时保留默认样式。个人信息页通过 colonists-personal-info-header 单独设置分割线。此调整尚未构建、运行静态检查、测试或游戏内验收。

个人信息的“职业”标签展示当前职业和职业履历。点击该页内的“转职”按钮打开独立的“职业之路”页面，返回后继续查看该居民的职业页。按住树的空白背景可上下左右拖动，窗口缩小时仍保留完整画布。职业节点均可查看详情，包括基础职业和暂时不满足转职条件的职业。

职业之路主窗口、职业节点、操作按钮、装备选项及悬停提示使用直角方框。窗口、树区域和 graph-viewport 在隐藏溢出的同时显式设置 clip: always，强制裁剪绝对定位的节点及连线；仅有 overflow: hidden 不保证 RmlUi 对此类子元素建立裁剪区域。树区域设置独立的 z-index: 0 层级，节点和高亮连线的层级限制在该区域内，详情面板保持在职业树上方。

悬停某个职业会突出其进阶路线和全部前置路径，其他节点及连线变淡。多前置职业的所有前置线均使用虚线；例如新晋医兵同时连接新晋民兵和学徒药剂师。高亮线位于普通线之上，节点位于连线之上。操作说明、阶级、等级上限、当前职业和职业等级通过悬停提示显示。

职业详情列出前置条件、等级能力和真实储存区装备。打开详情时左侧树保持清晰；点击左侧树区域只关闭详情，不选择下面的节点。Escape 先关闭详情，再返回个人信息。详情内容可滚动，关闭与确认控件保留在独立区域。

职业节点来自服务端已加载的职业注册表与角色职业快照，支持 Mod 提供的职业。布局由 CoreMod/scripts/ui/career_tree.lua 生成；career_tree_state 通过原生 typed DataView 绑定到 career_tree.rml。转职仍提交到现有服务端命令 core:colonists.change_class，由服务端重新核对装备来源和转职条件并排队；页面不会把排队成功显示为转职完成。世界卸载、断线及 Mod 关闭会清理页面状态。

career_tree_state 的发布由 CoreMod 的 Page.init() 通过 engine.ui.data.register("career_tree_state", Page.view, {publish=true}) 声明。引擎从当前客户端运行时自动发现发布通道，供定期和命令后按需刷新；原生接收端也按发布声明建立 JSON 绑定，不再要求修改两份 C++ 业务通道名单。职业树全屏透明根元素不接收鼠标事件，仅可见窗口恢复鼠标命中；内容隐藏或尚未收到快照时，透明根元素不会挡住下层界面。提供者撤销后的 null 快照会清空职业树视图及可见状态。页面显式使用已注册的 Unicode 字体族。后续需确认人员页“转职”入口、职业节点、返回/关闭及 Escape 的完整交互。

后续合并验收应覆盖小窗口、较长本地化文字、Mod 职业、多前置虚线及高亮、详情快速关闭、装备来源失效和真实转职排队结果。
