游戏内 RmlUI

游戏内 UI 的目标主路线是 RmlUI（HTML/CSS 风格、进程内渲染、合成进 Vulkan 画面）。本页记录它的依赖状态、资源入口、stub/真 backend 边界，以及把真 RmlUI 库接入构建的步骤。宿主层（RmlUiHost / RmlUiRuntime / RmlUiBridge）的接口与数据通道契约见 UI 框架 · 游戏内 RmlUI 宿主层。

引擎不再启动本地 HTTP server，不再以外部浏览器作为 UI 验收路径（ExternalBrowser / WebServer 已删除）。旧即时模式 UI 依赖也已从代码、构建和 vcpkg 依赖中移除。

当前状态（一句话）

玩家构建固定使用真实 RmlUI backend，构建系统无条件链接 RmlUi::RmlUi，在游戏窗口内绘制 main.rml 与副文档，并通过 RmlUiBridge 暴露通用数据模型与命令事件入口。NullRmlUiRuntime 只保留为显式诊断/失败回退路径；启用时会记录错误级日志且不渲染任何文档。

三层结构

组件文件职责
RmlUiHostEngine/UI/RmlUiHost.{hpp,cpp}引擎唯一集成点；持有后端与桥，暴露生命周期、输入、数据推送与命令消费。
RmlUiRuntimeEngine/UI/RmlUiRuntime.{hpp,cpp}RmlUI backend 抽象接口 + NullRmlUiRuntime stub + make_rml_ui_runtime() 工厂。
RealRmlUiRuntimeEngine/UI/RmlUiRealRuntime.{hpp,cpp}真 RmlUI backend，玩家构建必编译；负责生命周期、主文档加载、输入、原始通道绑定、命令事件与最小 Vulkan RenderInterface。
RmlUiPanelRegistryEngine/UI/RmlUiPanelRegistry.{hpp,cpp}真 backend 的副文档注册表；集中声明并尽力加载 debug_input.rml、hud.rml、build_panel.rml、research.rml、crafting.rml、colonists.rml、minimap_zone.rml、pause_menu.rml、dev_console.rml，挂载输入验证页调试监听器与 DevConsole 的 form submit/close 监听器，并在每帧把控制台可见时的键盘焦点送进输入框。
RmlUiDataViewsEngine/UI/RmlUiDataViews.{hpp,cpp}面板 typed/derived view 边界；集中注册与刷新 HUD 的 hud_* 字段、Build Panel 的 build_defs_list / construction_active_list / command_result_view，Research 面板的 research_nodes / current_research_view，Crafting 面板的 crafting_recipes_list / craft_result_view，Colonist 面板的 colonists_list / selected_colonist_view，Minimap/Zone 的 minimap_status / zone_mode / available_zone_tools，DevConsole 的 console_visible / console_history / console_prompt，以及 UI phase 派生的 main_menu_visible / playing_visible / pause_visible / pause_menu_visible / settings_visible 与 settings_rows。
RmlUiBridgeEngine/UI/RmlUiBridge.{hpp,cpp}C++ ↔ 文档层双向数据/事件通道（快照 + 命令队列），与具体 backend 无关。

面板 runtime 边界

新增 RML 面板时，资源注册和 typed view 不再直接堆进 RmlUiRealRuntime.cpp。副加载文档（入口 main.rml 之外的面板/验证页）统一登记在 RmlUiPanelRegistry.cpp 的注册表中，保持“缺失不致命、主文档照常渲染”的加载语义。面板需要的结构化 DataModel 字段统一放在 RmlUiDataViews.{hpp,cpp}：在 register_bindings() 注册 struct/array/bind，在 refresh() 从原始 JSON 通道派生 typed view，并只 dirty 变更字段。

RmlUiRealRuntime.cpp 仍保留稳定底座：创建 nc DataModel、绑定十二个原始 JSON 通道、缓存引擎推送的 UI 控制变量、处理通用 data-command / data-action click 事件、驱动 RmlUI 生命周期与 Vulkan 渲染。主菜单已迁到 RML 的完整页面 shell（Create World、Load Game、Multiplayer、Settings、Mod Manager、Content Browser、Wiki、Credits、Exit），游戏内 HUD 底栏也改为 RML 命令入口，用 core:panel.toggle 控制 Build、Craft、Colonists、Map/Zones 面板显隐；研究栏位当前保留为空按钮，不发送命令。后续面板不得替换原始通道名契约；typed view 只能作为面板专用的附加绑定。

main.rml 是最小游戏内 UI 占位（顶部状态条），不是浏览器网页布局。真 backend 由 RealRmlUiRuntime::load_document("main.rml") 加载；Null stub 下 load_document 返回 false（预期行为），但会记录请求的文档名与资源根用于诊断。

字体：RealRmlUiRuntime::init() 优先加载 <doc_root>/main.ttf。CoreMod 当前内置 Noto Sans Regular（Google / Noto Fonts 项目，SIL Open Font License 1.1；来源见 CoreMod/assets/ui/rml/FONT_SOURCE.md，许可见 NotoSans-OFL.txt），并随 staging 进入 cmake-build-release/bin/mods/core/assets/ui/rml/main.ttf。Windows 下的 C:/Windows/Fonts/arial.ttf 只作为项目字体缺失或损坏时的开发机兜底；缺字体不会导致启动失败。
字体家族名和字体样式必须精确匹配。RML 样式表的 font-family 要写成单一家族名 Noto Sans，不要带 CSS 风格的 , sans-serif 回退列表。RmlUI 会把整串值（含逗号和空格）当成一个家族名去查找，命中不了 LoadFontFace 注册的「Noto Sans」，结果文档里所有字形都不绘制，只剩没有文字的彩色矩形——主菜单不可见的根因之一就是这个。CoreMod 当前只加载 Noto Sans Regular，因此样式也应保持正体；不要在 RML/RCSS 中使用 font-style: italic，除非同时引入来源和许可清楚的斜体字形并在 backend 中加载。
dev 构建自动 staging：可执行文件按自身所在目录解析 core mod（EnginePaths::defaults() 令 base_dir = executable_dir()，故 core 路径为 cmake-build-release/bin/mods/core）。cmake --build --preset build-export-release 通过 stage_core_mod 这个 ALL 自定义目标，把整个 CoreMod/（Lua/data/assets/config/lang + mod.json）自动同步到该目录，每次构建都刷新（file(COPY) 增量，未改动文件不重写）。因此 main.rml/main.rcss 与 assets/shaders/rmlui.vert/rmlui.frag 总会出现在运行时目录，无需手动复制。同步复用 cmake/CopyDirectoryExcludingGit.cmake.in（与 wiki staging 同源）。

backend 选择

make_rml_ui_runtime() 工厂按以下顺序选择 backend：

条件返回
NC_UI_BACKEND=nullNullRmlUiRuntime（即使真 backend 已编译也强制 stub，便于无头/自动化运行）。
未设置 / 空 / rmlRealRmlUiRuntime（backend_name()=="rml-real"，is_real_backend()==true）。
真实 backend 初始化失败NullRmlUiRuntime stub（失败回退；不渲染文档，日志明确报错）。

Fallback：真 backend 的 init() 失败时，RmlUiHost::init() 会 shutdown 它并用 make_null_rml_ui_runtime() 替换，宿主层照常运行，游戏绝不因缺依赖崩溃。

接入真 RmlUI backend

vcpkg.json 已包含 rmlui 端口依赖（v6.1，默认 feature freetype，CMake 目标 RmlUi::RmlUi）。普通玩家构建会编译 RmlUiRealRuntime.cpp 并使用真实 backend。诊断/自动化场景如需禁用可见 UI，可设置 NC_UI_BACKEND=null：

  1. 常规 configure：cmake --preset export-release。第一次配置会让 vcpkg 安装/复用 rmlui[core,freetype] 及其依赖。
  2. 构建：cmake --build --preset build-export-release。构建脚本会 find_package(RmlUi CONFIG REQUIRED)、把 UI/RmlUiRealRuntime.cpp 加入编译并链接 RmlUi::RmlUi。
# vcpkg.json 片段
{
  "dependencies": [
    ...
    "rmlui"
  ]
}

RmlUI 不是可关闭的构建选项；null stub 只通过 NC_UI_BACKEND=null 或真实 backend 初始化失败进入。

验证状态：RealRmlUiRuntime.cpp 已适配 RmlUi 6.1 的 RenderInterface 签名（CompiledGeometryHandle、Span、Rectanglei、GenerateTexture 返回 texture handle）。本机已验证 cmake --preset export-release 与 cmake --build --preset build-export-release 通过。短启动验证显示 real backend 初始化为 rml-real，并成功加载 main.rml。

数据模型与命令事件

RealRmlUiRuntime 在 RmlUI context 上创建名为 nc 的 DataModel。当前通用层把十二个稳定通道全部绑定为 JSON 字符串变量：world_info、resource_snapshot、colonist_list、event_list、tech_tree、view_modes、orders_kinds、build_defs、craft_recipes、combat_state、construction_active、command_result。每帧 update 前，runtime 从 RmlUiBridge::latest_snapshot(channel) 读取最新值；缺通道或空字符串会暴露为 null，不会让文档层崩溃。变量变化时调用 DataModelHandle::DirtyVariable(channel)，由 RmlUI 在后续 Context::Update() 中刷新绑定。

RML 文档使用 data-model="nc" 后可直接绑定这些变量，例如 {{world_info}} 或 {{resource_snapshot}}。通用层始终保留原始 JSON 字符串绑定；特定 RML 面板可以在 RmlUiDataViews 内叠加最小 typed/derived view，但不得替换十二个通道名契约。command_result 也是同一个数据模型变量，由 Engine::dispatch_rml_ui_command() 写入桥后进入文档层。

列表绑定约定：当前 RML 静态文档不直接在循环体内写 data-for 别名字段（例如 {{def.id}}、data-attr-data-param-id="def.id"）。RmlUI 6.1 的当前 Windows/vcpkg runtime 在启动加载阶段会把这些循环体当作普通静态元素解析，导致别名变量解析诊断。列表仍由 RmlUiDataViews 的 typed views 维护；C++ 从 typed rows 生成已转义的 RML 片段，暴露为 *_rml 字符串（如 build_defs_rml、research_nodes_rml、console_history_rml），RML 文档用 data-rml="..." 挂载。空数组输出空字符串，仍由 *.size == 0 的静态空态控制；未知状态只作为普通文本写入；按钮行写最终 data-command 与 data-param-* 属性，继续走同一个 context 级命令监听器。

除十二个业务通道外，runtime 还缓存一组UI 控制变量（与业务通道分开维护，不参与和 ScriptEngine/Lua 的数据契约）。当前有 ui_phase（取值 "menu" / "playing" / "pause" / "settings"），由引擎每帧按世界、暂停菜单和设置 shell 状态推入桥；RmlUiDataViews 将它暴露为 typed binding，并派生 main_menu_visible、playing_visible、pause_visible（pause 或 settings 都为真，控制遮罩背景）、pause_menu_visible（仅 pause 为真，控制按钮列表本身）、settings_visible（仅 settings 为真）与 settings_rows。RML 文档使用这些布尔派生变量做 data-if，避免依赖字符串表达式兼容性。

文档到引擎的通用命令入口是 context 级 click 监听。监听器从事件目标向父级查找 data-command 或 data-action，找到后向 RmlUiBridge::enqueue_command({target, payload}) 入队。payload 规则：若元素带 data-payload，其内容作为 JSON 字符串原样入队；否则把所有 data-param-* 属性打包成简单 JSON 对象，例如 data-param-id="x" 会产生 {"id":"x"}。onclick 属性也作为 target fallback 读取，便于迁移旧写法；推荐新 RML 使用 data-command。

Pause / Settings MVP

pause_menu.rml 是当前最小暂停与设置入口。真 backend 加载 main.rml 后由 RmlUiPanelRegistry 尽力副加载 pause_menu.rml；文件缺失或解析失败不影响主文档。Null stub 只在显式诊断/失败回退路径下存在，不加载文档。

引擎继续使用既有 MainMenuState::pause_visible 与 TickManager::set_paused()。游戏中按 Escape 会打开/关闭暂停菜单；暂停菜单可见时，普通游戏快捷键和相机更新不会继续处理。RmlUI 按钮使用引擎拥有命令：core:pause.resume 取消暂停并返回游戏，core:pause.settings 保持暂停并切到设置 shell，core:pause.quit_game 调用 request_exit()。当前不提供 Quit to Menu，因为返回主菜单生命周期还没有明确的可复用流程。

Pause / Settings typed view 由 RmlUiDataViews 提供：ui_phase、pause_visible、pause_menu_visible 和 settings_rows。文档布局上 #pause-overlay（暗色遮罩）在 pause 和 settings 阶段都显示，body 与遮罩显式铺满 RmlUI 视口，当前可见面板用 left/top: 50% 和负 margin 做绝对居中；#pause-menu（Resume/Settings/Quit Game 按钮列表）只在 pause_menu_visible 为真时进入布局，#settings-shell 只在 settings_visible 为真时进入布局，两者互斥，避免设置阶段按钮列表与设置 shell 同屏重叠。设置 shell 只显示安全占位状态行：当前语言（来自 world_info.locale 派生的 hud_locale）和 UI backend（当前真 backend 为 rml-real）。音量、图形和控制项不会在这里写配置，直到对应配置入口有明确 RmlUI 路径。

互斥派生变量的由来。先前 #pause-menu 与 #settings-shell 都用 pause_visible / settings_visible 控制，而 pause_visible 在 settings 阶段也为真，结果两块同尺寸的绝对定位面板在设置阶段同屏重叠绘制。新增只在该相位为真的 pause_menu_visible，让按钮列表与设置 shell 互斥：#pause-menu 改用 data-if="pause_menu_visible"，遮罩继续用 pause_visible。这是 RML/typed-view 层的小修，不改动 Escape 路径或暂停状态机。

Minimap / Zone MVP

minimap_zone.rml 与 minimap_zone.rcss 是当前最小小地图 / 区域入口。真 backend 加载 main.rml 后由 RmlUiPanelRegistry 尽力副加载到同一个 RmlUI context；文件缺失或解析失败不影响主文档。Null stub 只在显式诊断/失败回退路径下存在，不加载文档、不解析该面板数据。

面板新增三个派生绑定：minimap_status、zone_mode、available_zone_tools。minimap_status 从 world_info 派生日期文本，从 view_modes 派生当前视图模式，从 construction_active 派生活跃施工计数；因为当前十二个稳定通道里没有 minimap 纹理、camera footprint 或 world-map tile 数据，has_map=false，地图框明确显示占位状态。available_zone_tools 从 orders_kinds 派生按钮行，当前主要覆盖已有的 mine/chop designation 工具。

主菜单（Main Menu MVP）

主菜单是最小可用的开始/退出入口，直接画在 main.rml 内（不开新文档、不依赖已移除的即时模式 UI 或浏览器）。面板包在一个 <div data-if="main_menu_visible"> 里：引擎进入世界后 ui_phase 变为 "playing"，main_menu_visible 变为 false，面板自动从文档布局中移除；回到主菜单（世界卸载）后又自动出现，无需额外开关。面板使用明确 px 单位和绝对定位，保证 RmlUI hit-test 的可点击几何与屏幕位置一致。面板提供两个按钮和一行小型状态文本：

按钮data-command引擎侧动作
Start Worldcore:menu.new_game置 start_world_pending（种子缺省时随机一个），主循环随后调用现有 Engine::start_new_world() 流程生成世界；ui_phase 下一帧切到 "playing"，主菜单自动隐藏。
Wikicore:menu.wiki解析可执行文件旁边的 wiki/index.html，并交给系统默认浏览器打开；不再进入主菜单内的 Wiki 二级页面。
Exitcore:menu.quit调用现有 Engine::request_exit()，主循环退出。

这两个 target 是引擎级命令，在 Engine::dispatch_rml_ui_command() 顶部拦截、直接驱动生命周期，不转发给 Lua UI 命令处理器，也不会写 command_result。它们与既有宿主命令 core:rmlui.reload、smoke 命令 core:rmlui.debug_ping 不冲突。main.rml 顶部状态条与 core:rmlui.debug_ping 按钮作为 smoke 绑定保留，不随菜单显隐。

可见性是 UI 行为，不是开始游戏的判定条件。世界是否在运行始终由 m_world_active 决定；ui_phase 只是把同一事实镜像给文档，让面板显隐。若点击 New Game 后世界生成出现的问题，属于既有世界生成流程，与 RmlUI 无关。
主菜单不可见的两个根因（已修复）。其一，RmlUI 的字体匹配把样式表里的 font-family: "Noto Sans", sans-serif 当成单个家族名「Noto Sans , sans-serif」去查找，永远命中不了 LoadFontFace 注册的「Noto Sans」，于是文档里所有字形都不绘制——窗口上只剩没有文字的彩色按钮块（深灰 Quit、蓝色 New Game），主菜单因此看不出形状，只被当成两根色条。把全部 RML 样式表的字体声明改成单一家族名 font-family: Noto Sans 后，标题「New Colony」、状态行与「New Game / Quit」按钮文字都恢复。其二，字形虽然画出来了，但整张 UI 是上下颠倒的：RmlUI 给的是屏幕像素坐标（原点在左上、纵向向下），而 rmlui.vert 里纵向分量沿用了 OpenGL 的翻转写法，在 Vulkan 视口（同样原点在左上、纵向向下、视口高度为正）里等于多翻了一次，于是 topbar 落到窗口底部、主菜单面板跑到下方、字形头朝下。把顶点纵向分量改成与 Vulkan 视口一致的直接映射后，topbar 回到顶部，主菜单回到左上 top:60px left:32px 的位置，文字方向正常。这一层翻转此前被字体缺失掩盖，文字一旦恢复才显出来。
New Game 真人端到端复验。ON 构建启动后主菜单可见、文字正向；用注入点击命中「New Game」按钮，日志依次出现 [RmlUi] command 'core:menu.new_game' payload={}、[RmlUi] main menu: New Game requested、[World] start_new_world(...) 与 [World] World started，随后 ui_phase 由 menu 切到 playing、main_menu_visible 变为 0，主菜单按预期隐藏。本轮没有再出现 integer value will be misrepresented in lua，世界成功启动；Lua seed 修复点暂未触发新阻断，留待世界内进一步观察。
副面板空态字体约束（已修复）。建造/制造/研究/殖民者/小地图等副面板的空态占位文本曾使用 font-style: italic，但 CoreMod 当前只加载 Noto Sans Regular，RmlUI 找不到「Noto Sans [italic]」时会逐元素告警且不绘制这些文本。空态文字只是弱化提示，现已统一改回正体，通过颜色区分层级，避免新增字体资源和运行时告警。
可见性诊断。RealRmlUiRuntime 在每次文档加载后会输出一行 [RmlUi][vis]，报告 #main-menu 是否在布局中、它的偏移尺寸与按钮尺寸；RmlUiDataViews 在 ui_phase 每次变化时输出一行派生结果（main_menu_visible/playing/pause/settings）；render() 首帧会输出一行确认主文档可见与渲染尺寸。这些都是低噪声、只在加载或相位变化时各一行，便于以后主菜单再次回归时从 latest.log 直接定位是「面板没进布局」「没被绘制」还是「相位派生错」。

渲染路径（RenderInterface）

RmlUI 通过 Rml::RenderInterface 把文档几何交给宿主渲染后端。真 backend 当前实现了最小 Vulkan path：RmlUI compiled geometry 上传到 host-visible VMA 顶点/索引缓冲，纹理通过 VulkanTexture 上传并绑定 descriptor，支持 scissor，RealRmlUiRuntime::render(VkCommandBuffer) 会在 renderer UI callback 中调用 context->Render() 并录制 draw call。RmlUI 释放 compiled geometry 或 generated texture 时，backend 不会立即销毁 Vulkan 资源，而是按帧延迟回收，避免页面切换、输入框聚焦和 caret/文本重排期间上一帧 command buffer 仍引用已释放的 buffer、image view 或 sampler。

接入点：

  • Renderer::add_ui_render_callback() 维护 UI draw 回调链；旧 debug/UI overlay 已禁用，RmlUI 是唯一目标 UI 渲染路径。
  • Engine.cpp 在 RmlUI host 初始化后追加 m_rml_ui_host.render(cmd)，不启动浏览器、不走 HTTP/WebServer。
  • CoreMod/assets/shaders/rmlui.vert / rmlui.frag 由现有 MOD shader 预处理生成 SPIR-V。

当前限制：这是最小占位 UI 渲染路径，不包含复杂 effect、clip mask、render-to-texture、图片文件加载或业务面板。文本优先使用随 CoreMod staging 的 main.ttf；如果项目字体缺失或损坏且平台 fallback 不存在，矩形仍可渲染但文字不会显示。

顶点坐标约定：RmlUI 供应的顶点是屏幕像素坐标（原点在左上、纵向向下），rmlui.vert 用 push constant 里的视口尺寸把它映射到 Vulkan 裁剪空间。Vulkan 视口同样原点在左上、纵向向下且高度为正，因此纵向分量必须用直接映射（像素 / 视口 × 2 − 1）；若误用 OpenGL 的翻转写法，整张 UI 会上下颠倒——topbar 落到窗口底部、主菜单跑到下方、字形头朝下。

输入路由与焦点捕获

InputManager 是 GLFW 输入入口。初始化 RmlUI host 后，Engine 会把 RmlUiHost 指针交给 InputManager；每个 GLFW 回调先注入 RmlUI，再保留现有游戏输入状态，游戏侧随后通过 ui_wants_mouse() / ui_wants_keyboard() 决定是否处理相机、选择、建造和快捷键。

GLFW 事件RmlUI 调用说明
cursor positionContext::ProcessMouseMove(x, y, modifiers)窗口坐标直接传入 RmlUI context。
mouse buttonProcessMouseButtonDown/Up(button, modifiers)GLFW left/right/middle button index 与 RmlUI button index 对齐；按钮回调会即时读取 glfwGetCursorPos()，避免使用过期的 cached cursor position 点击到旧坐标。
scrollProcessMouseWheel(Vector2f(dx, dy), modifiers)保留 GLFW 的水平/垂直滚轮 delta。
key press/release/repeatProcessKeyDown/Up(key_identifier, modifiers)按键通过 GLFW key 映射到 Rml::Input::KeyIdentifier。
charProcessTextInput(codepoint)用于文本输入；控制台反引号打开逻辑会吞掉对应字符，避免误输入。

Key 映射覆盖字母、数字、F1-F24、Escape/Enter/Tab/Backspace/Space、方向键、Home/End/Page、Insert/Delete、锁定键、左右 Shift/Ctrl/Alt/Super、数字小键盘和常用 US 符号键。Modifier 由 GLFW mods 与当前按键状态合并，映射到 RmlUI 的 Ctrl/Shift/Alt/Meta/CapsLock/NumLock 位；窗口启用 GLFW_LOCK_KEY_MODS 以便 GLFW 在支持的平台上提供 CapsLock/NumLock 状态。

捕获规则：当鼠标按下起点位于实际 UI 交互区域，或光标 hover 在按钮、带 data-command/data-action/onclick 的元素、输入控件、或计算样式为 pointer-events:auto 的非 rml/body 区域内时，wants_mouse=true，游戏不处理鼠标点击、拖拽和滚轮驱动的选择/相机逻辑；只用于覆盖展示的 HUD 壳层应保持 pointer-events:none，不会阻挡右键相机拖拽。当 RmlUI 有焦点元素时，wants_keyboard=true，游戏不处理文本输入和冲突快捷键。按 Escape 时，如果 RmlUI 当前持有键盘焦点，Engine 优先调用 RmlUiHost::clear_focus()，不触发暂停菜单/取消建造等游戏动作。Null backend 下所有输入安全忽略，wants_mouse 和 wants_keyboard 始终为 false。

输入验证页（debug_input）

为了实测上述输入路由是否真的端到端打通，CoreMod 提供一个最小交互验证面板 debug_input.rml（样式见 debug_input.rcss）。它不是业务面板，由真 backend 加载，用于验证 hover / click / 文本输入 / scroll / 焦点 / Escape blur。

RealRmlUiRuntime::load_document() 在加载主文档 main.rml 之后，会让 RmlUiPanelRegistry 尽力副加载 debug_input.rml 到同一个 context。RmlUI 天然支持单 context 多文档叠加，因此验证面板与主文档同帧渲染。文件缺失或解析失败属于非致命错误：日志里会出现 [RmlUi] debug_input.rml not available at '...'，主文档照常渲染。Null stub 不触发这条路径。

验证面板包含三类控件，并在加载后由 RmlUiPanelRegistry 挂上 DebugInputEventListener（一个 Rml::EventListener），把事件以单行 [RmlUi][debug] 形式写入 game/logs/latest.log：

字体：验证面板与其它 RML/RCSS 文档统一使用 font-family: "Noto Sans", sans-serif，真 backend 启动时优先从 staged main.ttf 加载该字体。若字体文件缺失，输入验证仍不因文字失败而阻断；日志会明确说明是否使用系统 fallback。

生命周期

  • init：RmlUiHost::init(doc_root, w, h) 创建 backend；真 backend 调 Rml::Initialise()、CreateContext("main", ...)，尝试加载字体。
  • load_document：入口文档 main.rml（相对 doc_root）；真 backend 解析为绝对路径后 context->LoadDocument() 并 Show()。
  • update / resize：每帧 context->Update()；窗口尺寸变化且 framebuffer 为非零尺寸时调用 context->SetDimensions()。窗口最小化或 Vulkan surface 暂时报告 0 extent 时，Renderer 暂停 swapchain recreate/acquire/present 并等待恢复，RmlUI 不接收 0×0 尺寸。
  • handle_input：鼠标移动、按钮、滚轮、键盘按下/释放和文本输入都经 RmlUiHost 转发到 backend；真 backend 按 RmlUI 6.1 API 调用 ProcessMouseMove、ProcessMouseButtonDown/Up、ProcessMouseWheel、ProcessKeyDown/Up 和 ProcessTextInput。
  • shutdown：RemoveContext + Rml::Shutdown()。真 backend 的 Vulkan 资源（管线、描述符池、纹理，以及 Rml::Shutdown() 触发释放的编译几何顶点/索引缓冲与纹理）随 backend 一起在 RmlUiHost::shutdown() 内释放，时机早于 Renderer::shutdown() 销毁 device，因此 RmlUI 侧不存在 device 失效后释放的风险。
  • shutdown 的 GPU 排空约束：RmlUiHost::shutdown() 在 Engine::shutdown() 中位于 Renderer::shutdown() 之前调用，而 Renderer::shutdown() 才是引擎在退出阶段第一次排空 GPU 队列（vkDeviceWaitIdle）的地方。这意味着 RmlUI 释放资源时，最近一帧记录了 RmlUI 绘制的 command buffer 可能仍被 GPU 占用，其引用的顶点/索引缓冲、纹理 image view、sampler、管线会被 validation 层标记为"仍被 command buffer 使用"。运行中释放的 geometry 和 texture 进入按帧延迟回收队列；shutdown 时真 backend 在 RealRmlUiRuntime::shutdown() 入口、于 Rml::Shutdown() 之前调用 vkDeviceWaitIdle(renderer device)，并在 VulkanRmlRenderInterface::shutdown() 入口再排空一次（覆盖 backend 重建等独立析构路径），保证 GPU 不再持有 RmlUI 资源引用后才开始销毁。null stub 没有 Vulkan 资源，不受影响。

退出顺序约束（引擎级，非 RmlUI 自身）：历史上短启动退出末尾的 0xC0000005 曾被怀疑为 RmlUI shutdown，实际根因在 mod 生命周期回调：mod 的 on_world_init/on_tick/on_shutdown 回调捕获了指向 Lua 函数的引用，其析构会回访 Lua 状态。因此这些引用必须在脚本引擎关闭 Lua 状态之前释放。ModLoader::release_lua_references() 在 Engine::shutdown() 关闭脚本引擎之前清空回调向量，确保 ~ModLoader 析构时不再触达已关闭的 Lua 状态。RmlUI shutdown 本身顺序正确，无需为该崩溃调整。
