袭击注册

袭击定义（Raid）放在 data/raids/ 下，以 JSON 描述。一条记录声明“由谁来袭、来多少人、从多远来、持续多久”。RaidSystem 负责读取定义、按权重抽取敌人组合、把来袭者生成到目标周围并让他们走向目标；命中、伤害和攻击冷却公式不在这里定义。

JSON 格式

{
    "id": "my_mod:probe",
    "faction": "my_mod:raiders",
    "origin": "settlement",
    "enemy_groups": [
        { "entity_id": "my_mod:raider", "weight": 3.0, "count_min": 2, "count_max": 4 },
        { "entity_id": "my_mod:raider_heavy", "weight": 1.0, "count_min": 1, "count_max": 2 }
    ],
    "group_picks_min": 1,
    "group_picks_max": 2,
    "max_attackers": 6,
    "waves": 2,
    "wave_interval_ticks": 600,
    "spawn_distance_min": 24.0,
    "spawn_distance_max": 40.0,
    "alert_level": 1,
    "max_duration_ticks": 12000
}

origin 为必填字段，只接受 settlement 或 generated_bandits。前者的来源 UUID 在触发时明确指定，保存于 Raid 状态及各波袭击者的归属字段；后者没有殖民地来源。控制台用 raid <raid_id> [source_instance_uuid]。

字段说明

字段类型必填说明
idstring是唯一标识，格式 <mod_id>:<name>。
factionstring是来袭者的阵营数据 ID。生成时写入 ecs::Civilization，因此 CombatSystem::faction_id_of 会返回该阵营而不是中立。相对 ID 会按当前 MOD 前缀补全。
enemy_groupsobject[]是非空、entity_id 不重复的加权敌人组数组，语义与产出表一致（权重 + 闭区间数量），但选择的是实体原型而不是物品。
enemy_groups[].entity_idstring是实体原型 ID。必须存在于 data/entities/；带 ColonistTag 的殖民者原型会被拒绝。
enemy_groups[].weightnumber是该组被抽中的相对权重，必须大于 0。
enemy_groups[].count_min / count_maxpositive integer是该组入选后生成数量的闭区间，count_max >= count_min。先抽组，再在区间内抽数量。
group_picks_min / group_picks_maxpositive integer是每波从 enemy_groups 中抽取多少个不同的组（不重复抽取）。必须满足 1 <= min <= max <= enemy_groups.size()。
max_attackerspositive integer是单波生成上限。RaidSystem 不会超过该值；这是唯一的硬上限。
wavespositive integer是波数。每波重新抽取组合，因此同一场袭击的敌人构成会变化。
wave_interval_ticksnon-negative integer是两波之间的间隔（ticks，20 ticks = 1 秒）。0 表示下一波紧接着上一波。
spawn_distance_min / spawn_distance_maxnumber是来袭者相对目标的生成距离（格）的闭区间，必须 min > 0 且 max >= min。方向按确定性随机取角度，因此来袭者会从目标周围一圈出现。
alert_levelnon-negative integer是警报等级，原样出现在状态摘要、Lua 接口和 raid:started 等事件中，供 UI 或脚本决定表现。
max_duration_ticksnon-negative integer否0 或缺省表示“来袭者全部消失才结束”。大于 0 时在该时长后让残余来袭者撤离（从世界中移除）并以 duration_elapsed 结束。
记录里只有“投送”参数，没有命中率、伤害、攻击冷却或压制公式。NCDOCS 尚未定义战斗专项规则，因此 RaidSystem 生成的是带有阵营、生命、移动属性和导航组件的普通实体，不结算伤害，也不从旧原型恢复任何数值。

随机化如何发生

  1. 每波先用权重抽取 group_picks_min 到 group_picks_max 个不同的敌人组。
  2. 每个入选组在自己的 count_min–count_max 区间内抽取数量，再乘以当前难度的袭击倍率。
  3. 总量被 max_attackers 截断；waves > 1 时每波重复上述过程。

随机数来自 Xoshiro256，种子由世界种子、袭击实例编号、波次和 tick 组合而成，不使用系统时钟，因此同一存档在相同操作序列下会得到相同的敌人构成，便于复现和联机同步。

来袭者死亡后的掉落沿用实体原型自带的 death_output_table。产出表支持 "selection": "weighted_one"，把多行战利品按权重抽一行，于是“敌人构成随机”和“掉落随机”可以分别用两层数据表表达。

投送与目标

  • 目标优先取 BuildingSystem::select_raid_target()：已完成的城镇大厅（稳定实例 ID 最小者），否则价值最高的玩家建筑。
  • 既没有大厅也没有高价值建筑时，退化为殖民者平均位置（殖民地中心），这样在建成第一座建筑之前也能验证袭击链路。
  • 目标每 100 ticks 复核一次；目标建筑被摧毁或新建大厅后，来袭者会改用新的目标重新寻路。
  • 移动复用现有导航链路：NavAgent + MovementTarget + MovementIntent，由 NavigationSystem、EntityMovementSystem 和 EntityPhysicsSystem 推进。来袭者的基础速度来自顶层 move_speed，状态修正来自属性 Map。与其它实体一致，位于强加载范围外的来袭者不会推进，直到所在区块被加载。
  • 来袭者的战斗属性由原型引用的 battler pack 在生成时展开到属性 Map；RaidSystem 不安装第二份属性组件。袭击结束并撤退时，系统在销毁兵模前清理对应实体的运行时属性修正组。

难度倍率

难度的“袭击”维度倍率（DifficultyRuntimeState::raid_multiplier）在触发时读取：0 表示关闭袭击并拒绝预约（原因 raid_disabled_by_difficulty），大于 0 时按比例缩放每个入选组的数量（至少保留 1 个）。

运行时接口

接口说明
engine.raids.list()已注册的袭击定义 ID 列表。
engine.raids.definition(id)单条定义的全部字段与 enemy_groups 行；不存在时 exists=false。
engine.raids.active()当前进行中的袭击摘要：实例 ID、定义、阵营、来源殖民地 UUID、警报等级、波次、存活/累计人数和目标坐标。
engine.raids.trigger(id, source_instance_uuid)origin=settlement 必须传现存且属于声明派系的来源殖民地 UUID；origin=generated_bandits 必须传空字符串。返回袭击实例 ID；失败返回 0，原因见 engine.raids.last_error()。客户端返回 0。
engine.raids.configuration_error()配置屏障原因，例如 raids_missing 或 raid_enemy_group_invalid。
require("systems.raid_data")Lua 侧薄封装：definitions()、definition(id)、active()、trigger(id, source_instance_uuid)、raw_json(id)、configuration_error()。

袭击生命周期会发布 raid:started、raid:wave 和 raid:ended 事件，载荷包含 instance_id、def_id、faction_id、source_instance_uuid、reason、alert_level、wave_index、waves、spawned、alive 和 tick。结束原因目前有 attackers_cleared 和 duration_elapsed。

存档与联机

进行中的袭击随世界存档保存（raids_schema_version + raids 实例数组），来袭者本身仍是普通实体记录，成员按稳定实体 ID 恢复。Server 的通用世界状态同步包含同一份数据，客户端不自行触发或推进袭击。

CoreMod 测试内容

ID说明
core:mvp_test_raid两波、两组权重的系统验证用袭击，目标 1 号警报等级，12000 ticks 后撤离。仅用于贯通加载、随机抽取、投送和结束链路，不代表正式平衡。

core:mvp_test_raider_deathweighted_one 产出表：木棍（权重 3）或测试野生食物（权重 1）。

文件放置规则

  • 放在 data/raids/ 下，支持子目录。
  • 文件名随意，引擎只关心 JSON 内的 id 字段。
  • 引用的实体原型必须同时存在于某个已加载 MOD 的 data/entities/，否则加载会被拒绝。

验证命令

raid                          -- 列出已注册的袭击定义
raid status                   -- 查看进行中的袭击
raid core:mvp_test_raid       -- 触发一场测试袭击
list_data raids               -- 通过数据注册表查询
data raids core:mvp_test_raid -- 查看原始 JSON
