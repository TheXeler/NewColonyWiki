UI 图片资源

客户端 UI 图片由引擎按目录自动收集，mod.json 不再声明图片或图片池。当前唯一的自动资源池是主菜单背景图。

主菜单背景图（自动扫描）

启用中的每个 MOD 都可以把背景图放进自己的 assets/background/ 目录。引擎启动时递归扫描所有启用 MOD 的该目录，把找到的图片组成背景图池。不写任何 mod.json 配置。

my_theme/
  mod.json
  assets/
    background/
      background001.png
      background002.png
      deep_space/
        nebula.jpg

启动后引擎随机从池中抽一张作为主菜单背景，之后每 30 秒淡入淡出切换到池中另一张：旧图保持不透明，新图以 1.2 秒淡入覆盖上去。池中只有一张图时不切换；池为空时主菜单只显示 #main-menu 的底色。

支持的扩展名是 PNG、JPG/JPEG、BMP、TGA、GIF（大小写不敏感），由 RmlUI 的 stb_image 解码路径读取。子目录会被递归收集，文件名没有约定。

池的构造与 MOD 加载顺序无关：所有路径解析为绝对路径后排序并去重，所以同一批 MOD 和文件总是得到同一个池；只有“本次启动从哪张开始”和“下一张是谁”是随机的。

背景图是客户端表现资源，不参与方块纹理图集，也不会写入 generate/ 中间目录。不要把全屏 UI 背景放进 assets/textures/block/。
旧的 mod.json ui 字段（ui.images、ui.image_pools、ui.main_menu）已删除，加载器现在完全忽略该字段。迁移方式只有一步：把图片移入 assets/background/。

背景上的可读性遮罩由引擎固定（黑色 35% 不透明度），滑片间隔定义在 Engine/UI/MainMenuBackground.hpp（30 秒），淡入动画与遮罩样式定义在 CoreMod/assets/ui/rml/main_menu/styles/base.rcss。两者都不可由 MOD 覆盖。

RML/RCSS 文档资源（RmlUI 入口）

游戏内 RmlUI 的文档资源放在 <core_assets>/ui/rml/（即 CoreMod/assets/ui/rml/）。这是当前正式玩家可见 UI 资源目录，与 assets/background/ 背景图池相互独立，不进方块纹理图集。

CoreMod/assets/ui/rml/
├── main.rml      # 入口文档（RmlUiHost 默认加载 main.rml）
└── main.rcss     # main.rml 链接的 RCSS 样式

main.rml 是游戏内 UI 入口文档，不是浏览器网页布局。默认玩家构建由 RealRmlUiRuntime 加载并渲染；Null stub 只在显式诊断/失败回退路径下存在，不实际加载文档。HUD 的右上角时间条由 hud.rml/hud.rcss 渲染，并包含暂停、1x、2x、4x、无限速按钮。暂停使用 core:time.pause，其余倍率使用 core:time.speed。依赖状态、CMake option、stub/真 backend 边界见 游戏内 RmlUI。

字体：CoreMod 和发行包不包含字体文件。真 backend 只加载操作系统的 Unicode 字体，并以统一的 Unicode 家族名提供给 RML/RCSS；缺少系统候选字体不会阻止启动。

加载与热重载

  • 入口：RmlUiHost::init() 默认加载 main.rml。
  • 热重载：页面发 core:rmlui.reload 命令，或开发期调用 engine.rml_ui().reload()。
  • 创建或读取世界时，main.rml 先显示复用启动视觉的加载进度条；只有相机可见半径内的区块全部达到可渲染状态后，Host 才触发 on_world_init() 并重推 world_info。
完整桥契约（C++ ↔ 文档的快照与命令）、生命周期、当前支持/未支持能力，见 UI 框架 · 游戏内 RmlUI 宿主层。
