Building design system

Building designs are sparse semantic documents compiled into authoritative block cells. Object order is significant: later objects replace earlier cells, deletions reveal the preceding object, and explicit cell overrides are applied last. A design has no editor canvas size limit.

Block metadata

Every block with placeable: true must declare palette_category, palette_order, a non-empty duplicate-free allowed_directions array, can_support, positive construction_work, and positive durability_contribution. Optional building_capabilities are attached to the block cell. Invalid metadata rejects the mod data record.

Direction and persistence

Block direction is a six-way value: east, west, up, down, north, or south. It is independent of the legacy data byte. Chunk palettes, region files, network chunk deltas, live block updates, and model rendering retain this value. Region and network formats intentionally reject the previous format; this pre-release subsystem has no compatibility adapter.

Compilation and support

Compilation derives bounds, one matching item per cell, total work, total durability, capability points, and direction validity. Whole-building rotation changes horizontal coordinates and directions together.

Blueprint content IDs use BLAKE3-256 over deterministic canonical binary content. The local library filename is intentionally excluded, so renaming an identical blueprint does not duplicate world content. There is no legacy digest compatibility path.

Natural solid cells seed support from below or the eight same-level neighbors. Supporting player blocks propagate through eight-neighbor horizontal steps for distance zero through seven, and vertically upward. Non-supporting cells may terminate a supported path but cannot propagate it. Missing neighboring chunks produce a pending result rather than air or collapse.

Construction core

The construction plan exposes a lazy ready frontier. Each cell reserves one item instance and commits only after its own work completes. Cancellation releases uncommitted reservations and exposes completed cells for top-down demolition. Player block ownership is stored separately from block identity so natural and player-built blocks with the same ID remain distinguishable.

RmlUi

The bottom palette shows two rows of compact icon buttons, with horizontal scrolling for additional columns. Block names appear on hover; blocks without an authored icon use a diamond placeholder. Selected blocks retain their highlighted background.

The palette is populated from every registered block, independently of inventory. Core block definitions now all declare placement metadata; missing inventory is a construction wait condition, not a palette filter. Tool selection is stored by the engine and mirrored through building_design_state. Dragging edits a local sparse draft and displays translucent cell previews without modifying terrain. Select picks the frontmost draft object; delete, clear, undo and redo operate on draft history. Roof points close by clicking the first point again. Height controls and the mouse wheel adjust vertical tools. The Room tool emits a hollow ring of perimeter walls with no floor and no ceiling, so the player decides how the space is closed above and below.

Draft and drag previews are drawn as translucent real block geometry rather than abstract boxes. The engine meshes the draft through ChunkMesher per chunk and writes the result into host-visible vertex and index buffers that are rewritten in place, so authored block models, per-face atlas metadata and block direction match what will actually be built and no staging copy or per-frame allocation is involved. Greedy meshing merges adjacent cells of one block into a shared quad, so the draft, the selected object and the live drag preview are meshed as separate groups and keep their own tint. The ghost ignores world light. It is recorded in the SSAO geometry pass, which is where the visible scene is rasterized whenever SSAO is active, and in the single-pass path as well, because recording it in only one of the two leaves it invisible in the other. It is rebuilt at most once per frame and only when the cell signature changes, so dragging does not re-upload every frame. Only the roof polygon control points remain as debug markers.

Blueprint file buttons occupy a compact four-column square grid. Start Building and Exit Design form a separate row, with Start Building on the left. History buttons use border-box sizing and explicit positions. The properties panel remains anchored near the lower right.

Start Building submits the draft through systems.building_design, which hands the cells to the ordinary block-placement pipeline so work posting, item reservation and settlement stay in one place. Only cells whose support already exists are accepted; the rest stay queued and are retried on a slow tick, so a multi-storey design fills in bottom-up. A cell that is already ordered, or that already holds the designed block, counts as resolved and leaves the draft. Cells blocked by a different block, outside the world, or without a placement definition stay in the draft and are reported, so a conflict is never dropped silently; permanent conflicts leave the retry queue so they are not re-validated on every pass. An accepted submission also closes the workspace, exactly as Exit Design does, so the player lands back in the running world with the work already ordered; a rejected press (empty or invalid draft) keeps the workspace open so it can be corrected. Re-entering the workspace later shows only the cells that are still waiting, because accepted and resolved cells left the draft. The blueprint file library keeps player-authored designs as JSON files in blueprints/, beside saves/ and logs/, and manages them entirely inside the workspace panel: no system file dialog is involved, so the library stays usable in exclusive-fullscreen and on platforms without a native dialog. Saving shifts the design so its minimum corner sits on the origin with the base plane at y = 0, orders cells, objects and overrides deterministically and renumbers object ids, which is what makes the BLAKE3-256 content id stable across sessions and edit orders, so an identical blueprint keeps one identity under any file name; cells store the block data id rather than a registry hash, so a file stays readable and diffable. The panel is a browser: its caption shows the folder being viewed, folder rows navigate into a subfolder, blueprint rows open a file and wait for its landing cell, which is stamped by clicking the ground so the blueprint's minimum corner lands there, and every row carries its own delete button that asks for a confirming second press and removes a folder together with its contents. 新建 starts an empty blueprint and keeps the discarded draft on the undo stack, 新建文件夹 creates a subfolder in the current folder, 保存 overwrites the current file, 另存 writes a new file into the folder being viewed under the name typed in the panel's name field, 重命名 renames the current file, and 返回上级 leaves the folder. The library is local player state that never travels to the Host, so every one of these commands runs on the main thread; an unplaced blueprint blocks saving and Start Building, so neither can drop it silently.

Remote clients submit through the same command. The workspace holds local engine state, so a client sends its draft cells in the command payload and the Host runs the identical submission path; the reply lists the cells the Host took over, and the client applies that list to its own draft, so both sides converge on one ghost set. The reply is handed over under its own lock and applied on the main thread, which owns the design workspace; the same handling closes the submitting client's workspace once the Host accepts the submission.

building_design.rml is a dedicated full-screen RmlUi document. The ordinary bottom bar exposes a separate Building Design button. Entering switches to the building_design UI phase, hides ordinary playing documents, and pauses simulation. Exit or Escape restores the previous pause and speed state. A paused world still services queued network commands between ticks, so a Start Building press made inside the paused workspace is handled right away instead of waiting for unpause; that is also what keeps the draft readable while the Host handles the command.

The document keeps the world viewport transparent and overlays definite-size panels: the tool rail and history actions are on the left, design status is at the top, blueprint actions are at the upper right, above the name field, the folder/blueprint list and the last file message, the property inspector grows upward from the lower right, and the block palette is along the bottom. The ordinary HUD remains visible so its existing clock and simulation-speed controls stay in their normal location; the design document does not create a second speed control. Its root fills the RmlUi context and uses the Unicode font family. Every visible label is supplied by the shared ui_text localization model.
