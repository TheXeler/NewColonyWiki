数据组件 API

给 Lua 脚本使用的实体附加数据表，适合保存任务状态、临时标记、计数器和脚本私有配置。结构参考 Minecraft NBT 的 compound 思路，但使用 Lua 表和点分路径。

当前数据组件是运行时 Lua 状态，不进入存档，也不参与网络复制。联机时客户端本地写入可能被主机状态覆盖；需要跨网络生效的操作应通过网络命令请求主机执行。

基本用法

所有接口挂在 engine.data 下。数据只允许附加到存活实体；实体销毁后接口会返回失败或 nil。

local entity = engine.ecs.spawn_prototype("core:colonist")

engine.data.ensure(entity)
engine.data.set(entity, "quest.stage", 2)
engine.data.set(entity, "quest.flags.met_elder", true)
engine.data.set(entity, "quest.owner", "core:village")

local stage = engine.data.get(entity, "quest.stage", 0)
if engine.data.get(entity, "quest.flags.met_elder", false) then
  engine.log.info("quest stage: " .. tostring(stage))
end

路径规则

路径用点号分隔，每一段都是 compound 里的键。写入深层路径时，中间 compound 会自动创建。

路径含义
quest.stagedata.quest.stage
quest.flags.met_elderdata.quest.flags.met_elder
cooldowns.mining脚本自定义的挖矿冷却计数。

战斗组件字段

战斗职业会在转职成功时建立原生 ECS 战斗组件。Lua 侧的 components.combat 模块公开字段清单，后续战斗系统和 HUD 可用它对齐数据视图。

组件字段说明
Squadsquad_id, leader_entity, member_count, member_cap, hp, hp_max, attack, hit_rate, dodge, move_speed, range, attack_cooldown, attack_frequency, formation_width, facing, combat_state, hold_ground, has_move_order, attack_order, move_target_x/y/z, suppression_stacks小队由队长殖民者和虚拟士兵人数构成；V2 使用隐藏 attack_cooldown，attack_frequency 和 suppression_stacks 仅兼容保留。
SquadSoldierVisualleader_entity, slot战斗系统生成的临时显示实体，用于让虚拟士兵在队长周围形成方阵；保存时跳过。
CombatStatealert_range, target_squad, state, cooldown目标小队、和平/战斗状态和动作冷却；V2 交战由方阵接触触发，不使用警戒距离入战。
ManaReservemana, mana_max, reserve, regeneration, region_key兼容保留组件；V2 基础战斗不创建或消费区域法力。

空路径、连续点号或末尾点号都是无效路径，例如 quest..stage 和 quest.。

支持的值

建议使用确定、轻量的 Lua 值：nil、布尔、数字、字符串和表。表会作为 compound 使用，也可以直接写入子表。实现层不会阻止函数或 userdata 被写入，但这些值不适合长期状态，也不会进入存档。

engine.data.set(entity, "npc.reputation", 12)
engine.data.set(entity, "npc.tags", {
  hostile = false,
  faction = "core:merchant_guild"
})

local tags = engine.data.get(entity, "npc.tags")
if tags and tags.faction == "core:merchant_guild" then
  engine.log.info("merchant related entity")
end

API 列表

API说明
engine.data.ensure(entity)创建数据组件。实体不存在时返回 false。
engine.data.has(entity)检查实体是否已有数据组件。
engine.data.set(entity, path, value)写入路径上的值。成功返回 true。
engine.data.get(entity, path, fallback)读取路径上的值。不存在时返回 fallback，没有 fallback 时返回 nil。
engine.data.remove(entity, path)删除路径上的值。路径存在并被删除时返回 true。
engine.data.type(entity, path)返回 Lua 类型名：常见值为 nil、boolean、number、string、compound；如果脚本写入函数或 userdata，也会返回对应类型名。
engine.data.get_all(entity)返回整个 compound；实体没有数据组件时返回 nil。
engine.data.clear(entity)移除整个数据组件。

典型场景

数据组件适合把脚本事件串起来，例如给被玩家交互过的实体打标记，在后续事件里读取。

engine.events.subscribe("block:interacted", function(evt)
  local entity = evt.entity_id
  engine.data.set(entity, "last_action.type", evt.action)
  engine.data.set(entity, "last_action.x", evt.x)
  engine.data.set(entity, "last_action.y", evt.y)
  engine.data.set(entity, "last_action.z", evt.z)
end)

engine.timers.every(20, function()
  for _, entity in ipairs(engine.ecs.query_all_entities()) do
    local action = engine.data.get(entity, "last_action.type")
    if action == "mine" then
      engine.log.info("recent miner: " .. tostring(entity))
    end
  end
end)

边界

  • 不要用数据组件保存必须读档恢复的核心进度；当前它不是存档格式的一部分。
  • 不要保存 C++ userdata、函数或协程作为长期状态。推荐只存标量和普通 Lua 表。
  • 需要大量实体查询时，先用 engine.ecs.query_* 缩小范围，再读取数据组件。
