方块注册

方块定义放在 data/blocks/ 下，引擎加载时自动扫描。方块既是世界中的体素单元，也是库存中的物品——没有单独的"物品"类型。

JSON 格式

{
  "id": "copper_age:copper_ore",
  "name": "Copper Ore",
  "stack_size": 64,
  "hardness": 3.0,
  "emission": 0,
  "category": "material",
  "drops": [
    "copper_age:copper_ore",
    { "item": "core:stone_chunk", "min": 1, "max": 2 }
  ]
}

字段说明

字段类型必填说明
idstring是唯一标识，格式 <mod_id>:<name>。允许字符：小写字母、数字、下划线、短横线、冒号。省略前缀时引擎自动补全为 <mod_id>:<名称>。
namestring否显示名称。
stack_sizeint否背包每格最大堆叠数，范围 1~999。不填默认为 1（不可堆叠）。
hardnessfloat否挖掘硬度，决定挖掘所需时间。
emissionint否方块光源强度，范围 0 到 15。省略或为 0 时不发光；大于 0 的任意方块都会作为 block light 光源注册，不限于火把。
dropsarray否挖掘后掉落的物品列表。元素可以是字符串 ID，也可以是 { "item": "...", "min": 1, "max": 2 } 对象；引用必须指向已注册的方块 ID。
categorystring否分类标签，如 material、tool、food、equipment 等。
materialstring否材质类型，如 rock、earth、wood、plant、metal、fluid、glass。
food_valueint否食物饱腹值，正整数。当前由数据和脚本/界面读取，不会单独自动生成可执行进食逻辑。
equip_slotstring否装备槽提示字段。当前装备系统实际固定槽位是 MainHand、OffHand、Armor、Accessory，此字段不注册新槽位。
has_item_blockbool否是否具有物品形态，默认 true。设为 false 时 Lua get_block_info 不暴露 drops；加载器会警告这些 drops 将被忽略。
block_classstring否方块占用与遮挡分级：opaque 不透明，遮挡相邻面且不可通行；translucent 半透明，不遮挡相邻面但不可通行；transparent 透明，不遮挡相邻面且可通行。未填写时根据 translucent 和 material 推断，默认 opaque。
translucentbool否旧版半透明标记，默认 false。新内容优先使用 block_class；该字段仍会让方块不遮挡相邻可见面，但导航上仍不可通行。
random_tickobject否Minecraft 风格的随机方块刻规则。引擎每 tick 在每个加载的 chunk 里随机采样若干个方块，被采中的方块若声明了 random_tick 就按概率执行转化。详见下方"随机方块刻"小节。

随机方块刻

random_tick 对象支持以下字段：

字段类型必填说明
actionstring是规则类型：decay_unless_in_zone（不在指定 zone 内时退化）或 spread_from_neighbor（周围一圈一格高度差内有指定方块时扩散）。
todata id是转化目标方块 ID。
probability_permilleint是每次被采样命中时触发的概率，单位千分比（0~1000）。
zonedata iddecay_unless_in_zone 必填豁免退化的 zone type id；方块只要位于该类型的任一实例内就不退化。
require_air_abovebool否decay_unless_in_zone 专用。设为 true 时，只有当正上方是空气才允许退化（用于让耕地上面有作物时不退化）。
neighbordata idspread_from_neighbor 必填扩散源方块 ID；周围一圈（4 个水平邻居）的一格高度差范围内出现此方块就允许扩散。正上正下不参与扩散。

CoreMod 内置两条规则：

  • core:farmland 在自身正上方一格不属于 core:growing 区域、且正上方为空气时，按 100/1000 的概率退化为 core:dirt。这模拟了 Minecraft 中无人维护的耕地逐渐干裂变回泥土。判定时探测上方一格是因为 growing 区域 2D 模式下圈的是作物层，而 farmland 实际位于其下方一格。
  • core:dirt 在 4 个水平邻居（同层或上下各一层）中出现 core:grass 时，按 300/1000 的概率扩散为 core:grass。
方块和物品是同一个概念。放在背包里就是物品，放在世界里就是方块。stack_size 控制了物品形态下的堆叠行为，hardness 和 drops 控制方块形态下的交互行为；CoreMod 的挖矿脚本会按 drops 的字符串或对象配置发放产物。

ID 规则

  • ID 只能包含小写字母 a-z、数字 0-9、下划线 _、短横线 -、冒号 :。
  • 推荐格式 <mod_id>:<name>，例如 copper_age:copper_ore。
  • 如果省略冒号前缀（只写 copper_ore），引擎自动补全为 <当前mod_id>:copper_ore。
  • 以冒号开头（:copper_ore）同样自动补全。
  • 引用其他方块（drops）时必须写完整 ID（含 mod 前缀），否则跨引用校验失败会导致加载报错。

文件放置规则

  • 放在 data/blocks/ 下，支持任意深度的子目录，例如 data/blocks/materials/copper.json 也合法。
  • 文件名随意，引擎只关心 JSON 内的 id 字段。但建议文件名和 ID 的 <name> 部分保持一致方便维护。

验证命令

在控制台（按物理 Grave/反引号键）中确认方块注册成功：

mods                             —— 确认 MOD 已加载
list_data blocks prefix=copper_age:  —— 列出该前缀下所有方块
data copper_age:copper_ore        —— 查看单个方块的完整 JSON

引擎内部处理

方块类型在 ModRegistry 中有特殊处理：

  • 每个方块 ID 被哈希为 32 位整数；运行时 BlockId、网络同步和 resolve_block_id 均使用该 32 位值。
  • stack_size 被独立解析存入 m_block_stack_limit 表，库存系统直接查询哈希表获取堆叠上限。
  • emission 会在世界初始化时注册到体素光照系统，所有 emission > 0 的方块都会被光源 registry 扫描和增量跟踪。
  • block_class 和旧 translucent 字段会在世界初始化时写入体素遮挡/通行分类；未显式设置时，material=fluid 或 material=plant 会被推导为 transparent。
  • 热重载时旧元数据自动清理，新元数据重新填入。
