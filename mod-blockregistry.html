方块注册

方块定义放在 data/blocks/ 下，引擎加载时自动扫描。存量方块记录会派生同 ID 的兼容物品定义；不需要成为体素的新物品应放在 data/items/。

JSON 格式

{
  "id": "copper_age:copper_ore",
  "name": "Copper Ore",
  "icon": "textures/items/copper_ore.png",
  "stack_size": 64,
  "hardness": 3.0,
  "emission": 0,
  "category": "material",
  "output_table": "copper_age:copper_ore_outputs",
  "output_table_executions": 1
}

字段说明

字段类型必填说明
idstring是唯一标识，格式 <mod_id>:<name>。允许字符：小写字母、数字、下划线、短横线、冒号。省略前缀时引擎自动补全为 <mod_id>:<名称>。
namestring否显示名称。
iconstring否物品形态使用的图标，源数据中的路径相对当前 MOD 的 assets/。运行时会附带所属 MOD 身份解析，不依赖 UI 文档的相对目录。省略时，启动资源预处理会从同名方块纹理或方块模型引用的纹理派生临时图标。
stack_sizeint否背包每格最大堆叠数，范围 1~999。不填默认为 1（不可堆叠）。
hardnesspositive float可采对象必填一次性采掘/伐木工作的时长秒数；缺失、零或无效时目标显示配置屏障，不使用代码默认时长。
emissionint否方块光源强度，范围 0 到 15。省略或为 0 时不发光；大于 0 的任意方块都会作为 block light 光源注册，不限于火把。
output_tabledata id可采对象必填采掘、伐木或采集完成时执行的统一产出表。缺失或无效时对象保留并报告稳定配置错误。
output_table_executionsint否本次完成执行产出表的次数，默认 1，必须大于 0。
ground_despawn_ticksint否该方块兼容物品形态落地后的消失 tick；0 或省略表示不计时。有效搬运来源预留会暂停计时。
categorystring否分类标签，如 material、tool、food、equipment 等。
materialstring否材质类型，如 rock、earth、wood、plant、metal、fluid、glass。
food_valueint否食物饱腹值，正整数。当前由数据和脚本/界面读取，不会单独自动生成可执行进食逻辑。
equip_typestring否装备类型标记。装备物品统一使用 Equipment；该字段不注册额外槽位。
has_item_blockbool否是否具有物品形态，默认 true；不改变产出表结算。
placement_supportstring可放置方块可选below 表示候选格必须有下方支撑。候选格始终沿命中面的外法线取相邻空格：顶面在上方、底面在下方、侧面在对应外侧，不会强制改到命中方块顶部。
placement_support_blocksdata id array否限制下方支撑的允许方块 ID；仅与 placement_support: "below" 配合使用。树苗使用 ["core:dirt", "core:grass"]，所以点击其他方块侧面时，只要侧边候选格下方是泥土或草方块仍可放置。
choppablebool否显式声明方块可作为伐木目标。地形树特征仍会自动视为可伐木；独立放置或生长产生的树方块应声明此字段，CoreMod 的 core:tree 使用 true。
block_classstring否方块占用与遮挡分级：opaque 不透明，遮挡相邻面且不可通行；translucent 半透明，不遮挡相邻面但不可通行；transparent 透明，不遮挡相邻面且可通行。未填写时根据 translucent 和 material 推断，默认 opaque。
translucentbool否旧版半透明标记，默认 false。新内容优先使用 block_class；该字段仍会让方块不遮挡相邻可见面，但导航上仍不可通行。
存量方块可派生同 ID 的兼容物品定义，但世界对象产出只能读取统一产出表。伐木、采石和野采会先填执行者统一背包，溢出在目标位置形成自动回收授权地面实例；不会直接写入仓储或旧 HeldItem。

物品图标推导

方块物品的图标按以下顺序选择：

  1. 方块或同 ID 独立物品记录显式声明的 icon。
  2. assets/textures/block/<name>.png。
  3. assets/models/block/<name>.json 中能解析到 PNG 的代表纹理，依次优先 top、all、layer0、side、particle、bottom，最后再尝试其他纹理。

第 2、3 项在启动预处理阶段复制到 generate/<mod_id>/item_icons/，属于可重建缓存，不应提交到 MOD。models/item/ 中仅通过 parent 引用方块模型的记录不包含可直接交给 RmlUI 的位图，因此仍从被引用方块的代表纹理派生。没有显式图标且找不到可用方块 PNG 时保持无图标；程序生成的运行时方块颜色不能反向生成源图片。

ID 规则

  • ID 只能包含小写字母 a-z、数字 0-9、下划线 _、短横线 -、冒号 :。
  • 推荐格式 <mod_id>:<name>，例如 copper_age:copper_ore。
  • 如果省略冒号前缀（只写 copper_ore），引擎自动补全为 <当前mod_id>:copper_ore。
  • 以冒号开头（:copper_ore）同样自动补全。
  • output_table 引用缺失或引用的表无效时，方块定义仍注册，但采集入口排除该目标并显示带来源路径的配置屏障；旧 drops 字段不再属于当前 schema。

文件放置规则

  • 放在 data/blocks/ 下，支持任意深度的子目录，例如 data/blocks/materials/copper.json 也合法。
  • 文件名随意，引擎只关心 JSON 内的 id 字段。但建议文件名和 ID 的 <name> 部分保持一致方便维护。

验证命令

在控制台（按物理 Grave/反引号键）中确认方块注册成功：

mods                             —— 确认 MOD 已加载
list_data blocks prefix=copper_age:  —— 列出该前缀下所有方块
data copper_age:copper_ore        —— 查看单个方块的完整 JSON

引擎内部处理

方块类型在 ModRegistry 中有特殊处理：

  • 每个方块 ID 被哈希为 32 位整数；运行时 BlockId、网络同步和 resolve_block_id 均使用该 32 位值。
  • stack_size 被独立解析存入 m_block_stack_limit 表，库存系统直接查询哈希表获取堆叠上限。
  • emission 会在世界初始化时注册到体素光照系统，所有 emission > 0 的方块都会被光源 registry 扫描和增量跟踪。
  • block_class 和旧 translucent 字段会在世界初始化时写入体素遮挡/通行分类；未显式设置时，material=fluid 或 material=plant 会被推导为 transparent。
  • core:item_pile 是地面物品实例专用的渲染代理方块。它使用半格模型、没有物品形态且不可放置；渲染时不会把代理方块写入地形。
  • 热重载时旧元数据自动清理，新元数据重新填入。
