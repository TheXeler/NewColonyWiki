从头开始

先做一个最小 MOD：能被游戏发现、输出日志、注册一条方块数据。跑通这个流程后，再往上加配方、职业、文明、焦点。

完整的可复制模板参考 CoreMod/ 的目录结构。你可以直接参考它来组织自己的 MOD，比从零开始快。

1. 建目录

把 MOD 放在 mods/ 下。目录名随便起，但建议和 MOD ID 一样，好管理。最小目录结构如下：

mods/copper_age/
  mod.json
  scripts/
    bootstrap.lua
  data/
    blocks/
    entities/
    recipes/
    professions/
    civilizations/
    focuses/
    factions/
    name_pools/
    actions/
    crops/
    biomes/
  assets/
  lang/

各目录的详细用途和规则见 MOD 目录结构。

2. 写 mod.json

id 是最重要的字段，后面所有数据 ID 都建议以它开头。至少写一个 dependencies 指向 core，不然你的 MOD 数据可能引用不到 core 里已有的方块和职业。

{
  "id": "copper_age",
  "name": "Copper Age",
  "version": "0.1.0",
  "description": "Adds early copper content.",
  "api_version": "0.1",
  "license": "MIT",
  "entry": "scripts/bootstrap.lua",
  "dependencies": [
    {"name": "core", "minVer": "0.1.0", "maxVer": "1.0.0"}
  ],
  "settings": {}
}

3. 写入口脚本

入口脚本文件必须存在，并返回一个表。纯数据 MOD 可以只写 return {}；调试时建议加一个 on_load 日志，方便确认脚本确实执行了。

local M = {}

function M.on_load()
  engine.log.info("[copper_age] loaded")
end

return M

如果你在脚本里需要加载额外的 Lua 文件（比如 worldgen 辅助函数），用 dofile，不要用 require——后者在当前沙箱里不可用。

local Blocks = dofile("CoreMod/scripts/worldgen/blocks.lua")

4. 注册第一个方块

新方块放在 data/blocks/*.json。文件名随便取，真正的唯一标识是 JSON 里面的 id。

{
  "id": "copper_age:copper_ore",
  "name": "Copper Ore",
  "stack_size": 64,
  "category": "material"
}

5. 启动后检查

非 core MOD 首次发现时默认未启用，需要先在主菜单 MOD 管理器启用并重启；也可以确认 config/copper_age.json 里的 enabled 为 true。进入游戏后打开控制台（按物理 Grave/反引号键），按下面顺序确认每一步都正常。这是调试 MOD 的标准流程。

mods
list_data blocks prefix=copper_age:
data copper_age:copper_ore

如果 mods 没看到你的 MOD，先查 mod.json 的路径和 JSON 格式。如果 MOD 已加载但 list_data 没结果，检查文件是否放在 data/blocks 下，以及 id 是否有 copper_age: 前缀。

另外看一下 logs/latest.log——即使控制台打不开，日志通常也会写进去。

最小 MOD 跑通以后，再逐步加配方、职业、文明和焦点。一次只加一类内容，加完就在控制台验证，这样更容易定位加载失败的原因。
