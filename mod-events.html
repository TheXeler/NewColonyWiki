Lua 事件系统

Lua 可以监听引擎/CoreMod 事件，也可以在 MOD 之间发布自定义 Lua 事件。

事件回调在 Lua 主线程执行。回调使用 protected call 隔离：某个回调报错会写入日志，但不会阻止同一事件的其他回调继续执行。

监听事件

local handler_id = engine.events.subscribe("inventory:changed", function(evt)
  if evt.item_key == "core:wood" then
    engine.log.info("wood delta=" .. tostring(evt.delta))
  end
end, 10) -- priority 越大越早执行；默认是 0

-- 在 MOD 卸载或不再需要时取消（来源也可放在最前）
engine.events.unsubscribe("inventory:changed", handler_id)
engine.events.unsubscribe("core", "inventory:changed", handler_id)

subscribe(name, fn, priority?) 省略来源时匹配所有来源；也可以把来源放在最前：subscribe("ui", "panel:opened", fn)。来源为 e（引擎）、core（CoreMod）或 ui。相同 priority 的回调保持注册顺序。

按来源和前缀监听

-- 只监听 CoreMod 的 inventory:changed
engine.events.subscribe("core", "inventory:changed", on_inventory, 0)

-- 监听 UI 来源下的所有 ui:panel:* 事件
local id = engine.events.subscribe_prefix("ui", "panel", function(evt)
  engine.log.info("panel event")
end)

subscribe_prefix(prefix, fn, priority?) 或 subscribe_prefix(source, prefix, fn, priority?) 支持嵌套前缀。上例会匹配 ui:panel:opened 和 ui:panel:closed，不会匹配 ui:panelist。发布时来源放在最前：engine.events.emit("ui", "panel:opened", payload)。

发布自定义事件

-- mod_a
engine.events.emit("core", "copper_age:ore_found", {
  x = 12, y = 48, z = -3,
  block_id = "copper_age:copper_ore"
})

-- mod_b
engine.events.subscribe("copper_age:ore_found", function(evt)
  engine.log.info(string.format("ore at %d,%d,%d", evt.x, evt.y, evt.z))
end)

emit(source, name, payload) 只在当前 Lua runtime 内分发，不会自动进入 C++ 事件总线、网络同步或存档。payload 必须是 Lua table；非 table payload 会被忽略并记录警告。

清理订阅

-- 删除指定订阅
local removed = engine.events.unsubscribe("copper_age:ore_found", handler_id)

-- 删除某个事件的全部订阅（会影响同一 runtime 的其他 MOD）
engine.events.clear("copper_age:ore_found")

clear(name) 是全局操作，除非确定事件由本 MOD 独占，否则优先使用 unsubscribe。

recipe:crafted配方产物完成entity_id, recipe_id, output_item_key, output_count

与 on_tick 的选择

对“某件事发生后才需要运行”的逻辑使用事件；只有需要按固定模拟 tick 轮询的逻辑才使用 on_tick。事件回调中避免修改正在遍历的同一业务集合，复杂操作可记录状态后交给下一 tick 处理。
