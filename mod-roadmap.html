面向 MOD 作者的路线图

描述能力方向，不代表具体发布日期。计划随时可能调整。

已经公开的能力

  • 数据驱动内容：方块、实体、配方、职业、文明、焦点、NPC 阵营和名称池。
  • 职业与配方：职业 1-5 级，支持前置职业、转职方块和配方解锁。
  • 焦点：面向玩家的焦点信息，支持条件、冷却、一次性触发和选项。
  • Lua 扩展：日志、事件、定时器、数据查询、实体操作、焦点、地形、阵营、本地化和网络命令。
  • 调试控制台：多个命令，涵盖 MOD 加载、数据注册、配方、实体、背包、阵营、网络、Lua 热重载等。
  • 网络同步：TCP Host/Client、快照广播、客户端预测、延迟补偿、MOD 数据交换。
  • AI 系统：需求驱动、优先级任务分配、A* 寻路、行为树（Sequence/Selector/Decorator）、Blackboard 共享状态。

近期已完成

  • MOD 清单解析会拒绝损坏的 mod.json、重复 MOD ID 和格式错误的依赖/排序字段。
  • 数据 ID 冲突时会同时报告冲突双方的 MOD 和来源路径。
  • 提供可直接参考的 CoreMod/ 标准目录结构和数据模板。
  • 示例覆盖方块、职业、文明开局、配方、焦点和 Lua 入口脚本，MOD 可按 CoreMod/ 结构参照编写。
  • 文明数据会校验开局配置和配方规则字段，交叉引用失败时报告缺失目标。
  • 新增了定时器 engine.timers。
  • 新增了 7 个内置事件（inventory:changed、recipe:crafted、profession:assigned、block:interacted、job:completed、focus:chosen、focus:dismissed）。
  • 新增了 data/factions、data/name_pools 和 engine.factions 阵营系统。
  • 新增了 data/actions、data/crops 数据类型。
  • 补充了 engine.network、engine.terrain、engine.locale 的完整绑定和文档。
  • 网络同步全面升级（增量快照、客户端预测、延迟补偿、重连恢复）。

近期方向

  • 修复 inventory_block_action 与运行时 held_item_block_action 名称不一致的问题，让进食/饮水动作进入 ActionRegistry 闭环。
  • 梳理 Craft 工作完成路径，避免 C++ 直接制作和 CoreMod stockpile 队列对同一工作重复产出。
  • 补齐 data/audio、data/techs 的公开注册或明确保持为专用系统输入。
  • 补齐存档中的 chunk overrides、建筑实例、区域实例和 MOD 自定义运行时状态。

中期方向

  • 更稳定的 engine API 版本约束。
  • 更多内置事件。
  • 更完整的背包、实体查询、阵营事件和世界操作 API。

长期方向

  • 任务系统扩展点。
  • AI 行为定义入口。
  • 权威的方块放置、破坏、掉落结果事件。
  • 世界生成数据接口。
  • MOD 打包、发布和兼容性检查流程。

AI Dispatch Notes

WorkPool dispatch keeps the existing worker priority calculation and now uses category/type indexes, same-type preference, utility scoring, and online HTN-style navigation/execute decomposition.
