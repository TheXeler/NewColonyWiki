群系注册

群系（Biome）推荐放在 data/biomes/ 下用 JSON 注册；加载器会把它们作为 biomes 数据类型交给地形系统。每个群系定义地表方块、次地表方块、是否生成洞穴和河流等属性，以及偏好气候范围。地形生成器在生成 chunk 时根据对应位置的世界地图气候数据（温度、湿度、海拔）选择匹配的群系；当气候范围存在缺口时，会选择气候距离最近的群系作为混合过渡。树木生成由 特性系统（Features） 单独管理，不再属于群系数据。

JSON 示例

把文件放在 data/biomes/wasteland.json：

{
  "id": "my_mod:wasteland",
  "surface_block": "my_mod:cracked_soil",
  "subsurface_block": "core:stone",
  "weight": 1,
  "subsurface_depth": 2,
  "has_caves": false,
  "has_rivers": false,
  "climate": {
    "temperature_min": 0.60,
    "temperature_max": 1.00,
    "moisture_min": 0.00,
    "moisture_max": 0.25,
    "elevation_min": 0.40,
    "elevation_max": 0.90
  },
  "vegetation": {
    "density": 0.05,
    "noise_weight": 0.35,
    "moisture_weight": 0.30,
    "temperature_weight": 0.25,
    "random_weight": 0.10,
    "noise_scale": 0.03125
  }
}

字段说明

字段类型必填说明
idstring是唯一标识，格式 <mod_id>:<name>。遵循标准 ID 规则。
surface_blockstring是地表方块数据 ID。地形最顶层放置此方块。
subsurface_blockstring是次地表方块数据 ID。地表和基岩之间的填充层。
weightint否群系选择权重，必须为正整数，默认 1。在气候匹配的候选群系中按权重随机选取。
subsurface_depthint否次地表深度（层数），默认 3。地表下方这么厚的层使用 subsurface_block。
map_colorstring否保留字段。CoreMod 数据中可见该字段，但当前小地图颜色由地表/次地表方块推导，尚未把 map_color 作为稳定控制入口。
has_cavesbool否是否在此群系中生成洞穴，默认 true。
has_riversbool否是否在此群系中生成河流，默认 true。
climatetable否偏好气候范围。省略或部分省略的字段默认为 0.0~1.0（匹配任何气候）。
vegetationtable否此群系整体植被概率场。最常调的是 density，用于控制该群系树木总体多少。

气候子表字段

世界地图群系分配：创建或载入世界时，引擎会先生成世界地图，并把地图 chunk 直径限制为至少 max(视距 * 2, 64)。每个世界地图格子的群系 ID 会在此时固定，后续 chunk 生成只读取这个预计算结果，不再为每个 chunk 临时随机选择群系。

climate 表中的所有字段均为 float，取值范围 0..1。它们对应世界地图（WorldMap）中每个六边形格子的气候数据：

字段默认值含义
temperature_min0.0最低温度偏好。0 = 极寒。
temperature_max1.0最高温度偏好。1 = 酷热。
moisture_min0.0最低湿度偏好。0 = 干旱。
moisture_max1.0最高湿度偏好。1 = 潮湿。
elevation_min0.0最低海拔偏好。0 = 深海。
elevation_max1.0最高海拔偏好。1 = 山巅。

植被子表字段

vegetation 控制当前群系整体植被概率场；具体树种是否适合某个温度由 树类型地物 的 temperature_optimum 和 temperature_range 控制。

字段默认值含义
density1.0群系整体植被密度，范围 0..1。制作某个群系时，优先改这个值。
noise_weight0.35连续噪声斑块权重，越高越容易形成成片树林和稀疏区。
moisture_weight0.30湿度权重，越高越依赖世界地图湿度。
temperature_weight0.25树种温度适宜度权重。
random_weight0.10坐标随机扰动权重，用于打散过密区域。
noise_scale0.03125植被噪声采样尺度；0.03125 表示约 32 block 的变化尺度。
群系中的树木种类由地物系统（data/features/）接管。群系负责整体植被密度和概率场，树类型地物负责具体树种、间距、相对密度和温度适宜度。

海洋 core:ocean

大面积深水区域，匹配最低海拔的格子。底部覆盖粘土层。不生成洞穴和河流。

  • 地表：水，次地表：粘土（4 层）
  • 海拔偏好 0.0–0.35
  • 无树木、无洞穴、无河流

浅海 core:ocean_shallow

靠近陆地的浅水带，作为深海与海滩之间的过渡。底部仍为粘土。同样不生成洞穴和河流。

  • 地表：水，次地表：粘土（3 层）
  • 海拔偏好 0.35–0.50
  • 无树木、无洞穴、无河流

海滩 core:beach

沿着海岸线的沙带，作为水域与陆地之间的过渡。在温暖至炎热的纬度才会形成。

  • 地表：沙，次地表：沙（2 层）
  • 偏好温度 0.20–1.0，海拔 0.50–0.58
  • 无树木、无洞穴、无河流

河流 core:river

狭窄的水道，匹配略高于海洋的低海拔区域。底床为粘土。与海洋类似，不生成洞穴和河流。

  • 地表：水，次地表：粘土（2 层）
  • 海拔偏好 0.0–0.55
  • 无树木、无洞穴、无河流

冻原 core:tundra

寒冷干燥的极地平原，地表为裸露的冻土。几乎没有植被，但偶尔有零星灌木。是寒冷带中最干旱的生态位。

  • 地表：泥土，次地表：泥土（3 层）
  • 偏好温度 0.0–0.20，湿度 0.0–0.40，海拔 0.0–0.65
  • 植被密度极低

针叶林 core:taiga

寒冷带的中湿度群系，地表为草地，下方是泥土。松树密集，是寒带主要的木材产区。

  • 地表：草地，次地表：泥土（3 层）
  • 偏好温度 0.15–0.40，湿度 0.30–0.65
  • 植被密度中等

雪林 core:snow_forest

寒冷带最潮湿的群系，茂密的针叶林覆盖在积雪之上。比起针叶林更冷更湿，是寒带雨林生态。

  • 地表：草地，次地表：泥土（3 层）
  • 偏好温度 0.05–0.25，湿度 0.55–1.0，海拔 0.0–0.75
  • 植被密度 0.45

干草原 core:steppe

温暖带最干旱的群系，大片干燥的草地，偶有零星灌木。过渡到沙漠的湿润版本。

  • 地表：草地，次地表：泥土（3 层）
  • 偏好温度 0.30–0.60，湿度 0.0–0.25，海拔 0.0–0.65
  • 植被密度 0.10

平原 core:plains

温和的草原群系，偏好中等温度和中等湿度。地表为草地，下方是泥土层。适合殖民者定居和农业开垦。

  • 地表：草地，次地表：泥土（3 层）
  • 偏好温度 0.30–0.65，湿度 0.25–0.60
  • 稀疏树木（通过 feature 注册）

森林 core:forest

温带潮湿群系，树木高大且数量众多，提供丰富的木材资源。是温带的主要林区。

  • 地表：草地，次地表：泥土（3 层）
  • 偏好温度 0.30–0.65，湿度 0.60–1.0
  • 植被密度 0.85

沙漠 core:desert

炎热干燥的沙海，地表覆盖沙层，下方是石头。完全没有植被。温度极高。

  • 地表：沙，次地表：石头（2 层）
  • 偏好温度 0.60–1.0，湿度 0.0–0.20
  • 无树木、无洞穴、无河流

稀树草原 core:savanna

热带中湿度群系，草地夹杂零星的金合欢状树木。是沙漠和丛林之间的过渡生态。

  • 地表：草地，次地表：泥土（3 层）
  • 偏好温度 0.60–1.0，湿度 0.20–0.50，海拔 0.0–0.65
  • 植被密度 0.20

丛林 core:jungle

炎热潮湿的热带雨林，植被极其茂密，树木高大交错。是木材和生物资源最丰富的群系。

  • 地表：草地，次地表：泥土（4 层）
  • 偏好温度 0.60–1.0，湿度 0.50–1.0，海拔 0.0–0.70
  • 植被密度 0.95

沼泽 core:swamp

泥泞的低洼群系，偏好温暖潮湿且低海拔的环境。树木矮小稀疏。泥土层较深，适合挖掘粘土。

  • 地表：泥土，次地表：泥土（4 层）
  • 偏好温度 0.35–1.0，湿度 0.55–1.0，海拔 0.0–0.45
  • 植被密度 0.65

高山 core:mountains

海拔最高的山地区域，地表裸露岩石，植被稀疏。不生成河流（山脊上无水道）。覆盖任何温度带的高海拔格子。

  • 地表：石头，次地表：石头（1 层）
  • 海拔偏好 0.85–1.0
  • 植被密度 0.05，无河流

群系选择机制

地形生成器使用 multi-noise 气候空间模型为每个 column 选择群系（类似 Minecraft 1.18+）。群系不是 chunk 大小的离散格子，而是从连续气候场里"涌现"出来的连续区域。流程：

  1. 根据星球半径把 chunk 坐标 (cx, cz) 归一化到有限星球：东西方向按直径回绕；越过南极或北极后会折返到星球另一面，并让经度旋转半圈。
  2. 在世界地图六边形格子的经纬度气候场上做连续采样，获取温度、湿度、海拔；chunk 级宏观气候之上再叠加 block 级中频 Perlin 扰动（周期约 48 块、幅度约 0.14），让气候在 chunk 内连续漂移。采样海拔同时会按方块列插值地移动地形基准高度，使相邻 chunk 之间有高低差过渡。
  3. 在所有已注册群系中按气候距离最近邻选择：计算每个群系的 climate range 到当前 (温度, 湿度, 海拔) 的距离平方和（落在 range 内为 0，否则按超出边界的距离平方累加），取距离最小的群系。同距离时按注册顺序最早者优先（确定性 tie-break）。
  4. 由于气候场连续且选择算法是纯最近邻（无 hash 随机），相同气候必然映射到相同群系——这是消除"草原/深海交错"问题的核心。气候跨越群系 climate range 边界处就是天然的过渡带。
  5. 水面高度由创建世界时的海平面选项决定。陆地群系的地表不会低于 sea_level；水域群系使用较低的海床/河床高度，并把床面以上的方块填充为水直到 sea_level，水块不会出现在 sea_level 以上。
weight 字段在 multi-noise 模型中保留供未来扩展（例如在气候 distance 完全相等的群系之间做加权 tie-break），但当前实现使用注册顺序做 tie-break。不同群系的气候范围可以重叠——重叠区域内的某个具体气候值只会落在 distance = 0 的某个群系，但相邻 column 会因气候漂移落到不同群系，创造自然的过渡效果。
省略 climate 表的群系默认范围为 0.0–1.0（匹配任何气候），因此向后兼容：旧 mod 注册的群系仍然会出现在所有位置。
想了解群系在完整地形生成 pipeline 中的位置（世界地图采样、高度混合、洞穴河流装饰等阶段），见 地形生成流程。

Lua 注册入口

engine.terrain.register_biome(table) 仍然存在，主要用于兼容旧脚本或运行时实验。内容型 MOD 不建议把群系只写在 Lua 里，因为 JSON 会参与 ModLoader 的格式校验、重复 ID 检查和跨引用诊断。

engine.terrain.register_biome({
    id = "my_mod:wasteland",
    surface_block = 1,          -- 数字方块 ID；JSON 中推荐写字符串数据 ID
    subsurface_block = 1,
    weight = 1,
    subsurface_depth = 2,
    has_caves = false,
    has_rivers = false,
    climate = {
        temperature_min = 0.60,
        temperature_max = 1.00,
        moisture_min = 0.00,
        moisture_max = 0.25,
        elevation_min = 0.40,
        elevation_max = 0.90,
    },
})
scripts/worldgen/biome_registry.lua 现在只是 legacy 兼容入口和日志提示；CoreMod 的运行时群系来自 data/biomes/，地物来自 data/features/。

验证命令

在控制台（按物理 Grave/反引号键）中确认群系注册成功：

engine.terrain.list_biomes()   -- 返回所有已注册群系 ID 列表

或在 Lua 脚本中调用：

local biomes = engine.terrain.list_biomes()
for _, id in ipairs(biomes) do
    engine.log.info("Registered biome: " .. id)
end
