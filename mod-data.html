注册物品、方块和规则

所有内容数据都放在 data/ 下。引擎在加载阶段自动扫描这些目录，不需要你在 Lua 里手动注册。

通用规则

不管哪种数据类型，下面几条规则是通用的：

  • 每个 JSON 都必须有唯一的 id，推荐格式 <mod_id>:<name>。
  • 引用其他内容时必须写完整 ID，比如 copper_age:copper_ingot。
  • 配方、职业、文明和方块掉落会做跨引用校验。引用不存在会导致 MOD 加载失败，引擎会报出具体是哪个文件和哪条记录。
  • 文件可以放在对应类型目录下的任意位置（包括子目录），只要文件在正确的类型根目录下即可。例如 data/blocks/materials/copper.json 和 data/blocks/copper.json 都行。
  • 当前引擎支持 14 种数据类型：blocks、entities、recipes、professions、civilizations、focuses、factions、name_pools、actions、features、crops、buildings、biomes、zones。

方块（blocks）

方块是体素世界的基本构成单位，放在 data/blocks/ 下。stack_size 表示一个背包格子能堆叠多少个，范围 1~999。category 用来分类，可以取 material、tool、food、equipment 等。

{
  "id": "copper_age:copper_ingot",
  "name": "Copper Ingot",
  "stack_size": 64,
  "category": "material"
}

方块既是世界中的体素单元，也是库存中的物品——没有单独的"物品"类型。hardness 决定挖掘所需时间，drops 里的 ID 必须指向已注册的方块。

{
  "id": "copper_age:copper_ore_block",
  "name": "Copper Ore",
  "hardness": 3.0,
  "drops": ["copper_age:copper_ore"]
}

工作台类的方块（如 workbench、stone_furnace）还会声明关联的配方类型或可用操作。

材质

方块材质用于决定每个面的显示贴图。当前 data/blocks/*.json 只负责注册方块数据，不能单独通过新增 texture 字段让方块换贴图；实际渲染贴图由渲染器的方块材质注册表加载。

内置内容目前有两类材质来源：

  • NewColonyTextures/*.json + .png：Blockbench / Minecraft Bedrock 风格的模型 JSON 和贴图图集。JSON 里的 elements[0].faces 声明六个面的 UV，PNG 会按 16x16 tile 切入纹理图集。
  • 程序生成 fallback：没有材质映射的基础方块会按固定颜色生成临时纹理，例如 stone、wood、leaves、water 等。
{
  "texture_size": [64, 64],
  "elements": [
    {
      "from": [0, 0, 0],
      "to": [16, 16, 16],
      "faces": {
        "north": { "uv": [0, 0, 4, 4], "texture": "#0" },
        "east":  { "uv": [0, 4, 4, 8], "texture": "#0" },
        "south": { "uv": [4, 0, 8, 4], "texture": "#0" },
        "west":  { "uv": [4, 4, 8, 8], "texture": "#0" },
        "up":    { "uv": [4, 12, 0, 8], "texture": "#0" },
        "down":  { "uv": [12, 0, 8, 4], "texture": "#0" }
      }
    }
  ]
}
这部分仍属于渲染器内部能力，不是稳定的 MOD 数据接口。内容型 MOD 现在可以安全依赖 data/blocks/ 的注册、掉落和堆叠行为；自定义方块材质需要等材质映射被暴露为正式的 MOD 配置后再作为稳定接口使用。

实体原型（entities）

实体原型用于 spawn_proto 控制台命令和 engine.ecs.spawn_prototype。放在 data/entities/ 下。一个实体由多个组件拼成，每个组件描述一种能力或属性。

引擎内置了 17 种标准组件——你可以混搭它们来定义不同类型的实体：

组件描述
Position世界坐标 (x, y, z)
Velocity移动速度向量
Rotation朝向 (yaw, pitch)
Scale缩放比例 (x, y, z)
Health生命值 (current, max)
Needs三项需求 (hunger, fatigue, social)
Inventory背包（最多 20 个格子）
Equipment装备栏（武器、护甲、手持物品）
Profession职业 ID 和等级 (1-5)
Name显示名称
ColonistTag殖民者标记（用于查询过滤）
AIStateAI 状态（行为树 ID, 当前节点, LoD 层级, busy 标志）
NavAgent导航代理（路径跟随）
WorkerPriorityConfig工作优先级配置（5 类任务，1-7 级）
Civilization所属文明 ID
BlockInteractor方块交互意图（挖掘/放置/交互）
PrototypeRef原型引用（记录实体的数据来源）

下面是一个殖民者的实体原型示例：

{
  "id": "copper_age:copper_worker",
  "components": {
    "Position": { "x": 0, "y": 64, "z": 0 },
    "Velocity": { "x": 0, "y": 0, "z": 0 },
    "Health": { "current": 100, "max": 100 },
    "Needs": { "hunger": 40, "fatigue": 20, "social": 50 },
    "ColonistTag": {},
    "AIState": { "behavior_tree_id": 0, "current_node": 0, "lod_level": 0 },
    "Profession": { "id": "copper_age:coppersmith", "level": 1 },
    "Name": { "data": "Copper Worker" },
    "Inventory": { "slots": [] }
  }
}

配方（recipes）

配方放在 data/recipes/ 下。声明输入、输出和可选的职业要求。写了 profession 后，只有满足职业与等级要求的实体能制作。

{
  "id": "copper_age:smelt_copper",
  "inputs": [
    { "id": "copper_age:copper_ore", "count": 2 }
  ],
  "profession": { "id": "copper_age:coppersmith", "level": 1 },
  "output": { "id": "copper_age:copper_ingot", "count": 1 }
}

合成成功时会触发 recipe:crafted 事件，你可以在 Lua 里订阅它来响应。

职业（professions）

职业定义放在 data/professions/ 下。声明转职需要的方块、前置职业和到达特定等级后解锁的配方。等级范围 1-5。

{
  "id": "copper_age:coppersmith",
  "name": "Coppersmith",
  "max_level": 5,
  "required_block": { "id": "copper_age:copper_hammer", "count": 1 },
  "prerequisites": [
    { "id": "core:worker", "level": 1 }
  ],
  "unlocks_recipes": [
    { "id": "copper_age:smelt_copper", "level": 1 }
  ]
}

分配职业成功时会触发 profession:assigned 事件。

文明（civilizations）

文明用来把职业、开局选项和配方限制组织在一起。放在 data/civilizations/ 下。目前建议保持简单：声明可用职业、一个开局选项，需要时再加配方限制。

{
  "id": "copper_age:copper_clan",
  "name": "Copper Clan",
  "professions": ["copper_age:coppersmith"],
  "starting_options": [
    {
      "id": "copper_age:starter",
      "blocks": [
        { "id": "copper_age:copper_ore", "count": 4 }
      ],
      "professions": [
        { "id": "copper_age:coppersmith", "level": 1, "count": 1 }
      ]
    }
  ]
}

焦点事件

焦点是展示给玩家的消息。放在 data/focuses/ 下。条件可以是内置条件（tick_at_least、entity_count、colonist_need），也可以是 Lua 注册的自定义条件。

{
  "id": "copper_age:copper_found",
  "title": "Copper Discovered",
  "body": "Your colony can start working copper.",
  "severity": "info",
  "one_shot": true,
  "conditions": [
    { "type": "tick_at_least", "tick": 20 }
  ],
  "choices": [
    { "id": "ok", "label": "OK" }
  ]
}

NPC 阵营（factions）

阵营定义放在 data/factions。name_template 可以包含 ${random_name}，生成实例时会从指定的名称池里取词；关系值会被限制在 min_relation 和 max_relation 之间。

{
  "id": "copper_age:merchant_guild",
  "name_template": "${random_name} Merchant Guild",
  "initial_relation": 10,
  "max_relation": 100,
  "min_relation": -100,
  "name_pools": ["copper_age:metals"]
}

名称池（name_pools）

名称池给 NPC 阵营生成名称使用。放在 data/name_pools/ 下。words 必须是字符串数组，空数组会被跳过。

{
  "id": "copper_age:metals",
  "words": ["Copper", "Bronze", "Tin", "Verdigris"]
}

动作（actions）、地物（features）与作物（crops）

data/actions/ 定义 AI 可执行的原子动作（如 mine、chop_wood、eat_food、harvest_crop 等）。data/features/ 定义地形装饰阶段生成的地物。data/crops/ 定义作物的生长阶段和产出。core 内容里已有示例，可以对照 CoreMod/data/actions/ 和 CoreMod/data/crops/。

验证命令

在控制台中用这些命令确认数据注册成功：

list_data blocks prefix=copper_age:
list_data recipes prefix=copper_age:
list_data professions prefix=copper_age:
list_data civilizations prefix=copper_age:
list_data focuses prefix=copper_age:
data type:factions
data type:name_pools
list_factions
list_name_pools
gen_name ${random_name}_guild 42
spawn_proto copper_age:copper_worker
