焦点注册

焦点是一种事件驱动的提示系统。当游戏内条件满足时，引擎会触发一个焦点，向玩家展示一段信息并提供可选的响应动作。焦点定义放在 data/focuses/ 下，也是事件界面的当前后端。

JSON 格式

{
  "id": "core:first_colonist",
  "title": "ui.core:events.first_colonist.title",
  "body": "ui.core:events.first_colonist.body",
  "severity": "info",
  "icon": "colonist",
  "enabled": true,
  "one_shot": true,
  "cooldown_ticks": 0,
  "priority": 0,
  "conditions": [
    { "type": "tick_at_least", "tick": 1 },
    { "type": "entity_count_at_least", "count": 1 }
  ],
  "choices": [
    {
      "id": "inspect",
      "label": "ui.core:events.first_colonist.inspect",
      "description": "ui.core:events.first_colonist.inspect.desc",
      "action": "inspect_last_colonist"
    },
    {
      "id": "dismiss",
      "label": "ui.core:events.dismiss",
      "description": "ui.core:events.dismiss.desc"
    }
  ]
}

字段说明

字段类型必填说明
idstring是唯一标识，格式 <mod_id>:<name>。
titlestring否焦点触发时显示的标题。可以写普通文本，也可以写 ui.core:events.example.title 这类本地化引用。
bodystring否焦点触发时显示的正文描述。可以写普通文本，也可以写 ui. 开头的本地化引用。
severitystring否严重程度，影响 UI 显示风格。可选值：info（默认）、warning、critical。
iconstring否焦点图标名称，对应实体或 UI 图标 ID。
enabledbool否是否启用该焦点，默认 true。设为 false 可临时禁用。
one_shotbool否是否只触发一次，默认 true。设为 false 表示满足条件时会反复触发。
cooldown_ticksuint否冷却时间（游戏刻）。仅在 one_shot 为 false 时有效，控制两次触发的最小间隔。默认 0 表示无冷却。
priorityint否优先级，数值越小越优先展示给玩家。同一时刻有多个焦点触发时按优先级排序。默认 0。
conditionsobject[]是触发条件列表。所有条件同时满足时焦点才会触发。每个条件必须包含 type 字段（见下方条件类型说明）。
choicesobject[]否玩家可选的响应动作列表。如果不提供，系统会自动添加一个 "Dismiss"（关闭）选项。

条件类型

type所需字段说明
tick_at_leasttick (uint)当前游戏刻大于等于指定值时满足。
entity_count_at_leastcount (uint)世界中的实体数量大于等于指定值时满足。
entity_count_at_mostcount (uint)世界中的实体数量小于等于指定值时满足。
colonist_needneed (string)、op (string)、value (float) 检查任一殖民者的需求值。
need 可选值：hunger（饥饿）、fatigue（疲劳）、social（社交）。
op 可选值：<、<=、==、>=、>。
luaname (string)调用 Lua 条件函数，name 为 Lua 中注册的函数名（如 core:faction_relation_daily_8_up）。

选项字段

字段类型必填说明
idstring是选项的唯一标识（在同一焦点内不重复）。
labelstring是选项按钮上显示的文本。可以写普通文本，也可以写 ui. 开头的本地化引用。
descriptionstring否选项的详细描述（鼠标悬停提示）。可以写普通文本，也可以写 ui. 开头的本地化引用。
actionstring否关联的 Lua 动作名称，玩家选择后由脚本引擎执行。
enabledbool否选项是否可选，默认 true。设为 false 时 HTML 命令不会消费事件。
reasonstring否禁用原因。选择 disabled option 时 core:events.act 返回该 reason。
焦点系统通过 one_shot + cooldown_ticks 控制触发频率。one_shot: true（默认）时事件只触发一次；设为 false 并配合 cooldown_ticks 可实现周期性提醒（如每 24000 刻检查一次派系关系）。
旧 Lua 事件面板和 RmlUI 数据桥会在显示前调用本地化解析：title、body、choices[].label、choices[].description、choices[].reason 若写成 ui.<key>，会按当前语言显示；普通文本保持原样。

Lua 条件函数

使用 lua 类型的条件时，需要在 Lua 脚本中注册对应的条件函数。回调收到一个上下文表，包含 condition、focus_id 和 tick：

-- 返回 true 表示条件满足
engine.focus.register_condition("core:faction_relation_daily_8_up", function(ctx)
  -- ctx.condition, ctx.focus_id, ctx.tick
  return true
end)

事件界面 API

事件列表复用焦点系统。右侧事件列表读取 engine.focuses.active()，详情窗口调用 engine.focuses.choose(instance_id, choice_id) 或 engine.focuses.dismiss(instance_id)。活动项包含 severity、tick 和 choices，可用于显示优先级/严重度和后续操作。

RmlUI 数据桥

RmlUI 文档可以读取 event_list 快照通道。该通道直接来自 FocusSystem 的活动焦点，稳定字段为 id、title、body、severity、priority、options、choices、dismissible 和 location。choices 是 options 的短期兼容别名。

{
  id = 1,
  title = "首位殖民者已就绪",
  body = "首位殖民者已经进入世界。",
  severity = "info",
  priority = 0,
  options = {
    { id = "inspect", label = "查看殖民者", enabled = true }
  },
  choices = options,
  dismissible = true,
  location = nil
}
NC.snapshot("event_list")
NC.sendCommand("core:events.act", { id: 1, optionId: "inspect" })
NC.sendCommand("core:events.dismiss", { id: 1 })

core:events.act 和 core:events.dismiss 接入真实焦点系统；未注册或暂时无法执行的 choice 会返回 { ok: false, reason: "choice_unavailable" } 或等价 reason。选择 enabled=false 的 option 时返回 { ok: false, reason }，并且不会消费事件。

验证命令

在控制台（按物理 Grave/反引号键）中确认焦点注册成功：

mods                            —— 确认 MOD 已加载
list_data focuses               —— 列出所有已注册焦点
data core:first_colonist        —— 查看单个焦点的完整 JSON
