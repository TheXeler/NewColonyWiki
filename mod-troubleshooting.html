MOD 常见问题

按症状查找你遇到的问题。

MOD 没有出现在 mods 列表中

  • 确认目录是 mods/<mod_id>/。
  • 确认根目录有 mod.json 且是合法的 JSON（可以用在线 JSON 校验工具检查）。
  • 确认 id 字段不为空、不和其他 MOD 重复。
  • 确认 entry 指向的 Lua 文件存在；没有写 entry 时默认要求 scripts/bootstrap.lua 存在，所以纯数据 MOD 也需要放一个最小入口脚本。
  • 查看 logs/latest.log 是否有报错。

数据在 list_data 里找不到

list_data blocks prefix=copper_age:
list_data civilizations prefix=copper_age:
list_data focuses prefix=copper_age:
data copper_age:copper_ore

确认文件放在了正确的类型目录下（比如 data/blocks/ 不是 data/blocks 作为文件），每个 JSON 都有唯一的 id，且 ID 的命名空间前缀和 mod.json.id 一致。

配方不能制作

  • 输入物品和输出物品的 ID 是否注册成功。
  • stockpile 账本或实体手持物里有没有足够的输入物品，实体手中有没有输出空间。
  • 配方是否声明了职业要求，实体的职业等级是否满足。
  • engine.crafting.craft 只检查实体当前单个 HeldItem；多输入制作通常应走 CoreMod 的 systems.crafting.queue stockpile 队列。
  • Craft 工作完成时 C++ 会先尝试直接制作，然后 Lua 才收到 job:completed。如果工人手持输入物且队列也预留了 stockpile 材料，要检查是否发生双路径产出。
  • 用 inventory <entity> 和 data <recipe_id> 在控制台查看实际状态。

进食或饮水动作没有执行

当前数据校验接受 inventory_block_action，CoreMod 的吃饭/喝水动作也使用这个类型；但运行时 ActionRegistry 仍检查旧名 held_item_block_action。因此动作会出现在通用数据注册里，但不会进入 held-item 动作执行表。这是当前实现缺口，不是 MOD JSON 写法错误。

焦点 没有触发

  • 确认文件在 data/focuses 目录下。
  • 确认 conditions 数组不为空。
  • 用了 lua 条件的话，确认已经在 on_load 里通过 engine.focus.register_condition 注册。
  • engine.focus.subscribe 只负责把触发通知交给 Lua 脚本；是否显示给玩家还取决于当前 UI/焦点系统是否消费该焦点。

Lua 脚本没有执行

  • 入口脚本末尾是否有 return M。
  • 生命周期函数名是否拼写正确：on_load、on_world_init、on_tick、on_shutdown。
  • 查看 logs/latest.log 里是否有 Lua 报错。
  • 如果用了 require，换成 dofile——package 库在 MOD 沙箱中未加载。

NPC 阵营实例生成失败

  • 确认阵营定义在 data/factions 下。
  • 用 data type:factions 确认定义已注册。
  • 用 list_name_pools 确认引用的名称池存在。

math.random 报错

这是有意为之。math.random 在脚本环境中被禁用了。改用 engine.random.int(min, max) 或 engine.random.float()。
