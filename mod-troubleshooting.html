MOD 常见问题

按症状查找你遇到的问题。

MOD 没有出现在 mods 列表中

  • 确认目录是 mods/<mod_id>/。
  • 确认根目录有 mod.json 且是合法的 JSON（可以用在线 JSON 校验工具检查）。
  • 确认 id 字段不为空、不和其他 MOD 重复。
  • 确认 entry 指向的 Lua 文件存在；没有写 entry 时默认要求 scripts/bootstrap.lua 存在，所以纯数据 MOD 也需要放一个最小入口脚本。
  • 查看 logs/latest.log 是否有报错。

数据在 list_data 里找不到

list_data blocks prefix=copper_age:
list_data civilizations prefix=copper_age:
list_data focuses prefix=copper_age:
data copper_age:copper_ore

确认文件放在了正确的类型目录下（比如 data/blocks/ 不是 data/blocks 作为文件），每个 JSON 都有唯一的 id，且 ID 的命名空间前缀和 mod.json.id 一致。

配方不能制作

  • 输入物品和输出物品的 ID 是否注册成功。
  • 露天仓储或储存体素中是否有足够、可达、未保留且符合过滤条件的统一物品实例，兼容工作点的输入/输出暂存是否可用。
  • 配方是否声明了职业要求，实体的职业等级是否满足。
  • Lua 不提供直接制作入口；制作必须走 CoreMod 生产订单或 systems.crafting.queue。
  • 检查生产订单的 status、指定工人、库存可用量和 reservation 数量。取消订单应释放预留；中断工作后订单需要重新派发。
  • 在生产订单/工作点面板查看具体实例、输入与输出暂存；用 data recipes <recipe_id> 在控制台核对配方注册数据。

进食或用药动作没有执行

优先检查进食方案/治疗模板过滤、物品营养或药品载荷、统一实例是否可达和未预留，以及个人药品 CD 槽。普通进食、药品和医疗包互不作为后备行为。

焦点 没有触发

  • 确认文件在 data/focuses 目录下。
  • 确认 conditions 数组不为空。
  • 用了 lua 条件的话，确认已经在 on_load 里通过 engine.focus.register_condition 注册。
  • engine.focus.subscribe 只负责把触发通知交给 Lua 脚本；是否显示给玩家还取决于当前 UI/焦点系统是否消费该焦点。

Lua 脚本没有执行

  • 入口脚本末尾是否有 return M。
  • 生命周期函数名是否拼写正确：on_load、on_world_init、on_tick、on_shutdown。
  • 查看 logs/latest.log 里是否有 Lua 报错。
  • 如果用了 dofile 或 loadfile，换成 require。沙箱只允许加载引擎预注册的同 MOD Lua 模块。

只在 DEBUG 日志里看到的解析失败

部分控制台参数、本地设置和存档区域文件解析会保持原来的容错流程：解析异常或失败返回被吞掉，命令继续尝试其它格式、返回既有默认值，或把存档加载报告为失败。启动时加 --DEBUG 可以在 logs/latest.log 里看到这些被忽略的异常细节，例如 time set 的无效时间、doctor archive 命令的无效数字参数、settings JSON 中无效的数字字段，或 regions/*.ncr 的无效 header、表项、压缩 payload 和 chunk 坐标。

NPC 阵营实例生成失败

  • 确认阵营定义在 data/factions 下。
  • 用 data type:factions 确认定义已注册。
  • 用 list_name_pools 确认引用的名称池存在。

math.random 报错

这是有意为之。math.random 在脚本环境中被禁用了。改用 engine.random.int(min, max) 或 engine.random.float()。

LuaJIT 与 Lua 5.4 差异

脚本运行时是 LuaJIT 2.1（Lua 5.1 语言）。从 Lua 5.3/5.4 移植脚本时需要特别注意：

  • 位运算符：&、|、~、<<、>>（5.3+）在 LuaJIT 中不存在。改用 bit 库：bit.band、bit.bor、bit.bxor、bit.lshift、bit.rshift。注意 bit 库只在 32 位整数上运算。
  • 整除 //：5.3+ 才有。LuaJIT 下用 math.floor(a / b)。
  • 整数 / 浮点分离：5.3+ 区分 integer 和 float 子类型，math.type(1) 返回 "integer"。LuaJIT 下所有数字都是 double，math.type 不存在。
  • math.tointeger：LuaJIT 提供扩展实现，可用。
  • 64 位整数字面量：例如 0x9E3779B97F4A7C15。LuaJIT 的 number 是 53 位精度的 double，超过 2^53 的字面量会丢精度。需要 64 位运算时把算法移到 C++ 端，或用 engine.random。
  • utf8 标准库：5.3+ 才有。LuaJIT 没有 utf8 库。
  • goto/::label::：LuaJIT 支持，与 5.3+ 一致。
世界生成在 C++ 端：CoreMod 不再包含 Lua worldgen 脚本。所有世界生成算法（地形 noise、群系选择、地物放置、RNG）都在 C++ TerrainGenerator 中实现，由 data/biomes/ 和 data/features/ 下的 JSON 配置驱动。MOD 不应再 require("worldgen.*")。
