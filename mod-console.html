MOD 调试控制台

控制台是你调试 MOD 最重要的工具。按键盘左上角的物理 Grave/反引号键打开；焦点在控制台时按 Esc 关闭。控制台会像 Source/CSGO 风格一样从屏幕顶部展开，占据上半屏，输入栏在面板底部。

如果控制台没反应，先看 logs/latest.log。即使控制台不可见，日志通常还是会写到 logs/ 目录。

客户端输入与服务端执行

控制台窗口、输入和历史记录属于客户端。世界命令通过已有网络命令通道发送 core:console.execute 请求，载荷为 {"line":"raid start core:mvp_test_raid"}；服务端在模拟线程中校验命令、权限和世界生命周期，然后执行。单机使用 loopback 会话，遵循相同的请求和回包流程。客户端不会在键盘回调中直接创建实体或修改 ECS。

raid、spawn_proto、tp、lua、echo、emit、time 及世界查询都由服务端处理。help、相机、视图、语言、RML 重载、渲染调试和连接管理命令由请求客户端处理；服务端拒绝执行客户端命令。没有可用服务端会话时，世界命令明确失败，不会回退到客户端执行。

提交后的 Submitted to server: request=... 只表示请求已提交。最终回包包含 ok 和 console_rows 数组，每行具有 type（output / warning / error）和 text。网络层按请求编号将结果交还发起者，客户端帧线程更新历史记录。断线和超时也会结束该请求，控制台回包不会进入普通游戏 UI 的命令结果通道。

玩家默认权限由服务端启动参数决定：服务端使用 --DEBUG 启动时，本机客户端和远程玩家均默认为 developer；否则均默认为 player。客户端自己的启动参数不会提升远程服务端授予的权限。服务端的 config/console_permissions.json 可用可选的 access_level 和 remote_access_level 显式覆盖本机与远程等级；CoreMod 默认文件不写这两个字段，以采用启动模式默认值。执行仍检查 command_permissions 中逐命令要求，普通模式的服务端会按 player 等级校验请求，不会一概禁用服务端命令入口。连接身份由网络层提供，客户端载荷中的权限或用户名不会授予执行权限。别名先展开，再检查实际目标命令权限。

帮助和补全

控制台输入框支持命令历史。当前 RML 伪输入尚未接入 Tab 补全；用 help 查看命令与用法：

help                  -- 分页列出命令
help 2 20             -- 查看第 2 页，每页 20 条
help list_data        -- 查看单条命令用法
help ?faction 1 20    -- 按关键词搜索命令和说明

当前内置别名会在读取 console_aliases.json 前注册：

常用命令

命令用途
mods查看已安装的 MOD 列表与其中真正加载的数量；禁用（或已启用但需重启）的条目会带 [disabled] / [enabled, restart required] 标记。
help [page] [size] / help <command> / help ?keyword列出命令、查看单条命令说明或按关键词搜索。
mod_settings [mod_id] [key]查看 MOD 的最终配置值（禁用 MOD 的配置同样可查，条目会带 [disabled] 标记）。
list_data [type] [page] [size] [prefix=...] [mod=...] [sort=asc|desc]分页查看注册表。type 可使用基础内容、经营规则、生态、动态天气、视野和难度等已注册类型；不写 type 时列出全部类型。
data <id> / data type:<type>查看单条数据的详情，或列出某类型全部数据。data type:factions、data type:faction_spawn_rules 和 data type:name_pools 可查看阵营、阵营生成规则和名称池。
list_recipes [page] [size] [prefix=...] [sort=asc|desc]查看所有已注册的配方。
list_protos [page] [size] [prefix=...] [sort=asc|desc]查看所有实体原型。
spawn_proto <id>按原型 ID 生成非殖民者实体；带 ColonistTag 的原型固定拒绝，自动补全也不会列出。
raid list / raid statusraid list 列出全部袭击定义；raid status 列出全部活动袭击、袭击 UUID、定义 ID、波次、存活数、目标和 active/paused 状态。
raid start <RaidID>通过服务端启动指定袭击。服务端为活动实例分配 UUID；定居点来源从该阵营的非玩家实例中按 UUID 稳定选择。生成失败时返回稳定原因。
raid stop [RaidUUID] / raid pause [RaidUUID] / raid resume [RaidUUID]停止、暂停或恢复袭击。省略 UUID 时作用于全部活动袭击；停止会撤回并清理剩余袭击者。暂停冻结波次、目标刷新和时限计时，已生成袭击者仍按普通 AI、战斗和物理规则活动。UUID 会随存档和联机状态保留。
inventory <entity_uuid> / inventory_page <entity_uuid>只读查看所有者背包内容和实体装备槽，显示槽位、定义 ID、数量与品质；穿戴装备没有独立库存 UUID。
list_factions / list_name_pools查看已注册的 NPC 阵营定义和名称池。
list_faction_instances查看已经生成的 NPC 阵营实例。
gen_name <template> [seed]按名称模板生成调试名称。模板里可写 ${random_name}。
net_status查看网络角色、连接状态和同步计数。
net_server [port] / net_join server [port]启动服务器或连接到服务器。
net_disconnect断开网络连接。
mod_list / export_mod_list列出/导出 MOD 列表及校验码（调试网络 MOD 一致性）。
lua <code>发送服务端命令，在服务器 Lua VM 执行代码，与 emit、echo 按网络接纳顺序处理，结果回传请求客户端。运行时不可用或世界正在迁移时拒绝。
echo <lua_expression>发送服务端命令求值 Lua 表达式。暂停时仍可处理，结果由客户端主线程显示；错误详情见服务端日志。执行由统一 watchdog 监测。
time query / time set <时刻> / time add <增量>发送服务端命令查询或调整时间。时刻支持 morning/noon 等名称、00:00 至 23:59 或日内数值，增量为正整数。按每个模拟 Tick 的时间精度取整；目标时刻已过则前进到次日，不倒退模拟时钟。增量保留日内取模行为。
locale_list / locale_set <id> / locale_reload查看、切换和重载本地化资源。
reload / reload rml仅 --DEBUG 可用。reload 向服务端发送注册表重载请求，由服务端在可用帧间准备双端 Lua、状态、UI、原生定义和渲染资源；候选准备失败保留旧环境。保存或载入期间延后。Lua 文件变化由自动监听单独处理，不能传 Lua 路径给此命令。reload rml 在请求客户端重载游戏内 RML/RCSS。
ui_lab / ui_lab show / ui_lab hide / ui_lab toggle / ui_lab components / ui_lab tech_tree切换、显示、隐藏真实 RmlUI 设计实验室，或直接打开指定预览场景。仅 --DEBUG 运行会加载该文档；普通/Release 路径不可用。Components 与 Tech Tree fixture 场景都使用真实共享 RCSS；修改后执行 reload rml 即可刷新。
save [name] / load [name] / save_list保存、加载和列出存档。
list_entities [page] [size]分页查看当前世界所有实体。
list_civs查看文明系统状态。

标准检查流程

做好 MOD 后，按这个顺序跑一遍，基本能把注册问题都找出来：

  1. mods —— 确认 MOD 出现在加载列表中。
  2. list_data blocks prefix=copper_age: —— 检查方块是否注册。
  3. list_data jobs prefix=copper_age: —— 检查职业是否注册。
  4. list_data civilizations prefix=copper_age: —— 检查文明是否注册。
  5. list_data focuses prefix=copper_age: —— 检查 要闻 是否注册。
  6. data type:factions —— 检查 NPC 阵营定义是否注册。
  7. data copper_age:copper_clan —— 查看单条记录详情。
  8. list_recipes 1 20 prefix=copper_age: —— 检查配方是否注册。

说明

doctor_*、diff_*snapshot*、*doctor_archives* 这些命令主要给引擎维护者用。普通 MOD 作者一般不需要关心它们。
