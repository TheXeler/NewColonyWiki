本地化与翻译文件

翻译文件放在 MOD 根目录的 lang/ 下。文件名去掉 .json 后就是 locale ID，例如 en-us、zh-cn。

文件结构

每个 locale 文件必须是 UTF-8 JSON 对象。第一层是分类，第二层是 key 和文本。引擎用 category.key 作为完整翻译 key。

{
  "ui": {
    "menu.start": "Start",
    "menu.quit": "Quit"
  },
  "blocks": {
    "my_mod:copper_ore": "Copper Ore"
  }
}

对应的中文文件可以写成：

{
  "ui": {
    "menu.start": "开始",
    "menu.quit": "退出"
  },
  "blocks": {
    "my_mod:copper_ore": "铜矿石"
  }
}

加载与合并

  • 核心语言目录在引擎初始化时先加载；当前 CoreMod 提供 en-us.json 和 zh-cn.json。
  • 每个已加载 MOD 的 lang/ 会在 MOD 脚本加载完成后合并到同一个 LocalizationManager。
  • merge_mod_translations(mod_id, dir) 不会自动给分类或 key 加命名空间；如果两个 MOD 写了相同 locale、category 和 key，后加载的 MOD 会覆盖前面的文本。
  • load_directory() 只扫描 lang/ 顶层的 .json 文件，不递归子目录。
  • set_locale(id) 只会切换到已经加载的 locale；ID 应使用文件名里的小写形式，例如 zh-cn，不是 zh_CN。
MOD 入口脚本执行时，该 MOD 自己的 lang/ 还没有完成合并。需要依赖 MOD 翻译内容的 UI 查询，建议放到 on_world_init、UI 打开时或更晚的运行时逻辑中。

查询规则

翻译查询会先查当前 locale，再查 fallback chain，再查默认 en-us。仍然找不到时，引擎返回原 key 并写入缺失翻译日志。

local current = engine.locale.current_locale()
local start = engine.locale.translate("ui.menu.start")
local same = engine.locale.translate_cat("ui", "menu.start")
local resolved = engine.locale.resolve("blocks.my_mod:copper_ore")

Lua API

函数说明
engine.locale.translate(key)按完整 key 查询，等价于按第一个 . 拆成分类和 key。
engine.locale.translate_cat(category, key)按分类和 key 查询。
engine.locale.resolve(text)只有文本里包含 . 时才尝试翻译，否则原样返回。
engine.locale.current_locale()返回当前 locale ID。
engine.locale.set_locale(id)切换当前 locale；无效 ID 会保留当前语言。
engine.locale.get_locale()返回当前 locale ID。
engine.locale.get(category, key)按分类和 key 查询。
engine.locale.t(key)按完整 key 查询。
engine.locale.list_locales()返回已加载 locale ID 列表。
engine.locale.reload()重新加载核心语言目录和已记住的 MOD 语言目录。
engine.locale.load_locale(id, path)从指定 JSON 文件加载或覆盖一个 locale。

控制台命令

运行时可以用控制台检查和切换语言：

  • locale_list：列出当前已加载 locale。
  • locale_set <id>：切换当前语言。
  • locale_reload：重新加载核心和 MOD 翻译文件。
