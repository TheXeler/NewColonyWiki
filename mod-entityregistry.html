实体注册

实体原型（Entity Prototype）定义在 data/entities/ 下，以 JSON 描述。每个实体原型通过组件拼装定义一类实体的初始状态——殖民者、农民、矿工等都是不同的实体原型。引擎在运行时根据原型创建实体实例。

JSON 格式

{
    "id": "my_mod:hunter",
    "components": {
        "Position": { "x": 0, "y": 64, "z": 0 },
        "Velocity": { "x": 0, "y": 0, "z": 0 },
        "Needs": { "hunger": 50.0, "fatigue": 20.0 },
        "ColonistTag": {},
        "AIState": { "behavior_tree_id": 0, "current_node": 0, "lod_level": 0 },
        "Profession": { "id": "my_mod:hunter", "level": 1 },
        "Name": { "data": "Hunter" },
        "Stats": { "strength": 12.0, "dexterity": 14.0, "intelligence": 8.0 },
        "HeldItem": {},
        "Equipment": {}
    }
}

字段说明

字段类型必填说明
idstring是唯一标识，格式 <mod_id>:<name>。
componentsobject是组件表。键为组件名，值为组件初始数据。必须是一个非空对象。
实体原型的核心是组件拼装——你不需要写代码，只需在 JSON 中声明"这个实体有哪些组件、初始值是什么"。引擎根据组件列表创建 ECS 实体并填充数据。

可用组件

组件名字段说明
Positionx, y, z (float)世界坐标。
Velocityx, y, z (float)移动速度向量。
Rotationyaw, pitch (float)朝向。yaw 为水平偏航，pitch 为俯仰。
Scalex, y, z (float)缩放。
Healthcurrent, max (float)生命值。
Needshunger, fatigue (float, 0~100)需求值。hunger 越高越饿，fatigue 越高越累。两项均随时间上升，AI 会根据需求自动寻求满足。
Moodmood_value (float, 0~100)心情值。JSON 中写 "Mood": { "mood_value": 50.0 }。
ColonistTag（无字段）标记为殖民者。拥有此组件的实体参与殖民者相关的 AI 逻辑和统计。
AIStatebehavior_tree_id (int), current_node (int), lod_level (int)AI 状态。behavior_tree_id 决定使用哪个行为树，lod_level 控制更新频率。
NavAgenttarget_x, target_y, target_z (float)；运行时还有 waypoints[]、path_count、current_index导航代理。携带寻路目标坐标和路径数据。
Professionid (string), level (int, 1~5)职业。id 必须指向已注册的职业。
BlockInteractortarget_block (Vec3i), action_type (int)方块交互器。action_type: 1=挖掘, 2=放置, 3=交互。
HeldItemitem_id (u32), count (u32)手持物品。
Inventory（legacy，最多 32 格）遗留多槽背包。当前实体原型以 HeldItem 为主；若 JSON 同时提供 Inventory（含 slots 数组），加载器会取第一个 slot 作为 HeldItem。
Equipment（由系统管理）装备栏。
Statsstrength, dexterity, intelligence (float)属性值。影响各种游戏计算。
Namedata (string)显示名称。
PrototypeRefdata (string)引用创建该实例的原型 ID。

殖民者 core:colonist

通用殖民者原型，全属性 10，使用通用行为树（ID 0）。作为文明开局的基础单位，后续可转职为其他职业。

职业原型

各职业原型有针对性的属性分配：铁匠和石匠力量高（13~14），厨师和陶工智力高（11~12），农民较均衡。行为树 ID 对应不同的 AI 行为模式。注意部分实体 ID 带有 _entity 后缀。

生成实体

通过 Lua API 从原型生成实体：

-- 在指定位置生成一个矿工
local id = engine.ecs.spawn_prototype("core:miner")
engine.ecs.set_position(id, 10, 70, 20)

或在控制台中：

spawn_proto core:miner          -- 在玩家附近生成一个矿工实体

文件放置规则

  • 放在 data/entities/ 下，支持子目录。
  • 文件名随意，引擎只关心 JSON 内的 id 字段。

验证命令

list_data entities               -- 列出所有已注册的实体原型
data core:miner                  -- 查看单个原型的完整 JSON
spawn_proto core:miner           -- 在世界中生成一个实例

实体模型与动画

实体渲染由 Visual 和 Animation 组件驱动。没有声明 Visual 的原型仍会使用默认 box 外观；声明 model: "biped" 后会渲染为头、身体、双臂、双腿的分块模型。RimWorld/RimColony pawn 语义由 RimColonyCompact 的 Lua converter 转换成普通 NewColony 实体视觉数据；converter 可解析 RimWorld 风格 texPath 和朝向贴图路径。

"Visual": {
  "model": "biped",
  "texture": "textures/entities/colonist.png",
  "width": 0.45,
  "height": 1.70,
  "depth": 0.45
},
"Animation": {
  "enabled": true,
  "walk_speed": 6.0,
  "walk_amplitude": 35.0,
  "idle_bob": 0.015
}

Animation 当前支持 biped 的程序行走动画：实体有水平速度时摆臂摆腿，walk_speed 控制频率，walk_amplitude 控制角度。完整 MOD 写法见仓库根目录 Entites Model.html。
