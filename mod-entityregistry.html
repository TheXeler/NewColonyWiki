实体注册

实体原型（Entity Prototype）定义在 data/entities/ 下，以 JSON 描述。每个实体原型通过组件拼装定义一类实体的初始状态——殖民者、农民、矿工等都是不同的实体原型。引擎在运行时根据原型创建实体实例。

JSON 格式

{
    "id": "my_mod:hunter",
    "components": {
        "Position": { "x": 0, "y": 64, "z": 0 },
        "Speed": { "x": 0, "y": 0, "z": 0 },
		"PhysicsCollider": { "affected_by_gravity": true },
        "Needs": { "hunger": 50.0, "fatigue": 20.0 },
        "ColonistTag": {},
        "AIState": { "behavior_tree_id": 0, "current_node": 0, "lod_level": 0 },
        "Job": { "id": "my_mod:hunter", "level": 1 },
        "Name": { "data": "Hunter" },
        "Backstory": { "data": "Former trail scout with steady hands." },
		"Health": { "current": 80, "max": 80 },
		"ColonistAttributes": { "work_efficiency": 1.0, "backpack_slots": 1, "backpack_stack_capacity": 8 },
        "Equipment": {}
    }
}

字段说明

字段类型必填说明
idstring是唯一标识，格式 <mod_id>:<name>。遵循标准 ID 规则。
componentsobject是组件表。键为组件名，值为组件初始数据。必须是一个非空对象。
death_output_tabledata id否实体死亡时执行的统一产出表。省略时不产生定义级死亡掉落。
death_output_table_executionspositive integer否死亡时执行产出表的次数；声明产出表但省略本字段时为 1。
animalboolean否标记原型是可被狩猎指定的动物。不会自动把普通实体视为动物。
aggressionenum动物必填passive、neutral 或 aggressive，用于狩猎预览。

生命值降到 0 的非殖民者实体会直接在当前位置执行死亡产出表并移除，不创建尸体。结果写入统一地面物品实例，自动允许玩家回收，但进入仓储前不计入玩家仓储资源。产出表缺失或结构无效时原型保留，engine.modding.get_entity_info(id) 返回稳定屏障原因及来源路径；不会用默认掉落代替。

狩猎只接受当前被单选或多选的具体 animal=true 实体，并要求有效死亡产出表。面板显示每个目标的攻击性、可达性和合格执行者数量。确认后每个动物对应一个独立 Hunt 工作；动物移动时工作目标随之更新，死亡、消失或玩家从目标来源取消后授权结束。系统不创建持续狩猎区，也不会把后续刷新的动物加入旧指定。

狩猎工作量由唯一的 data/hunting_rules/ 记录提供，例如 { "id": "mod:hunting", "work_amount": 100 }。该内容表可以为空；缺失时入口显示配置屏障，不使用代码默认值。职业通过 allowed_work_tags: ["hunt"] 声明资格。

实体原型的核心是组件拼装——你不需要写代码，只需在 JSON 中声明这个实体有哪些组件、初始值是什么。引擎根据组件列表创建 ECS 实体并填充数据。

可用组件

组件名字段说明
Positionx, y, z (float)世界坐标。
Speedx, y, z (float)移动速度向量。
Healthcurrent, max (integer)生命值。殖民者原型必须显式提供有效值；不会由另一组属性推导。
Needshunger, fatigue (float, 0~100)剩余饱食度和精力值。两项随时间下降；低于阈值后 AI 会生成进食或休息需求，归零后开始累积对应负面状态。
Moodmood_value (float, 0~100)心情值。JSON 中写 "Mood": { "mood_value": 50.0 }。
ColonistTag（无字段）标记为殖民者。拥有此组件的实体参与殖民者相关的 AI 逻辑和统计。
AIStatebehavior_tree_id (int), current_node (int), lod_level (int)AI 状态。behavior_tree_id 决定使用哪个行为树，lod_level 控制更新频率。
NavAgent不从 JSON 读取拥有 AIState 的原型生成实体时会自动附加导航代理。寻路只写入路线；实体 locomotion 层把局部目标转换为有水平和垂直极值的三维移动矢量，跳跃也通过垂直速度实现。物理层只积分矢量并解算碰撞；动画依据碰撞解算后的实际水平速度播放。
Speed runtimegrounded, in_fluid运行时物理状态，用于重力、落地和流体碰撞处理。NCDOCS 未定义摔落伤害或水流推动实体，因此引擎不提供这些隐式玩法。
PhysicsColliderhalf_width, height, half_depth, collision_enabled, affected_by_gravity引擎定义的权威物理属性，Mod 只能配置初始值，不能替换其语义或碰撞规则。位置表示脚底中心，碰撞箱向上延伸；collision_enabled 控制体素碰撞以及静止实体间的重叠分离，affected_by_gravity 控制重力，两者默认均为 true。移动中的实体不会互相阻挡，但仍与地形碰撞；两者静止且碰撞箱重叠时会互相挤开。物理层每 tick 重新检查脚下支撑，并处理墙面滑动、落地及流体接触。组件随存档保存。
Jobid (string), level (int, 1~5)职业。id 必须指向已注册的职业。
BlockInteractor不从 JSON 读取拥有 AIState 的原型生成实体时会自动附加方块交互器。运行时 action_type: 1=采掘, 2=放置, 3=交互。
Equipmentitem单一装备栏。原型中写 {"Equipment": {"id": "core:tool", "count": 1}}；省略或写空对象表示没有装备。
ColonistAttributes文档属性字段直接声明基础、工作和战斗属性；运行时不会从力量、敏捷或智力推导。省略背包格数时为 0，不能携带物品；仅单格容量允许按经营文档缺省为 8。
Namedata (string)显示名称。
Backstorydata 或 value (string)角色经历文本。人员界面的角色菜单会通过聚合接口展示该字段。
PrototypeRef自动生成引用创建该实例的原型 ID。实体原型 JSON 不需要声明。
Visualmodel, texture, width, height, depth实体外观。未声明时使用默认 box 外观；model: "biped" 会自动生成默认头部视觉。
Animationenabled, walk_speed, walk_amplitude, idle_bobbiped 程序动画参数。
HeadVisualcenter_x, center_y, center_z, width, height, depth头部视觉盒，用于看向 InterestPoint。可覆盖 biped 自动生成的头部。
Rotation 和 Scale 是运行时 ECS/Lua 可用组件，但当前实体原型解析器不会从 JSON 中读取它们。需要旋转或缩放时，可在 Lua 里调用 engine.ecs.set_rotation 或 engine.ecs.set_scale。

殖民者属性

ColonistAttributes 直接表达设计文档中的初始属性、工作属性和战斗属性。职业、殖民者状态和药剂进入同一修饰器汇总：最终值等于初始值加全部固定加值，再加初始值乘全部比例；来源顺序不产生复利。只读聚合入口是 engine.jobs.aggregate_attributes(entity)。

人员界面聚合接口

HTML/Lua UI 可通过 engine.colonists 读取页面所需数据：

API说明
engine.colonists.list(Job_filter?, sort_key?)返回殖民者列表摘要，字段包含名称、职业 ID/名称、等级、经验和心情；sort_key 支持 name、Job、level、xp、mood。
engine.colonists.detail(entity)返回角色菜单数据：名称、职业、职业等级/经验、经历、心情、thoughts、基础/工作/战斗属性分组。
engine.colonists.equipment(entity)返回统一装备槽、统一背包物品实例及筛选/排序字段。

内置实体原型

CoreMod 只注册 1 个殖民者实体原型。职业不是实体类型；矿工、木匠、铁匠等都从 core:colonist 开始，进入世界后通过指定装备实例的换装事务转入职业。

原型ID初始职业行为树
殖民者core:colonistcolonist（无等级）0

殖民者 core:colonist

通用殖民者原型使用通用行为树（ID 0），初始职业无等级。NCDOCS 尚未给出基础生命、需求、心情和属性数值，因此 CoreMod 当前不填写这些数值。新世界先报告 initial_site_selection_required；玩家通过 Host 权威命令选择预生成地图中的 q/r 后，选址写入 core:initial_colony schema v1，并改报 initial_roster_and_supplies_undefined。固定坐标初始生成入口已删除，初始 roster、物资和散布规则不采用代码默认值；招募待登记实体也会在基础属性缺失时拒绝。

生成实体

运行时 Lua 不提供通用原型生成入口。殖民者必须走初始生成或招募登记链；生态动物由 animal_distributions 规则驱动，并通过 engine.ecology.spawn_animal_at(rule_id, x, y, z) 解析该规则声明的动物原型。开发者诊断仍可在控制台中使用：

spawn_proto my_mod:pack_animal

生成时自动补全

  • 生成实体总会写入 PrototypeRef，值为原型 ID。
  • 声明 AIState 的原型会自动获得 WorkerPriorityConfig、NavAgent、BlockInteractor；殖民者原型未声明 Job 时使用无等级初始节点 core:colonist。
  • 殖民者原型必须显式声明 Health、Needs、Mood 和 ColonistAttributes；缺少任一项时初始生成和招募入场返回 colonist_base_attributes_undefined，不会补代码默认值。

文件放置规则

  • 放在 data/entities/ 下，支持子目录
  • 文件名随意，引擎只关心 JSON 内的 id 字段。

验证命令

list_data entities               -- 列出所有已注册的实体原型
data core:colonist               -- 查看殖民者原型的完整 JSON
spawn_proto my_mod:pack_animal   -- 在世界中生成非殖民者实体

实体模型与动画

实体渲染由 Visual 和 Animation 组件驱动。没有声明 Visual 的原型仍会使用默认 box 外观；声明 model: "biped" 后会渲染为石质摩尔庄园风格的 Q 版三头身模型——大头、小身体、浮动的手脚（脚与身体之间保留较小间隙，整体控制在实体高度内）。

"Visual": {
  "model": "biped",
  "texture": "textures/entities/colonist.png",
  "width": 0.8,
  "height": 1.80,
  "depth": 0.8
},
"Animation": {
  "enabled": true,
  "walk_speed": 8.0,
  "walk_amplitude": 25.0,
  "idle_bob": 0.015
}

Animation 当前支持 biped 的程序行走动画：实体有水平速度时双脚和双手前后摆动，walk_speed 控制频率，walk_amplitude 控制角度。Biped 模型头部约占实体高度 40%，身体约 35%，脚底贴地，脚与身体之间使用紧凑间隙以适配 1.8 格实体高度。模型资源写法见 模型资源。

带有 HeadVisual 的实体会跟踪运行时 InterestPoint；没有 active interest point 时，头部使用身体朝向。方块交互会把 interest point 设置到被交互方块中心。

任意实体都可以通过 HeadVisual 组件加入这个行为。使用 center_x、center_y、center_z、width、height 和 depth 描述模型局部空间中的头部盒。
