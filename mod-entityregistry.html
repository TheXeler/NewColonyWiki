实体注册

实体原型（Entity Prototype）定义在 data/entities/ 下，以 JSON 描述。每个实体原型通过组件拼装定义一类实体的初始状态——殖民者、农民、矿工等都是不同的实体原型。引擎在运行时根据原型创建实体实例。

JSON 格式

{
    "id": "my_mod:hunter",
    "components": {
        "Position": { "x": 0, "y": 64, "z": 0 },
        "Speed": { "x": 0, "y": 0, "z": 0 },
        "Needs": { "hunger": 50.0, "fatigue": 20.0 },
        "ColonistTag": {},
        "AIState": { "behavior_tree_id": 0, "current_node": 0, "lod_level": 0 },
        "Job": { "id": "my_mod:hunter", "level": 1 },
        "Name": { "data": "Hunter" },
        "Backstory": { "data": "Former trail scout with steady hands." },
        "Stats": { "strength": 12.0, "dexterity": 14.0, "intelligence": 8.0 },
        "HeldItem": {},
        "Equipment": {}
    }
}

字段说明

字段类型必填说明
idstring是唯一标识，格式 <mod_id>:<name>。遵循标准 ID 规则。
componentsobject是组件表。键为组件名，值为组件初始数据。必须是一个非空对象。
实体原型的核心是组件拼装——你不需要写代码，只需在 JSON 中声明这个实体有哪些组件、初始值是什么。引擎根据组件列表创建 ECS 实体并填充数据。

可用组件

组件名字段说明
Positionx, y, z (float)世界坐标。
Speedx, y, z (float)移动速度向量。
Healthcurrent, max (integer)生命值；未声明时会根据 Stats.max_hp 推导。
Needshunger, fatigue (float, 0~100)剩余饱食度和精力值。两项随时间下降；低于阈值后 AI 会生成进食或休息需求，归零后开始累积对应负面状态。
Moodmood_value (float, 0~100)心情值。JSON 中写 "Mood": { "mood_value": 50.0 }。
ColonistTag（无字段）标记为殖民者。拥有此组件的实体参与殖民者相关的 AI 逻辑和统计。
AIStatebehavior_tree_id (int), current_node (int), lod_level (int)AI 状态。behavior_tree_id 决定使用哪个行为树，lod_level 控制更新频率。
NavAgent不从 JSON 读取拥有 AIState 的原型生成实体时会自动附加导航代理。
Speed runtimefall_distance, grounded, in_fluid运行时物理状态。实体会受重力影响，下落超过 4 格后受伤；在水中忽略摔落伤害，并会受流体推动。
Jobid (string), level (int, 1~5)职业。id 必须指向已注册的职业。
BlockInteractor不从 JSON 读取拥有 AIState 的原型生成实体时会自动附加方块交互器。运行时 action_type: 1=挖掘, 2=放置, 3=交互。
HeldItemid (string), count (u32)手持物品。id 会被哈希为运行时 item_id；空对象表示有手持槽但初始为空。
Equipmentitem单一装备栏。原型中写 {"Equipment": {"id": "core:tool", "count": 1}}；省略或写空对象表示没有装备。
Statsstrength, dexterity, intelligence (float)基础属性。加载、生成、读档或通过 Lua 修改基础属性后会重新计算派生属性；导航实体会使用派生移动速度。
Namedata (string)显示名称。
Backstorydata 或 value (string)角色经历文本。人员界面的角色菜单会通过聚合接口展示该字段。
PrototypeRef自动生成引用创建该实例的原型 ID。实体原型 JSON 不需要声明。
Visualmodel, texture, width, height, depth实体外观。未声明时使用默认 box 外观；model: "biped" 会自动生成默认头部视觉。
Animationenabled, walk_speed, walk_amplitude, idle_bobbiped 程序动画参数。
HeadVisualcenter_x, center_y, center_z, width, height, depth头部视觉盒，用于看向 InterestPoint。可覆盖 biped 自动生成的头部。
Rotation 和 Scale 是运行时 ECS/Lua 可用组件，但当前实体原型解析器不会从 JSON 中读取它们。需要旋转或缩放时，可在 Lua 里调用 engine.ecs.set_rotation 或 engine.ecs.set_scale。

基础属性与派生属性

Stats 只在实体原型 JSON 中声明三项基础属性：strength、dexterity 和 intelligence。运行时会由 Stats.recompute() 推导其他属性。

基础属性派生属性公式当前影响
strengthmax_hp50 + strength * 5未显式声明 Health 时用于生成初始最大生命。
strengthmining_speed0.5 + strength * 0.05预留给挖掘效率。
strengthcarry_move_speed0.5 + strength * 0.05带有 HeldItem 且正在手持物品的 NavAgent 使用该倍率移动。
strengthmelee_damage1 + strength * 0.3预留给近战伤害。
dexteritymove_speed1 + dexterity * 0.04空手 NavAgent 使用该倍率移动；不要求实体是殖民者。
dexteritydodge_ratemin(dexterity * 0.01, 0.5)预留给闪避。
dexterityranged_damage1 + dexterity * 0.3预留给远程伤害。
intelligencework_speed0.5 + intelligence * 0.05预留给通用工作效率。
intelligencework_success_ratemin(0.5 + intelligence * 0.02, 1)预留给工作成功率。
intelligencespell_damage1 + intelligence * 0.4预留给法术伤害。

没有 Stats 的导航实体默认速度为 0，不会获得隐含移动速度。拥有 Stats 的实体空手时直接使用 move_speed 作为导航速度；如果正在手持物品，则改用 carry_move_speed。

人员界面聚合接口

HTML/Lua UI 可通过 engine.colonists 读取页面所需数据：

API说明
engine.colonists.list(Job_filter?, sort_key?)返回殖民者列表摘要，字段包含名称、职业 ID/名称、等级、经验和心情；sort_key 支持 name、Job、level、xp、mood。
engine.colonists.detail(entity)返回角色菜单数据：名称、职业、职业等级/经验、经历、心情、thoughts、基础/工作/战斗属性分组。
engine.colonists.equipment(entity)返回装备槽、装备属性、HeldItem/Inventory 物品栏，并提供 sort_keys 与 filter_keys。

内置实体原型

CoreMod 只注册 1 个殖民者实体原型。职业不是实体类型；矿工、木匠、铁匠等都应生成为 core:colonist，再通过 Job 数据组件或 engine.jobs.assign 分配职业。

原型ID默认职业力量/敏捷/智力行为树
殖民者core:colonistcolonist (Lv.1)10 / 10 / 100

殖民者 core:colonist

通用殖民者原型，全属性 10，使用通用行为树（ID 0）。作为文明开局的基础单位，后续可转职为其他职业。

生成实体

通过 Lua API 从原型生成实体，并按需分配职业：

-- 在指定位置生成一个殖民者并分配矿工职业
local id = engine.ecs.spawn_prototype("core:colonist")
engine.ecs.set_position(id, 10, 70, 20)
engine.jobs.assign(id, "core:miner", 1)

或在控制台中：

spawn_proto core:colonist       -- 在玩家附近生成一个殖民者实体

生成时自动补全

  • 生成实体总会写入 PrototypeRef，值为原型 ID。
  • 声明 AIState 的原型会自动获得 WorkerPriorityConfig、NavAgent、BlockInteractor 和默认职业 core:worker（如果 JSON 没有声明 Job）。
  • 声明 Needs 但未声明 Mood 时，会自动添加默认 Mood。
  • 声明 Stats 时会重新计算派生属性；未声明 Health 时，生命值会用派生 max_hp。

文件放置规则

  • 放在 data/entities/ 下，支持子目录
  • 文件名随意，引擎只关心 JSON 内的 id 字段。

验证命令

list_data entities               -- 列出所有已注册的实体原型
data core:colonist               -- 查看殖民者原型的完整 JSON
spawn_proto core:colonist        -- 在世界中生成一个殖民者实体

实体模型与动画

实体渲染由 Visual 和 Animation 组件驱动。没有声明 Visual 的原型仍会使用默认 box 外观；声明 model: "biped" 后会渲染为石质摩尔庄园风格的 Q 版三头身模型——大头、小身体、浮动的手脚（脚与身体之间保留较小间隙，整体控制在实体高度内）。RimWorld/RimColony pawn 语义由 RimColonyCompact 的 Lua converter 转换成普通 NewColony 实体视觉数据；converter 可解析 RimWorld 风格 texPath 和朝向贴图路径。

"Visual": {
  "model": "biped",
  "texture": "textures/entities/colonist.png",
  "width": 0.8,
  "height": 1.80,
  "depth": 0.8
},
"Animation": {
  "enabled": true,
  "walk_speed": 8.0,
  "walk_amplitude": 25.0,
  "idle_bob": 0.015
}

Animation 当前支持 biped 的程序行走动画：实体有水平速度时双脚和双手前后摆动，walk_speed 控制频率，walk_amplitude 控制角度。Biped 模型头部约占实体高度 40%，身体约 35%，脚底贴地，脚与身体之间使用紧凑间隙以适配 1.8 格实体高度。模型资源写法见 模型资源。

带有 HeadVisual 的实体会跟踪运行时 InterestPoint；没有 active interest point 时，头部使用身体朝向。方块交互会把 interest point 设置到被交互方块中心。

任意实体都可以通过 HeadVisual 组件加入这个行为。使用 center_x、center_y、center_z、width、height 和 depth 描述模型局部空间中的头部盒。
