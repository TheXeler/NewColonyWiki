NewColony

一款殖民地模拟游戏。你带领一群殖民者来到新的土地，从零开始建造一个能运转的家园。每个殖民者有自己的名字、职业、技能和需求——饿了要找吃的，累了要休息，还需要和其他人交流。你的工作是给他们分配工作、规划生产线、应对各种事件，让他们活下去并且过得越来越好。游戏里的世界由体素（方块）组成，支持程序化地形生成、昼夜循环和动态天空。

这份 Wiki 是写给 MOD 作者的。我们不会讲引擎内部实现，只告诉你"能配置什么、脚本能调用什么、出了问题怎么查"。C++ 内部类和未列出的字段都不应作为兼容承诺依赖。

查阅系统现状，了解存档、战斗、城邦模拟、外交、网络和界面的使用范围与兼容边界。

推荐阅读顺序

  1. 先看概念。了解 MOD 如何被加载，理解目录结构、加载顺序、多类数据注册和 Lua 生命周期。这样后面看 data/blocks 和监听器时不会混淆。
  2. 再注册新东西。从 mod.json 开始，按系统入口选择数据文件注册表或代码注册表。物品、方块、科技项目等使用 JSON；科技界面分类、外交提议、效果生命周期等使用 Lua 注册。
  3. 最后写 Lua。Lua 用来处理事件响应、定时器、要闻条件和运行时逻辑，不是用来重建数据系统的。

MOD 能力概览

能力状态说明
MOD 发现与加载可用mod.json 清单、依赖顺序、load_before 通配符、严格清单检查、用户设置覆盖。
数据注册可用通过 data/ 注册基础内容、经营规则、生态、动态天气、视野和难度等多类数据；职业定义只从 jobs 读取，没有旧目录别名。Tags 是统一物品分类标签，不再承担旧矿物体素词典。科技见 科技注册。
代码注册入口按具体系统说明代码注册总览集中列出科技分类、外交提议与指标、效果生命周期、监听器、定时器类型及 UI 提供器。执行端、重复定义和恢复规则由各接口分别约定。
Lua 生命周期可用scripts/listeners/ 下的监听器按 @Event、@Priority 和执行端声明自动注册；其他模块按需 require。
事件和定时器可用engine.events 和 engine.timers。10+ 内置事件，支持自定义。
控制台系统可用75 个控制台命令，权限系统，别名，配置验证（doctor），快照和差异对比。
其他殖民地与外交部分支持MOD 可注册 Lua 外交提议与查询指标。谈判、战争状态和条约由服务器管理，RmlUI 提供操作界面。
体素世界部分支持支持可变高度区块列、地形生成与群系配置。石材开采和加工使用矿脉、切石机及共用搬运系统。详见 石材矿脉、切石机与搬运。
网络同步可用Server/Client TCP 同步、快照广播、MOD 列表校验码交换。
本地化可用本体 assets/lang/、CoreMod/MOD lang/ 合并、Lua 查询/切换/热重载 API 和控制台命令。详见 本地化与翻译。
UI 框架部分可用玩家可见 UI 统一走 RmlUI；旧 Lua UI 注册 API 已通过 RmlUI HUD 兼容层显示底栏扩展、窗口和浮动提示，主题扫描仍只作旧配置兼容。
经营界面部分可用游戏内底栏注册伐木、采掘、区域、指令、制造、仓储、科技、招募、策略和日志入口；区域打开持续区域二级菜单，运行中不显示难度入口。实现阶段暂时增加人员列表入口，双击殖民者会从上方聚焦该实体。其他专项管理面板只从对应聚合入口、对象摘要或状态跳转打开。旧小地图悬浮窗和底栏地图按钮已由进入世界时自动显示的战略地图悬浮窗取代。UI 主路线是游戏内 RmlUI（宿主层 RmlUiServer），运行时文档位于 CoreMod/assets/ui/rml/。
区域系统部分可用持续区域只注册露天仓储区和种植区；采集与采掘使用一次性选择工具，不存在旧收获区、采掘区或居住区类型。
实体 AI 与 Task部分实体 AI 通过 TaskPool 调度与执行任务；使用需求、LOD、A* 和 NavMesh。战斗 Reaction 与漫游规则尚未实现。
存档部分实体、世界配置、动态天气区域、文明研究、建筑与区域实例、纪念记录、阵营、工作资源预留、要闻、统一物品和 Lua 订单与计划可保存。覆盖范围见 存档系统现状。
当前最适合开发内容型 MOD：物品、方块、配方、职业、实体原型、要闻、NPC 阵营、作物、区域和少量 Lua 辅助逻辑。完整能力清单见 当前能力状态。参考 CoreMod/ 了解目录结构和数据格式。
