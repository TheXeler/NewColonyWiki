NewColony

Engine implementation notes: Engine Lighting · Resource IO / UTF-8 Paths.

一款殖民地模拟游戏。你带领一群殖民者来到新的土地，从零开始建造一个能运转的家园。每个殖民者有自己的名字、职业、技能和需求——饿了要找吃的，累了要休息，还需要和其他人交流。你的工作是给他们分配工作、规划生产线、应对各种事件，让他们活下去并且过得越来越好。游戏里的世界由体素（方块）组成，支持程序化地形生成、昼夜循环和动态天空。

这份 Wiki 是写给 MOD 作者的。我们不会讲引擎内部实现，只告诉你"能配置什么、脚本能调用什么、出了问题怎么查"。C++ 内部类和未列出的字段都不应作为兼容承诺依赖。
如果你想先判断整个项目现在做到什么程度，阅读 项目完成度审计。它按引擎、玩法、MOD 数据、测试覆盖和发布门槛整理当前工作树的完成度。
存档系统的当前覆盖范围和限制见 存档系统状态；近战小队接触、命中公式、攻击冷却和测试命令见 战斗规则。

推荐阅读顺序

  1. 先看概念。了解 MOD 如何被加载，理解目录结构、加载顺序、多类数据注册和 Lua 生命周期。这样后面看 data/blocks 和 on_world_init 时不会混淆。
  2. 再注册新东西。从 mod.json 开始，然后添加方块、实体、配方、职业、文明、焦点、NPC 阵营、名称池、作物、区域类型和本地化文本。能用 JSON 表达的内容优先写 JSON。
  3. 最后写 Lua。Lua 用来处理事件响应、定时器、焦点条件和运行时逻辑，不是用来重建数据系统的。

当前能稳定使用的能力

能力状态说明
MOD 发现与加载可用mod.json 清单、依赖顺序、load_before 通配符、严格清单检查、用户设置覆盖。
数据注册可用通过 data/ 注册基础内容、经营规则、生态、动态天气、视野和难度等多类数据；旧 professions 作为 jobs 别名读取。Tags 是统一物品分类标签，不再承担旧矿物体素词典。科技见 科技注册。
Lua 生命周期可用入口脚本返回表，支持 on_load、on_world_init、on_tick、on_shutdown。
事件和定时器可用engine.events 和 engine.timers。10+ 内置事件，支持自定义。
控制台系统可用80+ 控制台命令，权限系统，别名，配置验证（doctor），快照和差异对比。
其他殖民地与外交接口保留 faction/name_pool、关系和空谈判状态 schema；专项文档未定义生成、关系范围或外交周期时，不随机创建 NPC 阵营或推进外交事件。
体素世界配置待补可变高度区块列、地形生成和六类群落接口已接入；Core 群落生成参数尚无文档数值，当前以配置屏障阻止使用旧噪声阈值。矿物只通过区块矿井规则存在，不生成矿石体素。
网络同步可用Host/Client TCP 同步、快照广播、MOD 列表校验码交换。
本地化可用本体 assets/lang/、CoreMod/MOD lang/ 合并、Lua 查询/切换/热重载 API 和控制台命令。详见 本地化与翻译。
UI 框架部分可用玩家可见 UI 统一走 RmlUI；旧 Lua UI 注册 API 已通过 RmlUI HUD 兼容层显示底栏扩展、窗口和浮动提示，主题扫描仍只作旧配置兼容。
经营界面部分可用游戏内底栏注册伐木、采掘、区域、指令、制造、仓储、科技、招募、策略和日志入口；区域打开持续区域二级菜单，运行中不显示难度入口。实现阶段暂时增加人员列表入口，双击殖民者会从上方聚焦该实体。其他专项管理面板只从对应聚合入口、对象摘要或状态跳转打开。旧小地图悬浮窗和底栏地图按钮已由进入世界时自动显示的战略地图悬浮窗取代。UI 主路线是游戏内 RmlUI（宿主层 RmlUiHost），运行时文档位于 CoreMod/assets/ui/rml/。
区域系统部分可用持续区域只注册露天仓储区和种植区；采集与采掘使用一次性选择工具，不存在旧收获区、采掘区或居住区类型。
AI 与行为树部分基于需求、调度、寻路（A* + NavMesh）、LOD 系统，行为树可运行。
存档部分实体、世界配置、动态天气区域、文明研究、建筑/区域实例、纪念记录、阵营、工作资源预留、焦点、统一物品和 Lua 订单/计划可保存；完整往返仍需活体验证。
当前最适合开发内容型 MOD：物品、方块、配方、职业、实体原型、焦点、NPC 阵营、作物、区域和少量 Lua 辅助逻辑。完整能力清单见 当前能力状态。参考 CoreMod/ 了解目录结构和数据格式。
