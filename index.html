NewColony

一款殖民地模拟游戏。你带领一群殖民者来到新的土地，从零开始建造一个能运转的家园。每个殖民者有自己的名字、职业、技能和需求——饿了要找吃的，累了要休息，还需要和其他人交流。你的工作是给他们分配工作、规划生产线、应对各种事件，让他们活下去并且过得越来越好。游戏里的世界由体素（方块）组成，支持程序化地形生成、昼夜循环和动态天空。

这份 Wiki 是写给 MOD 作者的。我们不会讲引擎内部实现，只告诉你"能配置什么、脚本能调用什么、出了问题怎么查"。C++ 内部类和未列出的字段都不应作为兼容承诺依赖。
如果你想先判断整个项目现在做到什么程度，阅读 项目完成度审计。它按引擎、玩法、MOD 数据、测试覆盖和发布门槛整理当前工作树的完成度。
存档系统的当前覆盖范围和限制见 存档系统状态；它会明确哪些文件和组件已保存，以及哪些世界状态仍不会恢复。

推荐阅读顺序

  1. 先看概念。了解 MOD 如何被加载，理解目录结构、加载顺序、数据注册（16 种类型）和 Lua 生命周期。这样后面看 data/blocks 和 on_world_init 时不会混淆。
  2. 再注册新东西。从 mod.json 开始，然后添加方块、实体、配方、职业、文明、焦点、NPC 阵营、名称池、作物、区域类型和本地化文本。能用 JSON 表达的内容优先写 JSON。
  3. 最后写 Lua。Lua 用来处理事件响应、定时器、焦点条件和运行时逻辑，不是用来重建数据系统的。

当前能稳定使用的能力

能力状态说明
MOD 发现与加载可用mod.json 清单、依赖顺序、load_before 通配符、严格清单检查、用户设置覆盖。
数据注册可用通过 data/ 注册 16 种类型：blocks、entities、recipes、professions、civilizations、focuses、factions、name_pools、actions、features、ores、crops、buildings、terrain、biomes、zones。
Lua 生命周期可用入口脚本返回表，支持 on_load、on_world_init、on_tick、on_shutdown。
事件和定时器可用engine.events 和 engine.timers。10+ 内置事件，支持自定义。
控制台系统可用50+ 控制台命令，权限系统，别名，配置验证（doctor），快照和差异对比。
NPC 阵营可用faction/name_pool 注册，模板命名，阵营实例化，关系值系统和外交事件。
方块世界可用体素地形生成、程序化生物群系、矿石沉积、洞穴、河流、昼夜天空盒。
网络同步可用Host/Client TCP 同步、快照广播、MOD 列表校验码交换。
本地化可用核心语言文件、MOD lang/ 合并、Lua 查询/切换/热重载 API 和控制台命令。详见 本地化与翻译。
UI 框架部分可用底边栏槽位、浮动提示、窗口系统、CSS 主题；API 已稳定，渲染层持续完善中。
区域系统部分可用矩形区域指定（拖拽模式）、收获/存储/种植/居住区域类型。
AI 与行为树部分基于需求、调度、寻路（A* + NavMesh）、LOD 系统，行为树可运行。
存档部分实体、世界配置、天气、阵营、工作和焦点可保存；方块改动、建筑/区域实例、迁移和 MOD 自动解析仍未完成。
当前最适合开发内容型 MOD：物品、方块、配方、职业、实体原型、焦点、NPC 阵营、作物、区域和少量 Lua 辅助逻辑。完整能力清单见 当前能力状态。参考 CoreMod/ 了解目录结构和数据格式。
