Wiki/模型格式

模型格式

方块模型使用 Blockbench/Minecraft 风格 JSON 子集。当前引擎会在启动预处理阶段把 assets/models/ 下的 JSON 编译为运行时 .model 缓存，渲染层再读取可用字段。

支持的格式

格式扩展名说明
Blockbench JSON 子集.json支持 texture_size、textures、elements、from/to、rotation、faces、uv 和 texture。
推荐使用 Blockbench 编辑器创建模型，但不要假设完整 Bedrock 规范都可用。引擎当前只解析本文列出的字段，未列出的动画、骨骼、display、材质属性等会被忽略。

目录放置

模型 JSON 放在 assets/models/ 下；对应纹理放在 assets/textures/ 的同名相对目录下。对 assets/models/block/foo.json，纹理引用 "foo" 会优先解析到 assets/textures/block/foo.png，找不到时才尝试模型文件旁边路径。

assets/textures/block/NewColonyTextures/
  grass.png                  -- 纹理图（64×64）
  lantern.png                -- 纹理图

assets/models/block/
  grass.json                 -- Blockbench 模型定义
  lantern.json               -- Blockbench 模型定义

模型 JSON 结构

{
    "format_version": "1.21.11",
    "credit": "Made with Blockbench",
    "texture_size": [64, 64],
    "textures": {
        "0": "my_texture"
    },
    "elements": [
        {
            "from": [0, 0, 0],
            "to": [16, 16, 16],
            "rotation": {"angle": 0, "axis": "y", "origin": [8, 8, 8]},
            "faces": {
                "north": {"uv": [0, 0, 4, 4], "texture": "#0"},
                "east":  {"uv": [0, 4, 4, 8], "texture": "#0"},
                "south": {"uv": [4, 0, 8, 4], "texture": "#0"},
                "west":  {"uv": [4, 4, 8, 8], "texture": "#0"},
                "up":    {"uv": [4, 12, 0, 8], "texture": "#0"},
                "down":  {"uv": [12, 0, 8, 4], "texture": "#0"}
            }
        }
    ]
}

字段说明

字段类型说明
format_versionstring可保留给编辑器使用；当前运行时代码不依赖该字段。
texture_size[number, number]纹理图尺寸（像素），如 [64, 64]。UV 坐标基于此尺寸计算。缺省按 [16, 16] 处理。
texturesobject纹理引用表。键为纹理 ID（如 "0"、"13"），值为 PNG 文件名（不含扩展名）。
elementsarray模型元素数组。每个元素是一个长方体。一个模型可以有多个元素组成复杂形状。

元素字段

字段类型说明
from[float × 3]长方体最小角坐标，范围 0~16（方块像素单位）。
to[float × 3]长方体最大角坐标，范围 0~16。
rotationobject旋转参数。支持 {"angle": N, "axis": "x|y|z", "origin": [...]}，也支持直接写 x/y/z 角度和 origin。复杂旋转行为仍需在游戏中验证。
facesobject六个面的 UV 和纹理引用。

面方向

方向名朝向
north-Z
south+Z
east+X
west-X
up+Y
down-Y

面字段

字段类型说明
uv[float × 4]UV 坐标 [u0, v0, u1, v1]，以 texture_size 为基准的像素坐标。例如 texture_size 为 64 时，[0, 0, 4, 4] 表示纹理图左上角 4×4 像素区域。
texturestring纹理引用，格式 "#纹理ID"（如 "#0"）。指向 textures 表中的条目。

预处理缓存

启动时 ModPreprocessor 会扫描每个 active MOD 的 assets/models/ 目录，把 JSON 编译到运行目录的 generate/<mod_id>/models/...。源码 JSON 修改时间晚于缓存时会重新编译。

预处理失败会回退到运行时解析 JSON；但发布和开发时仍应修复预处理错误，因为缓存路径是正常启动流程的一部分。

当前接入边界

模型解析能力已经存在，但通用 MOD 方块模型注册还不是完整稳定 API。当前渲染初始化主要为 CoreMod 的内置模型和程序化方块映射建立贴图/模型资源。内容 MOD 可以参考本文准备资源格式，但不要依赖未文档化的自动接入规则。

示例：多元素灯笼模型

灯笼由底座、灯柱、灯罩和火焰多个元素组成，每个元素有独立的 from/to 和 UV：

{
    "format_version": "1.21.11",
    "textures": {
        "13": "lantern_texture"
    },
    "elements": [
        {
            "from": [6.9, 1.45, 6.9],
            "to": [9.1, 1.75, 9.1],
            "rotation": {"angle": 0, "axis": "y", "origin": [5, 1, 5]},
            "faces": {
                "north": {"uv": [9, 12, 11, 12.5], "texture": "#13"},
                "east":  {"uv": [11, 12, 13, 12.5], "texture": "#13"},
                "south": {"uv": [12, 11, 14, 11.5], "texture": "#13"},
                "west":  {"uv": [7, 13, 9, 13.5], "texture": "#13"},
                "up":    {"uv": [9, 9, 7, 7], "texture": "#13"},
                "down":  {"uv": [5, 8, 3, 10], "texture": "#13"}
            }
        },
        {
            "from": [7, 1.75, 7],
            "to": [9, 5, 9],
            "rotation": {"angle": 0, "axis": "y", "origin": [5, 1, 5]},
            "faces": {
                "north": {"uv": [3, 0, 5, 3.5], "texture": "#13"},
                "east":  {"uv": [3, 4, 5, 7.5], "texture": "#13"},
                "south": {"uv": [5, 0, 7, 3.5], "texture": "#13"},
                "west":  {"uv": [5, 4, 7, 7.5], "texture": "#13"},
                "up":    {"uv": [7, 10, 5, 8], "texture": "#13"},
                "down":  {"uv": [2, 9, 0, 11], "texture": "#13"}
            }
        }
    ]
}
