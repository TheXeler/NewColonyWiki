资源 IO 与 UTF-8 路径

引擎运行时资源、MOD 数据、配置、存档和日志路径统一按 UTF-8 处理。Windows 上不要直接把 UTF-8 字符串交给 fopen、std::ifstream、std::ofstream 或第三方库的 char 路径 API。

统一入口是 Engine/Core/IO/FileIO.hpp。读取文本/二进制文件使用 nc::io::read_file、read_binary_file；写出使用 write_text_file、write_binary_file。需要 simdjson DOM 时使用 Engine/Core/IO/JsonIO.hpp 的 nc::io::load_dom，不要调用 parser.load(path)。

覆盖范围

  • JSON 数据和配置：MOD 清单、数据注册、控制台配置、本地化、设置和存档 JSON 都先通过 FileIO 读入内存，再解析。
  • 图片、shader、模型和脚本：stb_image、SPIR-V、Lua 脚本和 glTF 主文件改为内存加载；glTF 的外部文件读取通过 tinygltf filesystem callbacks 接到 FileIO。
  • glTF 路径转换使用 C++20 的 std::u8string 构造 std::filesystem::path，替代已弃用的 u8path()。模型主路径、外部纹理和 buffer URI 解码后的路径继续按 UTF-8 解释，与 GB2312 控制台代码页相互独立。
  • Shader 预处理的 #include 路径同样通过 std::u8string 构造文件系统路径；依赖时间检查和递归扫描保留 UTF-8 文件名语义。
  • 音频：Windows 上 miniaudio 使用 ma_sound_init_from_file_w；其他平台继续使用原生 char 路径。
  • RmlUI：运行时注册自定义 Rml::FileInterface，RML、RCSS 和字体文件都通过 UTF-8 安全路径打开。
  • 日志和随机访问文件：日志使用 FileIO 打开底层文件句柄；需要 seek/read 的区域文件先安全读入内存再解析。

开发约束

  • 新增资源加载点时，优先使用库的 memory API；如果库只有路径 API，Windows 上必须走宽字符 API 或接入该库的 filesystem callback。
  • 从 std::filesystem::directory_iterator 得到的 path 应直接传给 nc::io 的 std::filesystem::path 重载，不要先转成 path.string() 再打开。
  • std::filesystem 的 exists、directory_iterator、last_write_time 等路径查询可以继续使用；问题集中在实际打开文件的 char 路径 API。

io::write_binary_file_atomic(path, data, size) 在同目录临时文件完整写入并关闭后替换目标；失败时保留原目标，父目录由调用方创建。Windows 使用宽字符 MoveFileExW，POSIX 使用同目录 rename。实体 NCEM 与组合依赖清单使用该接口，避免读取未写完的缓存；它不保证断电持久性。本轮源码尚未编译或运行测试，验证由项目所有者手动进行。
