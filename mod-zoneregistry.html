区域注册

区域类型（Zone Type）定义在 data/zones/ 下，以 JSON 描述。每种区域类型定义了名称和显示颜色。玩家在游戏中通过拖拽指定矩形的区域范围，系统根据区域类型决定该区域的用途——储存、种植、居住、收获等。

JSON 格式

{
    "id": "my_mod:workshop",
    "name": "Workshop Zone",
    "name_key": "zones.my_mod:workshop",
    "color": "#9B59B6"
}

字段说明

字段类型必填说明
idstring是唯一标识，格式 <mod_id>:<name>。
name_keystring否本地化 key，例如 zones.my_mod:workshop。新建区域实例的默认名称会用 ${name_key} 模板形式存储，UI 渲染时实时按当前界面语言解析，所以切换语言后已存在的区域名称也会跟着变。未填则按 zones.<id> 合成回退 key。
namestring否显示名称。省略时使用 id 作为名称。
colorstring否区域在地面上显示的颜色，使用十六进制颜色值（如 "#FF5500"）。省略时不显示高亮。
shapestring否区域维度："2d"（地面平面）或 "3d"（包含垂直范围）。默认 "2d"。
targetsstring[]否区域操作的目标类型。可选值："blocks"、"entities"、"items"、"features"。省略时默认为 ["blocks"]。
filterobject否目标过滤规则。键为目标类型（如 "blocks"），值为数据 ID 数组。仅匹配的方块/实体/物品会被纳入区域操作。
区域类型定义是轻量级的——只包含标识、名称和颜色。区域的具体行为（储存区放什么、种植区种什么）由 Lua 脚本通过事件系统和区域查询来处理，不写在 JSON 中。

内置区域类型

CoreMod 注册了 5 种区域类型：

区域ID颜色形状目标用途
储存区core:stockpile■ #8B73552ditems殖民者将物品搬运到此处集中存放。
种植区core:growing■ #4A7C3F2dblocks殖民者在此区域播种和管理作物。
居住区core:home■ #5B8BB43dentities指定殖民者的居住范围，殖民者会在此休息。
挖掘区core:mine■ #6E6A5E3dblocks3D 方块指定区，确认后为可挖方块发布挖掘工作。
伐木区core:chop■ #8A6F2A2dfeatures2D 地物指定区，确认后为树木地物发布伐木工作。

储存区 core:stockpile

最基本的区域类型。殖民者执行搬运任务时会将物品放到储存区内的空位上。多个储存区可以并排放置以扩大容量。

点击储存区打开区域面板时，面板会显示当前仓储账本中的区域内物品一览，包括物品 ID、数量和内部哈希 ID。

种植区 core:growing

殖民者会在种植区内的空农田方块上播种。配合作物定义和配方（如 wheat_seed_to_farmland）实现完整的种植流程。引擎自带的 farming 系统会扫描每个种植区：发现下方是草/泥土就发布 till 工作把它们翻成农田；发现农田上空为空就发布 plant 工作播种；作物成熟后殖民者会自动收获。

打开种植区的区域设置窗口后，玩家可以通过 Crop 下拉框锁定该区域种植的作物。该选项存储在区域实例的 settings["crop_id"] 字段，值为作物数据 ID（如 core:wheat_crop_data）。未设置时为休耕：殖民者会翻地，但不会自动播种。

居住区 core:home

定义殖民者的居住范围。殖民者在休息时会优先前往居住区内的床位。居住区也影响殖民者的心情和归属感。

区域实例

区域类型是定义，区域实例是运行时数据。每个区域实例包含：

  • 类型：引用某个区域类型定义。
  • 名称：玩家可以给每个区域实例起名字。默认名称形如 ${zones.core:growing} #1 的模板字符串——${...} 是本地化占位符，UI 显示时按当前界面语言解析为对应翻译（中文界面下渲染为"种植区 #1"，英文界面下渲染为"Growing Zone #1"）。直接编辑名称会把整段文本视为字面值，不再解析占位符。
  • 形状：矩形（通过拖拽指定两角）或任意形状（通过逐个添加方块）。
  • 方块集合：区域内包含的所有方块坐标。
  • 设置：键值对形式的区域特定配置。

${} 模板语法

引擎使用 ${category.key} 作为通用的本地化占位符。LocalizationManager::resolve_template(text) 会扫描字符串中所有 ${...} 段，把其中内容当作点号分隔的 qualified key 交给翻译表（与 locale.t("zones.core:growing") 等价），其余字符原样保留。Lua 端可通过 engine.locale.resolve_template(text) 调用同一逻辑。

玩家拖拽指定 2D 区域时，区域实例保存的是被选中地面方块上方的可用空间层，并且固定为 1 格高。例如在 Y=70 的方块上拖拽，区域坐标会落在 Y=71。指定过程中可按 Esc 取消。脚本通过 engine.zone.create_rect 创建区域时仍使用传入的显式坐标。

拖拽预览和确认创建都会按区域类型过滤不可用格子：储存区要求区域格为空且下方有方块支撑；种植区要求区域格为空且下方是土、草或农田。脚本可以调用 engine.zone.remove_cell(x, y, z) 删除区域中的单个格子，例如地面方块被挖掉时删除其上方的 2D 区域格。

Lua 集成

Lua 脚本可以通过 ECS 和事件系统与区域交互：

  • 查询某个坐标是否在某个区域内。
  • 获取某个区域的所有方块坐标。
  • 监听区域创建/删除事件。

挖掘指定

core:mine 是内置 3D 区域类型。底栏的挖掘按钮会进入 3D 拖拽指定模式；默认指定 1 格高，按住区域操作辅助键（默认 Ctrl）并滚轮可向上增加垂直范围但不会低于起始层，Esc 可取消当前指定。未按住辅助键时滚轮仍用于镜头缩放。确认拖拽后会创建挖掘区域，并为选中的每个可挖实体方块向 WorkPool 发布一个 mine 工作。空气、水、岩浆、流体、植物材质和注册地物方块不会被加入挖掘任务。该工作使用 core:mine 方块动作，完成后会触发 block:interacted 并进入 CoreMod 挖掘系统，掉落来自方块 JSON 的 drops 字段。

挖掘区域透明化

挖掘区域内的方块默认渲染为透明，使玩家可以看到区域内部的方块布局。区域周围会显示淡蓝色（75% 透明度）的 3D 边框标记。在区域设置窗口中可以通过 "Transparent Blocks"（方块透明）复选框切换此行为——取消勾选后区域内的方块恢复为不透明渲染。该设置通过区域实例的 settings["transparent"] 字段存储（值为 "true" 或 "false"）。

伐木指定

core:chop 是内置 2D 指定类型。底栏的伐木按钮会进入地面拖拽指定模式，Esc 可取消当前指定；确认拖拽后不会保留伐木区域本身，而是为选中的每个匹配 core:chop_wood 方块动作的 core:tree 单体树地物向 WorkPool 发布一个挖掘工作。该工作完成后触发 block:interacted，由 CoreMod 的挖掘/采集系统移除整棵树，按 core:tree 的 drops 产出木材，并发出 block:chopped。

拖拽选区格子的验证规则：格子本身必须是 core:tree 树木或空气，且正下方（y-1）必须是非空气、非流体的实心支撑方块——这意味着选区不能跨越空中浮空区域或水面/熔岩面，只能贴着地面框选。空气格子通过验证后不会创建砍伐工作（仍由 is_choppable_block 过滤），便于玩家直接框选一片混杂树木与空地的区域。

文件放置规则

  • 放在 data/zones/ 下，支持子目录。
  • 文件名随意，引擎只关心 JSON 内的 id 字段。

验证命令

在控制台（按物理 Grave/反引号键）中确认区域类型注册：

list_data zones                  -- 列出所有已注册的区域类型
data core:stockpile              -- 查看单个区域类型的完整 JSON
data core:chop                   -- 查看伐木指定区域类型
