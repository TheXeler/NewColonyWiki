区域注册

区域类型（Zone Type）定义在 data/zones/ 下，以 JSON 描述。每种区域类型定义了名称和显示颜色。玩家在游戏中通过拖拽指定矩形的区域范围，系统根据区域类型决定该区域的用途——储存、种植、居住、收获等。

JSON 格式

{
    "id": "my_mod:workshop",
    "name": "Workshop Zone",
    "name_key": "zones.my_mod:workshop",
    "color": "#9B59B6"
}

字段说明

字段类型必填说明
idstring是唯一标识，格式 <mod_id>:<name>。
name_keystring否本地化 key，例如 zones.my_mod:workshop。新建区域实例的默认名称会用 ${name_key} 模板形式存储，UI 渲染时实时按当前界面语言解析，所以切换语言后已存在的区域名称也会跟着变。未填则按 zones.<id> 合成回退 key。
description_keystring否区域类型说明的本地化 key。区域类型选择窗口和地图选取确认窗口共同读取该字段，避免分别维护提示文本。
namestring否显示名称。省略时使用 id 作为名称。
colorstring否区域在地面上显示的颜色，使用十六进制颜色值（如 "#FF5500"）。省略时不显示高亮。
shapestring否选取维度："2d"（地面平面）、"3d"（视角深度体积）或 "vertical"（水平框加向上/向下范围）。默认 "2d"。
default_vertical_down / default_vertical_upnon-negative integer否垂直选取工具进入时读取的默认向下/向上格数；未声明时为 0。仅影响初始范围，玩家仍可在工具内调整。
targetsstring[]否区域操作的目标类型。可选值："blocks"、"entities"、"items"、"features"。省略时默认为 ["blocks"]。
filterobject否目标过滤规则。键为目标类型（如 "blocks"），值为数据 ID 数组。仅匹配的方块/实体/物品会被纳入区域操作。
区域类型定义是轻量级的——只包含标识、名称和颜色。区域的具体行为（储存区放什么、种植区种什么）由 Lua 脚本通过事件系统和区域查询来处理，不写在 JSON 中。

内置区域类型

CoreMod 只注册 NCDOCS 明确列出的 2 种持续区域类型：

区域ID颜色形状目标用途
储存区core:stockpile■ #8B73552ditems殖民者将物品搬运到此处集中存放。
种植区core:growing■ #4A7C3F2dblocks殖民者在此区域播种和管理作物。

储存区 core:stockpile

最基本的区域类型。殖民者执行搬运任务时会将物品放到储存区内的空位上。多个储存区可以并排放置以扩大容量。

zone instance ID 同时是露天仓储的稳定位置 ID。core:storage.policy.set 设置物品/分类/标签过滤、入库优先级、取用优先级和整区保留；空过滤允许全部物品。修改过滤后，已有不合格实例保留在原位并标记待清运。搬运激活时锁定具体地面格，区域删除或策略拒绝目标时取消自动工作并释放目标预留。

点击储存区或种植区后可从选择摘要打开区域管理面板。面板在打开时绑定所选区域实例，之后不再跟随选中或悬停变化。当前面板只提供带二次确认的“删除区域”操作；仓储汇总与策略不放在该面板中。删除成功后面板立即关闭，不显示空的兜底内容；区域因重叠划区被清空而消失时面板也会关闭。

种植区 core:growing

种植区仅提供持续空间规则和设置存储接口。当前内容没有专门的种植玩法设计定义，因此 CoreMod 不生成翻地、播种、成长或收获循环。

区域实例

区域类型是定义，区域实例是运行时数据。每个区域实例包含：

同一类型的重叠持续区域会合并到原有实例并保留其稳定 ID；不同类型的持续区域在同一格互斥，新区域会移除旧区域的重叠格，空区域随之清理。

  • 类型：引用某个区域类型定义。
  • 名称：玩家可以给每个区域实例起名字。默认名称在创建时通过区域类型的 name_key 按当前界面语言生成，例如中文界面保存为“种植区 #1”，英文界面保存为“Growing Zone #1”；不会把 core:growing 或 ${zones.core:growing} 暴露为玩家可见名称。直接编辑名称会把整段文本视为字面值。
  • 形状：矩形（通过拖拽指定两角）或任意形状（通过逐个添加方块）。
  • 方块集合：区域内包含的所有方块坐标。
  • 设置：键值对形式的区域特定配置。

${} 模板语法

引擎仍支持 ${category.key} 通用本地化模板，但区域类型提示和默认实例名直接通过 name_key 翻译，不把模板字符串保存到区域状态。LocalizationManager::resolve_template(text) 仅用于需要延迟解析的普通 UI 文本。

玩家拖拽指定 2D 区域时，区域实例保存的是被选中地面方块上方的可用空间层，并且固定为 1 格高。例如在 Y=70 的方块上拖拽，区域坐标会落在 Y=71。指定过程中可按 Esc 取消。脚本通过 engine.zone.create_rect 创建区域时仍使用传入的显式坐标。

拖拽预览和确认创建都会按区域类型过滤不可用格子：储存区要求区域格为空且下方有方块支撑；种植区要求区域格为空且下方是土、草或农田。2D 持续区域位于地表方块上方的空气格，并以贴地平面显示；储物区和种植区的可见平面拥有独立射线拾取，点击任一实际区域格会直接选中该区域，而不是依赖地形命中后的坐标猜测。脚本可以调用 engine.zone.remove_cell(x, y, z) 删除区域中的单个格子，例如地面方块被挖掉时删除其上方的 2D 区域格。

Lua 集成

Lua 脚本可以通过 ECS 和事件系统与区域交互：

  • 查询某个坐标是否在某个区域内。
  • 获取某个区域的所有方块坐标。
  • 监听区域创建/删除事件。

采掘指定

core:mine 是 selection 工具 ID，不是 zone 类型。它使用水平矩形和独立向上/向下范围；滚轮或面板接口可调整垂直范围。确认时把每个合格体素的坐标和当时方块 ID 固定到一次性工作；目标消失或被替换时旧工作不会处理新方块。重复框选会释放重叠旧工作的预留并按新优先级和指定者重建，未重叠工作不变，工具保持激活直到取消。

有效采掘工作存在期间，采掘工具激活时把目标体素从区块渲染网格中隐藏，并把六向连通的目标合并为整体外框、叠加淡黄色半透明表面（表面参与深度测试，黄色外框不做深度测试，因此可透过地形看到标记）；离开采掘模式后不再绘制标记，被隐藏的目标体素也按原样重新进入渲染网格。渲染网格的六向邻面剔除和仅用于显示的光照覆盖层在覆盖生效期间把目标视为空气，因此洞壁各方向会显露且预览孔不会继续遮光。权威方块数据始终不变，射线检测、碰撞、寻路、模拟光照和存档仍按尚未挖除的实体方块处理。工作完成或取消、工具进入或退出后重新生成目标及相邻区块网格。包含采掘显示覆盖的区块暂时保持完整 LOD，避免远处粗网格重新显示目标体素。采掘导航额外接受目标正下方同列的站位：两格高的小人在脚下有支撑、身体空间畅通，且头顶到目标之间没有实心方块遮挡时，最多可以采掘高出脚底三格的方块（身体两格加一格挥镐距离），因此头顶方块和一格更高的天花板都能从地面采掘；该纯竖直站位不开放给伐木或建造。

可采方块必须有可执行的统一产出表。缺失或无效引用不会阻止方块注册，但会从可选目标中排除并在指令数据中报告原因、来源类型、来源 ID 和来源路径。成功产物优先进入执行者统一背包，溢出在目标位置落地并自动授权回收。

工具打开时同时打开通用确认面板。engine.selection.designation_preview() 从完整几何范围返回合格目标、无效目标、已有标记、碰撞、不可达原因和满足职业、工作计划及基础可达条件的殖民者。面板可在确认前循环设置特级/1-9 级优先级和可选指定者；确认函数重新调用同一预览契约，只提交当时仍合格的目标，因此预览和结算不会使用两套筛选规则。垂直体积的滚轮深度以起始层为有符号零点，跨过 0 时会清空另一方向的层数；高精度滚轮的非零小数输入至少移动一格。确认后工具与面板保持激活以支持连续操作；采集和采掘只以 Esc 退出，右键仍用于旋转镜头。

伐木指定

core:chop 是 selection 工具 ID，不是 zone 类型。它执行 2D 一次性采集指定，从注册表读取所有当前可砍且产出配置有效的方块，不硬编码树木 ID。确认时绑定具体对象；新刷新对象不会进入旧工作，重复选择采用与采掘相同的重叠重建规则。有效伐木工作存在期间，目标上方显示菱形工作标记；该标记用相机屏幕右/上轴构建，因此始终正对镜头，不会随视角旋转退化成一条线。

可砍类型从地形特征的 is_tree 元数据解析，不比较 core:tree 常量。采集确认面板复用采掘的目标数量、无效数量、已有标记、可达性、资格、优先级和指定者契约；采集不显示采掘专用碰撞行。

文件放置规则

  • 放在 data/zones/ 下，支持子目录。
  • 文件名随意，引擎只关心 JSON 内的 id 字段。

验证命令

在控制台（按物理 Grave/反引号键）中确认区域类型注册：

list_data zones                  -- 列出所有已注册的区域类型
data core:stockpile              -- 查看单个区域类型的完整 JSON
data core:growing                -- 查看种植区类型
