当前实施状态

阶段已有源码仍需接入
身份、状态与布局城邦、居民、建筑、工作、队伍和战斗事实使用 Lua 世界状态；模板生成保留结果、游标与进行中的身份。正式模板、地域选取、原生建筑及实体状态的完整交接；既有无经营状态城邦需要显式迁移。
预测与评分抽象库存、实际人口消耗、带完成时点的工作产出与返程货物自动进入预测；倾向缺省来源不算零，评分限幅。实体共享库存／订单的原生捕获适配；正式资源分类与评分参数。
规划与调度确定性跨轮搜索、前置子树执行顺序、覆盖数量消费、共用工作与来源分配；1200／20 Tick 调度和完成后沿承诺路径再投入。主路径和实际能力注册、实体 Task 的无损暂停与原生经营接入。
分层模拟实际抽象物品扣除、产能推进、缺粮负担、营养余量与具体身份伤亡；模式协议保持单一权威。全城区块占用、多玩家触发、实体准备和显示屏障、原生库存／建筑／Task 导入导出；代表性吞吐校准。
对外行动统一外交适配、冷静／保护期、积分和授权检查；队伍资产划出／返回；可配置分段抽象战斗。正式外交目标／回应政策、现场贸易算法、实体队伍桥、战斗换算配置与实体战斗连续交接。

未注册能力不能被报告为成功。CoreMod 没有新增隐藏平衡值，也没有用空接口自动生成城邦、免费完成生产或交换远程库存。当前正常新世界不会自动出现这些模板城邦。

模块与配置

公共模块为 core:systems.city_math、city_planner、city_model、city_ledger、city_allocation、city_runtime、city_generation、city_diplomacy、city_teams 和 city_combat。依赖 core 的 Mod 在 Server 注册具体内容；函数不进入存档。

city_runtime.register_rules(id, rules) 验证 tendency_weights（leader > city > faction）、tendency_min/max、reserves、score、planner.depth/nodes_per_round、exit_wait_ticks、forecast_window_ticks、crisis_shortfall/crisis_workers_required 和 survival。survival 明确提供 nutrition、food_per_resident_tick、burden_per_death、burden_recovery_per_tick。数值缺失报错；1200／20 Tick 和外交天数来自已确认设计，不是未确认默认值。

每个 reserve 声明 item_ids、unit（days/construction/money/quantity）、lower、upper、tendency 和 tendency_scale，可指定 measure（quantity/nutrition）及 consumption_per_resident_tick。nutrition 直接使用生存配置的实际营养和消费率；其他持续消耗需要明确单位换算，缺少时报告 city_reserve_consumption_missing。city_ledger 自动读取库存、营养余量、居民、工作和返程队伍，派生消费量、未来材料／支出与完成时点；额外 forecast 的 locks/events/checkpoints 仍可由专项适配器提供。事件带 work_uuid 时由实时工作输出替代，人口消费不会重复导入。

city_math.tendencies/reserve/forecast/score/aggregate 为纯算法。预测包含每个收支边界，不能用最终库存掩盖到货前的短缺；未成交 purchase 的 confidence 必须小于 1。item:定义ID、building:建筑UUID、facility:设施定义ID 的覆盖由真实库存和有效建筑派生，不重复保存为资源账本。

承诺路径与工作

register_focus(id,{evaluate}) 的 evaluate 读取同一城邦快照、预测和倾向，返回候选 goal、urgency、satisfaction、timeliness、remaining_cost、risk、tendency、available、requirements 及满足／永久失效标记。goal 含 key/quantity，可标 reusable（设施等持续能力）、deadline 和 demand_id（解决同一个储备需求的多个途径）。独立消耗需求不共享 demand_id，有限库存和预期产出只分配一次；deadline 前尚未完成的输出不抵扣早期缺口。能力尚未提供时明确不可用。

register_action(id,{plan,start,valid,settle,strategic}) 注册实际途径。plan 返回前置 requires、完整 remaining_cost 和 available；start 在候选数据中准备真实工作规格；valid 在每段前检查设施和目标；settle 在候选数据中按共享专项规则结算。回调不可直接修改外部系统来伪装候选提交，实体工作必须通过 bridge 使用现有 Task。

抽象工作规格包含 uuid、action_id、workers、materials、required、facility_factor、state_factor、work_fraction、interruptible；产能单位为每模拟 Tick 工作量。materials 精确匹配物品 id/count/components，缺料不部分扣除。可用 facilities 指定建筑 uuid/slots，建筑 work_capacity 必须来自明确设施配置；开始与恢复都校验实际占用。暂停保留进度和已耗材料，恢复只取得原需人数。完成时在候选城邦结算；失败不发布候选产出，不返还真实投入或重试已失败工作。

outputs 是连续数组，含 key、可选 item_id、quantity、confidence 和 source。没有产出信息不能虚构预测收益。city_ledger 按真实劳动力产能和剩余工作量估算完成时点，暂停或无产能工作不承诺到货。动作 start 可以只提供实际可执行的小批次，runtime 检查真实目标是否达成后继续追加，不把一次小批完成当作整条路径完成。

可复用前置声明 share_key 和完整 compatibility 参数，目标、动作及参数签名一致才共用一个持久 work_uuid。city_allocation 保存各路径的数量和用途，按最高来源优先度执行；不同建筑位置不能合并。shared_jobs 随城邦事实保存，读档不重复下单。普通工作完成沿原路径重用闲置能力，不触发全城重排；能力变化、失败和危机仍按规则重评。

2026-10-12 已把抽象多路径覆盖和共用前置关联到实际工作，不再只有解释记录。完整配方、农业、温度、建设与实体经营适配仍需完成；不得直接把生产订单原有的取消式 pause 当作无损 Task 暂停。新增测试源码未编译或运行。

生成、模式与数据查询

city_generation.register(id,{density_per_100_chunks,minimum_distance,seed,initial}) 使用独立保存的随机流和稳定候选顺序；generate 接受实际区块候选（key/chunk_x/chunk_z）。initial 提供城邦状态和派系身份，选择结果只创建一次。进行中生成保存身份和初始结果，可继续而不重新抽取；空间不足记录原因。没有配置地图／模板供应器时不会启动生成。

新原生 API engine.factions.create_settlement(spec) 要求 uuid、已存在的非玩家 def_id、display_name、map_q/map_r/map_color，使用定义的初始关系和当前权威 Tick。恢复不能通过此生成入口重放。engine.factions.calendar() 返回现有日历换算常量，外交天数不按现实时间计算。

register_bridge 明确要求 observe/prepare/discard/activate/capture/deactivate/start/pause/resume。observe 分开提供玩家加载与必须实体处理的交互；activate 必须对完整城邦原子校正和启用，deactivate 必须导出真实事实并停止实体推进。准备未完成仍由抽象状态权威；无玩家且无交互达到 exit_wait_ticks 后退出。这里只实现协议协调，原生全城桥尚未提供。

人口通过 core:city_population 指标从实际居民记录统计；没有经营数据时返回 nil 与 city_operating_state_unavailable。外交 query 保留指标供应器返回的不可用原因。实体库存和居民的实时查询依赖 bridge 捕获，没有额外石材／人口权威整数账本。

外交、队伍与抽象战斗

city_diplomacy.register 为规则 ID 注册 choose/approve。initiate 核对战略授权、冷静期、玩家保护和未结束提议；respond 接受需要当前版本、回应权、积分 >= 0 和绑定目标／提议／城邦 revision 的批准。议和绕过 7／5／9 日与一天保护等待，但不重复发送。成功才记录发起时点，直接调用现有外交模块。正式政策仍待路径能力内容，未注册时记录 city_diplomacy_policy_missing。

city_teams.depart 将真实居民和携带物移出本城；transport→onsite→returning→return_settlement→returned 保留队员身份。到达后通过注册的现场贸易供应器处理两个候选库存，未实现交易时拒绝，不能远程预约成交。返回处理一次后清空队伍资产，避免重复入库。实体出发／返回与现场实体交易尚无原生适配器，会明确拒绝。

city_combat.register 需要 segment_ticks、loss_coefficient、retreat_fraction，以及 capability/damage/dead/retreat/goal 配置回调。能力读取真实人员及装备，独立随机流按分段概率结算，写回人员和装备损失。非边界保存补齐时间；同段双方能力从段前状态读取。实体战斗接入尚未完成，当前报告 city_entity_combat_adapter_required，不声称两种战斗已经连续对接。

持久化、诊断与验证

core:systems.city_runtime 的 @State cities 保存 records/teams/battles；生成过程和外交等待时点由各自模块世界状态保存。save_started 补齐不足 20 Tick 的抽象进度和队伍／战斗时间。恢复不生成新的身份，不自动为旧城邦补随机经营状态。core:city_simulation 共享状态发布城邦解释和已注册能力清单，缺少经营状态的 NPC 明确标记迁移需求。

新增验收源码 Tests/UnitTests/test_core_city_algorithms.cpp 覆盖预测、倾向、规划、抽象暂停、生存、非边界时间、队伍返回、外交等待和模式协议等。仅进行 Lua／嵌入片段语法解析与源码差异检查；没有 C++ 编译、测试运行、联机或吞吐校准。
