科技注册

data/techs/ 保存研究项目定义。CoreMod 当前提供七项科技：打制石器、磨制石器、水塔研究，以及中级、高级、精英、大师招募。每项科技都有独立的描述。

科技项目属于数据文件注册表；下面的界面分类属于代码注册表，两者使用不同入口。

注册科技分类

分类通过公共 Lua 模块 core:ui.research_categories 注册。其他 Mod 需在 manifest 中声明对 core 的依赖，并在 Client 生命周期中调用注册接口，例如：

-- scripts/listeners/mod_ready/research_categories.lua
-- @Event core:mod_ready
-- @Priority 0
-- @ClientSideEvent
local Categories = require("core:ui.research_categories")
return function(e)
    Categories.register("example:agriculture", {
        name_key = "ui.example:research.agriculture",
        order = 15,
    })
end

科技 JSON 继续用 "category": "example:agriculture" 引用分类。分类无需独立 JSON 定义；原先增加的分类数据加载入口和 engine.research.ui_categories() 已移除。

register(id, definition) 要求完整命名空间 ID、非空 name_key 和有限整数 order，重复 ID 报错；unregister(id) 返回是否移除了已有分类；list() 返回按顺序排列的独立副本。注册时复制传入字段，外部修改定义或返回列表不会改变内部分类。更新分类可先注销再注册。

在该 Mod 的语言文件 ui 段注册 example:research.agriculture 的显示名称。分类按 order 升序排列，同值按完整 ID 排序；即使没有科技也保留注册的标签页。缺少翻译时显示分类 ID。未注册分类的科技仍显示在以分类 ID 命名的标签页中，排在注册分类之后，不因分类配置缺口隐藏条目。

CoreMod 的生产、建筑、战斗分别注册为 core:production、core:building、core:combat，排序值依次为 10、20、30。科技 JSON 必须提供非空字符串 category。省略命名空间时按所属 Mod 补全：CoreMod 中 "category": "production" 和 "category": "core:production" 都接受，读取后同为 core:production；:production 也表示所属 Mod 的分类。跨 Mod 引用应写完整 ID。

加载校验接受本地分类名或命名空间 ID，不再限制为五个内置名称，因此 example:agriculture 等 Lua 自定义分类也可使用。名称字符限小写英文字母、数字、下划线和连字符；命名空间与名称之间最多一个冒号，冒号后的名称不能为空。空值、非字符串、非法字符及多个冒号会使数据加载失败。

内置分类的注册调用集中在 scripts/ui/research_category_defaults.lua，客户端科技投影通过该模块取得公共分类模块。默认分类依赖模块缓存，每个 Client 脚本环境只注册一次。分类保存在模块局部变量中，不进入存档；重建 Mod 脚本环境时重新注册。不要在普通世界卸载时清空分类，否则同一 Mod 环境内下次进入世界会丢失标签页。

客户端投影每次读取 Categories.list() 并解析本地化名称，再通过 research_categories 类型数组生成 RML 按钮。快照刷新保留仍存在的选中分类，删除后回到排序第一项；分类多时标签栏可横向滚动。现有 engine.research.categories() 仍返回科技实际使用的分类 ID，list_by_category(id) 使用补全后的完整 ID 查询。

科技描述

description 是科技 JSON 中用于说明研究目的和解锁效果的字符串，与名称 name、前置 prerequisites 和解锁列表 unlocks 分开保存。例如：

{
    "id": "example:stone_tools",
    "name": "石制工具",
    "description": "掌握石材成形与装柄技术，制作适合日常劳动的石制工具。"
}

以上只展示身份和文案字段；可研究项目仍需提供下文的分类、研究量、工作点和职业资格等契约。所有内置科技都提供非空描述。其他 Mod 缺少描述时，详情页隐藏说明段落，不虚构内容，也不把缺少文案作为研究屏障。

描述沿科技加载、engine.research.get_tech()、研究快照和客户端投影传递；原生 RmlUI 的节点视图与选中详情视图均接收 description，选中科技后在名称下方显示完整说明。说明使用文本绑定，不作为 RML 标记执行。兼容投影中只有 desc 的节点，按 description 优先、空值再读取 desc 的规则解析。

描述本地化使用语言文件的 tech_descriptions 段，以科技完整 ID 为键。客户端先查 tech_descriptions.example:stone_tools；缺少翻译时，若原始 description 是可解析的本地化引用，则解析该引用，否则显示原始文字。CoreMod 已提供全部七项科技的简体中文和英文说明。显示层的翻译不修改权威快照、科技身份、研究量、前置、解锁或研究进度。

当前科技

全部项目要求 core:workbench 工作点和 core:scholar_2 一级资格。研究量为工作单位，不是固定等待秒数。先建造工作台，制作无需科技的 core:research_tablet（2 石材，工时 10），把石板存入可达的方块库存，再通过转职入口让居民成为学者。开题材料独立消耗一次，不替代制作成品所需的材料。

工具和水塔研究归入 core:production，武器类归入 core:combat；跨分类前置仍为完整科技 ID。配方解锁使用 recipe:core:craft_...，由既有制作目录和 Server 下单入口限制。水塔研究另声明 building:core:irrigation_tower，同时限制建筑菜单和建造下单入口。所有成品在工作台制作，每批固定一件，详见 配方数据。

四项招募科技归入 core:colony_development，按中级、高级、精英、大师顺序逐级前置。候选者数量、职业积累范围等实际招募参数由 data/recruitment_rules/ 定义，描述文字不参与招募计算。

石刀、石斧、石镐、石铲、石锄分别支持 hunter_2、lumberjack_2、miner_2、worker_2、farmer_2，均增加 colonist.work_efficiency 0.1。石锤和石矛支持 militia_2，分别增加 battler.melee_power 4 和 6。研究石板支持 scholar_2，无数值加成。装备切换工时均为 3 秒，堆叠上限 1；本批暂复用石材图标，不声明工具专属采掘、翻土、长柄攻击距离或投掷机制。

本批为源数据实现；研究付款、暂停/继续、前置解锁、制作与转职的实际链路留待统一验证。

有效项目的必需契约

  • research_ticks 必须显式为正数；不存在代码默认研究量。
  • required_workstations 必须至少引用一个现存建筑或工作点类型。
  • required_job 必须引用一个现存职业节点，required_job_level 必须为 1-5；派生工作会转换为该节点的 #career_RANK_LEVEL 资格表达式。
  • opening_materials 可为空；有条目时必须引用现存物品并声明正数量。
  • prerequisites 和 unlocks 只读取数据中明确列出的引用。

缺少研究量、工作点或职业资格时，节点保持可见并报告稳定 configuration_error，不会生成默认数值或可执行工作。

运行时语义

开题先预留并确认实际材料；全部兼容工作点按剩余研究量派生工作单元，激活时预留工作点，完成时提交进度。暂停取消未完成工作并保留付款和已提交进度；继续按剩余量重新派发。项目没有取消入口。

轮作、木构、民兵操练、贸易和外交等旧 CoreMod 科技没有 NCDOCS 内容来源，已从内容目录删除。
