引擎服务层

把 Engine.cpp 中的 UI 命令分发、地形查询、方块修改三类逻辑抽成独立服务类，降低 Engine 的体量与耦合。

当前状态

逻辑角色与程序部署分离：单人世界的 PhysicalClient 内同时运行 LogicServer 和 LogicClient，玩法权威属于 LogicServer；PhysicalServer 可以仅运行 LogicServer。进程内共存不代表共享 Lua VM 或可绕过服务端修改世界。网络模型概览说明各部署形态。RmlUiServer 是本地 UI 集成类名称，不因此变成 LogicServer 上的玩法系统。

  • 三个服务类已落地，加入 NewColonyEngine 静态库源列表，可独立编译。
  • 方块修改 / 地形查询已接线：Engine 持有 BlockEditService、TerrainQueryService 实例，modify_block_at、terrain_block_at、terrain_standable_y_at、gpu_probe_occlusion / gpu_probe_sky_light 均改为委托，行为与原实现逐行等价。
  • UI 命令分发 facade 已接线：Engine 持有 UiCommandDispatcher 成员，dispatch_rml_ui_command 在 lua_ui: fast-path 之后、core:* if-链之前先调用 dispatcher.dispatch(cmd)。core:menu.quit 是已迁移 handler；时间控制由 Lua 数据桥转为 Server UiCommand，并通过 save_state:time_control 回传客户端。其余未命中命令落回现有 if-链与 ScriptEngine。旧静态底栏面板已移除，core:panel.toggle 不再作为游戏内菜单入口。
  • 依赖通过引用注入，服务自身不持有任何子系统生命周期，也不 include Engine.hpp，避免循环依赖。
  • 接线后 Engine.cpp 中只服务于被替代方法的 file-scope helper（chunk_coord_key、floor_mod、entity_block_id_is_clear_for_feet）已删除；仍有其他调用点的 floor_div、mark_light_radius_dirty、entity_block_id_is_solid 保留原处。

BlockEditService

位置：Engine/Voxel/BlockEditService.hpp。职责：单方块写入及其全部副作用。已由 Engine 持有，modify_block_at 委托给它。

  • edit(x, y, z, block_id) 等价于 Engine::modify_block_at。
  • 副作用顺序与现状一致：写 chunk store、GpuLightRegistry::on_block_changed 失效、把自身 chunk 与光照半径内 chunk 标记 dirty、边界方块额外标记邻接 chunk dirty、BlockUpdateSystem::notify_block_change（BUD）、流体方块调度 FluidSystem::schedule_flow_check。
  • 依赖：ChunkManager、simulation::GpuLightRegistry、voxel::BlockUpdateSystem、voxel::FluidSystem、TickManager。
  • floor_div 与 mark_light_radius_dirty 作为本编译单元内的同名 helper 复刻，逻辑与 Engine.cpp 内 file-scope 版本逐行一致。

TerrainQueryService

位置：Engine/Voxel/TerrainQueryService.hpp。职责：地形只读查询与 GPU 地形探测。已由 Engine 持有，地形查询与 GPU 探测 facade 方法委托给它。

  • block_at(x, y, z) 等价于 Engine::terrain_block_at：优先读 ChunkDataStore，未加载列回退到确定性程序化生成（带 thread-local 128 项缓存）。
  • standable_y_at(x, z) 查询可变高度区块列；已加载但完全空的列返回无结果，Lua 侧得到 nil，不会回退到已被移除的程序地形。
  • gpu_probe_occlusion / gpu_probe_sky_light 等价于 Engine::gpu_probe_*；GPU 关闭、渲染器未初始化或 chunk 无数据时返回 false。occlusion 探测会写入 renderer 高度缓存，因此方法为非 const。gpu_probe_fluid 已随 GPU 流体候选流水线删除（流体为 CPU 权威实现），服务也不再依赖 FluidSystem。
  • 依赖：ChunkManager、voxel::TerrainGenerator、worldmap::WorldMap、renderer::Renderer、simulation::GpuSimulationChunkRunner、世界种子、GPU 探针开关。其中世界种子与 GPU 探针开关以引用注入而非拷贝快照：前者随世界创建/载入而变，后者由控制台命令在运行时切换，引用保证服务始终读到当前值，与被替代 facade 方法的实时读取语义一致。
  • 通用选取的目标校验由调用方提供声明式的方块/物品 ID 或 TAG 列表（filter.blocks、filter.items / filter.tags）；选取器只负责几何范围和匹配格子，不内置伐木或采掘谓词。

UiCommandDispatcher

位置：Engine/UI/UiCommandDispatcher.hpp。职责：RmlUI 文档到引擎命令的路由总线，替代 Engine::dispatch_rml_ui_command 约 1400 行的 target if-链。

  • register_handler(target, fn) / unregister_handler 维护 target 到 handler 的注册表。
  • dispatch(cmd) 查表执行，命中返回 Outcome::Handled，未命中返回 Outcome::Unhandled 交由调用方回退（现状为 ScriptEngine::run_ui_command）。
  • is_lua_ui_target(target) 静态判定 "lua_ui:" 前缀，集中今日散落在 dispatch 入口的 fast-path 判定。
  • next_command_result(result) 持有单调递增的命令结果序号并折叠进结果 JSON，等价于 Engine.cpp 的 add_rml_command_result_sequence(result, ++m_rml_ui_command_result_sequence)。
  • 不依赖 Engine；各 target 的 handler 在接线期以 lambda 捕获所需子系统注册进来，逐步把 if-链迁出 Engine。
  • 对外契约不变：core:* 引擎级命令仍引擎侧拦截、业务命令仍走 Lua 数据桥，command_result 通道与序号语义不变。

接线状态

  • 已完成：Engine 以可选成员形式持有 BlockEditService 与 TerrainQueryService，在 Engine::init 末尾、模拟线程启动之前按依赖注入构造；modify_block_at、terrain_block_at、terrain_standable_y_at、gpu_probe_* 已委托。被替代的 Engine.cpp 方法体与只服务于它们的 file-scope helper 已删除。
  • 已完成（facade 接线 + handler 样板）：Engine 以直接成员形式持有 UiCommandDispatcher。dispatch_rml_ui_command 在 lua_ui: fast-path 之后、core:* if-链之前调用 m_ui_command_dispatcher.dispatch(cmd)；命中返回 Outcome::Handled 提前返回，未命中落回原 if-链与 ScriptEngine。当前 handler 样板为 core:menu.quit。core:time.pause / core:time.speed 则统一进入 Server 权威 Lua 命令桥，只接受暂停、1x、2x、4x、无限速五态。
  • 待办（其余 handler 迁移）：逐 target 把剩余 core:* if-链分支体注册为 handler，每注册一个并验证等价后删除 Engine::dispatch_rml_ui_command 对应分支，避免双处理。lua_ui: fast-path 不经 dispatcher，优先级不变。后续低风险候选：core:menu.wiki/wiki_cancel/wiki_confirm、core:content_browser.category。高风险（依赖 ScriptEngine 返回值、位于 run_ui_command 之后）：core:combat.toggle_hud，暂不迁移。

与其它拆分工作的关系

  • 本服务层（thread_2）与主菜单/世界生命周期协调器（WorldLifecycleCoordinator）互补：后者收口世界启动/返回主菜单等生命周期入口，文件域不重叠。
  • RmlUiDataViews 的拆分由独立线程处理；本服务层只关心命令分发路由，不触碰 data-view 通道结构。

世界生命周期与系统初始化

Pathfinder 的 NavMesh、地形查询及 AI 线程池在 Engine::init() 接线，不能由 tick == 0 判断首次运行：新世界从早上 8 点（tick 9600）开始，存档使用保存时的 tick。未配置 NavMesh 或实体方块查询的 Pathfinder 拒绝生成路线和可行走判断。

天气定义和初始区域模板属于内容配置。返回主菜单调用 WeatherSystem::clear_runtime()，只清理当前区域、索引、天气状态及世界地图引用；再次创建或载入世界通过 reset(seed, map, tick) 建立世界状态，保留已加载的定义。世界服务端退出时显式清理 AI 停滞计时、派生工作缓存、移动诊断和物理台阶状态，避免相同 UUID 的存档实体继承旧状态。清理不会删除引擎持有的依赖接线。

相关回归用例覆盖未接线寻路拒绝、天气清理后再次初始化，以及相同实体/任务身份下的停滞计时重置。此次修改未编译或运行测试。

Windows 原生崩溃诊断

EngineEntry.cpp 在创建引擎之前注册 Core/Debug/CrashDiagnostics.hpp 的 SEH 异常处理器。未处理的异常记录异常代码、访问类型和目标地址，并在 latest.log 中增加一条 [CRASH][module]：包含崩溃线程 ID、故障模块路径、加载基址和模块相对偏移（RVA）。仅查询故障指令所在模块，不展开调用栈、不加载 DbgHelp、不生成转储文件。

分析模块偏移时保留对应版本的 DLL 和 PDB；模块信息不代表导致崩溃的业务问题已修复。本次精简未编译或运行测试。
