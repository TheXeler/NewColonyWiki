代码注册表

通过 Lua 注册函数、模块返回值或监听器注释登记可执行行为。静态 JSON 定义见数据文件注册表。

两类注册表的边界

分类依据是定义来源。科技项目来自 data/techs/，科技界面分类通过 Lua 注册；事件字段来自 data/events/，监听器由 Lua 提供；通道和命令由 JSON 声明入口，再连接 Lua 导出函数。JSON 引用了代码，并不使它变成代码注册表。

下面列出常用代码注册入口。专项系统还可以提供自己的策略注册接口，其参数、执行端和生命周期以对应系统文档为准。

注册入口

内容入口与执行端登记时机及身份规则详细说明
科技界面分类Client：require("core:ui.research_categories").register(id, {name_key, order})在客户端生命周期登记，使用完整命名空间 ID；重复 ID 报错，可先 unregister 再注册。内置分类由默认分类模块加载一次。科技与分类
外交提议与查询指标Server：require("core:systems.diplomacy").register(id, definition)、register_metric(id, provider)在 Server 的 core:mod_ready 等适当生命周期登记。提议提供 validate、score、execute；提议与指标各自拒绝重复 ID。旧提议 JSON 不驱动新谈判。外交系统
效果生命周期Server：require("core:systems.effects").register_definition(effect_id, definition)在使用效果前登记 instant、modifier_start、modifier_tick、modifier_end 回调；无效参数返回 false，同 ID 当前替换定义。Client 只读取同步快照。Lua API：效果组生命周期
静态监听器scripts/listeners/**/*.lua 的 @Event、@Priority 和执行端注释脚本加载时自动登记，模块返回回调。事件须先有数据定义；两端按声明分别登记，同一事件可有多个监听器。事件与监听器
动态监听器当前端的 engine.events.subscribe(event_id, priority, fn, world_bound)事件 ID 必须已声明；保存返回的订阅句柄，用 unsubscribe 撤销。世界绑定订阅遵循世界生命周期。事件订阅
持久定时器类型scripts/timers/<name>.lua 返回含 serialize、deserialize 的表脚本加载时自动登记模块类型，随后由本 Mod 的 engine.timers.create(name, ...) 创建实例。类型来自模块身份；不是原生实体 Task 的 JSON 定义。Lua API：定时器
UI 数据提供器Client：engine.ui.data.register(channel, provider)通常在 core:mod_ready 按通道显式登记；snapshot(name) 只调用已登记 provider，未登记返回 nil。撤销遵循模块所有权限制。RmlUI 数据通道
UI 窗口与面板Client：engine.ui.window.register(def)、engine.ui.rml.register_panel(def)按界面生命周期登记并保存句柄；关闭和注销使用对应接口。文档路径指向 Mod 内 RML，资源仍属于 assets。UI 注册 API

模块、执行端与恢复

  • 跨 Mod 导入公共模块时，在 manifest 声明依赖，使用完整模块名，例如 core:ui.research_categories。被导入模块须公开，不通过任意文件路径加载。
  • Client 与 Server 使用独立 Lua 环境。在一端注册不会自动在另一端登记，也不会自动创建网络同步。
  • 普通模块按需 require；监听器和定时器类型有各自的自动登记路径。不要假设任意 scripts 下的模块都会执行。
  • 回调和模块局部定义不作为可序列化世界事实保存。重建脚本环境后需要重建注册；保存和恢复的业务状态遵循对应模块契约。
  • 注册的存活范围各不相同：例如科技分类属于 Client 脚本环境，普通世界卸载时不应清空；世界绑定监听器则受世界生命周期管理。
  • 重复定义、覆盖和撤销规则由具体接口决定。数据文件的 reload 覆盖字段不能用于控制这些代码注册接口。

实现入口：Engine/Scripting/ScriptRegistry.cpp 收集脚本及 JSON 声明，Engine/Scripting/ModRuntime.cpp 连接监听器、定时器类型、通道接收函数和命令处理函数；CoreMod 模块维护各自的业务注册表。
