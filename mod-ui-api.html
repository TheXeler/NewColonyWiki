UI 框架

通过 Lua 注册底边栏按钮、窗口和浮动提示。旧即时模式 UI 渲染层已经移除；当前 Lua UI API 已由 RmlUI 文档渲染为玩家可见界面。

设计思路

  • 所有 Lua UI API 挂在 engine.ui 全局表下。
  • Lua 注册 UI 内容；RmlUI HUD 文档消费兼容快照并渲染底栏扩展按钮、窗口和浮动提示。
  • 注册 API 返回正整数句柄（失败时返回 0），方便后续更新、隐藏和注销。
  • 同一 id 重复注册会覆盖旧定义，适合脚本热重载。
  • 回调中的错误不会中断游戏循环——引擎记录日志并跳过本帧对应 UI。

命名空间

UI API 分为四个子命名空间：

命名空间用途
engine.ui.bottom_bar屏幕底部的常驻工具栏按钮、状态指示器
engine.ui.window可移动/可关闭的窗口面板，支持表格和分页表格内容
engine.ui.floating浮动提示、屏幕消息、教程提示和告警
engine.ui.data面向经营页面的聚合快照：资源、殖民者、工作、科技、事件
engine.ui.command面向 Lua UI 和 RmlUI 文档层的统一命令入口
engine.ui.style样式枚举（severity 等）

通用字段

所有可注册 UI 共享以下字段：

字段类型必填默认值说明
idstring是-全局唯一稳定 ID，建议 mod_id:name
priorityinteger否0渲染排序，值越大越靠前
visibleboolean / function否true是否显示；函数返回 boolean
enabledboolean / function否true是否可交互；函数返回 boolean
tooltipstring / function否nil鼠标悬停提示
on_clickfunction否nil点击回调

回调上下文

on_click 回调接收一个上下文表 ctx：

{
    id = "core:jobs",
    handle = 12,
    tick = 12345,
    dt = 0.016,
    hovered = true,
    active = false
}

底边栏 API

底边栏用于注册屏幕底部的常驻工具、状态按钮和模式切换入口。引擎负责布局，Lua 只提供按钮文本/状态。

注册槽位

engine.ui.bottom_bar.register_slot(def) —— 注册一个底边栏槽位，成功返回句柄，失败返回 0。

local handle = engine.ui.bottom_bar.register_slot({
    id = "core:build_menu",
    priority = 100,
    kind = "button",
    icon = "hammer",
    label = "建造",
    tooltip = "打开建造菜单",
    hotkey = "B",
    on_click = function(ctx)
        engine.events.emit("ui:build_menu:toggle", { source = ctx.id })
    end
})

除通用字段外，槽位还支持以下字段：

字段类型必填默认值说明
kindstring否"button""button"、"toggle"、"label"、"meter"
labelstring / function否""显示文本
iconstring / function否nil保留字段；icon 当前不渲染。button/toggle 渲染文本、角标与热键，label 渲染纯文本，meter 渲染进度条与数值。
hotkeystring否nil仅作 UI 提示显示；实际输入走输入系统
valuenumber / functionmeter 必填nilmeter 当前值，范围 0..1
activeboolean / functiontoggle 推荐falsetoggle 是否处于激活状态
badgestring / number / function否nil角标，如任务数量

更新槽位

engine.ui.bottom_bar.update_slot(handle_or_id, patch) —— 局部更新已注册槽位。返回 true 或 false。

engine.ui.bottom_bar.update_slot("core:jobs", {
    badge = 5,
    tooltip = "当前有 5 个待处理工作"
})

注销槽位

engine.ui.bottom_bar.unregister_slot(handle_or_id) —— 注销底边栏槽位。返回 true 或 false。

engine.ui.bottom_bar.unregister_slot("core:build_menu")

批量清理

engine.ui.bottom_bar.clear(mod_id) —— 清理指定 MOD 注册的所有底边栏槽位。留空时只允许 debug/dev 场景清理全部。

engine.ui.bottom_bar.clear("core")

窗口 API

engine.ui.window.register(def) 注册窗口，成功返回句柄。窗口的 render(ctx) 必须返回内容表；当前支持 kind = "table" 和 kind = "tabs_table"。

local handle = engine.ui.window.register({
    id = "core:craft_menu_window",
    title = { key = "ui.core:craft_menu.window_title" },
    size_hint = { w = 720, h = 460 },
    position = { x = 72, y = 112 },
    background_argb = "0xe815191d",
    draggable = true,
    flags = { "movable", "closable", "resizable", "scrollable" },
    render = function(ctx)
        return {
            kind = "tabs_table",
            tabs = {
                {
                    id = "core:worker",
                    label = { key = "jobs.core:worker" },
                    columns = { "产出", "输入", "配方", "等级" },
                    rows = {
                        { id = "core:craft_stick", columns = { "木棍 x4", "木板 x2", "core:craft_stick", "1" } }
                    },
                    reserve_footer = 46.0
                }
            },
            buttons = {
                {
                    id = "craft",
                    label = { key = "ui.core:craft_menu.craft_button" },
                    tooltip = { key = "ui.core:craft_menu.craft_tooltip" },
                    on_click = function(button) engine.log.info("clicked") end
                }
            }
        }
    end
})

表格行支持 on_click(row) 和 on_double_click(row)。双击很适合打开二级窗口，例如派系列表里双击某一行后打开单独的外交面板。按钮支持 label、tooltip、enabled 和 on_click(button)。按钮的 label、tooltip、窗口 title、分页 label 和单元格都可以直接传字符串、函数，或 { key = "category.id", params = {...} } 翻译引用。窗口 render() 返回表时可以提供 content_rml 原始 RML 片段，用于地图等非表格布局。窗口可选 background_argb，默认使用小地图同款半透明背景 0xe815191d；也支持 #15191de8 或 rgba(...)。窗口可选 draggable，缺省时由 flags 中是否包含 "movable" 决定；拖动手柄是窗口标题栏。

engine.ui.window.unregister(handle_or_id) 注销窗口；engine.ui.window.update(handle_or_id, patch) 局部更新；engine.ui.window.is_open(handle_or_id) 查询打开状态；engine.ui.window.clear(mod_id) 清理指定 MOD 的窗口。

经营数据桥

经营页面不要直接散落调用 ECS、库存、工作池、科技树和焦点系统。CoreMod 在启动时注册 engine.ui.data 和 engine.ui.command，作为 Lua UI 与 RmlUI 文档层共用的数据桥。

接口说明
engine.ui.data.snapshot("world_info")世界信息：day/year/season/tick_of_day/locale。
engine.ui.data.snapshot("resource_snapshot")资源栏数组：{ id, label_key, label, amount, capacity }。
engine.ui.data.snapshot("colonist_list")人员面板数组：左侧名单派生成 colonists_list；选中人员派生成 selected_colonist_view，包含身份、职业等级/经验、心情 thoughts、基础/工作/战斗属性、四槽装备、物品栏和转职树。
engine.ui.data.snapshot("event_list")事件面板数组：id/title/summary/detail/severity/options。
engine.ui.data.snapshot("tech_tree")科技树：按分类分组的 { id, label_key, nodes }。
engine.ui.data.snapshot("view_modes")当前视图与可选模式；Building View 保留 shader 色调并隐藏实体绘制，其他模式仍以状态反馈为主。
engine.ui.data.snapshot("orders_kinds")采集/挖矿等指令入口。
engine.ui.data.snapshot("build_defs")建造定义入口：{ id, label, label_key, category, size, cost, materials, missing, available, can_order, status }。
engine.ui.data.snapshot("construction_active")已下单施工入口：{ instance_id, def_id, status, position, materials, missing, reserved_materials }。
engine.ui.data.snapshot("craft_recipes")制造配方入口。
engine.ui.data.snapshot("combat_state")战斗面板占位状态：colonists、threats、alert_level。
engine.ui.data.snapshot("battle_hud")战斗 HUD Lua 通道：visible、battle_mode、squads、selected_squad、mana 和可用指令。该通道由 combat_hud.lua 包装数据桥提供；要作为 RML typed view 直接绑定，还需要宿主层把 battle_hud 加入快照白名单。
engine.ui.data.resources()返回 colony/resources 快照，汇总 stockpile 账本和殖民者手持资源。
engine.ui.data.colonists()返回人员界面所需的名称、状态、职业等级/经验、心情 thoughts、基础/工作/战斗属性、四槽装备、物品栏和转职树。
engine.ui.data.work()返回当前工作池实例、建造定义和制造配方入口。
engine.ui.data.research()返回科技节点、分类、前置、解锁、已研究/可研究/当前研究状态。
engine.ui.data.events()返回事件/焦点列表、严重度、详情和可执行动作。
engine.ui.data.snapshot(name)按名称读取单个快照；留空时返回完整经营快照。
 
local data = engine.ui.data.snapshot("colonists")
for _, colonist in ipairs(data.rows) do
    engine.log.info(colonist.name .. " / " .. tostring(colonist.Job.id))
end

统一命令入口是 engine.ui.command.run(target, payload)。RmlUI 文档层（及过渡期 HTML 参考）传入 core:* target；Lua UI 仍可用旧短名。返回值统一为 { ok, target, reason?, status?, changed_channels? }；失败 reason 稳定为 invalid_payload、unknown_command、research_unavailable、event_not_found、invalid_view_mode、build_definition_not_found、placement_required、craft_recipe_not_found。

core:bottombar.*panel.toggle，并广播 ui:data:changed。
core:orders.startengine.zone.start_designate(kind)。
core:colonists.selectengine.selection.select_entity。
core:colonists.change_classengine.jobs.assign。
core:colonists.resign_classengine.jobs.resign，返回父职业或 core:colonist。
core:colonists.sort / core:colonists.filter更新人员面板名单排序和职业筛选，并刷新 colonist_list。
core:research.startengine.research.start。
core:view.set_mode / core:view.toggle_xrayengine.view.set_mode / engine.view.toggle_terrain_xray。

core:build.beginsystems.construction.order（有坐标时）或 engine.buildings.begin_placement。无坐标 { id } 只启动 placement 并返回 status="placement_started"；带 { id, x, y, z } 才创建施工订单，缺料时仍返回 ok=true,status="waiting_materials"。
core:craft.queuesystems.crafting.queue；无 worker 时退回发布 craft job。

engine.ui.command.run("core:research.start", { nodeId = "core:basic_crafting" })
engine.ui.command.run("core:colonists.select", { id = 12 })
engine.ui.command.run("core:craft.queue", { id = "core:craft_stick", entity_id = 12 })

桥接层通过现有 engine.events 推送刷新信号：库存、stockpile、工作、科技和焦点变化会广播 ui:data:changed；payload 至少包含 channel。建造下单会刷新 build_defs 和 construction_active；stockpile 变化会刷新 resource_snapshot 和 build_defs，施工系统随后在材料重试事件中刷新 construction_active。命令执行会广播 ui:command，并把命令返回 JSON 写入 command_result 快照通道，页面可轮询该通道显示 toast 或错误。命令返回 changed_channels 时，C++ 会优先刷新这些通道；约 5 Hz 的全量刷新仍保留为兜底。

浮动提示 API

浮动提示用于短生命周期的屏幕提示、教程提示和告警。当前稳定模式是 mode = "screen"；mode = "world" 字段已预留，但 LuaUi.cpp 还没有做世界坐标投影，只会把提示放到屏幕中心附近并应用偏移。

注册常驻锚点

engine.ui.floating.register_anchor(def) —— 注册可重复使用的浮动提示锚点，适合常驻的实体状态提示、选中对象提示。

local anchor = engine.ui.floating.register_anchor({
    id = "core:selected_block_hint",
    mode = "screen",
    x = function() return 24 end,
    y = function() return 92 end,
    visible = function()
        return engine.selection and engine.selection.has_block and engine.selection.has_block()
    end,
    render = function(ctx)
        return {
            title = "方块",
            body = "左键选择，Esc 取消",
            severity = "info"
        }
    end
})

锚点特有字段：

字段类型必填默认值说明
modestring否"screen""screen" 可稳定使用；"world" 当前是占位定位。
xnumber / functionscreen 必填0屏幕 X
ynumber / functionscreen 必填0屏幕 Y
world_xnumber / function否0预留世界 X；当前渲染尚未使用。
world_ynumber / function否0预留世界 Y；当前渲染尚未使用。
world_znumber / function否0预留世界 Z；当前渲染尚未使用。
offset_xnumber否0屏幕偏移 X
offset_ynumber否0屏幕偏移 Y
ttl_ticksinteger否00 表示常驻，正数表示自动过期 tick 数
renderfunction是nil返回提示内容表的函数

render 函数返回值

render(ctx) 返回一个描述提示内容的表：

{
    title = "库存已满",
    body = "殖民者无法继续搬运。",
    icon = "warning",
    severity = "warning",   -- info | success | warning | error
    progress = 0.35,        -- 可选，0..1 进度条
    tooltip = "打开库存区查看详情" -- 可选
}

显示一次性提示

engine.ui.floating.show(def) —— 显示一次性浮动提示，适合教程和短消息。字段与锚点基本一致，但可直接提供 title/body 等字段，无需 render 函数。

engine.ui.floating.show({
    id = "core:first_colonist_tip",
    mode = "screen",
    x = 24,
    y = 120,
    title = "殖民者已抵达",
    body = "为他安排采矿、搬运或建造工作。",
    severity = "success",
    ttl_ticks = engine.time.tps * 6
})

更新提示

engine.ui.floating.update(handle_or_id, patch) —— 更新常驻锚点或一次性提示。

engine.ui.floating.update("core:first_colonist_tip", {
    body = "选择一个方块开始建造。",
    severity = "info"
})

关闭提示

engine.ui.floating.dismiss(handle_or_id) —— 关闭指定提示。

engine.ui.floating.dismiss("core:first_colonist_tip")

样式枚举

Lua UI 只提供有限的 severity 枚举。旧样式栈已移除；全局颜色和几何样式后续应迁移到 RmlUI RCSS 资源，见 UI 主题状态。

engine.ui.style.severity = {
    info = "info",
    success = "success",
    warning = "warning",
    error = "error"
}
severity渲染映射
info普通提示，灰色调
success成功反馈，绿色调
warning可恢复问题，黄色调
error失败或阻塞问题，红色调

RML 面板注册

engine.ui.rml.register_panel(def) 注册一个 RmlUI panel document，成功返回句柄。当前实现会按 def.id 的 modid 定位该 MOD 根目录，读取 document 指向的 .rml 文件，并通过 lua_ui_rml_panels 通道让真实 RmlUI runtime 在同一个 context 内加载、显示和关闭该文档；路径会规范化并禁止越出 MOD 目录。document 是字面路径，不走本地化解析，即使包含 .rml 也不会被当作翻译键。若只想输出轻量片段，可以继续使用 engine.ui.window.register({ content_rml = ... })。

local handle = engine.ui.rml.register_panel({
    id = "example:overview",
    title = "Overview",
    document = "assets/ui/rml/overview.rml",
    background_argb = "0xe815191d",
    draggable = true,
    position = { x = 96, y = 96 },
    size_hint = { w = 640, h = 420 },
    on_close = function(ctx) engine.log.info(ctx.id .. " closed") end,
})

engine.ui.rml 提供与 window 分组对称的完整生命周期，全部通过 lua_ui_rml_panels 快照通道驱动真实 RmlUI runtime。background_argb 与窗口 API 一致，默认是 0xe815191d，runtime 会把它应用到动态 RML document 根背景上。draggable 控制该动态 document 是否允许拖拽；document 内仍需要声明 data-drag-handle 作为拖动手柄。

  • register_panel(def) 注册 RML document 并返回句柄；unregister_panel(handle_or_id) 关闭并卸载，移除前触发 on_close 回调（与 window 的关闭路径一致）。
  • update_panel(handle_or_id, patch) 合并 patch 字段；show_panel / hide_panel 是 visible 的便捷封装；is_registered(handle_or_id) 查询；clear(mod_id) 批量卸载该 MOD 或全部面板。
  • reload(mod_id) 强制热重载：递增面板的内部 reload_epoch，runtime 在下一帧快照中检测到该值变化即 Close + LoadDocument，即便 .rml 路径未变也会重新读取磁盘内容。传 mod_id 只重载该 MOD，省略则重载全部；返回是否有面板被标记。
编辑 .rml 文件后调用 engine.ui.rml.reload("example") 即可在不重启游戏的前提下看到改动；改变 def.document 路径本身也会触发重载。reload 只对已注册的面板生效，返回 false 表示没有匹配的面板。

生命周期与调用时机

  1. on_load —— 注册静态底边栏槽位（按钮、toggle 等）。
  2. on_world_init —— 注册依赖世界状态的浮动锚点。
  3. 引擎每帧 UI 阶段调用渲染系统，Lua 函数字段被求值。
  4. 回到主菜单只清理窗口、浮动提示和面板可见态；on_load 注册的底边栏槽位会保留，避免二次创建或加载世界后缺少入口。
  5. 一次性提示当前由脚本自行 dismiss；ttl_ticks 字段保留但不自动回收。
  6. 热重载或 MOD 卸载时调用 clear(mod_id)。
注册 UI 的时机要和生命周期配合：bottom_bar 在 on_load 注册；floating 锚点在 on_world_init 注册。一次性提示可以在任何时机调用 floating.show。

完整示例

以下是一个 MOD 注册底边栏和浮动提示的完整示例：

local M = {}

local jobs_badge = 0

function M.on_load()
    -- 底边栏：工作按钮
    engine.ui.bottom_bar.register_slot({
        id = "core:jobs",
        priority = 90,
        kind = "button",
        icon = "briefcase",
        label = "工作",
        badge = function() return jobs_badge end,
        tooltip = function()
            return "待处理工作：" .. tostring(jobs_badge)
        end,
        on_click = function()
            engine.events.emit("ui:jobs:toggle", {})
        end
    })

    -- 底边栏：暂停/继续切换
    engine.ui.bottom_bar.register_slot({
        id = "core:speed",
        priority = 10,
        kind = "toggle",
        label = "暂停",
        active = function()
            return engine.simulation and engine.simulation.paused and engine.simulation.paused()
        end,
        on_click = function()
            engine.events.emit("simulation:pause:toggle", {})
        end
    })
end

function M.on_world_init()
    -- 欢迎提示，8 秒后自动消失
    engine.ui.floating.show({
        id = "core:welcome_tip",
        mode = "screen",
        x = 24,
        y = 96,
        title = "欢迎来到 NewColony",
        body = "使用底边栏打开工作和建造界面。",
        severity = "info",
        ttl_ticks = engine.time.tps * 8
    })
end

function M.on_tick(tick, dt)
    if tick % 20 == 0 then
        -- 实际实现后应从工作系统读取
        jobs_badge = jobs_badge
    end
end

return M

当前边界

能力当前状态
底边栏支持 button、toggle、label、meter；图标字段保留但不绘制图标。
窗口内容支持 table 和 tabs_table；没有通用任意控件 DSL。
浮动提示屏幕坐标可用；世界坐标字段尚未投影到真实屏幕位置。
翻译引用字符串字段可用 { key = "...", params = {...} }，参数会递归解析，循环引用会记录警告并保留占位符。
错误隔离Lua 字段函数、render、按钮和行回调使用 protected call，失败时记录日志并回退或跳过当前内容。

游戏内 RmlUI 宿主层（目标主 UI 路线）

UI 技术路线已从旧即时模式 UI / 外部浏览器（ExternalBrowser + 本地 HTTP server）转向游戏内 RmlUI：HTML/CSS 风格、进程内渲染、合成进 Vulkan 画面。引擎不再启动本地 HTTP server，不再以外部浏览器作为 UI 验收路径；旧即时模式 UI 依赖已完全移除。玩家构建固定使用真实 RmlUI backend，宿主层完整生命周期、数据桥、命令通道和 Vulkan 合成都由 RmlUiHost / RealRmlUiRuntime 驱动。Null stub 只保留为显式诊断/失败回退路径，启用时不会渲染文档并会记录错误级日志。

新增复杂玩家界面应以独立 RML 为结构源，并链接 CoreMod/assets/ui/rml/shared/base.rcss、layout.rcss 和 components.rcss。engine.ui.window.register 保留给单表格、短按钮组和临时选择器等兼容窗口，不应继续承载多视图、双栏详情、嵌套对话框等业务结构。策划契约模板见 docs/ui-design-brief-template.md，迁移边界见 docs/ui-window-migration-assessment.md。

三层结构

组件文件职责
RmlUiHostEngine/UI/RmlUiHost.{hpp,cpp}引擎唯一集成点；持有后端与桥，暴露生命周期、输入、数据推送与命令消费。
RmlUiRuntimeEngine/UI/RmlUiRuntime.{hpp,cpp}RmlUI backend 抽象接口 + NullRmlUiRuntime stub + make_rml_ui_runtime() 工厂。
RmlUiBridgeEngine/UI/RmlUiBridge.{hpp,cpp}C++ ↔ 文档层双向数据/事件通道（快照 + 命令队列），与具体 backend 无关。

生命周期与引擎接入

引擎通过 engine.rml_ui() 拿到 RmlUiHost。Host 在 Engine::init() 创建并加载 <core_assets>/ui/rml/main.rml；主循环每帧 update(dt)、drain_commands()，并由 renderer UI pass 调用 render(cmd) 合成到窗口；shutdown() 时释放。世界加载时触发 on_world_init()（重载文档 + 重推 world_info），回到主菜单触发 on_return_to_main_menu()，窗口尺寸变化调用 resize()。对应 Engine.cpp 中 RmlUi 帧采样段。

数据刷新走统一入口 Engine::publish_rml_ui_snapshots()：遍历 RML_UI_SNAPSHOT_CHANNELS 的经营通道和 Lua UI 兼容通道。经营通道逐个调用 ScriptEngine::get_ui_snapshot(channel)（内部走 Lua 数据桥 engine.ui.data.snapshot 并序列化为 JSON）后推入 RmlUiBridge；兼容通道由 LuaUi 直接生成 RML 片段。刷新按 RML_UI_REFRESH_INTERVAL（约 5 Hz）节流，避免每帧重复聚合快照；世界（重新）进入的那一帧强制立即刷新一次，保证新加载页面不会短暂空白。命令派发同样集中：Engine::dispatch_rml_ui_command() 调用 ScriptEngine::run_ui_command(target, payload)，由 Lua 桥 engine.ui.command.run 落到具体系统；命令返回的 changed_channels 会驱动局部刷新，返回 JSON 追加事件序号 sequence 后另写入 command_result 通道。

C++ → 文档：快照通道

C++ 按通道名推送 JSON 快照，最新值覆盖旧值，文档侧自行轮询。经营数值由 ScriptEngine::get_ui_snapshot(channel) 调用 Lua 数据桥生成，避免把业务适配塞进文档层。十一个常规数据通道全部接通到宿主层，另有事件式 command_result 通道，数据来源如下：

文档 → C++：命令队列

文档以 { target, payload } 形式向引擎发指令。引擎每帧 drain_commands() 取出，先经 handle_host_command() 过滤宿主保留命令，其余调用 ScriptEngine::run_ui_command(target, json_payload) 转交 Lua 数据桥。ScriptEngine 保存最近一次命令结果，RmlUiBridge 同步暴露 command_result 快照；若结果含 changed_channels，引擎只刷新这些通道，否则回退全量刷新。宿主保留命令包括 core:rmlui.reload、DEBUG UI Lab 场景，以及 Tech Tree 的分类/选择展示状态；这些展示命令不修改业务数据。core:research.start 仍进入 Lua 数据桥和正式研究系统。

渲染接入点

真实 RmlUI backend 已通过 RmlUiRuntime::render(VkCommandBuffer) 接入 Vulkan UI pass。RealRmlUiRuntime 的 RenderInterface 负责 compiled geometry、纹理描述符、scissor 和 context->Render() 命令录制；Null stub 的 render() 返回 false，仅用于显式诊断/失败回退。

backend 选择

UI backend 由 make_rml_ui_runtime() 工厂选择，可用环境变量 NC_UI_BACKEND 覆盖：

取值行为
未设置 / 空 / rml默认真实 RmlUI backend，玩家可见 UI 从 RML/RCSS 文档渲染。
null显式强制 stub，即使已编译真 backend 也可禁用 UI（仅用于无头/自动化诊断）；运行时会记录错误级提示。
已移除 external 路径。 此前的 NC_WEBUI_BACKEND=external / ExternalBrowserWebUiRuntime 调试后端（绑定 127.0.0.1 的微型 HTTP server + ShellExecuteW 打开系统浏览器 + ws2_32/shell32 链接）已整体删除。引擎不再启动本地 HTTP server，不再以外部浏览器作为 UI 验收路径。游戏内 UI 统一走 RmlUI；真 backend 接入方式见下文。

Fallback：RmlUiHost::init 调用真实 backend 的 init()，若失败会 shutdown 该 backend 并用 make_null_rml_ui_runtime() 替换，宿主层照常运行，同时日志明确指出没有可见 UI。

接入真 RmlUI backend

vcpkg.json 已声明 rmlui 端口（v6.1，默认 feature freetype，CMake 目标 RmlUi::RmlUi）。普通构建会编译真实 backend；只有设置 NC_UI_BACKEND=null 或真实 backend 初始化失败时才走诊断 stub。资源入口、stub 与真 backend 边界统一见 游戏内 RmlUI。要点：

  1. Release configure 使用 cmake --preset export-release：构建系统会 find_package(RmlUi CONFIG REQUIRED)、把 Engine/UI/RmlUiRealRuntime.cpp 加入编译、链接 RmlUi::RmlUi；make_rml_ui_runtime() 默认返回 RealRmlUiRuntime（is_real_backend()==true）。
  2. 真实 backend 的 render(VkCommandBuffer) 通过 RmlUI 6.1 RenderInterface 录制 UI 几何、纹理和 scissor，并由 renderer 的 UI 命令缓冲合成到游戏窗口。
  3. RmlUI 事件/数据绑定已桥接到 RmlUiBridge 的 snapshot 与 command 队列。

旧 Lua UI 的可见输出通过 lua_ui_bottom_bar、lua_ui_windows、lua_ui_floating 三个 RmlUI 快照通道进入 hud.rml。按钮和窗口内 action 使用 lua_ui:<handle>:... 内部命令回调原 Lua 函数；table row 与 button 的回调 target 会优先基于声明的 id（没有 id 时基于稳定遍历位置）生成，避免节流刷新时仅因临时 action id 变化而重建 RML、打断 hover 状态。

真 backend 的实现文件 Engine/UI/RmlUiRealRuntime.{hpp,cpp} 是当前受维护玩家可见 UI 路线。详见 游戏内 RmlUI · 接入真 backend。

与旧 Lua UI 的关系

RmlUI 是唯一玩家可见 UI 路线。旧 Lua UI（底边栏/窗口/浮动提示）的即时模式实现已移除，但兼容 API 现在会生成 RmlUI-backed 可见界面；保留的 C++ 类负责注册仓库、RML 片段生成、回调命令和数据通道。DevConsole、MainMenu、HUD、Pause/Settings、小地图和全局提示仍由静态 RML/RCSS 文档驱动。Tech Tree 已通过 engine.ui.rml.register_panel 迁移到独立 tech_tree.rml，仍复用原底栏入口、tech_tree 通道和 core:research.start；旧 table 仅作为注册失败回退。Build、Crafting、Colonists 后续按同一边界逐步迁移。

文档侧数据契约

文档侧按通道名读取快照、以 { target, payload } 发命令，与 RmlUiBridge 对接。通道名字符串、命令 target 命名、command_result 反馈通道均为稳定契约，不随后端实现变化。当前玩家可见 UI 文档都维护在 CoreMod/assets/ui/rml/。
