UI 框架

通过 Lua 注册底边栏按钮、窗口和浮动提示。旧即时模式 UI 渲染层已经移除，当前 Lua UI API 仅保留数据注册兼容入口，实际可见界面需要迁移到 RmlUI。

设计思路

  • 所有 Lua UI API 挂在 engine.ui 全局表下。
  • Lua 注册 UI 内容；旧渲染层已移除，后续由 RmlUI 文档消费这些数据。
  • 注册 API 返回正整数句柄（失败时返回 0），方便后续更新、隐藏和注销。
  • 同一 id 重复注册会覆盖旧定义，适合脚本热重载。
  • 回调中的错误不会中断游戏循环——引擎记录日志并跳过本帧对应 UI。

命名空间

UI API 分为四个子命名空间：

命名空间用途
engine.ui.bottom_bar屏幕底部的常驻工具栏按钮、状态指示器
engine.ui.window可移动/可关闭的窗口面板，支持表格和分页表格内容
engine.ui.floating浮动提示、屏幕消息、教程提示和告警
engine.ui.data面向经营页面的聚合快照：资源、殖民者、工作、科技、事件
engine.ui.command面向 Lua UI 和 RmlUI 文档层的统一命令入口
engine.ui.style样式枚举（severity 等）

通用字段

所有可注册 UI 共享以下字段：

字段类型必填默认值说明
idstring是-全局唯一稳定 ID，建议 mod_id:name
priorityinteger否0渲染排序，值越大越靠前
visibleboolean / function否true是否显示；函数返回 boolean
enabledboolean / function否true是否可交互；函数返回 boolean
tooltipstring / function否nil鼠标悬停提示
on_clickfunction否nil点击回调

回调上下文

on_click 回调接收一个上下文表 ctx：

{
    id = "core:jobs",
    handle = 12,
    tick = 12345,
    dt = 0.016,
    hovered = true,
    active = false
}

底边栏 API

底边栏用于注册屏幕底部的常驻工具、状态按钮和模式切换入口。引擎负责布局，Lua 只提供按钮文本/状态。

注册槽位

engine.ui.bottom_bar.register_slot(def) —— 注册一个底边栏槽位，成功返回句柄，失败返回 0。

local handle = engine.ui.bottom_bar.register_slot({
    id = "core:build_menu",
    priority = 100,
    kind = "button",
    icon = "hammer",
    label = "建造",
    tooltip = "打开建造菜单",
    hotkey = "B",
    on_click = function(ctx)
        engine.events.emit("ui:build_menu:toggle", { source = ctx.id })
    end
})

除通用字段外，槽位还支持以下字段：

字段类型必填默认值说明
kindstring否"button""button"、"toggle"、"label"、"meter"
labelstring / function否""显示文本
iconstring / function否nil保留字段；当前底边栏渲染只显示文本、角标和热键。
hotkeystring否nil仅作 UI 提示显示；实际输入走输入系统
valuenumber / functionmeter 必填nilmeter 当前值，范围 0..1
activeboolean / functiontoggle 推荐falsetoggle 是否处于激活状态
badgestring / number / function否nil角标，如任务数量

更新槽位

engine.ui.bottom_bar.update_slot(handle_or_id, patch) —— 局部更新已注册槽位。返回 true 或 false。

engine.ui.bottom_bar.update_slot("core:jobs", {
    badge = 5,
    tooltip = "当前有 5 个待处理工作"
})

注销槽位

engine.ui.bottom_bar.unregister_slot(handle_or_id) —— 注销底边栏槽位。返回 true 或 false。

engine.ui.bottom_bar.unregister_slot("core:build_menu")

批量清理

engine.ui.bottom_bar.clear(mod_id) —— 清理指定 MOD 注册的所有底边栏槽位。留空时只允许 debug/dev 场景清理全部。

engine.ui.bottom_bar.clear("core")

窗口 API

engine.ui.window.register(def) 注册窗口，成功返回句柄。窗口的 render(ctx) 必须返回内容表；当前支持 kind = "table" 和 kind = "tabs_table"。

local handle = engine.ui.window.register({
    id = "core:craft_menu_window",
    title = { key = "ui.core:craft_menu.window_title" },
    size_hint = { w = 720, h = 460 },
    position = { x = 72, y = 112 },
    flags = { "movable", "closable", "resizable", "scrollable" },
    render = function(ctx)
        return {
            kind = "tabs_table",
            tabs = {
                {
                    id = "core:worker",
                    label = { key = "professions.core:worker" },
                    columns = { "产出", "输入", "配方", "等级" },
                    rows = {
                        { id = "core:craft_stick", columns = { "木棍 x4", "木板 x2", "core:craft_stick", "1" } }
                    },
                    reserve_footer = 46.0
                }
            },
            buttons = {
                {
                    id = "craft",
                    label = { key = "ui.core:craft_menu.craft_button" },
                    tooltip = { key = "ui.core:craft_menu.craft_tooltip" },
                    on_click = function(button) engine.log.info("clicked") end
                }
            }
        }
    end
})

表格行支持 on_click(row) 和 on_double_click(row)。双击很适合打开二级窗口，例如派系列表里双击某一行后打开单独的外交面板。按钮支持 label、tooltip、enabled 和 on_click(button)。按钮的 label、tooltip、窗口 title、分页 label 和单元格都可以直接传字符串、函数，或 { key = "category.id", params = {...} } 翻译引用。

engine.ui.window.unregister(handle_or_id) 注销窗口；engine.ui.window.update(handle_or_id, patch) 局部更新；engine.ui.window.is_open(handle_or_id) 查询打开状态；engine.ui.window.clear(mod_id) 清理指定 MOD 的窗口。

经营数据桥

经营页面不要直接散落调用 ECS、库存、工作池、科技树和焦点系统。CoreMod 在启动时注册 engine.ui.data 和 engine.ui.command，作为 Lua UI 与 RmlUI 文档层共用的数据桥。

接口说明
engine.ui.data.snapshot("world_info")世界信息：day/year/season/tick_of_day/locale。
engine.ui.data.snapshot("resource_snapshot")资源栏数组：{ id, label_key, label, amount, capacity }。
engine.ui.data.snapshot("colonist_list")人员面板数组：扁平的 id/profession_id/level/mood/equipment/inventory/class_tree。
engine.ui.data.snapshot("event_list")事件面板数组：id/title/summary/detail/severity/options。
engine.ui.data.snapshot("tech_tree")科技树：按分类分组的 { id, label_key, nodes }。
engine.ui.data.snapshot("view_modes")当前视图与可选模式；Building View 保留 shader 色调并隐藏实体绘制，其他模式仍以状态反馈为主。
engine.ui.data.snapshot("orders_kinds")采集/挖矿等指令入口。
engine.ui.data.snapshot("build_defs")建造定义入口：{ id, label, label_key, category, size, cost, materials, missing, available, can_order, status }。
engine.ui.data.snapshot("construction_active")已下单施工入口：{ instance_id, def_id, status, position, materials, missing, reserved_materials }。
engine.ui.data.snapshot("craft_recipes")制造配方入口。
engine.ui.data.snapshot("combat_state")战斗面板占位状态：colonists、threats、alert_level。
engine.ui.data.resources()返回 colony/resources 快照，汇总 stockpile 账本和殖民者手持资源。
engine.ui.data.colonists()返回殖民者名称、职业、等级/经验、状态、需求、属性、装备和手持物。
engine.ui.data.jobs()返回当前工作池实例、建造定义和制造配方入口。
engine.ui.data.research()返回科技节点、分类、前置、解锁、已研究/可研究/当前研究状态。
engine.ui.data.events()返回事件/焦点列表、严重度、详情和可执行动作。
engine.ui.data.snapshot(name)按名称读取单个快照；留空时返回完整经营快照。
 
local data = engine.ui.data.snapshot("colonists")
for _, colonist in ipairs(data.rows) do
    engine.log.info(colonist.name .. " / " .. tostring(colonist.profession.id))
end

统一命令入口是 engine.ui.command.run(target, payload)。RmlUI 文档层（及过渡期 HTML 参考）传入 core:* target；Lua UI 仍可用旧短名。返回值统一为 { ok, target, reason?, status?, changed_channels? }；失败 reason 稳定为 invalid_payload、unknown_command、research_unavailable、event_not_found、invalid_view_mode、build_definition_not_found、placement_required、craft_recipe_not_found。

target落点
core:bottombar.*panel.toggle，并广播 ui:data:changed。
core:orders.startengine.zone.start_designate(kind)。
core:colonists.selectengine.selection.select_entity。
core:colonists.change_classengine.professions.assign。
core:research.startengine.research.start。
core:view.set_mode / core:view.toggle_xrayengine.view.set_mode / engine.view.toggle_terrain_xray。
core:events.act / core:events.dismissengine.focuses.choose / engine.focuses.dismiss。
core:build.beginsystems.construction.order（有坐标时）或 engine.buildings.begin_placement。无坐标 { id } 只启动 placement 并返回 status="placement_started"；带 { id, x, y, z } 才创建施工订单，缺料时仍返回 ok=true,status="waiting_materials"。
core:craft.queuesystems.crafting.queue；无 worker 时退回发布 craft job。
core:locale.set记录 UI locale；当前引擎未暴露运行时切换 locale API 时返回 { ok=true, status="stored", reason="runtime_locale_switch_unavailable" }。
 
engine.ui.command.run("core:research.start", { nodeId = "core:basic_crafting" })
engine.ui.command.run("core:colonists.select", { id = 12 })
engine.ui.command.run("core:craft.queue", { id = "core:craft_stick", entity_id = 12 })

桥接层通过现有 engine.events 推送刷新信号：库存、stockpile、工作、科技和焦点变化会广播 ui:data:changed；payload 至少包含 channel。建造下单会刷新 build_defs 和 construction_active；stockpile 变化会刷新 resource_snapshot 和 build_defs，施工系统随后在材料重试事件中刷新 construction_active。命令执行会广播 ui:command，并把命令返回 JSON 写入 command_result 快照通道，页面可轮询该通道显示 toast 或错误。命令返回 changed_channels 时，C++ 会优先刷新这些通道；约 5 Hz 的全量刷新仍保留为兜底。

浮动提示 API

浮动提示用于短生命周期的屏幕提示、教程提示和告警。当前稳定模式是 mode = "screen"；mode = "world" 字段已预留，但 LuaUi.cpp 还没有做世界坐标投影，只会把提示放到屏幕中心附近并应用偏移。

注册常驻锚点

engine.ui.floating.register_anchor(def) —— 注册可重复使用的浮动提示锚点，适合常驻的实体状态提示、选中对象提示。

local anchor = engine.ui.floating.register_anchor({
    id = "core:selected_block_hint",
    mode = "screen",
    x = function() return 24 end,
    y = function() return 92 end,
    visible = function()
        return engine.selection and engine.selection.has_block and engine.selection.has_block()
    end,
    render = function(ctx)
        return {
            title = "方块",
            body = "左键选择，Esc 取消",
            severity = "info"
        }
    end
})

锚点特有字段：

字段类型必填默认值说明
modestring否"screen""screen" 可稳定使用；"world" 当前是占位定位。
xnumber / functionscreen 必填0屏幕 X
ynumber / functionscreen 必填0屏幕 Y
world_xnumber / function否0预留世界 X；当前渲染尚未使用。
world_ynumber / function否0预留世界 Y；当前渲染尚未使用。
world_znumber / function否0预留世界 Z；当前渲染尚未使用。
offset_xnumber否0屏幕偏移 X
offset_ynumber否0屏幕偏移 Y
ttl_ticksinteger否00 表示常驻，正数表示自动过期 tick 数
renderfunction是nil返回提示内容表的函数

render 函数返回值

render(ctx) 返回一个描述提示内容的表：

{
    title = "库存已满",
    body = "殖民者无法继续搬运。",
    icon = "warning",
    severity = "warning",   -- info | success | warning | error
    progress = 0.35,        -- 可选，0..1 进度条
    tooltip = "打开库存区查看详情" -- 可选
}

显示一次性提示

engine.ui.floating.show(def) —— 显示一次性浮动提示，适合教程和短消息。字段与锚点基本一致，但可直接提供 title/body 等字段，无需 render 函数。

engine.ui.floating.show({
    id = "core:first_colonist_tip",
    mode = "screen",
    x = 24,
    y = 120,
    title = "殖民者已抵达",
    body = "为他安排采矿、搬运或建造工作。",
    severity = "success",
    ttl_ticks = engine.time.tps * 6
})

更新提示

engine.ui.floating.update(handle_or_id, patch) —— 更新常驻锚点或一次性提示。

engine.ui.floating.update("core:first_colonist_tip", {
    body = "选择一个方块开始建造。",
    severity = "info"
})

关闭提示

engine.ui.floating.dismiss(handle_or_id) —— 关闭指定提示。

engine.ui.floating.dismiss("core:first_colonist_tip")

样式枚举

Lua UI 只提供有限的 severity 枚举。旧样式栈已移除；全局颜色和几何样式后续应迁移到 RmlUI RCSS 资源，见 UI 主题状态。

engine.ui.style.severity = {
    info = "info",
    success = "success",
    warning = "warning",
    error = "error"
}
severity渲染映射
info普通提示，灰色调
success成功反馈，绿色调
warning可恢复问题，黄色调
error失败或阻塞问题，红色调

生命周期与调用时机

  1. on_load —— 注册静态底边栏槽位（按钮、toggle 等）。
  2. on_world_init —— 注册依赖世界状态的浮动锚点。
  3. 引擎每帧 UI 阶段调用渲染系统，Lua 函数字段被求值。
  4. 引擎每 tick 清理过期的 ttl_ticks 提示。
  5. 热重载或 MOD 卸载时调用 clear(mod_id)。
注册 UI 的时机要和生命周期配合：bottom_bar 在 on_load 注册；floating 锚点在 on_world_init 注册。一次性提示可以在任何时机调用 floating.show。

完整示例

以下是一个 MOD 注册底边栏和浮动提示的完整示例：

local M = {}

local jobs_badge = 0

function M.on_load()
    -- 底边栏：工作按钮
    engine.ui.bottom_bar.register_slot({
        id = "core:jobs",
        priority = 90,
        kind = "button",
        icon = "briefcase",
        label = "工作",
        badge = function() return jobs_badge end,
        tooltip = function()
            return "待处理工作：" .. tostring(jobs_badge)
        end,
        on_click = function()
            engine.events.emit("ui:jobs:toggle", {})
        end
    })

    -- 底边栏：暂停/继续切换
    engine.ui.bottom_bar.register_slot({
        id = "core:speed",
        priority = 10,
        kind = "toggle",
        label = "暂停",
        active = function()
            return engine.simulation and engine.simulation.paused and engine.simulation.paused()
        end,
        on_click = function()
            engine.events.emit("simulation:pause:toggle", {})
        end
    })
end

function M.on_world_init()
    -- 欢迎提示，8 秒后自动消失
    engine.ui.floating.show({
        id = "core:welcome_tip",
        mode = "screen",
        x = 24,
        y = 96,
        title = "欢迎来到 NewColony",
        body = "使用底边栏打开工作和建造界面。",
        severity = "info",
        ttl_ticks = engine.time.tps * 8
    })
end

function M.on_tick(tick, dt)
    if tick % 20 == 0 then
        -- 实际实现后应从工作系统读取
        jobs_badge = jobs_badge
    end
end

return M

当前边界

能力当前状态
底边栏支持 button、toggle、label、meter；图标字段保留但不绘制图标。
窗口内容支持 table 和 tabs_table；没有通用任意控件 DSL。
浮动提示屏幕坐标可用；世界坐标字段尚未投影到真实屏幕位置。
翻译引用字符串字段可用 { key = "...", params = {...} }，参数会递归解析，循环引用会记录警告并保留占位符。
错误隔离Lua 字段函数、render、按钮和行回调使用 protected call，失败时记录日志并回退或跳过当前内容。

游戏内 RmlUI 宿主层（目标主 UI 路线）

UI 技术路线已从旧即时模式 UI / 外部浏览器（ExternalBrowser + 本地 HTTP server）转向游戏内 RmlUI：HTML/CSS 风格、进程内渲染、合成进 Vulkan 画面。引擎不再启动本地 HTTP server，不再以外部浏览器作为 UI 验收路径；旧即时模式 UI 依赖已完全移除。默认构建使用 Null stub（backend 名 rml，is_real_backend()==false，不渲染、不启动任何外部进程），但宿主层完整生命周期、数据桥和命令通道全部接好。真 RmlUi 库接入后，在 make_rml_ui_runtime() 切换；初始化失败会自动退回 Null stub，不会崩溃。

三层结构

组件文件职责
RmlUiHostEngine/UI/RmlUiHost.{hpp,cpp}引擎唯一集成点；持有后端与桥，暴露生命周期、输入、数据推送与命令消费。
RmlUiRuntimeEngine/UI/RmlUiRuntime.{hpp,cpp}RmlUI backend 抽象接口 + NullRmlUiRuntime stub + make_rml_ui_runtime() 工厂。
RmlUiBridgeEngine/UI/RmlUiBridge.{hpp,cpp}C++ ↔ 文档层双向数据/事件通道（快照 + 命令队列），与具体 backend 无关。

生命周期与引擎接入

引擎通过 engine.rml_ui() 拿到 RmlUiHost。Host 在 Engine::init() 创建并加载 <core_assets>/ui/rml/main.rml（Null stub 下 load_document 返回 false，属预期）；主循环每帧 update(dt) 并 drain_commands()；shutdown() 时释放。世界加载时触发 on_world_init()（重载文档 + 重推 world_info），回到主菜单触发 on_return_to_main_menu()，窗口尺寸变化调用 resize()。对应 Engine.cpp 中 RmlUi 帧采样段。

数据刷新走统一入口 Engine::publish_rml_ui_snapshots()：遍历 RML_UI_SNAPSHOT_CHANNELS 全部十一个通道，逐个调用 ScriptEngine::get_ui_snapshot(channel)（内部走 Lua 数据桥 engine.ui.data.snapshot 并序列化为 JSON）后推入 RmlUiBridge。刷新按 RML_UI_REFRESH_INTERVAL（约 5 Hz）节流，避免每帧重复聚合快照；世界（重新）进入的那一帧强制立即刷新一次，保证新加载页面不会短暂空白。命令派发同样集中：Engine::dispatch_rml_ui_command() 调用 ScriptEngine::run_ui_command(target, payload)，由 Lua 桥 engine.ui.command.run 落到具体系统；命令返回的 changed_channels 会驱动局部刷新，返回 JSON 另写入 command_result 通道。

C++ → 文档：快照通道

C++ 按通道名推送 JSON 快照，最新值覆盖旧值，文档侧自行轮询。经营数值由 ScriptEngine::get_ui_snapshot(channel) 调用 Lua 数据桥生成，避免把业务适配塞进文档层。十一个常规数据通道全部接通到宿主层，另有事件式 command_result 通道，数据来源如下：

通道名数据来源（Lua 桥）连接状态

resource_snapshotsystems.hauling 账本 + 殖民者手持物汇总已接通

construction_activesystems.construction.active()已接通；建造面板显示已下单施工，支持 waiting_materials。

combat_state殖民者生命汇总（取自人员快照）部分接通：包含 colonists、空 threats、alert_level；威胁列表待战斗系统补全。
command_resultEngine::dispatch_rml_ui_command() 写入最近一次命令返回 JSON事件式通道；不在 5 Hz 全量刷新列表内，仅命令执行后更新。

除统一刷新入口外，RmlUiHost 仍保留 push_resource_snapshot/push_colonist_list/push_event_list/push_world_info/push_tech_tree/push_view_modes 等便捷方法，以及通用 push(channel, json) 转发器，供需要单通道直推的调用方使用；文档侧只认通道名字符串。

文档 → C++：命令队列

文档以 { target, payload } 形式向引擎发指令。引擎每帧 drain_commands() 取出，先经 handle_host_command() 过滤宿主保留命令，其余调用 ScriptEngine::run_ui_command(target, json_payload) 转交 Lua 数据桥。ScriptEngine 保存最近一次命令结果，RmlUiBridge 同步暴露 command_result 快照；若结果含 changed_channels，引擎只刷新这些通道，否则回退全量刷新。宿主保留命令：core:rmlui.reload（热重载文档）。

渲染接入点

当前 未 把 RmlUI 合成到 Vulkan 画面。接入点已留：RmlUiRuntime::render(VkCommandBuffer) 接口存在，Engine.cpp 主循环内标注 TODO(rmlui-render)。默认 Null stub 的 render() 返回 false，零开销。接入真后端时，在 make_rml_ui_runtime() 返回新后端，在其 render() 内把文档纹理 blit 到命令缓冲，并取消该 TODO 调用。注意不要覆盖 Renderer 现有的 set_ui_render_callback（已由 DevConsole 使用）——需要时扩展为回调链。

backend 选择

UI backend 由 make_rml_ui_runtime() 工厂选择，可用环境变量 NC_UI_BACKEND 覆盖：

取值行为
未设置 / 空 / rmlNullRmlUiRuntime stub（backend_name()=="rml"，is_real_backend()==false；不渲染、不启动任何外部进程，游戏行为不变）。这是当前默认且唯一的 backend。
null显式强制 stub，即使将来接入了真 backend 也可用此值禁用 UI（便于无头/自动化运行）。
已移除 external 路径。 此前的 NC_WEBUI_BACKEND=external / ExternalBrowserWebUiRuntime 调试后端（绑定 127.0.0.1 的微型 HTTP server + ShellExecuteW 打开系统浏览器 + ws2_32/shell32 链接）已整体删除。引擎不再启动本地 HTTP server，不再以外部浏览器作为 UI 验收路径。游戏内 UI 统一走 RmlUI；真 backend 接入方式见下文。

Fallback：真 backend 接入后，RmlUiHost::init 调用其 init()，若失败会 shutdown 该 backend 并用 make_null_rml_ui_runtime() 替换，宿主层照常运行，游戏绝不因缺依赖崩溃。

接入真 RmlUI backend

vcpkg 已有 rmlui 端口（v6.1，默认 feature freetype，CMake 目标 RmlUi::RmlUi），但默认构建不写进 vcpkg.json，避免每次 configure 强制联网构建。完整的启用步骤、CMake option（NEWCOLONY_ENABLE_RMLUI，默认 OFF）、资源入口（CoreMod/assets/ui/rml/）、stub 与真 backend 边界、剩余的 Vulkan RenderInterface 缺口，统一见 游戏内 RmlUI。要点：

  1. 在 vcpkg.json 的 dependencies 增加 "rmlui"（自带 freetype），随后 reconfigure 让 vcpkg 构建它。
  2. configure 时 -DNEWCOLONY_ENABLE_RMLUI=ON：该 option 会 find_package(RmlUi CONFIG)、把 Engine/UI/RmlUiRealRuntime.cpp 加入编译、链接 RmlUi::RmlUi、定义 NEWCOLONY_HAVE_RMLUI=1；make_rml_ui_runtime() 据此返回 RealRmlUiRuntime（is_real_backend()==true）。
  3. 真 backend 的 render(VkCommandBuffer) 当前是 no-op（StubRmlRenderInterface）；落地 Vulkan RenderInterface 后，在其中录制命令缓冲、调用 m_context->Render()、返回 true，并在 Engine.cpp 的 TODO(rmlui-render) 处调用 m_rml_ui_host.render(cmd)（或扩展 Renderer 的 UI 回调链，注意不要覆盖 DevConsole 已用的 set_ui_render_callback）。
  4. 把 RmlUI 的事件/数据绑定桥接到 RmlUiBridge 的 push_snapshot / enqueue_command。

文档层、桥契约、通道名约定在接入真 backend 时无需改动。

真 backend 的实现文件 Engine/UI/RmlUiRealRuntime.{hpp,cpp} 已作为受维护的文件边界存在；它针对 RmlUi 6.1 编写，但默认环境下未做构建验证（默认不编译）。详见 游戏内 RmlUI · 接入真 backend。

与旧 Lua UI 的关系

RmlUI 是目标主 UI 路线。旧 Lua UI（底边栏/窗口/浮动提示）与 DevConsole / MainMenu / Minimap 的可见渲染实现已禁用；保留的 C++ 类仅作为编译兼容和数据注册入口。后续需要把这些界面重写为 RML/RCSS 文档，并通过 RmlUiBridge 消费稳定通道数据。

文档侧数据契约

真 backend 接入 RmlUI 数据绑定后，文档侧按通道名读取快照、以 { target, payload } 发命令，与 RmlUiBridge 对接。通道名字符串、命令 target 命名、command_result 反馈通道均为稳定契约，不随后端实现变化。过渡期的 HTML/JS 参考实现（CoreMod/assets/ui/html/scripts/app.js 的 window.NC）见下节，仅供迁移参考。
