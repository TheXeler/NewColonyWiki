文明注册

文明定义放在 Data/civilizations/ 下，引擎加载时自动扫描。文明决定了初始工人配置、可制造物品、独特配方和加成效果。

JSON 格式

{
  "id": "core:cave_civ",
  "name": "Cave Civilization",
  "leader": "core:stonemason",
  "description": "A resilient civilization led by a master stonemason.",
  "workers": ["core:miner", "core:blacksmith_entity", "core:potter_entity"],
  "craftable_blocks": ["core:stone_pickaxe", "core:iron_pickaxe"],
  "unique_recipes": [
    "core:craft_stone_pickaxe",
    "core:smelt_iron",
    "core:build_anvil"
  ],
  "starting_buildings": ["core:stone_furnace"],
  "traits": ["mining", "stoneworking", "smithing", "resilient"],
  "bonuses": {
    "mine_speed": 1.1,
    "underground_vision": 1.2,
    "smelting_speed": 1.05
  }
}

字段说明

字段类型必填说明
idstring是唯一标识，格式 <mod_id>:<name>。允许字符：小写字母、数字、下划线、短横线、冒号。
namestring是文明显示名称。
leaderstring是领袖实体 ID，指向 Data/entities/ 下已注册的实体。
descriptionstring否文明描述文本。
workersstring[]是初始工人实体 ID 列表。游戏开始时该文明会生成这些实体。
craftable_blocksstring[]否该文明可直接制造的方块 ID 列表（无需配方工作台）。
unique_recipesstring[]是该文明独有的配方 ID 列表，指向 Data/recipes/ 下已注册的配方。
starting_buildingsstring[]否游戏开始时预置的建筑方块 ID 列表。
traitsstring[]否文明特性标签列表，用于脚本中的条件判断和风格标识。
bonusesobject否文明加成效果，键值对映射。键为加成名称（如 mine_speed），值为倍率（float），1.0 为基准值。例如 1.1 表示 10% 加成。

加成效果参考

加成键类型说明
mine_speedfloat挖掘速度倍率。
underground_visionfloat地下视野范围倍率。
smelting_speedfloat熔炼速度倍率。
farm_yieldfloat农作物产量倍率。
wood_gather_speedfloat伐木速度倍率。
cooking_qualityfloat烹饪品质倍率。
文明系统定义了游戏的初始条件和玩法风格。workers + leader 决定了初始人力资源，unique_recipes 决定技术路线，bonuses 提供数值差异化。不同文明的加成可以叠加使用。

ID 规则

  • 文明 ID 只能包含小写字母 a-z、数字 0-9、下划线 _、短横线 -、冒号 :。
  • 推荐格式 <mod_id>:<name>，例如 nomad:desert_tribe。
  • workers、leader、unique_recipes 中引用的 ID 必须是已注册的完整 ID（含 mod 前缀），否则加载报错。

文件放置规则

  • 放在 Data/civilizations/ 下，支持任意深度的子目录。
  • 文件名随意，引擎只关心 JSON 内的 id 字段。
  • 每个 JSON 文件定义一个文明。

验证命令

在控制台（按 ~）中确认文明注册成功：

mods                                  —— 确认 MOD 已加载
list_data civilizations               —— 列出所有已注册文明
data core:cave_civ                     —— 查看单个文明的完整 JSON
