文明注册

文明定义放在 data/civilizations/ 下，引擎加载时自动扫描。文明决定了可用职业、开局选项和配方限制；运行时文明实例还保存已研究科技、当前研究和研究进度。

JSON 格式

{
  "id": "core:cave_civ",
  "name": "Cave Civilization",
  "leader": "core:stonemason",
  "description": "A resilient civilization ...",
  "professions": [
    { "id": "core:miner", "count": 2 },
    { "id": "core:blacksmith", "count": 1 }
  ],
  "recipe_modifiers": [
    {
      "profession": "core:stonemason",
      "unlock": ["core:craft_stone_pickaxe", "core:build_stone_furnace"],
      "extra_recipes": ["core:craft_torch", "core:build_anvil"]
    },
    {
      "profession": "core:blacksmith",
      "deny": ["core:craft_wooden_tools"],
      "blocked_recipes": ["core:build_wooden_wall"]
    }
  ],
  "starting_options": [
    {
      "id": "default",
      "blocks": [
        { "id": "core:stone_chunk", "count": 20 },
        { "id": "core:torch", "count": 5 }
      ],
      "professions": [
        { "id": "core:miner", "level": 1, "count": 2 },
        { "id": "core:stonemason", "level": 2, "count": 1 }
      ]
    }
  ],
  "starting_buildings": ["core:stone_furnace"],
  "traits": ["mining", "stoneworking", "smithing"],
  "bonuses": {
    "mine_speed": 1.1,
    "underground_vision": 1.2
  }
}

字段说明

字段类型必填说明
idstring是唯一标识，格式 <mod_id>:<name>。允许字符：小写字母、数字、下划线、短横线、冒号。
namestring否文明显示名称。
professionsstring[] 或 object[]否该文明可用的职业 ID 列表，指向 data/professions/ 下的职业。对象形式只读取 id；CoreMod 中的 count 会被交叉引用校验允许，但不会存入 CivilizationDef.professions。
starting_optionsobject[]否开局选项。每项包含 id、可选的 name、blocks（初始方块及数量）和 professions（初始殖民者职业、等级和数量）。
recipe_modifiersobject[]否配方规则修改。每项包含 profession（职业 ID）以及 deny、blocked_recipes、unlock、extra_recipes 中的一个或多个，用于微调配方可制造性。
starting_buildingsstring[] 或 object[]否加载器会交叉校验建筑 ID，但 CivilizationSystem 当前不保存这个字段，开局建筑实例生成尚未接入。
leader / description / traits / bonusesmixed否CoreMod 数据中存在，当前 CivilizationSystem 不读取；可作为原始 mod_data 供脚本或未来系统使用。
文明系统定义了游戏的初始条件和玩法风格。professions 决定可选职业，starting_options 决定初始资源和人手，recipe_modifiers 提供配方层面的差异化控制。
当前 C++ 系统会保存文明 ID、名称、职业 ID、配方规则和 starting_options；starting_buildings 只做引用校验，leader、description、traits、bonuses 不进入 CivilizationDef。这些字段不应被当作已闭环的运行时机制。

科技研究状态

CivilizationInstance 保存 researched_techs、current_research 和 research_progress。科技定义本身放在 data/techs/，详见 科技注册。Lua 可通过 engine.research.state(1) 查询第一个文明实例，通过 engine.research.start(id, 1) 开始研究。

ID 规则

  • 文明 ID 只能包含小写字母 a-z、数字 0-9、下划线 _、短横线 -、冒号 :。
  • 推荐格式 <mod_id>:<name>，例如 nomad:desert_tribe。
  • professions、recipe_modifiers 中引用的 ID 必须是已注册的完整 ID（含 mod 前缀），否则加载报错。

文件放置规则

  • 放在 data/civilizations/ 下，支持任意深度的子目录。
  • 文件名随意，引擎只关心 JSON 内的 id 字段。
  • 每个 JSON 文件定义一个文明。

验证命令

在控制台（按物理 Grave/反引号键）中确认文明注册成功：

mods                                  —— 确认 MOD 已加载
list_data civilizations               —— 列出所有已注册文明
data copper_age:copper_clan            —— 查看单个文明的完整 JSON
