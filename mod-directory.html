MOD 目录结构

一个 MOD 的完整目录树及各目录的用途说明。引擎在加载阶段会自动扫描一组受支持的 data/ 类型目录；其他目录由脚本或具体系统按需读取。

完整目录树

mods/my_mod/
  mod.json                 —— MOD 清单：ID、版本、依赖、入口脚本
  README.md                —— 说明文档（可选）
  scripts/
    bootstrap.lua          —— 默认入口脚本（on_load、on_world_init、on_tick、on_shutdown）
    systems/               —— Lua 系统脚本（可选）
    ui/                    —— Lua UI 脚本（可选）
    worldgen/              —— Lua 世界生成脚本（可选）
  data/                    —— JSON 数据
    blocks/                —— 方块定义（name, hardness, drops）
    entities/              —— 实体原型（组件拼装：Position, Health, AIState…）
    recipes/               —— 合成配方（inputs 和 output, 可选职业要求）
    professions/           —— 职业定义（等级 1-5, 转职条件, 解锁配方）
    civilizations/         —— 文明定义（可用职业、开局选项）
    focuses/               —— 焦点事件（条件触发、玩家选择）
    factions/              —— NPC 阵营（关系范围、名称模板）
    name_pools/            —— 名称池（随机命名素材）
    actions/               —— AI 原子动作（mine, chop_wood, eat_food…）
    crops/                 —— 作物生长阶段和产出
    biomes/                —— 生物群系数据或脚本辅助数据（由 Lua/世界生成逻辑读取）
    buildings/             —— 建筑定义（系统目录；当前不在 ModLoader 自动扫描列表中）
    zones/                 —— 区域类型定义（系统目录；当前不在 ModLoader 自动扫描列表中）
    audio/                 —— 声音库 JSON（系统目录；当前核心音频从 core 路径读取）
  assets/                  —— 模型、纹理、着色器、音频（可选）
    audio/                 —— 音乐、环境音、音效文件（可选）
    models/                —— 模型文件（可选）
    shaders/               —— 着色器（可选）
    textures/              —— 纹理（可选）
  config/                  —— MOD 随附配置（可选，core 使用控制台/按键配置）
  lang/                    —— 翻译文件（可选，UTF-8 JSON）
  logs/                    —— 运行时输出或诊断日志（可选，不建议打包发布）

自动注册的数据目录

当前 C++ 加载器会递归扫描并注册下面 14 个目录中的 .json 文件。文件可以放在子目录里，只要位于对应类型根目录下即可。

  • data/blocks/
  • data/entities/
  • data/recipes/
  • data/professions/
  • data/civilizations/
  • data/focuses/
  • data/factions/
  • data/name_pools/
  • data/actions/
  • data/features/
  • data/crops/
  • data/buildings/
  • data/biomes/
  • data/zones/

各目录说明

路径必填用途
mod.json是MOD 清单文件，声明 ID、版本、依赖、入口脚本等。详见 mod.json 清单。
scripts/bootstrap.lua是*默认 Lua 入口脚本，返回一个可选生命周期表：on_load、on_world_init、on_tick、on_shutdown。entry 可在 mod.json 中改成别的路径；按当前加载器实现，最终入口文件必须存在。
data/blocks/否体素方块定义。字段包括 name、hardness、drops。工作台类方块可额外声明关联的配方类型。方块同时也是背包中的物品，没有单独的“物品”类型。
data/entities/否实体原型，用组件拼装来定义实体类型（如殖民者）。可用组件包括 Position、Velocity、Health、Needs、Inventory、Equipment、Profession、AIState、NavAgent、ColonistTag 等。
data/recipes/否合成配方。声明输入材料、产物、可选的职业与等级要求。合成成功触发 recipe:crafted 事件。
data/professions/否职业定义。等级范围 1-5，可声明转职所需方块、前置职业、各等级解锁的配方。分配成功触发 profession:assigned 事件。
data/civilizations/否文明定义。组织可用职业、开局选项（初始方块和殖民者）、配方限制。
data/focuses/否焦点事件。展示给玩家的消息，可附带选择项。条件可以是内置条件（tick_at_least、entity_count_at_least、entity_count_at_most、colonist_need）或 Lua 注册的自定义条件。
data/factions/否NPC 阵营定义。包含关系范围、名称模板（支持 ${random_name} 占位符）和引用的名称池。
data/name_pools/否名称池。给 NPC 阵营随机生成名称提供词汇素材。words 字段为字符串数组。
data/actions/否AI 可执行的原子动作定义（如 mine、chop_wood、eat_food、harvest_crop）。
data/features/否地形装饰阶段生成的地物定义，例如石堆、灌木或遗迹碎片。详见 地物注册。
data/crops/否作物定义，包含农田类型、生长阶段、温度/湿度范围和产出。
data/biomes/否生物群系数据。加载器会注册为 biomes 类型，地形生成器可在世界初始化时读取。
data/buildings/否建筑定义目录。BuildingSystem 会按 buildings 类型读取注册表。
data/zones/否区域类型定义目录。ZoneSystem 会按 zones 类型读取注册表。
data/audio/否声音库 JSON。当前启动流程从 core 数据路径加载默认声音库；普通 MOD 音频扩展仍需要配合脚本或后续加载器支持。
assets/否模型（.obj / .gltf）、纹理（.png）、着色器（.glsl）、音频文件等资源。
config/否MOD 随附配置文件。CoreMod 使用该目录提供控制台权限、别名和按键配置。
lang/否翻译文件目录，使用 UTF-8 JSON。当前仓库统一使用小写 lang/。
logs/否运行时日志或调试导出目录。发布 MOD 时通常不需要包含。

数据文件的通用规则

  • 自动注册的数据 JSON 都必须有唯一的 id。可以写完整 ID（<mod_id>:<name>），也可以写本 MOD 内短 ID；加载器会补成 <mod_id>:<name>。
  • 跨 MOD 引用其他内容时必须写完整 ID，比如 copper_age:copper_ingot。
  • 文件可以放在对应类型目录下的任意位置（包括子目录），只要在正确的类型根目录下即可。例如 data/blocks/materials/copper.json 和 data/blocks/copper.json 都行。
  • 配方、职业、文明、方块掉落和作物会做跨引用校验。引用不存在会导致 MOD 加载失败，引擎会报出具体是哪个文件和哪条记录。
  • 每个自动注册的数据 JSON 可选 reload 布尔字段，用于标记该条目是否参与热重载流程。
  • 能用 JSON 表达的内容优先放在 data/，Lua 只处理数据难以表达的规则、条件和选项行为。
注意：data/audio/ 已出现在 CoreMod 目录中，但按当前 ModLoader::load_mod_data 实现还不会作为通用 MOD 数据自动注册。给普通 MOD 使用音频目录前，应先确认对应系统的加载路径。
