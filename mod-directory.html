MOD 目录结构

一个 MOD 的完整目录树及各目录的用途说明。引擎在加载阶段会自动扫描一组受支持的 data/ 类型目录；其他目录由脚本或具体系统按需读取。

完整目录树

mods/my_mod/
  mod.json                 —— MOD 清单：ID、版本、依赖、入口脚本
  README.md                —— 说明文档（可选）
  scripts/
    bootstrap.lua          —— 默认入口脚本（on_load、on_world_init、on_tick、on_shutdown）
    systems/               —— Lua 系统脚本（可选）
    ui/                    —— Lua UI 脚本（可选）
  data/                    —— JSON 数据
    blocks/                —— 方块定义（name、hardness、output_table、可选 placeable）
    items/                 —— 独立物品定义
    tags/                  —— 分类 tag 接口
    entities/              —— 实体原型（组件拼装：Position, Health, AIState…）
    recipes/               —— 配方（inputs、target_item、output_table 和工作点）
    manufacturing_rules/   —— 全局制造公式、品质阈值和产出树深度
    quality_tables/        —— 品质修正表
    output_tables/         —— 固定制作与世界掉落共用的产出表
	item_bases/            —— 锻造物品基型、属性等级与词条等级
    experiences/           —— 候选人经历内容表
    medicinal_herbs/       —— 药材四性内容表
    potion_trait_effects/  —— 药剂性状区间效果表
    hunting_rules/         —— 狩猎工作量单记录规则
    medicine_slot_rules/   —— 通用个人药剂 CD 槽单记录规则
    colonist_survival_rules/ —— 殖民者生存单记录规则
    career_progression_rules/ —— 职业经验与升级单记录规则
    wild_food_rules/       —— 野生食材刷新规则
    animal_distributions/  —— 动物分布规则
    weather_definitions/   —— 天气定义
    dynamic_weather_regions/ —— 动态天气区域
    visibility_rules/      —— 三态视野单记录规则
    mine_rules/            —— 矿井单记录规则
    difficulty_rules/      —— 难度选项和预设
    jobs/           —— 职业定义（等级 1-5, 转职条件, 工作类型, 解锁配方）
    civilizations/         —— 文明定义（可用职业、开局选项）
    techs/                 —— 科技定义与研究要求
    focuses/               —— 焦点事件（条件触发、玩家选择）
    factions/              —— NPC 阵营（关系范围、名称模板）
    faction_spawn_rules/   —— 新世界阵营生成规则
    diplomacy_proposals/   —— 外交提议与条约效果
    name_pools/            —— 名称池（随机命名素材）
    features/              —— 地形地物
    crops/                 —— 作物生长阶段和产出
    terrain/               —— 默认地形参数
    biomes/                —— 群系定义（ModLoader 自动注册，地形系统读取）
    buildings/             —— 建筑定义（ModLoader 自动注册，建筑系统读取）
    combat/                —— 战斗相关数据（V2 仅保留启动默认值）
    zones/                 —— 区域类型定义（ModLoader 自动注册，区域系统读取）
    audio/                 —— 音频定义 JSON（ModLoader 自动注册）
  assets/                  —— 模型、纹理、着色器、音频（可选）
    audio/                 —— 音乐、环境音、音效文件（可选）
    models/                —— 模型文件（可选）
    shaders/               —— 着色器（可选）
    textures/              —— 纹理（可选）
  config/                  —— MOD 随附配置（可选，core 使用控制台/按键配置）
  lang/                    —— 翻译文件（可选，UTF-8 JSON）
  logs/                    —— 运行时输出或诊断日志（可选，不建议打包发布）

各目录说明

路径必填用途
mod.json是MOD 清单文件，声明 ID、版本、依赖、入口脚本等。详见 mod.json 清单。
scripts/bootstrap.lua是*默认 Lua 入口脚本，返回一个可选生命周期表：on_load、on_world_init、on_tick、on_shutdown。entry 可在 mod.json 中改成别的路径；按当前加载器实现，最终入口文件必须存在。
data/blocks/否体素方块定义。声明物品身份的 block 记录同时生成同 ID 的当前物品定义；显式 item 记录可按稳定 ID 覆盖该定义。
data/items/否独立物品定义。声明名称、图标、说明、主类别、用途标签、堆叠、价格、重量，以及可选腐坏、配方来源和装备元数据。
data/entities/否实体原型，用组件拼装来定义实体类型（如殖民者）。JSON 当前解析 Position、Speed、Health、Needs、Mood、ColonistAttributes、Name、ColonistTag、AIState、Job、Equipment、Visual、Animation 和 HeadVisual；背包物品由统一 ItemSystem 实例表达，NavAgent、BlockInteractor、WorkerPriorityConfig 和 PrototypeRef 由运行时自动附加或维护。
data/recipes/否制造配方。声明输入材料、目标物品、产出表、兼容工作点，以及可选的职业与等级要求。制作成功触发 recipe:crafted 事件。CoreMod 的工作台配方在手工制作点消耗 4 木板且没有职业门槛。
data/manufacturing_rules/否全局制造规则，声明成败/品质线性公式、品质随机范围、六级阈值和产出树最大深度。内容数值可以留空；需要这些规则的配方会进入可见配置屏障。
data/quality_tables/否品质修正表注册数据；品质配方未指定表时引用 core:default。
data/output_tables/否有限树形产出表。组声明选择方式与执行次数，物品项声明数量、权重和是否受制造模式影响。
data/item_bases/否锻造物品基型。基型 ID 同时是目标物品 ID；声明基础数值/难度/材料、基础属性最终等级、词条最终等级、容量、制造模式、品质表和兼容工作点。
data/experiences/否招募候选人的经历、互斥关系、属性/职业/倾向和初始状态修正；允许目录为空且不生成默认经历。
data/medicinal_herbs/否药材内容表。每条记录声明稳定 ID、名称和火/风/水/土四项有限数值；允许目录为空。
data/potion_trait_effects/否性状区间效果内容表。每条记录声明性状、区间、效果 ID、数值、时间和正负标记；允许目录为空。效果 ID 必须注册 Lua 生命周期定义。
data/hunting_rules/否狩猎工作量单记录规则；缺失时狩猎入口保留配置屏障。
data/medicine_slot_rules/否每个人通用的药剂 CD 槽基础容量和科技增量单记录规则，不限于治疗用途。
data/colonist_survival_rules/否需求、状态阶段、恢复和属性倍率的唯一生存规则记录。
data/career_progression_rules/否成功工作基础经验和 1-4 级升级需求的唯一规则记录；缺失时职业经验结算保持配置屏障。
data/wild_food_rules/否按群落和最终温度维护野生食材资源点的规则；允许为空。
data/animal_distributions/否按群落、最终温度和树木统计维护动物上限的规则；允许为空。
data/weather_definitions/否晴、阴、雨、雪、雾的局部光照、温度、视野、战斗环境和表现定义。
data/dynamic_weather_regions/否稳定天气区域、覆盖区块、当前天气和强度接口；不隐含周期、概率或移动公式。
data/visibility_rules/否三态视野更新间隔及单位、建筑、光照倍率的唯一规则记录。
data/mine_rules/否矿井矿物候选、丰度、工作量、产量、耗减和工作点类型的唯一规则记录。
data/difficulty_rules/否七组难度选项、预设引用和数据默认预设。
data/jobs/否职业定义。等级范围 1-5，可声明前置职业、允许接取的工作类型和各等级解锁配方；可转职装备由物品的 supported_jobs 声明。
data/civilizations/否文明定义。组织可用职业、开局选项（初始方块和殖民者）、配方限制。
data/techs/否科技定义：分类、前置、研究成本、开题材料、工作站/职业要求和解锁内容。
data/focuses/否焦点事件。展示给玩家的消息，可附带选择项。条件可以是内置条件（tick_at_least、entity_count_at_least、entity_count_at_most、colonist_need）或 Lua 注册的自定义条件。
data/factions/否NPC 阵营定义。包含关系范围、名称模板（支持 ${random_name} 占位符）和引用的名称池。
data/faction_spawn_rules/否新世界初始 NPC 阵营生成数量规则。
data/diplomacy_proposals/否外交提议、关系计分、条约效果和前置状态。
data/name_pools/否名称池。给 NPC 阵营随机生成名称提供词汇素材。words 字段为字符串数组。
data/features/否地形装饰阶段生成的地物定义，例如石堆、灌木或遗迹碎片。详见 地物注册。
data/crops/否作物定义，包含农田类型、生长阶段、温度范围和产出；当前 CoreMod 农业脚本把阶段 ticks 加总为成熟时间。
data/terrain/否地形默认方块配置。CoreMod 使用 core:default 定义基础方块、水和河床方块。
data/biomes/否群系数据。加载器会注册为 biomes 类型，地形生成器可在世界初始化时读取。
data/buildings/否建筑定义目录。BuildingSystem 会按 buildings 类型读取注册表。
data/combat/否战斗规则预留目录；当前 CoreMod 为空，专项文档建立前不生成默认玩法。
data/zones/否区域类型定义目录。ZoneSystem 会按 zones 类型读取注册表。
data/audio/否音频定义 JSON。与其他自动注册目录一致，它作为 audio 类型进入通用数据注册表；每个文件顶层 id 就是可播放声音 ID。详见 音频注册 与 音乐和音效格式。
assets/否模型（.obj / .gltf）、纹理（.png）、着色器（.glsl）、音频文件等资源。
config/否MOD 随附配置文件。CoreMod 使用该目录提供控制台权限、别名和按键配置。
lang/否翻译文件目录，使用 UTF-8 JSON。文件名即 locale ID，例如 en-us.json、zh-cn.json。详见 本地化与翻译。
logs/否运行时日志或调试导出目录。发布 MOD 时通常不需要包含。

数据文件的通用规则

  • 自动注册的数据 JSON 都必须有唯一的 id。可以写完整 ID（<mod_id>:<name>），也可以写本 MOD 内短 ID；加载器会补成 <mod_id>:<name>。
  • 跨 MOD 引用其他内容时必须写完整 ID，比如 copper_age:copper_ingot。
  • 文件可以放在对应类型目录下的任意位置（包括子目录），只要在正确的类型根目录下即可。例如 data/blocks/materials/copper.json 和 data/blocks/copper.json 都行。
  • 配方、职业、文明、方块掉落和作物会做跨引用校验。引用不存在会导致 MOD 加载失败，引擎会报出具体是哪个文件和哪条记录。
  • 每个自动注册的数据 JSON 可选 reload 布尔字段，用于标记该条目是否参与热重载流程。
  • 能用 JSON 表达的内容优先放在 data/，Lua 只处理数据难以表达的规则、条件和选项行为。
