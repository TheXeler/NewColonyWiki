矿物分布注册

矿物分布（Ore Deposit）放在 data/ores/ 下，用 JSON 描述某种方块在地下生成时如何替换基础方块。它由 ModLoader 自动注册，并在地形生成器的地下阶段读取。

JSON 格式

{
    "id": "my_mod:tin_ore_deposit",
    "block": "my_mod:tin_ore",
    "replace_block": "core:stone",
    "noise_scale": 0.09,
    "threshold": 0.62,
    "min_y": 8,
    "max_y": 48
}

字段说明

字段类型必填说明
idstring是唯一标识，格式 <mod_id>:<name>。用于注册表检查和调试输出。
blockstring是要生成的方块 ID，必须引用已注册的 data/blocks/ 条目。
replace_blockstring是可被替换的原始方块 ID，必须引用已注册方块。常见值是 core:stone。
noise_scalenumber是三维噪声采样尺度，必须大于 0。值越大，矿脉变化越密集；值越小，矿脉块状区域越大。
thresholdnumber是生成阈值。地形生成时对每个候选方块采样噪声，只有 noise > threshold 才替换为 block。阈值越高，矿物越稀少。
min_yint是最低生成高度，必须是非负整数。
max_yint是最高生成高度，必须是非负整数。生成循环会在 WORLD_HEIGHT 处截断。

生成规则

  • 矿物在地下生成阶段运行，早于地表装饰和地物放置。
  • 每个矿物定义会遍历 chunk 内所有 X/Z 列和 min_y 到 max_y 的高度。
  • 只有当前方块等于 replace_block 时才会被替换，因此矿物不会覆盖空气、水、植物或其他矿物，除非你明确把它们设为 replace_block。
  • 多个矿物定义按注册顺序处理。较早生成的矿物会改变方块 ID，后续只会替换它们自己的 replace_block。
threshold 没有硬性限制在 0 到 1。实际噪声函数的输出范围由引擎实现决定；通常推荐从 CoreMod 的 0.5 到 0.85 区间开始调参。

Lua 注册入口

需要运行时添加矿物时，可以通过 Lua 调用 engine.terrain.register_ore(table)。Lua 入口使用运行时 block hash，因此通常仍建议优先使用 JSON 注册。

engine.terrain.register_ore({
    block = engine.data.hash_id("my_mod:tin_ore"),
    replace_block = engine.data.hash_id("core:stone"),
    noise_scale = 0.09,
    threshold = 0.62,
    min_y = 8,
    max_y = 48
})

文件放置规则

  • 放在 data/ores/ 下，支持子目录。
  • 文件名随意，引擎只关心 JSON 内的 id 字段。
  • block 和 replace_block 会在跨引用校验阶段确认存在；引用不存在会导致 MOD 加载失败。

验证命令

在控制台（按物理 Grave/反引号键）中确认矿物分布注册：

list_data ores                  -- 列出所有已注册的矿物分布
data core:diamond_deposit       -- 查看单个矿物分布 JSON
data type:ores                  -- 查看 ores 类型下的注册数据
