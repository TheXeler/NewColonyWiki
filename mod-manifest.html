Wiki/mod.json

mod.json

清单文件告诉游戏：我是谁、从哪启动、依赖谁、默认配置是什么。

推荐模板

下面是一个完整的 mod.json 模板，可以直接复制。不需要的字段删掉就行。当前加载器只有 id 必填，但如果不写 entry，引擎仍会按默认值查找 scripts/bootstrap.lua。

{
  "id": "copper_age",
  "name": "Copper Age",
  "version": "0.1.0",
  "description": "Adds early copper content.",
  "license": "MIT",
  "entry": "scripts/bootstrap.lua",
  "lua": {
    "permissions": {
      "io": false
    }
  },
  "dependencies": [
    {"name": "core", "minVer": "0.1.0", "maxVer": "1.0.0"}
  ],
  "load_after": [],
  "load_before": [],
  "conflicts": [],
  "side": "both",
  "ui": {
    "images": {
      "main_menu_background_001": "assets/ui/background001.png"
    },
    "image_pools": {
      "main_menu_backgrounds": ["main_menu_background_001"]
    },
    "main_menu": {
      "background_pool": "main_menu_backgrounds",
      "selection": "first",
      "background_tint": [0.0, 0.0, 0.0, 0.35]
    }
  },
  "settings": {
    "enable_debug_logs": false,
    "ore_spawn_rate": {
      "value": 1.0,
      "label_key": "ui.copper_age:settings.ore_spawn_rate",
      "description_key": "ui.copper_age:settings.ore_spawn_rate.description"
    }
  }
}

字段说明

字段必填说明
id是MOD 的唯一标识。建议用小写英文、数字和下划线，比如 copper_age。内容数据再用 <mod_id>:<name> 格式，例如 copper_age:copper_ingot。
name否显示名称。不写就用 id 代替。
version否MOD 版本号，建议用语义化版本。不写默认为 0.0.0。
name_key否显示名称的本地化 key；主菜单和 MOD 管理 UI 可用它代替硬编码名称。
description_key否描述文本的本地化 key。
entry否Lua 入口脚本的路径。默认 scripts/bootstrap.lua；当前加载流程会要求入口文件存在，纯数据 MOD 也应提供一个返回空表的入口脚本，或显式把 entry 指向存在的空脚本。
license否MOD 的许可证标识，如 "MIT"、"GPL-3.0" 等。
side否MOD 的运行环境。默认 "both"（主机和客户端都需要）。设为 "client" 或 "server" 的 MOD 不参与网络校验码计算。详见网络同步。
lua.permissions.io否兼容字段。当前沙箱会读取该声明但不会开放 Lua io 库；脚本文件访问应改由受控引擎 API 提供。
dependencies否必须在这个 MOD 之前加载的其他 MOD。数组格式，每项包含 name（MOD ID）、可选的 minVer 和 maxVer（均为包含边界）。示例：[{"name":"core", "minVer":"0.1.0", "maxVer":"1.0.0"}]。
load_after否希望在指定 MOD 之后加载。目标不存在也不会报错。
load_before否希望在指定 MOD 之前加载。"*" 表示尽量比所有其他 MOD 早。
conflicts否和这些 MOD 同时存在时加载失败。
ui否客户端 UI 图片资源声明。支持 images、image_pools 和 main_menu 背景配置。详见 UI 图片资源。
settings否默认配置。支持直接写字符串、数字、布尔值，也支持 {"value": ..., "label_key": "...", "description_key": "..."} 对象格式。保留项 enabled 必须是布尔值。

玩家配置覆盖

加载器会自动确保每个 MOD 都有 enabled 设置。core 永远启用；其他 MOD 首次发现时默认为未启用。主菜单 MOD 管理器会写入同名配置文件中的 enabled 值；启用或禁用后需要重启使加载结果生效。

在 settings 里声明了默认值后，玩家可以用同名文件覆盖。覆盖文件放在 config/ 目录下：

config/copper_age.json

覆盖值必须和默认值类型一致。Lua 中读取配置时给一个 fallback，避免旧配置缺字段时崩溃。

local debug_logs = engine.modding.get_setting("copper_age", "enable_debug_logs", false)
覆盖文件也使用与 settings 相同的解析规则，可以直接写 "ore_spawn_rate": 1.25，也可以写带 value 的对象。未知 key 会被忽略；类型不匹配会导致加载失败。
dependencies 决定能否加载，load_after 只是排序建议。你的数据引用了另一个 MOD 的方块或职业时，应该写 dependencies，不能只靠 load_after。
当前没有“无入口脚本”的纯数据 MOD 路径。即使所有内容都在 JSON 里，也要保留一个存在的入口脚本，例如 scripts/bootstrap.lua 写 return {}。
