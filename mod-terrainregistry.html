地形配置注册

地形配置放在 data/terrain/ 下，用 JSON 提供默认地形方块和部分全局地形参数。它与 群系注册 和 矿物分布注册配合使用：群系决定地表/次地表，矿物决定地下替换，地形配置提供基础方块、水方块和导航流体深度等全局选项。

JSON 格式

{
    "id": "core:default",
    "base_block": "core:stone",
    "water_block": "core:water",
    "max_navigable_fluid_depth": 0,
    "cave": {
        "enabled": true,
        "noise_scale": 0.05,
        "octaves": 3,
        "persistence": 0.5,
        "lacunarity": 2.0,
        "threshold": 0.45,
        "min_y": 5,
        "max_y": 50
    }
}

字段说明

字段类型必填说明
idstring是唯一标识。当前 chunk 地形配置优先查找 core:default；如果没有这个 ID，则使用注册表中的第一个 terrain 条目。
base_blockstring是基础实心方块 ID，必须引用已注册方块。世界生成在没有群系覆盖时使用它作为默认地下方块。
water_blockstring否水体方块 ID，必须引用已注册方块。省略时使用运行时默认水方块。
max_navigable_fluid_depthint否寻路可通过的最大流体深度，必须是非负整数。省略时保留引擎默认值。
caveobject否洞穴生成参数。省略时使用 TerrainConfig 默认值。

洞穴字段

字段类型默认值说明
enabledbooltrue是否启用洞穴生成。群系的 has_caves 也必须允许洞穴。
noise_scalenumber0.05洞穴噪声采样尺度。
octavesint3洞穴噪声 octaves。当前配置会被读入 TerrainConfig，具体使用取决于地形生成实现。
persistencenumber0.5洞穴噪声 persistence。
lacunaritynumber2.0洞穴噪声 lacunarity。
thresholdnumber0.45洞穴生成阈值。阈值越低，洞穴系统越容易出现。
min_yint5洞穴最低高度。
max_yint50洞穴最高高度。

读取顺序

  • 引擎会先建立默认 TerrainConfig，其中海平面来自创建世界或存档中的世界设置。
  • 随后从 data/terrain/ 注册表中选择 core:default；如果没有该 ID，则使用第一个 terrain 条目。
  • 选中的 JSON 覆盖 base_block、water_block、max_navigable_fluid_depth 和 cave 子字段。
  • 群系仍然负责每列的 surface_block、subsurface_block、气候匹配和高度轮廓；terrain 配置不是群系列表。
CoreMod 当前的 data/terrain/default.json 只声明 core:default、base_block 和 water_block。没有写出的字段会使用引擎默认值。

和其他注册表的关系

注册表职责
群系注册决定某个气候位置使用哪种表层方块、次表层方块、植被概率和高度修正。
地物注册在地表装饰阶段放置树木、石堆等地物。
矿物分布注册在地下生成阶段按噪声替换基础方块。
方块注册提供 base_block、water_block、群系方块和矿物方块引用的实体数据。

文件放置规则

  • 放在 data/terrain/ 下，支持子目录。
  • 当前运行时只选用一个 terrain 配置。多个 MOD 同时提供 terrain 条目时，优先匹配 core:default，否则取注册表中第一个条目。
  • base_block 和 water_block 会在跨引用校验阶段确认存在；引用不存在会导致 MOD 加载失败。

验证命令

在控制台（按物理 Grave/反引号键）中确认地形配置注册：

list_data terrain               -- 列出所有已注册的地形配置
data core:default               -- 查看默认地形配置 JSON
data type:terrain               -- 查看 terrain 类型下的注册数据
