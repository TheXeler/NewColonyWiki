职业注册

职业定义放在 data/jobs/ 下，引擎加载时自动扫描。职业决定了殖民者可以解锁哪些配方，以及需要什么工具方块才能从事该职业。

JSON 格式

{
  "id": "core:blacksmith",
  "name": "Blacksmith",
  "description": "Metalworking specialist for smelting, tools, weapons, and armor.",
  "category": "work",
  "parent": "core:stonemason",
  "tier": 3,
  "sort_order": 80,
  "max_level": 6,
  "required_block": { "id": "core:anvil_item", "count": 1 },
  "prerequisites": [],
  "unlocks_recipes": [
    { "id": "core:smelt_iron", "level": 1 },
    { "id": "core:craft_iron_pickaxe", "level": 2 }
  ],
  "allowed_work_tags": ["craft"],
  "bonuses": [
    { "stat": "work_speed", "value": 0.12, "mode": "add_mult" },
    { "stat": "melee_damage", "value": 1.5, "mode": "add" }
  ]
}

字段说明

字段类型必填说明
idstring是唯一标识，格式 <mod_id>:<name>。允许字符：小写字母、数字、下划线、短横线、冒号。
namestring否职业显示名称。
descriptionstring否职业介绍文本，供转职界面展示。
categorystring否职业分类。combat 表示战斗职业；成功转职时会给殖民者建立小队、战斗状态，法师还会建立法力储备。省略时按普通工作职业处理。
parent / tree_parentstring否转职树父节点职业 ID。仅用于 UI/数据展示，不改变当前前置校验逻辑。
tierint否转职树层级，默认 1。
sort_orderint否职业列表和转职树中的稳定排序值。
civilizationstring否限制可分配该职业的文明 ID；实体必须有匹配的 Civilization 组件。
max_levelint否最大等级，范围 1-6，决定配方解锁的等级上限。
required_blockobject是从事该职业所需的工具方块。id 指向已注册的方块 ID，count 为所需数量。
prerequisitesobject[]否前置职业列表。每项包含 id（职业 ID）和 level（所需等级）。空数组表示无条件可转职。
unlocks_recipesarray否该职业解锁的配方列表。每个条目可以是一个配方 ID 字符串，也可以是包含 id（配方 ID）和 level（解锁所需等级）的对象。
allowed_work_tagsstring[]否该职业允许接取的玩家工作类型；旧字段 allowed_work_types / allowed_job_types 会作为迁移别名读取。支持需求文档用语 gather、mine/dig、build/plant、haul、craft/manufacture/cook、research、guard 和 patrol 等值；需求、社交和紧急工作不受此字段限制，省略时不限制旧 MOD。
bonusesobject[]否职业加成。每项包含 stat、value 和 mode（如 add、add_mult、mul、set）。当前会进入人员界面的只读聚合属性（基础 Stats + 当前职业加成）；其中 mining_speed、work_speed、construction_speed、crafting_speed、hauling_speed 已影响对应 work 的完成速度，carry_capacity 已影响搬运拾取掉落物时的一次携带数量，work_success_rate 已影响作物收获的额外产出概率。
职业系统通过 required_block 控制门槛——殖民者背包中必须持有指定数量和类型的方块才能转职。配方按 level 阶梯解锁，等级提升后可获得更高级的制造能力。显式玩家工作完成后会获得职业经验，经验阈值为 100 * 当前等级；心情会把经验效率调整到 50%-150%；达到职业 max_level 后不再累计经验。撤职会回到父职业的等级上限并清空当前经验；没有父职业时回到 core:colonist。

Lua/UI 聚合接口

经营界面可直接读取聚合后的职业数据，不需要逐个解析组件：

API说明
engine.jobs.defs()返回按 sort_order 排序的职业定义，包含 category、介绍、需求物品、前置、解锁配方和加成。
engine.jobs.tree()返回按 tier/sort_order 排序的转职树节点，节点同样包含 category。
engine.jobs.aggregate_stats(entity)返回指定实体基础属性叠加当前职业加成后的扁平属性表，并在 snapshot 字段提供 UI 分组视图。
engine.jobs.resign(entity)撤销当前职业，回到父职业或 core:colonist，等级设为目标职业上限并清空经验。
engine.jobs.add_xp(entity, xp)按职业等级表增加经验并自动升级；返回本次是否升级。
engine.jobs.xp_required_for_level(level)返回某一等级升到下一级所需经验。
engine.colonists.detail(entity)返回人员面板角色菜单字段，包含 id/entity、名称、职业 ID/名称、等级/经验、经历、心情、需求和聚合后的 base_attrs、work_attrs、combat_attrs。
engine.colonists.equipment(entity)返回装备槽、物品栏和页面用的 equipment/page_inventory 摘要。
engine.colonists.career_tree(entity?)人员界面同源转职树入口；传入实体时返回 { current, options }，每个选项包含职业介绍、加成、需求和 unlocked/reason。
bonuses 已分阶段接入模拟。工作时长接入包括：挖矿使用 mining_speed，建造使用 construction_speed 或回退到 work_speed，制作使用 crafting_speed 或回退到 work_speed，搬运 work 的移动型进度使用 hauling_speed 或回退到 carry_move_speed。搬运容量接入包括：carry_capacity 影响从方块掉落表拾取物品时的一次携带数量；无该 bonus 时默认仍为 1。成功率接入包括：work_success_rate 在 systems.farming 的成熟作物收获中按"聚合成功率 / 基础成功率"计算职业成功倍率，超过 1 的部分 clamp 到 0-100% 作为每种产出额外 +1 的概率；无职业 bonus 时倍率为 1，不改变原产量。max_hp、伤害、闪避等战斗字段仍只保证 UI 聚合展示，尚未进入战斗公式。

战斗职业接入

当 engine.jobs.assign 成功分配 category:"combat" 职业时，引擎会给该殖民者附加 Squad 和 CombatState。小队以该殖民者为队长，士兵用 member_count 表示，不创建额外实体。V2 不再为 core:mage 附加 ManaReserve。

当前战斗循环按 2026-07-20 V2 需求运行：只处理近战方阵接触、队长命中、士兵固定伤害和隐藏攻击冷却，不处理远程、法术、夹击压制和区域法力。

ID 规则

  • 职业 ID 只能包含小写字母 a-z、数字 0-9、下划线 _、短横线 -、冒号 :。
  • 推荐格式 <mod_id>:<name>，例如 copper_age:coppersmith。
  • 如果省略冒号前缀，引擎自动补全为 <当前mod_id>:<名称>。

文件放置规则

  • 放在 data/jobs/ 下，支持任意深度的子目录。
  • 文件名随意，引擎只关心 JSON 内的 id 字段。
  • 每个 JSON 文件定义一个职业。

前置职业示例

当前 CoreMod 所有职业的 prerequisites 均为空数组（无条件可转职）。如果需要前置职业链，可以这样写：

{
  "id": "copper_age:coppersmith",
  "prerequisites": [{"id": "core:worker", "level": 1}],
  ...
}

加载器会校验前置职业 ID 存在，但不会做拓扑排序或循环依赖检测。运行时实体只有一个当前 Job 组件；多个 prerequisites 按“满足任意一项”处理，而不是必须全部满足。

验证命令

在控制台（按物理 Grave/反引号键）中确认职业注册成功：

mods                                  —— 确认 MOD 已加载
list_data jobs                  —— 列出所有已注册职业
data core:blacksmith                   —— 查看单个职业的完整 JSON
