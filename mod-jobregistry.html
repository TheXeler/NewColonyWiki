职业注册

data/jobs/ 中的每个 JSON 表示职业树的一个节点。运行时身份为“节点数据 ID + 稳定职业 ID + RANK + 节点内 LEVEL”。

JSON 格式

{
  "id": "core:carpenter_3",
  "career_id": "carpenter",
  "rank": 3,
  "name": "学徒木匠",
  "parent": "core:crafter_2",
  "max_level": 5,
  "prerequisites": [
    { "id": "core:crafter_2", "level": 5 }
  ],
  "unlocks_recipes": [],
  "allowed_work_tags": ["craft"],
  "level_abilities": [
    { "id": "core:carpenter_3_level_1", "source_text": "配方解锁 I：解锁基础制作配方。" },
    { "id": "core:carpenter_3_level_2", "source_text": "制作速度 I：提升制作速度。" },
    { "id": "core:carpenter_3_level_3", "source_text": "配方解锁 II：解锁进阶制作配方。" },
    { "id": "core:carpenter_3_level_4", "source_text": "工作精度 I：提升工作精度。" },
    { "id": "core:carpenter_3_level_5", "source_text": "配方解锁 III：解锁分支职业相关配方。" }
  ]
}

字段

字段要求说明
id必填数据 ID职业树节点的唯一工程身份，例如 core:worker_2。
career_id必填文档稳定职业 ID，仅允许小写字母、数字和下划线，例如 worker。
rank必填，1-5职业树 RANK。相同 career_id + rank 不可重复。
max_level普通节点为 1-5节点内 LEVEL 上限。初始 colonist 节点固定为 0。
parent可选节点 ID职业树父节点，也是当前职业能力和职业 tag 的继承链。
prerequisites数组转职必须全部满足的前置节点和 LEVEL；交叉职业据此保留两条前置链。
allowed_work_tags数组当前节点可执行的工作大类。需求、基础急救等文档基础行为另行处理。
level_abilities普通节点恰好 5 项依次对应 1-5 级能力。每项必须有稳定 id 和文档原文 source_text；只有文档明确给数值时才写 modifiers。

职业资格表达式

工作实例保存由职业 tag、AND、OR 和括号组成的表达式。tag 格式为 #职业ID_RANK_LEVEL，例如 #worker_2_5。

  • tag 是最低门槛；同职业线中更高 RANK 或同 RANK 更高 LEVEL 可以满足。
  • 只读取当前装备对应节点及其父节点/前置链；已解锁但不在当前链中的履历不参与。
  • 交叉节点读取其全部前置链，不套用额外的固定组内或组间规则。
  • 旧 required_job_id + required_job_level 只在读档时转换成表达式，新工作不再写入它们。
(#militia_2_5 AND #apothecary_2_5) OR #combat_medic_3_1

能力与履历

当前节点只应用已达到 LEVEL 的能力；父节点和交叉前置节点按满级继承。切换职业后，普通能力不生效；只有数据中明确标为 permanent 或 cross_career 的能力可从独立履历继续生效。CoreMod 当前能力文本直接来自 NCDOCS，未定义数值的“提升”不会被引擎猜成倍率。

Lua/UI 接口

API说明
engine.jobs.defs()返回节点 ID、career_id、rank、前置、工作 tag 和五级能力。
engine.jobs.tree()按 RANK、排序值和节点 ID 返回职业树。
engine.jobs.can_transition_reason(entity, node_id)检查当前实体是否满足节点前置；实际转职还需具体装备实例支持该节点。
engine.jobs.progression_configuration()返回职业经验配置屏障；内容表为空时不会生成经验默认值。
engine.work.set_qualification_expression(work_id, expression)给工作保存权威资格表达式。

CoreMod 当前状态

CoreMod 注册文档规定的 66 个职业节点。职业装备内容尚未声明时，转职入口保留并显示装备配置缺口，不把旧工具方块猜作许可装备。战斗职业只保留职业、属性和装备接口；战斗专项规则仍未定义。
