HTML/CSS 页面

CoreMod 侧用 HTML/CSS/JS 编写的游戏主界面与二级菜单页面资源, 对应 System.docx 的经营界面设计。这是参考资产: UI 主路线已从旧即时模式 UI/外部浏览器转向游戏内 RmlUI, 本目录的 HTML/CSS/JS 仅作为迁移到 RML/RCSS 文档的参考, 不再作为游戏内 UI 验收路径。

这些页面是"实际游戏内 HUD", 不是宣传页。页面只依赖 window.NC.{snapshot,onSnapshot,sendCommand} 与引擎交互, 不直接碰 window.ncNative。宿主层 (RmlUiHost/RmlUiRuntime/RmlUiBridge) 与桥契约参考实现见 UI 框架 · 游戏内 RmlUI 宿主层。

独立预览

不依赖引擎, 直接用浏览器打开即可看到带 mock 数据的 HUD。原理: ncNative 缺失时 mock_data.js 接管 NC.snapshot/onSnapshot/sendCommand, 各快照通道返回内置 mock 数据, 命令在本地模拟处理。数据流与真后端完全一致 (页面只依赖 NC.*)。

  • CoreMod/assets/ui/html/index.html —— 完整主界面 (顶部出现"预览模式"横幅)
  • CoreMod/assets/ui/html/screens/*.html —— 单个面板聚焦预览

用普通 <script> 标签按序加载 (而非 ES module), 这样 file:// 双击不会被浏览器 CORS 策略拦截。

命令结果反馈 (command_result)

引擎把每条命令的返回 JSON 写入事件式快照通道 command_result, 形如 {ok, target, reason?, status?, changed_channels?} (仅写入出现的字段)。它不在 5 Hz 全量刷新列表内, 只在命令执行后由 Engine::dispatch_rml_ui_command() 更新; 通道是 latest-覆盖语义, 轮询会重复返回同一份。页面层在 scripts/hud.js 的 NC.CommandFeedback.init() 集中订阅 (HUD 启动时挂载), 不在各面板各自处理, 统一弹出轻量 toast:

  • 成功 (ok=true 且无等待状态) → 绿色 success toast, 文案取 core:cmd_result.success, 可带面板名前缀 (target → core:cmd.*)。
  • 等待 (status 为 waiting_materials / waiting / pending / queued / in_progress / researching 等) → 黄色 warning toast, 渲染成"等待 / 提示", 不当成失败; 缺料下单即走这条路径。
  • 阻止 (ok=false 且 status 为 blocked / locked / disabled / unavailable) → 黄色 warning toast (暂不可用, 非硬错误)。
  • 失败 (ok=false 且非阻止类) → 红色 error toast, 显示 reason 翻译; 稳定 reason 码 (invalid_payload / unknown_command / research_unavailable / event_not_found / invalid_view_mode / build_definition_not_found / placement_required / craft_recipe_not_found) 有 core:reason.* 本地化, 未知码原样显示不丢信息。
  • ok 字段缺失 → 防御式按未知处理, 蓝色 info toast, 不报错。

为避免噪音与重复:

  • 纯导航类命令 (core:bottombar.*) 与本地选中 (core:colonists.select) 的成功结果不弹 toast (已由 openPanel / 面板本地处理); 其失败仍会弹。
  • 消费者按 (severity, target, status, reason) 去重, 同一结果在轮询里只弹一次 — command_result 是 latest-覆盖语义, 真后端下 10 Hz 轮询会重复返回同一份 JSON。
  • 各面板原先在 sendCommand 后立即弹的"乐观"成功 toast 已移除, 统一改由 command_result 反馈; 仅保留下单前的本地守卫 toast (如建造行 can_order=false 时的"暂不可用"提示, 这类不触发命令, 故无 command_result)。

changed_channels 由 C++ 侧驱动局部刷新, 页面消费者只用于 toast, 不直接处理它; 各通道的订阅回调会照常重渲染。core:reason.* / core:status.* / core:cmd_result.* 翻译键在 scripts/i18n.js 内置字典。无 window.ncNative 时, mock_data.js 在每条命令后写入 command_result (含 waiting_materials 缺料示例), 预览模式同样能看到反馈 toast。

数据契约要点

  • 固定枚举项 (资源种类 / 指令种类 / 视图模式 / 科技树分类) 带 label_key, 页面用 NC.i18n.t(label_key) 翻译。
  • 自由文本 (殖民者姓名 / 科技节点名 / 事件标题) 直接给字符串, 由数据源本地化。
  • colonist_list 快照含完整字段 (摘要 + base_attrs / work_attrs / combat_attrs / equipment / inventory / class_tree), 列表与详情共用同一通道, 选中是页面侧状态。
  • build_defs 每条带 cost 数组 ({id,label_key,amount}), 可选 missing 数组表示当前缺料。缺料时页面仍允许下单 (core:build.begin), 仅标注"等待材料", 由后端排队等材料到位再施工。
  • construction_active 是独立快照通道, 每条为 {instance_id,def_id,status,position,materials,missing,reserved_materials}；建造面板订阅该通道显示已下单施工。
  • craft_recipes 的 inputs 是结构化数组, output 是单对象 ({id,label_key,amount}); core:craft.queue 的 count 省略时默认 1。

字段与结构兼容 (防御式)

页面层对各通道做防御式归一化, 后端字段名或结构有差异时不报错, 内部统一为面板所需模型。统一工具 NC.num(v,def) (number/string 兼容) 与 NC.asArray(x) (拆 rows/items/list 包装) 在 scripts/hud.js 提供。

通道兼容的输入归一化策略
event_list选项 options / choices / actions / responses; 项 label / text / name / title; 正文 detail / body / description; 时间 day / tick统一映射为 options:[{id,label}]; 命令仍发 core:events.act {id, optionId}
colonist_list数组, 或 {rows} 包装; 数值字段 number/string拆包装取数组; 数值用 NC.num 转 number (排序/比例不产生 NaN)
tech_tree树数组, 或 {categories} / {trees}; 节点 nodes / items / techs; 状态 completed=已研究 / researching=研究中 / available / locked (也兼容旧 researched / in_progress)统一为分类列表; 状态别名映射后显示与判断
resource_snapshot数组, 或 {rows}, 或 {totals:{id:N}} / {stockpile:{id:N}} map, 或单资源; 数量 amount / quantity / qty / count展开为 [{id,label_key,amount,capacity}]
build_defs材料 cost / materials / ingredients / inputs; 缺料 missing / missing_materials / unavailable; can_order (bool) / status (blocked/locked/disabled)缺料仅标注不禁用; 仅 can_order===false 或 status=blocked/locked 才禁用下单
craft_recipes输入 inputs / reagents / ingredients; 产出 output / result / outputs / yields归一化为 inputs 数组 + output 单对象
view_modes{current,modes} 或 modes 数组, 或 {options,active/selected}统一为 {current,modes}
orders_kinds / combat_state数组或 {rows}; combat 的 colonists/threats 也兼容 friendly/enemies拆包装; 数值兼容 number/string
空数组 / 空对象 / 缺字段均显示对应空态 (各面板的 nc-empty), 不抛异常。mock 数据 (mock_data.js) 刻意混用这些别名以覆盖兼容场景。

本地化

页面文案的 key 沿用 CoreMod/lang/{zh-cn,en-us}.json 的 ui 段约定 (core:<panel>.<field>), 例如 core:cmd.build、core:research.tree_production。新增 key 前缀: core:cmd.* / core:hud.* / core:resource(_bar).* / core:orders.* / core:colonists.* / core:research.* / core:view.* / core:events.* / core:attr.* / core:season.* / core:combat.* / core:common.*。预览用 scripts/i18n.js 内置字典, 真后端下经 world_info.locale 切换。详见 本地化与翻译。
