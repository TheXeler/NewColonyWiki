Wiki/配方注册

配方数据

固定制作配方位于 data/recipes/*.json。配方只声明材料、目标物品、工时和兼容工作点，实际结果与数量由产出表决定。

格式

{
  "id": "core:craft_wood_plank",
  "inputs": [
    { "id": "core:wood", "count": 1 }
  ],
  "target_item": "core:wood_plank",
  "manufacturing_mode": "none",
  "work_amount": 5,
  "processing_difficulty": 0,
  "output_table": "core:wood_plank_output",
  "output_table_executions": 1,
  "compatible_work_points": ["core:handcraft", "core:workbench"]
}

字段

字段类型必填说明
idstring是稳定配方 ID。缺失时文件解析失败，配方表加载中止。
inputsobject[]是材料清单。缺失或不是数组时加载失败；条目规则见下节。
target_itemstring是目标物品数据 ID，用于展示与维持库存统计，不决定产出数量。缺失或不是合法数据 ID 时加载失败。
compatible_work_pointsstring[]是非空的工作点类型数据 ID 数组。缺失、不是数组或为空时加载失败。
manufacturing_modestring否只能是 none、failure 或 quality；其他取值解析失败。可写作 mode，默认 none。
work_amountinteger否基础工时，单位为 1 倍速现实秒（1 现实秒对应 1 游戏分钟）。必须是 0 到 2^32-1 的整数，否则加载失败。省略或为 0 时，工作在完成激活、材料预留和到达条件后立即结算；正数工时仍受工人制作速度乘数影响。
processing_difficultynumber否基础加工难度。默认 0。
output_tablestring实际是产出表数据 ID。结果与数量只由产出表决定。留空时配方保留但标记 output_table_missing；引用不存在的产出表时标记 output_table_not_found。
output_table_executionsinteger实际是本次完成执行产出表的次数，必须为正数。缺失或为 0 时标记 output_table_executions_invalid。执行次数不与材料消耗自动换算。
quality_tablestring条件必填仅当 manufacturing_mode 为 quality 时必填。缺失时标记 quality_table_missing，引用不存在时标记 quality_table_not_found。
jobobject否制作资格。job.id 为职业数据 ID（必填且合法），job.level 为 1-5，默认 1。未写 job 时，资格改由职业定义的 unlocks_recipes 推导。
output 是禁止字段：产出只能由 output_table 定义，出现它会让文件加载失败。配方同样不能声明产出数量。

输入条目（inputs[]）

每个条目必须同时满足下列规则，否则加载失败：

字段类型说明
idstring物品类数据 ID，必须合法。与 tag 二选一。
tagstringTag 名称，必须非空。与 id 二选一。
countinteger消耗数量，必须是正整数。

id 与 tag 必须恰好出现一个：同时出现（语义歧义）或都不出现都会被拒绝。

校验与配置屏障

字段类型、取值和结构性错误会让整个文件加载失败；语义缺失则保留配方并写入稳定原因，使入口进入配置屏障而不是静默回退默认值。

情况结果
id、inputs、target_item 或 compatible_work_points 缺失/类型错误加载失败，文件被拒绝。
work_amount 越界；manufacturing_mode 取值非法；job.id 非法或 job.level 不在 1-5；出现 output加载失败，文件被拒绝。
output_table 为空配方保留，configuration_error = output_table_missing。
output_table 不在 output_tables 注册表配方保留，output_table_not_found，原因携带产出表 ID。
output_table_executions 缺失或为 0配方保留，output_table_executions_invalid。
模式为 quality 但 quality_table 为空或不存在配方保留，quality_table_missing 或 quality_table_not_found。
产出表结构错误、存在循环或超过深度上限配方保留，写入产出表的稳定 error_id 并携带来源路径。
全局制造规则缺失或多记录配方保留，写入制造规则的稳定 error_id；空内容表不会获得代码默认值。

CoreMod 当前内容

CoreMod 当前提供 4 条固定配方，全部使用 manufacturing_mode: "none"、processing_difficulty: 0 和 output_table_executions: 1。

配方 ID材料目标物品工时兼容工作点产出表（结果）
core:craft_wood_plank1 x core:woodcore:wood_plank5core:handcraft、core:workbenchcore:wood_plank_output（4 木板）
core:craft_stick2 x core:wood_plankcore:stick5core:workbenchcore:stick_output（4 木棍）
core:craft_wood_floor2 x core:wood_plankcore:wood_floor5core:workbenchcore:wood_floor_output（2 木地板）
core:craft_workbench4 x core:wood_plankcore:workbench_item15core:handcraftcore:workbench_output（1 工作台）

对应的 14 条产出表位于 data/output_tables/，全局制造规则位于 data/manufacturing_rules/。CoreMod 未提供 quality_tables 内容，因此当前没有可用品质表；使用 quality 模式的第三方配方必须自带品质表。

边界

  • 配方不能声明产出数量或 output；实际结果和数量只由有限无环产出表决定。
  • 激活时预留材料与工作点；完成时原子提交材料并把结果写入输出暂存，清空前工作点不接新单。
  • 取消或中断会释放预留并安排输入材料返还。
  • core:handcraft 是无需实体建筑工作点的徒手制作路径，因此第一张工作台不依赖既有工作台或制作点。
  • 制作由 CoreMod systems.production 创建生产订单，再由 systems.crafting.queue 发布工作；不存在直接制作入口。
  • 制作完成触发 recipe:crafted 事件。
  • 旧 core:wood_saw 及其固定 core:workbench 引用已经删除。
  • 锻造不使用固定配方产出表，按物品基型和设计方案契约执行。
