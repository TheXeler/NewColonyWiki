配方注册

配方（Recipe）定义在 data/recipes/ 下，以 JSON 描述。每份配方定义了输入材料、产出物品和可选的职业/等级要求。殖民者通过工作系统使用配方将原材料加工为成品；CoreMod 制作菜单会优先从 stockpile 账本预留材料并在工作完成后回写产物。

JSON 格式

基本配方（无职业要求）：

{
    "id": "my_mod:grind_flour",
    "inputs": [
        { "id": "my_mod:wheat", "count": 2 }
    ],
    "output": { "id": "my_mod:flour", "count": 1 }
}

带职业要求的配方：

{
    "id": "my_mod:forge_steel_sword",
    "inputs": [
        { "id": "my_mod:steel_ingot", "count": 3 },
        { "id": "my_mod:stick", "count": 1 }
    ],
    "output": { "id": "my_mod:steel_sword", "count": 1 },
    "Job": { "id": "my_mod:blacksmith", "level": 3 }
}

字段说明

字段类型必填说明
idstring是唯一标识，格式 <mod_id>:<name>。
inputsarray是输入材料列表。至少 1 项。每个材料包含 id 或 tag（二选一）和 count。
inputs[].idstring否材料方块的完整 ID。必须指向已注册的方块。与 tag 互斥：必须二选一。
inputs[].tagstring否材料 tag（矿物词典）。匹配所有声明了该 tag 的方块（参见 Tag 注册）。与 id 互斥。
inputs[].countint是材料数量，必须 ≥ 1。
outputobject是产出物品。包含 id 和 count。
output.idstring是产出方块的完整 ID。必须指向已注册的方块。
output.countint是产出数量，必须 ≥ 1。
Jobobject否职业限制。只有指定职业且达到指定等级的殖民者才能执行此配方。省略时任何殖民者都可执行。
Job.idstring是职业的完整 ID。必须指向已注册的职业。
Job.levelint否要求的职业等级，范围 1~5。省略时不检查等级。
配方中的所有 ID（材料、产出、职业）在加载时会进行交叉引用校验。引用不存在的方块或职业会导致加载报错并跳过该配方。
RecipeSystem::craft 的直接 C++/Lua 制作路径当前只读取实体的单个 HeldItem 槽。多输入配方只有在每个输入都是同一种方块、且手持数量足够时才可能通过；输入为不同方块时会失败。CoreMod 制作菜单另有 stockpile 账本预留与产出回写流程；预留路径发布的 Craft 工作使用 data=0，避免 C++ 直接制作和 Lua 预留制作重复消耗或重复产出。

配方分类

CoreMod 中配方按用途大致分为以下几类：

分类示例说明
冶炼core:smelt_iron矿石锭转换，需要熔炉工作站。
工具制造core:craft_wooden_pickaxe镐、斧、剑、锄等工具。
防具锻造core:copper_chestplate头盔、胸甲、护腿、靴子。
建筑方块core:stone_brick石砖、木地板、茅草屋顶等建材。
家具core:wooden_table桌、椅、床、箱子、门等。
烹饪core:bake_bread面包、炖汤、烤肉等食物。
饮品酿造core:beer啤酒、草药茶、果汁等。
种植core:wheat_seed_to_farmland种子 + 泥土 → 农田。
工作站core:workbench工作台、熔炉、铁砧、织布机等设施。

内置配方示例

面包 core:bake_bread

最基础的烹饪配方，3 个小麦合成 1 个面包。

{ "inputs": [{ "id": "core:wheat", "count": 3 }], "output": { "id": "core:bread", "count": 1 } }

木镐 core:craft_wooden_pickaxe

多材料输入示例：3 木板 + 2 木棍。

{
    "inputs": [
        { "id": "core:wood_plank", "count": 3 },
        { "id": "core:stick", "count": 2 }
    ],
    "output": { "id": "core:wooden_pickaxe", "count": 1 }
}

小麦种植 core:wheat_seed_to_farmland

1 麦种 + 1 泥土 → 1 农田方块。

{
    "inputs": [
        { "id": "core:wheat_seed", "count": 1 },
        { "id": "core:dirt_pile", "count": 1 }
    ],
    "output": { "id": "core:farmland", "count": 1 }
}

使用 tag 输入 core:compress_ingot

材料写成 tag 替代 id，匹配所有声明该 tag 的方块。这里 2 个任意金属锭 → 1 个铁锭：

{
    "inputs": [
        { "tag": "c:ingots", "count": 2 }
    ],
    "output": { "id": "core:iron_ingot", "count": 1 }
}

tag 必须在 data/tags/*.json 或 block JSON 的 tags 字段中声明过；具体写法见 Tag 注册。

交叉引用校验

引擎在加载配方时会校验：

  • inputs[].id 必须指向已注册的方块；inputs[].tag 必须非空字符串（tag 字典在 RecipeSystem 初始化时构建，不在此处校验存在性）。
  • inputs[] 必须明确写 id 或 tag 中的一项，两者都缺或都写都会报错。
  • output.id 必须指向已注册的方块。output 不允许使用 tag。
  • Job.id（如果填写）必须指向已注册的职业。
  • Job.level（如果填写）必须在 1~5 范围内。
  • 引用不存在的 ID 会导致加载报错。

验证命令

在控制台（按物理 Grave/反引号键）中确认配方注册：

list_data recipes                       -- 列出所有已注册的配方
list_data recipes mod=core:             -- 列出 core 前缀的配方
data core:bake_bread                    -- 查看单个配方的完整 JSON
list_recipes prefix=core:               -- 列出指定前缀的配方（含输入输出摘要）
