建筑蓝图注册

建筑是 MOD 数据，放在 data/buildings/ 下，由 ModLoader 自动注册并交给 BuildingSystem 初始化。建造菜单列出建筑蓝图，施工完成后按蓝图把方块放入世界。

基础结构

{
  "id": "my_mod:watch_hut",
  "name": "Watch Hut",
  "name_key": "buildings.my_mod:watch_hut",
  "size": [5, 5, 5],
  "materials": [
    { "item_id": "core:wood_plank", "count": 72 },
    { "item_id": "core:wooden_door", "count": 1 }
  ],
  "construction_ticks": 240,
  "blueprint": [
    { "from": [0, 0, 0], "to": [4, 0, 4], "block": "core:wood_floor" },
    { "from": [0, 1, 0], "to": [4, 3, 0], "block": "core:wood" },
    { "pos": [2, 1, 0], "block": "core:wooden_door" }
  ]
}

字段

字段说明
id建筑 ID。省略命名空间时会解析到当前 MOD。
name_key本地化 key，例如 buildings.my_mod:watch_hut。UI 可优先用它查翻译；没有翻译时回退到 name。
name建造菜单显示名称；没有本地化文本时使用。
size必填。蓝图包围盒，格式为 [x, y, z]，每项必须为正整数。
materials必填数组。施工开始前需要从库存取出的材料列表，item_id 必须是有效数据 ID，count 必须为正整数。
construction_ticks必填正整数。施工耗时，20 tick 约等于 1 秒。
blueprint可选的方块放置列表。没有蓝图的建筑仍可作为逻辑建筑存在。
design可选的高层建筑设计数据。由建筑设计器保存，用于未来重新编辑；当前 BuildingSystem 仍只消费 blueprint，会忽略该字段。

蓝图单元

blueprint 中每个元素都需要 block。可以用 pos 放置单个方块，也可以用 from/to 描述闭区间长方体。

{ "pos": [2, 1, 0], "block": "core:wooden_door" }
{ "from": [0, 0, 0], "to": [4, 0, 4], "block": "core:wood_floor" }

所有坐标都是相对于建筑原点的偏移，必须落在 size 范围内。from 的每个坐标必须小于或等于 to。block 必须引用已注册的 data/blocks/ 条目。

内置示例

CoreMod/data/buildings/matchbox_hut.json 提供了一个木头火柴盒小屋示例，展示地板、墙体、屋顶和门的组合写法。

运行时蓝图

Lua 可以通过 engine.buildings.register_runtime_definition(table) 注册运行时建筑定义。运行时定义会进入当前 BuildingSystem，因此可以被 engine.buildings.find_definition 查询，也可以交给 systems.construction 下达施工订单。

systems.construction.preview_materials(def_id) 会按当前 stockpile 账本返回材料可用性；systems.construction.order(def_id, x, y, z) 在定义和位置合法时创建建筑订单。材料足够时立即预留并推进施工，返回 { ok=true, status="constructing", info=..., reserved_materials=... }；材料不足时仍创建订单并返回 { ok=true, status="waiting_materials", materials=..., missing=... }，之后由施工系统在 stockpile:changed 或 60 tick 兜底检查时自动尝试预留并继续。

HTML 数据桥的 build_defs 快照直接返回建造面板可消费的数组行：{ id, label, label_key, category, size, cost, materials, missing, available, can_order, status }，其中 status 为 available、missing_materials 或 locked。已下单建筑由 construction_active 快照返回：{ instance_id, def_id, status, position, materials, missing, reserved_materials }，status 可为 ordered、waiting_materials、reserved、constructing 或 complete。

core:build.begin { id } 不带坐标时只启动现有 placement 流程，返回 status="placement_started"；只有传入 x/y/z 时才调用 systems.construction.order(id, x, y, z)。

engine.buildings.register_runtime_definition({
  id = "core:runtime_design_1",
  name = "Custom Hut",
  size_x = 5,
  size_y = 5,
  size_z = 5,
  materials = {
    { item_id = "core:wood_plank", count = 64 }
  },
  blueprint = {
    { x = 0, y = 0, z = 0, block_id = "core:wood_floor" }
  },
  construction_ticks = 120
})

运行时蓝图默认只存在于当前 BuildingSystem。逐方块蓝图编辑器保存时会额外把 JSON 写入 generate/core/data/buildings/player_blueprints/，便于玩家或 MOD 作者复制到正式 MOD 数据目录长期保留。保存文件保留顶层 blueprint、materials、size，并额外写入顶层 design；材料统计始终来自最终 blueprint 方块列表。

蓝图编辑器（3D 画布）

除了参数化生成器（building_editor.lua），核心 MOD 还提供一个逐方块绘制的蓝图编辑器（blueprint_editor.lua + C++ BlueprintEditor 类）。玩家在世界中打开一个 3D 幽灵画布，用鼠标逐格绘制蓝图，再把画布内容保存为可施工的建筑定义，并导出一份 JSON 到生成目录。

两个编辑器是并行功能：参数化编辑器走 core:runtime_design_* 前缀，画布编辑器走 core:canvas_design_* 前缀，都注册到同一个 BuildingSystem，所以两者保存的蓝图都可以被建造系统识别。

核心交互

  • 左键：在鼠标 hover 位置应用当前工具（笔刷/矩形/填充/擦除/选区）
  • Esc：干净画布会直接关闭；存在未保存修改时只取消拖拽，不丢弃内容
  • 快捷键：B/R/F/E/S 切换笔刷/矩形/填充/擦除/选区；[/] 切换层；Ctrl+Z/Ctrl+Y 撤销/重做；Ctrl+C/Ctrl+V 复制/粘贴
  • 笔刷和擦除是单击即生效；矩形和选区是按下-拖拽-松开
  • 矩形、填充和选区都作用于当前 Y 层，当前层由 UI 的 Layer +/- 按钮或快捷键切换
  • 清空和关闭未保存画布需要二次确认；保存页可输入蓝图名称

Lua API

所有 API 都在 engine.blueprint_editor 表下：

方法说明
open(x,y,z, sx,sy,sz)在 (x,y,z) 打开尺寸为 sx*sy*sz 的画布。最大 16x16x16。
close()关闭画布并丢弃所有未保存内容。
is_active() / is_dirty() / mark_clean()查询画布状态、未保存修改状态，并在保存后标记为干净。
set_tool(name)切换工具。name ∈ pen/rect/fill/erase/select/room/floor_plan/door/window/roof。
set_block(block_id)设置当前笔刷/矩形/填充使用的方块。字符串方块 ID。
set_layer(y) / get_layer()当前编辑的 Y 层。
undo() / redo() / can_undo() / can_redo()撤销/重做。撤销栈最多保留 100 项。
rotate()顺时针旋转整个画布 90°。size_x ↔ size_z 互换。
mirror_x() / mirror_z()沿 X 或 Z 轴镜像。
clear()清空所有方块。
copy() / paste(x,y,z) / paste_hover() / has_clipboard()复制选区到剪贴板，在指定位置或当前 hover 格粘贴。
clear_selection() / has_selection()管理当前选区。
load_from_file(path) / load_definition(id)从导出的建筑 JSON 路径或已注册建筑定义 ID 加载设计。优先恢复 design.rooms/default_materials/roofs/openings 并重新编译；旧文件没有 design 时导入顶层 blueprint 方块。
save(name)把画布内容打包成 BuildingDef，注册到 BuildingSystem，并尝试写入 generate/core/data/buildings/player_blueprints/。成功时返回包含 id、path、persisted 的表；空画布或注册失败返回 nil。

"Save & Build" 按钮在 Lua UI 层组合实现：先调 save，再 require("systems.construction").order(def_id, x, y, z)。建造流程复用参数化编辑器已建立的路径。

保存的 design 数据

建筑设计器保存的 JSON 会包含 design.version = 1、origin、default_materials、rooms、roofs、openings 和 patches。rooms 记录房间 id、二维 origin、size、floor_y、wall_height 以及可用的 floor/wall/roof 材料；roofs 支持 none、flat 和简单可见的 gable。Door/Window 工具会在墙体上写入 openings，编译时先扣墙洞，再按对应材料放置门/窗方块；如果材料为空则只保留洞口。高级体素编辑不会被强制转换为 patches，因此 patches 当前为空数组。没有房间设计数据时仍会输出空 design skeleton，并保留旧体素蓝图保存行为。

画布编辑器的材料调色板会从已注册 blocks 数据中按 ID 关键字扩展 floor/wall/roof/door 分类；保存后的 JSON 可作为玩家蓝图继续用于当前游戏，也可复制到 MOD 的 data/buildings/ 下作为正式建筑数据。
