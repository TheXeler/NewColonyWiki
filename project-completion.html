项目完成度审计

本页记录对当前工作树的审计结果，用来判断 NewColony 距离可长期开发、可对外发布和可扩展 MOD 平台还差什么。结论基于源码、CMake、CoreMod 数据、测试目录、Wiki 文档核对和 Debug 构建验证；本次未运行游戏或测试。

总体结论

领域完成度判断
引擎主干高C++20 静态库、可执行入口、Vulkan/GLFW/RmlUI/Lua/simdjson 等依赖、线程与运行时路径已形成完整主流程。
内容与 MOD 数据高ModLoader 自动扫描 17 类 JSON 数据；CoreMod 已提供约 340 个 JSON 数据文件，覆盖方块、配方、群系、建筑、区域、职业、文明、阵营等核心内容。
模拟玩法闭环中高职业、配方、文明、焦点、阵营、建筑、区域、天气、心情、AI 调度和体素世界都有实现；殖民者长期行为、社交、紧急行为和多阶段施工仍是 Alpha 级。
渲染与世界表现中Vulkan 管线、Chunk 网格、纹理图集、实体可视网格、SSAO、天空与地形生成存在；地形生成 pipeline 已有专门审计和 wiki 页面，复杂模型兼容、性能边界和美术资产完整度仍需实测。
工程质量中Debug 构建通过，CMake 源文件覆盖完整，单元测试有 8 个文件；测试集中在 ECS、网络协议、寻路、纹理图集、阵营、天气和区域，缺少渲染、存档、ModLoader 大规模集成和端到端玩法验证。
发布准备完成Windows 发布脚本会自动初始化 MSVC/Ninja 环境；CMake 安装规则包含可执行文件、运行库、glslang、引擎资源和 CoreMod，并通过 201 项回归测试与包内容校验。

审计证据

  • Engine/CMakeLists.txt 将引擎主体编译为 NewColonyEngine 静态库；源码覆盖检查显示 Engine/Main.cpp 是唯一不在静态库内的 .cpp，它由根 CMakeLists.txt 作为 NewColony 可执行入口编译。
  • cmake --build build -- -j1 在 2026-06-14 通过，输出 bin/NewColony.exe 和 bin/NewColonyTests.exe。构建仍有两个警告：BuildingSystem.cpp 未用参数，以及 LuaBindings.cpp 忽略 simdjson 返回值。
  • TERRAIN_PIPELINE_AUDIT.md 和 地形生成流程 已记录地形生成 pipeline 审查：删除未调用的 find_nearest_tile_for_chunk，并在 ChunkManager 中用 thread_local 缓存减少世界地图气候采样重复计算。
  • Lua API 速查 已按 ScriptEngine.cpp、LuaBindings.cpp 和 Engine.cpp 复核，补齐 settings、time、buildings、zone、world block data、HeldItem/Stats 和 NPC 阵营双边关系接口，并移除未绑定的装备槽注册条目。
  • 网络同步与 Mod 数据 已按 NetworkProtocol.hpp 复核命令名，确认当前命令类型为 MoveEntity、BuildBlock、MineBlock、AssignJob、GiveBlock、PostWork；旧的 GiveItem 文案已更正。ChunkDelta 现在按 ChunkSnapshot 与原始地形对比，跳过一致 sub-chunk，并用连续相同 BlockState{id,data} run 压缩长段修改。
  • 存档系统状态 已按 SaveSystem.cpp 和 RegionFile.cpp 更新：当前保存 world、entities、regions、mods、factions、jobs、focuses、manifest，其中 regions/*.ncr 用 region offset table 写出已加载 chunk 的 uniform/palette/dense sub-chunk payload，并把 light overlay 单独写入 chunk payload；payload 可用内置 RLE 压缩，读档和后续 chunk streaming 会从当前 slot 的 region payload 恢复 snapshot，targeted read 会缓存 region header/table 并只读取目标 payload，新 v2 region 会写入 block id dictionary 并在加载时按当前 MOD registry remap，运行时 far chunk unload 已对 terrain/light dirty chunk 做异步 region 写回。
  • 纹理格式、模型格式 和 着色器格式 已按 TextureAtlas.cpp、BlockTextureRegistry.cpp、ModPreprocessor.cpp 和 VulkanPipeline.cpp 复核：PNG 必须按 16×16 tile 切分，模型是 Blockbench/Minecraft 风格 JSON 子集，shader 会预编译但当前只由固定内置管线加载。
  • 音乐和音效格式 已按 AudioSystem.cpp、SoundBank.cpp 和 Engine.cpp 复核：data/audio/*.json 已通过 MOD 注册表加载到 SoundBank，Lua engine.audio 提供播放、停止、音量和 listener 位置接口。
  • 本地化与翻译 已按 LocalizationManager.cpp、LuaBindings.cpp、ScriptEngine.cpp 和 Engine.cpp 复核：本体 assets/lang/ 与 CoreMod/MOD lang/ 均可合并，Lua 同时暴露查询、切换、列表、热重载和文件加载接口；MOD 翻译合并发生在入口脚本加载之后，且相同 category/key 会按加载顺序覆盖。
  • UI 框架、UI CSS 主题 和 UI 图片资源 已按 LuaUi.cpp、UiTheme.cpp、CssParser.cpp、MainMenu.cpp 和 ModLoader.cpp 复核：玩家可见 UI 统一走 RmlUI；Lua UI 兼容 API 仅保留注册入口；主题系统只记录旧配置选择，不再应用到渲染层；主菜单背景由 mod.json 的 ui 字段声明，当前选择策略只支持 first。
  • MOD 调试控制台 和 配置文件 已按 DevConsole.cpp、EngineConsoleCommands.cpp、EnginePaths.cpp、InputManager.cpp 和 KeyBindings.cpp 复核：控制台支持 help/搜索/补全/权限/别名，配置路径固定在 mods/core/config/，别名目标只能是命令名，键位绑定读取 CoreMod 配置并在缺失时回退到 C++ 默认。
  • mod.json 和 MOD 是怎样加载的 已按 ModLoader.cpp 和 ModLoader.hpp 复核：当前只要求清单 id，但入口脚本默认 scripts/bootstrap.lua 且必须存在；enabled 是加载器保留布尔设置，非 core MOD 默认禁用。
  • 实体注册 和 数据组件 API 已按 EntityPrototypeFactory.cpp、StandardComponents.hpp 和 ScriptEngine.cpp 复核：实体原型 JSON 当前解析 Position、Speed、Health、Needs、Mood、Name、ColonistTag、AIState、Job、HeldItem、Equipment、Stats、Visual、Animation 和 HeadVisual；Rotation/Scale 是 Lua 可添加组件但不从原型 JSON 读取。
  • 配方注册、职业注册、文明注册 和 焦点注册 已按对应 Simulation 系统复核：直接 RecipeSystem 制作只支持单 HeldItem 槽，职业前置是“任一当前职业匹配”，文明的 starting_buildings/leader/traits/bonuses 尚未进入 CivilizationDef，Lua 焦点条件回调使用上下文表。
  • 数据类型总览 和 Lua API 指南 已按 WorkDefs.hpp、WorkPool.cpp、AISystem.cpp、LuaBindings.cpp、Engine.cpp 以及 CoreMod 的 crafting/construction/hauling/farming/mining 脚本复核：Lua 通过 engine.work 发布 build/mine/chop/haul/craft/research 等工作；工作完成事件包含 worker/tag/category/target/action/payload/tick；Craft 完成时仍由配方 payload 驱动产出。
  • 方块注册、地物注册 和 作物注册 已按 ModLoader.cpp、ModRegistry.cpp、LuaBindings.cpp、TerrainGenerator.cpp、Engine.cpp 以及 CoreMod farming/mining 脚本复核：方块 drops 支持字符串和对象，block_class/material 会影响遮挡与通行；作物阶段 ticks 当前被 CoreMod 加总为成熟时间，不会逐阶段替换方块；feature JSON 与 Lua 注册均会进入 TerrainGenerator。
  • 引擎源码按子系统分布约 191 个 C++ 源/头文件：Renderer 35、Core 28、Simulation 26、AI 16、UI 16、Voxel 14、Modding 10、ECS 9，以及 Audio、Input、Network、Save、WorldMap 等模块。
  • CoreMod/data 当前有 19 个数据目录，data/audio 已作为 audio 类型进入通用 ModLoader 注册表，并由音频系统加载为 sound bank。
  • 测试目录包含 19 个 GoogleTest 单元测试文件；原集中在 test_ecs.cpp 的覆盖已按主题拆到 test_ai_system.cpp、test_core_utilities.cpp、test_ecs.cpp、test_ecs_system_manager.cpp、test_modding.cpp、test_save_system.cpp、test_scripting.cpp、test_simulation_systems.cpp、test_tick_manager.cpp 和 test_voxel_terrain.cpp 等文件；各拆分文件已按实际使用裁剪 include，三处重复的临时目录 helper 收口到共享头 TestHelpers.hpp。
  • 本项目源码没有发现大量显式 TODO、FIXME 或 not implemented 标记；搜索命中主要来自第三方 miniaudio.h 和占位符字符串处理。

模块状态

模块状态已具备主要缺口
Core / ECS可用类型、数学、内存、日志、性能采样、线程、实体世界、Archetype、组件查询。需要更多负载测试和长时间运行诊断。
Modding / Scripting可用清单、依赖排序、科技和音频在内的多类数据注册、交叉引用校验、Lua 生命周期、事件、定时器、多组 engine API。公共 API 边界仍需固化。
Simulation部分完成Tick、确定性 RNG、配方、职业、文明、焦点、阵营、建筑、区域、心情、天气、CoreMod 系统。直接制作路径仍受单 HeldItem 槽限制，Craft 工作与 CoreMod stockpile 队列存在双路径产出风险，文明部分字段只校验不消费；殖民者生活循环、经济平衡、失败恢复和多阶段玩法还需要端到端验证。
AI部分完成WorkPool、WorkRegistry、方块 Action、物品 Action、Pathfinder、NavMesh、BehaviorTree、默认行为。Lua 工作发布 API 只暴露 build/mine/haul/craft/research，内部 Social/Patrol/Emergency 尚未作为脚本扩展点公开；巡逻、社交、应急、战斗和复杂任务规划仍需完善。
Voxel / WorldMap部分完成Chunk 数据、地形、群系、矿物、地物、流体、光照、方块更新、星球坐标和世界地图。世界生成规则仍在收敛，需要当前存档格式、性能和边界地形测试。
Renderer实验Vulkan 设备/交换链/管线、ChunkMesh、ChunkMesher、纹理图集、方块模型子集、实体视觉、SSAO、shader/model 预处理。跨 GPU 稳定性、资源热重载、通用 MOD 方块模型接入、复杂模型兼容和视觉验收仍不足。
UI / Input部分完成RmlUI 主菜单、HUD、暂停/设置、开发控制台、建造/研究/制造/殖民者面板、小地图/区域入口、help/补全/权限/别名、设置保存、主菜单背景资源、选择与按键绑定。通用控件 DSL、可访问性、键鼠冲突、第三方 MOD 配置合并和完整游戏内面板仍需整理；Lua UI 兼容层不再提供可见渲染。
Network / Save部分完成TCP Host/Client、快照、客户端命令、预测/补偿、MOD 数据交换、存档列表、原子写入、实体/天气/阵营/Job/焦点/chunk 方块状态恢复、ChunkDelta run 压缩、region offset table、RLE payload、targeted region header/table cache、region v2 block id dictionary/remap、far chunk 异步 dirty writeback 和 light-only dirty region 持久化。多人长期同步、断线恢复边界、建筑/区域实例存档、palette-aware delta 与 region 编码复用、已删除/重命名 block 的迁移规则和 MOD 自定义数据存档策略仍需加强。
Audio / Localization部分完成miniaudio 后端、SoundBank、data/audio 注册表、音量配置、Lua audio API、本体与 MOD 语言文件、参数化翻译、Lua locale API 和 locale 控制台命令。音频内容量和播放策略仍未达到完整发布级；本地化 key 冲突策略和入口脚本前翻译可见性需要 MOD 作者注意。

必须补齐的发布门槛

  1. 建立固定验证命令：Debug 构建、单元测试、至少一个无头或脚本化启动检查、CoreMod 数据完整性检查。
  2. 补充 ModLoader、当前存档格式、世界生成、建筑/库存/AI 闭环和网络同步的集成测试。
  3. 在当前 region chunk 存档、targeted header/table cache、region v2 block id dictionary、far chunk 异步 writeback 和 light-only dirty 写回上补齐 BuildingSystem 实例、ZoneSystem 实例、已删除/重命名 block 的迁移规则和 MOD 自定义运行时状态，否则读档无法证明完整恢复玩家修改过的世界。
  4. 补充 Craft 工作回归：验证 systems.crafting.queue 的 stockpile 预留路径不会和 C++ RecipeSystem::craft 直接路径重复发放产物。
  5. 把“实验”“部分可用”“稳定可依赖”的 API 边界继续同步到 当前能力状态 和各注册表页面。
  6. 整理发布流水线：生成可分发目录、复制运行时依赖、验证 shader 工具、校验 wiki、输出构建信息和变更清单。
本页不是“已发布完成”的证明。它说明当前代码已经具备可玩的引擎和 MOD 平台骨架，但发布级质量仍取决于运行验证、回归测试、性能测试、当前存档格式和内容平衡。
