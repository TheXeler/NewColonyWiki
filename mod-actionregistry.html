动作注册

动作（Action）定义在 data/actions/ 下，以 JSON 描述。动作是 AI 殖民者与世界交互的原子行为——挖矿、放置方块、收获作物、进食、饮水等。每个动作关联一个目标过滤器、执行时长和需求变化量。

动作不是配方，也不是工作分类。配方定义"输入 A + B → 输出 C"的合成关系；WorkType 定义工作属于哪个管理分类；WorkAction 定义"殖民者对某个方块或物品做什么，耗时多久，消耗多少体力/饥饿"的执行关系。动作由 AI 系统在调度时匹配和执行，不需要 Lua 脚本手动调用。
当前实现有一个需要修复的边界：ModLoader 校验和 CoreMod 数据使用 inventory_block_action，但 ActionRegistry 的运行时装载分支仍检查旧名 held_item_block_action。因此 core:eat_food 和 core:drink 会进入通用数据注册表，但不会作为 HeldItem 动作进入 ActionRegistry 执行路径；下面的物品动作格式是当前数据契约，不代表运行时闭环已经完成。

与 WorkType / WorkAction 的关系

工作实例进入 WorkPool 时会带有工作类型、所属势力、位置、基础时长和可选 data。工作类型负责分组、优先级和管理界面展示；动作负责完成时的实际效果。一个 WorkType 可以复用多个动作，例如“挖掘”工作可以执行 core:mine，也可以执行 core:chop_wood；它们都走方块交互 WorkAction，但目标过滤、时长和需求变化不同。

WorkAction 的基础种类由引擎硬性定义，MOD 通过本页的 JSON 注册具体动作参数。当前动作数据里的 base_type 对应执行路径，action_type 对应方块交互的基本类型。

两种动作类型

类型base_type说明
方块动作block_action殖民者对世界中的方块执行操作：挖掘、放置、交互。执行时设置 BlockInteractor 组件。
物品动作inventory_block_action殖民者从手持物品栏消耗物品：进食、饮水。执行时扣减 HeldItem 数量。

JSON 格式 — 方块动作

{
    "id": "my_mod:mine_stone",
    "base_type": "block_action",
    "filter": "my_mod:*_stone",
    "action_type": 1,
    "duration": 3.0,
    "needs": { "fatigue": 2.0 }
}

JSON 格式 — 物品动作

{
    "id": "my_mod:eat_berry",
    "base_type": "inventory_block_action",
    "filter": "my_mod:berry",
    "category": "food",
    "consume": 1,
    "duration": 1.5,
    "needs": { "hunger": -20.0 }
}

字段说明

字段类型必填说明
idstring是唯一标识，格式 <mod_id>:<name>。
base_typestring是"block_action" 或 "inventory_block_action"。
filterstring否Glob 过滤模式，决定动作匹配哪些方块/物品。默认 "*"（匹配全部）。
action_typeint方块动作必填交互类型：1 = 挖掘，2 = 放置，3 = 交互。仅 block_action 使用。
categorystring否物品分类过滤，如 "food"、"drink"。仅 inventory_block_action 使用。省略时不做分类过滤。
consumeint否每次执行消耗的物品数量，默认 1。仅 inventory_block_action 使用。
durationfloat否执行时长（秒）。方块动作默认 3.0，物品动作默认 2.0。
needsobject否动作完成后的需求变化量。键为需求名称，值为变化值（正数=增加，负数=减少）。
needs.hungerfloat否饥饿值变化。正值增加饥饿（恶化），负值减少饥饿（恢复）。范围 0~100。
needs.fatiguefloat否疲劳值变化。正值增加疲劳（恶化），负值减少疲劳（恢复）。范围 0~100。

Glob 过滤器

filter 字段使用简单的 glob 模式匹配方块 ID：

模式含义匹配示例
*匹配任意方块 ID所有方块
core:*匹配 core: 前缀的所有方块core:stone、core:wood
core:wood精确匹配仅 core:wood
core:*_ore前缀 + 后缀匹配core:iron_ore、core:copper_ore
*_crop后缀匹配core:wheat_crop、my_mod:corn_crop

规则：* 匹配任意字符序列；没有通配符时做精确匹配。多个动作可能匹配同一个方块——引擎按注册顺序返回第一个匹配结果。

action_type 说明

值名称说明
1挖掘（mine）破坏方块。方块的 drops 字段决定掉落物。
2放置（place）将手中物品放置到世界中。
3交互（interact）与方块交互但不破坏它，如收获作物。

执行流程

  1. 加载阶段：引擎从 data/actions/ 读取所有 JSON 文件，按 base_type 分类存入 ActionRegistry。
  2. 匹配阶段：AI 系统为殖民者分配任务时，根据目标方块的 ID 查找匹配的动作（遍历所有已注册动作，用 filter glob 匹配）。
  3. 执行阶段：
    • 方块动作：设置 BlockInteractor 组件（目标坐标 + action_type），动作完成时触发 block:interacted 事件。
    • 物品动作：检查 HeldItem 组件匹配后扣减数量，直接应用需求变化。
  4. 需求更新：needs 中的 delta 值应用到殖民者的 Needs 组件，结果 clamp 到 [0, 100]。
动作完成时会触发 block:interacted 事件（方块动作）或直接扣减物品（物品动作）。Lua 脚本可以监听这些事件来做后续处理——比如 mining.lua 监听 block:interacted 来处理挖掘掉落和经验奖励。

验证命令

在控制台（按物理 Grave/反引号键）中确认动作注册：

list_data actions              -- 列出所有已注册的动作
list_data actions mod=core:    -- 列出 core 前缀的动作
data core:mine                 -- 查看单个动作的完整 JSON
